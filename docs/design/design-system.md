# 수저 게임 디자인 시스템 (SPEC-003 DS3)

「수저 게임」은 한국에서 한국인으로 태어나 사는 한 번의 인생을 다루고, 태어난 집(수저)이 삶에 얼마나 영향을 주는지 체감하게 하는 게임이다. 디자인은 그 정체성을 첫 화면에서 바로 읽히게 하되, **담담하고 단정하게** 전한다 — 감탄사·과장·자극적인 이미지 없이, 서류와 통계표처럼 정직한 얼굴로.

- 토큰(값의 원본): `src/styles/tokens.css` — 색·간격·모서리·그림자·글자·움직임·크기. 라이트 / 다크(시스템·수동) / 강제 색상 / 움직임 줄이기.
- 컴포넌트 참고 구현: `docs/design/mockups/ds.css` — 시안 HTML이 쓰는 클래스. developer는 이 구조·클래스를 기준으로 `src/`에 옮긴다(토큰만 쓰고 색 값을 직접 적지 않는다).
- 자산: `src/assets/` — 심볼·로고(`symbol-*.svg`, `logo-*.svg`, `brand/`), 아이콘 스프라이트(`icons/ui-icons.svg`, `icons/spoon-grades.svg` — 칩 변형 `sp-1`~`sp-5` + 큰 변형 `sp-1-lg`~`sp-5-lg`), 얼굴 생성 함수(`faces/faceLayers.ts`).
- 점검: `npx vite-node scripts/checkContrast.ts --write` → `docs/design/contrast-report.md`(라이트 81쌍 + 다크 81쌍 — 토큰 쌍 77 + `src/styles/doc.css`가 불투명도로 합성하는 띠 표기 1쌍 + 장식 도장 글자·테두리 3쌍(불투명도 없음, QM3-5: 장식도 면제 없음), 실패 0. 2026-10-17 M4 후속 재생성 — 수치 변화 없음, 머리글은 developer가 고친 문구. 생성기는 `tokens.css`·`doc.css`만 읽으므로 `title.css`·`dash.css`의 불투명도 규칙(`.btn[aria-disabled]`·`.choice[aria-disabled]` 0.55 = 0.4초 입력 가드의 과도 상태)은 보고서에 없다 — 비활성 컨트롤의 대비 결정은 2절). `tests/designAssets.test.ts`가 같은 계산과 자산 계약을 단언한다(44건 — 2026-10-17 R-251 강제 색상 블록 특이도 포함). 상태 4색 색각 시뮬레이션 시트: `npx vite-node scripts/design/previewStatColorsCvd.mjs` → `screens/003/status-colors-cvd.png`.
- 시안: `docs/design/mockups/*.html` → 스크린샷 `docs/design/screens/003/*.png`. 다시 만드는 순서는 `docs/design/README.md`. 문구 기준은 `docs/design/copy.md`. 첫 화면 시안은 M2 구현(`src/screens/TitleScreen.tsx`·`src/styles/title.css`)과 같은 구조·같은 모델이다(2026-10-16, M3 착수 정리): 캐러셀 14장 전부를 품고 `?slide=<id>`로 보이는 슬라이드를, `title-continue.html?state=confirm`으로 확인 단계를 보인다.
- **M3·M4 화면 설계자가 먼저 읽을 것**: 11절 「공통 패턴」 — 고정 요소 높이 변수(`--bar-h`·`--head-h`)와 `scroll-padding`(CM10), 띠·헤더 고정 해제(QM2-12), 글자 200% 리플로(CM11), 구분 기호 사슬·짧은 쌍(QM2-10), 강제 색상의 상태 색(+ 시스템 색 배경의 백플레이트), 컨테이너 쿼리(+ 폴백), **11-7 서류 격자·칩·비교 표·FitPair(M3에서 확정)**, **11-8 낱말 끊김**. 룰렛·출생신고 시안은 M3 구현과 같은 모델(`core/roulette.ts#buildRoulette`·`core/birthReport.ts#birthSentence`·`core/peers.ts#peersOf`·`data/birthCompare.ts` …)이고(2026-10-16, R-270), 남은 차이·명세 차이는 `docs/design/diff-003.md`. **M4 대시보드 시안**(`dashboard-infant/adult.html`, 밀린·오류 화면 `system.html`)은 2026-10-17 M4 착수 정리에서 11절 규칙에 맞췄다(`ai-log/2026-10-17_SPEC-003_design-M4prep.md`) — 구현된 공용 부품(`ui/Brand.tsx#SiteHead`·`ui/Grade.tsx#GradeChip/GradeLine`·`ui/GuardedButton.tsx`·`ui/useBottomBar.ts`·`ui/FitPair.tsx`·`ui/Glue.tsx`)을 그대로 쓰는 전제다.

## 1. 정체성 — 톤·색·로고

### 톤
| 원칙 | 화면에서 |
|---|---|
| 담담함 | 큰 글자는 사실(이름·나이·숫자)에만 쓴다. 느낌표·이모지·감탄 문구 없음. 그림자는 얕고(`--shadow-1`) 움직임은 짧다(`--dur` 200ms) |
| 서류의 정직함 | 출생신고는 문서(띠·큰 이름·격자·「가상의 서류」 표기), 통계는 값·기준 연도·출처를 항상 함께 적는다. 가짜 데이터·설계값은 화면에 그렇게 적는다 |
| 풍자는 구조로 | 색이나 그림으로 조롱하지 않는다. 수저 다섯 자루를 **같은 모양·다른 재질**로 나란히 세우는 것, 선택지 아래 작은 영향 표기, 「다른 집 아이들과 견주면」 표(`copy.md`) 같은 **배치와 대비**가 풍자를 맡는다 |
| 한국의 밥상 | 바탕은 한지색(`--c-bg`), 글자와 심볼은 먹에 가까운 쪽빛(`--c-brand`), 강조는 놋쇠색(`--c-accent`). 숟가락은 한국 숟가락(둥근 머리·긴 자루) |

### 색의 뜻
- **쪽빛 `--c-brand` #26324a**: 로고·주요 버튼·선택 테두리·진행률. 먹색에 가까운 남색이라 특정 정당의 파랑·빨강과 겹치지 않는다. 순수 파랑·빨강은 어디에도 주색으로 쓰지 않는다.
- **놋쇠 `--c-accent` #8a6a14**: 인용 박스 왼쪽 막대, 「나의 기록」 줄, 접수 도장. 「사람이 남긴 것」의 색.
- **수저 5단계 `--c-grade-1~5`**: 재질색(흙·동·은·금·다이아몬드). 항상 **이름 + 점 개수**와 함께 쓴다 — 색만으로 단계를 전하지 않는다. 아이콘은 **무늬 없는 숟가락 실루엣**(칩, ≤ 24px — 강제 색상·단색에서도 채운 실루엣, R-190)이고 32px 이상에서만 닫힌 채움 표식을 둔다. 머리 안에 선 무늬는 어느 크기에도 없다(R-121 마스터 결정, 6절 「수저 칩」). **수저 아이콘은 이름·점 없이 단독으로 쓰지 않는다.**
- **상태 4색 `--c-stat-*`**: 건강(연지, 장밋빛 붉은색)·행복(자주, 자줏빛)·지식(**파랑** — 밝은 하늘빛 파랑. 「쪽빛」은 브랜드 `--c-brand`에만 쓰는 이름이다)·관계(보라). 규칙은 넷이고 모두 `tests/designAssets.test.ts`가 두 테마 각각 단언한다: ① **자리별 금지**(R-172(e) 취지를 REV-003-D-4에서 좁힘) — 건강은 녹(90~170°) 금지, 행복은 황(35~70°) 금지, 네 색의 계열 순서가 참고 캡처의 녹·황·청록·적갈이 아닐 것, 서로 색상 20° 이상(원형 거리). ② **뜻이 다른 토큰 — 수저 5색·▲▼ — 과 ΔE2000 ≥ 15, 상태색끼리 ≥ 12**(R-192), 크롬 색 `--c-link`·`--c-focus`와는 ≥ 10(R-195③ — 링크 글자·포커스 링은 상태 바와 같은 자리에 오지 않고 뜻을 나르지 않으므로 15보다 낮게 둔다). ③ **이웃 쌍 명도 차 ΔL\* ≥ 12**(지식↔관계·행복↔관계, R-195①) — 적록 색각 이상에서는 색상이 무너지므로 명도로 가른다(라이트 L\* 45·53·53·35, 다크 58·53·55·69). ④ **색각 시뮬레이션**(Machado 2009 protan·deutan 심각도 1.0)에서 모든 쌍 ΔE2000 ≥ 8(R-195②, 시트 `screens/003/status-colors-cvd.png`). 바에는 이름·아이콘·숫자를 함께 적는다. 상태 카드 안에 링크 글자(`--c-link`)를 두지 않는다.
- **`--c-up`(초록) / `--c-down`(붉음)**: 영향 표기 기호의 보조색 — 기호 **모양** ▲/▼이 방향(늘어남/줄어듦), **개수**가 크기, **색**은 그 변화가 **이로운지·해로운지**를 돕는다. 부채만 반대(부채 ▲ = `--c-down`, 부채 ▼ = `--c-up`; 2026-10-17 M5 r2 마스터 결정 — 다른 항목은 늘어남이 이로운 쪽이라 초록 ▲를 「좋아진다」로 읽는데, 빚이 늘어나는 것이 좋은 일처럼 보이면 안 된다). 색은 보조라 색맹·강제 색상 규칙은 그대로.

### 로고 규칙 (DS1·DS2 — 확정 A안 「담긴 땅」, R-128)

- **금지(R-130)**: 한반도 실루엣을 숟가락 없이 **단독으로 쓰지 않는다**(한반도기 구성과 겹친다 — 항상 수저와 한 묶음). **하늘색·연파랑 계열**(한반도기 색)로 칠하지 않는다. 로고를 기울이거나 늘이거나 색을 바꾸지 않는다(토큰 `--c-logo`만). 분단선·경계·지역 표시를 더하지 않는다.

## 3. 테마 선택 규칙 (DB6·CM4)

1. 기본은 시스템 설정 `prefers-color-scheme`. `tokens.css`의 `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) … }`.
2. 사용자가 다크 모드 버튼으로 고르면 `<html data-theme="light|dark">`를 쓰고 저장한다. 이 값이 시스템 설정보다 우선한다.
3. 다크 토큰은 두 블록(미디어쿼리 / `data-theme`)에 같은 값으로 적혀 있다 — `checkContrast`와 테스트가 두 블록의 불일치를 0으로 지킨다. **값을 고칠 때 두 곳을 함께 고친다.**
4. 강제 색상(`forced-colors: active`): 토큰이 시스템 색(Canvas·CanvasText·ButtonText·Highlight…)으로 바뀐다. 의미를 지닌 요소(눌린 버튼·선택 카드·바 채움·수저 점·토글)는 `ds.css`의 `@media (forced-colors: active)` 블록처럼 **모양**(이중 테두리·굵기·무늬·채움)으로 구분한다. 얼굴·로고 SVG는 `forced-color-adjust: none`. 상태(hover·active·focus) 색은 11-5절.
   - **R-251 반영(2026-10-17, M4 착수 조건 — designer, REV-003-M2-5)**: 강제 색상 블록의 선택자는 **`:root, :root:not([data-theme='light']), :root[data-theme='dark']`**다. `:root` 하나(특이도 (0,1,0))면 다크 두 블록(둘 다 (0,2,0))에 져서 OS 다크·수동 다크 + 강제 색상에서 시스템 색 매핑이 다크 팔레트에 덮였고, 밝은 고대비 테마 위에 수동 다크를 켜면 `forced-color-adjust: none` 요소(로고 `--c-logo`, 선택 카드 `__meta`·`__desc`, 포커스 링 `--c-focus`, 띠 표식 `--sp-mark`)가 밝은 Canvas 위에 어두운 팔레트 값으로 그려져 사라질 위험이었다. 셋을 한 규칙에 적으면 다크·수동 다크에서 특이도 (0,2,0)으로 맞고 소스 순서가 뒤라 이기며, 수동 라이트에서는 `:root`만 맞지만 그때는 다크 블록도 맞지 않아 기본 블록을 순서로 이긴다. `!important`는 쓰지 않고 블록 안의 값(`--sp-mark: Canvas` 포함)은 그대로다. 점검: `tests/designAssets.test.ts` 「R-251」이 선택자 목록·특이도(다크 두 선택자 각각 이상)·소스 순서·`!important` 없음·값 유지를 단언하고(옛 `:root {`로 되돌리면 실패함을 확인), `checkContrast`의 다크 두 블록 일치 검사는 그대로다. **실제 렌더 e2e(`colorScheme: 'light'` + 강제 색상 + `<html data-theme='dark'>`에서 로고·선택 카드 글자·포커스 링의 바탕 대비 ≥ 3:1)는 M4 developer가 수동 다크 토글을 만들 때 함께 넣는다.** `title.css`·`doc.css`가 요소마다 시스템 색을 직접 적어 둔 것(주 버튼·선택 카드·점·문서 띠)은 그대로 둔다(토큰에 기대지 않는 이중 안전).
5. 움직임 줄이기: `prefers-reduced-motion: reduce` 또는 앱 설정 `<html data-motion="reduce">`이면 `--dur-*`가 0.01ms가 된다. 캐러셀 자동 전환·진행률 애니메이션은 JS가 같은 신호를 읽어 끈다. **룰렛은 회전 화면을 거치지 않고 곧바로 결과 상태**(제목 「태어날 곳이 정해졌습니다」·결과·작은 글·「출생신고 보기」)를 보이고 제목 아래 안내 한 줄(`.motion-note`)을 더한다(R-171, 시안 `roulette-result-mobile-reduced.png`).

## 10. 구현할 때 (developer)

1. 색·간격·글자 크기는 **토큰만** 쓴다. `ds.css`를 `src/styles/`로 옮길 때 클래스 이름과 구조를 유지하면 시안과 1:1로 대조할 수 있다. 문구는 `docs/design/copy.md`에서 가져온다.
2. 다크 토큰을 고치면 `tokens.css`의 두 블록을 함께 고치고 `npx vite-node scripts/checkContrast.ts --write`로 실패 0을 확인한다(테스트도 같은 계산을 한다). 상태 4색을 고치면 §1 「상태 4색」의 네 규칙(자리별 금지·ΔE2000·ΔL\*·색각 시뮬레이션)을 `tests/designAssets.test.ts`로 함께 확인하고, 시트는 `npx vite-node scripts/design/previewStatColorsCvd.mjs`로 다시 만든다. SVG 자산에서 CSS 변수는 프레젠테이션 속성이 아니라 `style`에 쓴다(테스트가 막는다).
3. 로고: 헤더는 **`brand/a/logo-header.svg` 40px**(`--logo-h-header`), 첫 화면은 `brand/a/logo-stacked.svg`(모바일, 236px) / `logo-a.svg`(데스크톱, 108px). 크기 단언(DS1 e2e)은 **워드마크 글자 높이** 기준: 첫 화면 ≥ 40px, 헤더 ≥ 22px. 글자 높이 = 워드마크 칸 높이 × 0.9 (스택 로고: 로고 높이 × 72/248 × 0.9, 헤더 로고: 로고 높이 × 0.64 × 0.9).

### 11-1. 고정 요소(하단 띠·고정 헤더)와 키보드 포커스 (CM10·QM2-1)
- 화면 가장자리에 붙는 요소(`position: fixed`, 붙은 `sticky`)는 **실제 높이를 CSS 변수로 노출**한다: 하단 띠 `--bar-h`, 상단 고정 헤더가 생기면 `--head-h`. 높이는 상태·글자 크기마다 다르므로 **고정값을 적지 않고 잰다** — 첫 화면이 쓰는 `ui/barRelease.ts#watchBarRelease(bar, …)`(ResizeObserver, `<html>`에 변수·클래스)를 그대로 부른다(M3·M4는 `ui/useBottomBar.ts#useBottomBar(ref)` 경유). **M4 대시보드의 하단 띠는 < 960px에서 고정되는 진행 줄 `.controls-fixed`**다(`.bottom-bar`가 아니어도 같은 함수에 그 요소의 ref를 넘긴다 — 시안의 흉내 스크립트도 `.bottom-bar, .controls-fixed`를 잰다).
- 문서 루트(`<html>`)에 스크롤 여백: `scroll-padding-bottom: calc(var(--bar-h) + var(--sp-3))`, 위는 `scroll-padding-top: var(--sp-3)`(고정 헤더가 있으면 `html.has-sticky-head { scroll-padding-top: calc(var(--head-h) + var(--sp-3)) }`). 여유 12px은 포커스 링(3px + 간격 2~4px)보다 크다. 안쪽 스크롤 영역(따라다니는 카드·인생 기록 목록 등)은 자기 `scroll-padding`을 둔다.
- **고정 헤더의 해제(M4 대시보드 `.dash-head`, 2026-10-17 designer 제안 — developer가 같은 규칙으로 구현·e2e)**: 헤더 높이 + (진행 줄이 고정돼 있으면 그 높이)가 **작은 뷰포트 높이(`100svh`)의 50%를 넘으면** `<html class="head-released">` — 헤더는 `position: static`으로 보통 흐름에 놓여 스크롤되고 `scroll-padding-top`은 `var(--sp-3)`로 돌아간다. 가로 폰 667×375(헤더 약 100px + 진행 줄 약 120px = 59%)·400% 확대 상당 320×256이 여기 해당한다 — 고정 요소 둘이 화면 대부분을 덮어 본문·포커스가 설 자리가 없어지는 것을 막는다. 진행 줄 자체의 해제는 QM2-12 그대로(진행 줄 높이 > 50%, 그때는 둘 다 풀린다). 판정은 `--bar-h`와 같은 측정(ResizeObserver + resize, 작은 뷰포트 높이)이고 클래스만 바뀌므로 포커스는 그대로다. 시안 `dashboard-adult-low.png`(320×256: 헤더가 풀려 스크롤돼 올라가고 진행 줄만 고정).
- 본문 끝 여백은 `.page-end-space { height: calc(var(--bar-h, 164px) + var(--sp-2)) }` — 폴백 164px은 가장 큰 상태. 띠가 가리는 만큼만 비우고, 띠 높이가 바뀌면 함께 바뀐다.
- 가용 높이(뷰포트 − 고정 요소 − 스크롤 여백)보다 큰 포커스 대상(큰 글자의 라디오 카드·여러 줄 링크·슬라이드 영역)은 **위쪽 변과 링이 보이게** 맞춘다(`ui/focusReveal.ts#revealTopOfTallFocus`) — 키보드 포커스(`:focus-visible`)에서만, 눌러서 생긴 포커스는 화면을 점프시키지 않는다(R-241).
- 검사: `e2e/focusObscured.ts#auditFocus` × `STANDARD_VIEWPORTS` 11종 × 글자 100·200% × 화면 상태 전부 — 포커스 링 상자와 고정 요소 상자의 겹침 0, 조작 요소 집합 = 순회로 닿은 집합. 고정 요소는 테스트가 자동으로 모으므로 새 띠·헤더에 이름을 등록할 일은 없다.

### 11-2. 하단 띠 고정 해제 (QM2-12·R-233·R-240)
- 띠 높이가 **작은 뷰포트 높이(`100svh`)의 50%를 넘으면** `<html class="bar-released">` — 띠는 `position: static`으로 본문 끝(푸터 다음)에 놓인다. 판정·클래스는 `watchBarRelease`가 한다. `innerHeight`로 재지 않는다(모바일 주소창 접힘에 흔들려 스크롤 중 고정↔해제가 뒤집힌다). 높이 미디어 쿼리로 풀지 않는다(띠 높이는 상태마다 다르고 rem 미디어 쿼리는 글자 확대 시험에 반응하지 않는다).
- 함께 풀 것: `scroll-padding-bottom` → `var(--sp-3)`, `.page-end-space` 숨김, `--bar-h`에 묶인 다른 계산(첫 화면 오른쪽 열의 `max-height`). 띠 위끝 선은 **테두리가 아니라 그림자**(`--shadow-bar`, 풀린 띠 `0 -1px 0 var(--c-border-strong)`) — 테두리로 그리면 띠가 1px 커져 `--bar-h`가 해제 때문에 어긋난다. 강제 색상은 그림자를 지우므로 `.bottom-bar { border-top: 1px solid CanvasText }` **한 규칙을 고정·해제 공통**으로 둔다.
- 전환(창 크기·회전·글자 크기·확인 단계 열고 닫기)에서 포커스를 가진 요소는 포커스를 잃지 않는다(클래스만 바뀐다). 풀린 띠 안의 버튼이 포커스를 받으면 화면 안으로 스크롤되고, 확인 단계처럼 안내문이 있으면 안내문 첫 줄과 포커스 버튼이 함께 보이게 한다(`ui/focusReveal.ts#revealWithinReleasedBar`).
- 낮은 화면(400% 확대 상당 320×256 등)에서 주 버튼이 스크롤 아래로 가는 것은 받아들인 대가다. 시안: `screens/003/title-confirm-low.png`.

### 11-3. 글자 200% 리플로 (CM11·QM2-3)
- 측정 조건: (가) `html { font-size: 100~200% }` × 320·360 (나) 640×400·512×384·320×256. 가로 넘침 0px, 잘림 0, 이름표 겹침 0, 기본 버튼 높이 ≥ 44px·누름 가능, 고정 띠 ≤ 화면 높이 50%(아니면 11-2로 해제).
- `white-space: nowrap`은 **숫자+단위·날짜 같은 짧은 묶음**(`.nowrap`)에만. 구절·사슬은 `.keep-phrase`(inline-block, `max-width: 100%` — 줄에 안 들어가면 통째로 다음 줄로, 구절이 한 줄보다 길 때만 안에서 끊긴다).
- 가로 배열(수저 띠·버튼 줄·도구 줄)은 `flex-wrap`으로 다음 줄로 접는다 — 가로 스크롤로 해결하지 않는다. 칸의 최소 폭은 이름의 가장 긴 낱말(`min-width: min-content`). 접힘 모양을 미리 정한다(수저 띠: 앞 넷 같은 폭 + 다이아몬드 1.3배, 못 들어가면 줄바꿈 / 도구 줄 이름 두 줄까지).
- 큰 숫자는 칸 폭에 맞춰 글자 크기를 줄인다: `.slide__value { font-size: min(var(--fs-3xl), calc((100cqw − 단위 폭) / var(--value-em))) }` — 값 글자 폭(em)·단위 글자 수를 인라인 변수로 넣는다(`core/carousel.ts#valueWidthEm`). 숫자는 중간에서 끊기지 않는다.
- 글자·간격·고정 높이는 rem/em. 그래프 글자는 13px 아래로 내려가지 않는다(R-206).

### 11-4. 구분 기호 사슬·짧은 쌍·값 줄 (QM2-4·QM2-5·QM2-10·QM2-11)
- 「·」「/」「—」가 **줄 끝이나 첫머리에 혼자 남지 않는다**. 글자는 `ui/Glue.tsx`로 감싼다(`core/glue.ts`가 사슬·붙은 기호·괄호 낱말·숫자+단위·날짜를 자동으로 묶는다). 설계 쪽에서 정할 것 셋:
  1. **항목 수가 데이터·설정에 따라 바뀌는 나열은 쉼표 나열**(「국가데이터처, 행정안전부, 교육부」, `commaList`) — 가운뎃점 금지. 쉼표는 앞 낱말에 붙어 줄 끝에 와도 되고 첫머리에는 오지 않는다.
  2. 「·」는 **항목 수가 고정된 짧은 쌍**에만(「인구 10만 명당 · 2025년 기준」, 「통계 기준: 2025년 · 마지막 갱신 2026-10-15」). `src/`에서 `join(' · ')`로 화면 글자를 잇지 않는다(`tests/glue.test.ts`가 사용처를 잠근다).
  3. 짧은 쌍은 **`ui/Pair.tsx`**로 그린다: 한 줄에 들어가면 「A · B」, 칸이 좁거나 글자가 커서 넘치면 기호를 감추고 두 항목을 따로 줄로(두 항목 사이 공백은 기호 조각 밖에, R-242). 문턱은 **컨테이너 폭을 em으로** 견주는 컨테이너 쿼리(기준 줄 14em, 보조 줄 16.5em = 실측 한 줄 폭 + 15~20%). 새 쌍을 만들면 같은 방법으로 실측해 문턱을 더한다(`title.css`·`ds.css`의 `@container` 블록). 시안: `screens/003/title-a-pair-split-320.png`(두 줄 모드).
- **값 줄과 기준 줄을 나눈다**(형식표 A~D, SPEC QM2-4): 값 옆 칸에는 단위 낱말 하나(「27.8명」「240,326건」), 「인구 10만 명당」 같은 분모 문구는 기준 줄(「인구 10만 명당 · 2025년 기준」)이나 문장형(「인구 10만 명당 27.8명」). 「명당 명」「건 건」처럼 겹치는 표기 금지. 기준 연도는 한 값(`latest.year`)에서 만든다.
- **제목이 약속한 값은 눈에 보인다**(QM2-11): 제목(슬라이드·카드·패널 머리글)에 이름이 든 지표마다 그 값이 같은 화면의 눈에 보이는 글자에 있다 — 대체 텍스트·`sr-only` 표는 세지 않는다. 캐러셀은 큰 값 바로 아래 줄(「조혼인율 인구 1천 명당 4.7건」, 선 무늬 없음, 기준 줄 앞). M3 출생신고 비교표·M4 대시보드 패널의 제목도 같다 — 값을 보이거나 제목에서 이름을 뺀다.
- **데이터가 담아 온 구분 기호는 표시 함수가 1·2항에 맞춘다**(M7b 인용 출처 줄, 2026-10-19 — `src/core/citations.ts#sourceWho`·`sourceTitle`, `copy.md` 6-3): 데이터 파일의 기관 나열 「국가데이터처·교육부」는 화면에서 **「국가데이터처, 교육부」**(1항 — 기관 수가 자료마다 다르다), 수집자가 이어 쓴 자료 이름 「{조사 이름} — {표 이름}」은 **「{조사 이름}: {표 이름}」**(사슬이 글자 200% × 폭 320에서 늘 한 줄보다 길어 QM2-10 규칙 1대로 글을 바꾼다 — 쌍점은 쉼표처럼 앞 낱말에 붙는 문장부호라 줄 끝 허용·첫머리 불가). 원제를 그대로 보여야 하는 글(연구 논문 제목, M-11)에는 변환을 걸지 않으므로, 원제가 아닌데 연구 `kind`로 든 이름(누리집 안내 페이지)은 **데이터에서** 「: 」으로 적는다. 글자가 아닌 묶음(`Glue`·`.keep-phrase`)은 그대로 — `.keep-phrase`는 `inline-block`이라 덩어리가 한 줄보다 길면 안에서 공백 자리에 접힌다(「국가데이터처, / 교육부(2026),」 — 쉼표 뒤, 허용).

- **시간 값(`mm:ss`) 바로 뒤에는 조사를 붙이지 않는다**(M8, 2026-10-19 — `copy.md` 8-1 ④·8-2): 플레이 시간처럼 눈에 보이는 글자(「12:36」 → 「육」, 받침 ㄱ)와 낭독 글자(sr-only 「12분 36초」 → 「초」, 받침 없음)가 다른 값은 뒤에 오는 을/를·과/와·이/가가 한쪽에서 어긋난다. 문장을 「세월이 흐른 시간 12:36, 결정을 읽고 고른 시간 11:42의 합입니다.」처럼 쉼표·「의」(받침과 무관)로만 잇거나 값을 문장 끝(마침표 앞)이 아닌 명사 뒤 자리에 둔다. 같은 이유로 값 뒤에 「을 더한」 「과」를 쓰지 않는다. `tests/designAssets.test.ts`가 시안의 `</time>` 바로 뒤 글자를 쉼표·「의」·없음으로 잠근다.
- **한 음절 지시 관형사(「이」「그」「저」)는 뒤 어절과 한 묶음이다 — 줄 끝에 홀로 남지 않는다**(M8 후속 2, 2026-10-19 — REV-003-M8-1 관찰 4, designer 판단 「묶는다」): 좁은 폭·큰 글자에서 「…넣지 않았습니다. 이 / 기기에만 저장됩니다.」(엔딩 360)·「진행은 이 / 기기에 남아요.」(첫 화면 320 · 200%)처럼 관형사가 줄 끝에 남으면, 마침표 뒤의 「이」가 조사나 오타처럼 읽히고 다음 줄 첫머리의 명사가 주어처럼 읽힌다 — 관형사와 명사는 한 뜻 단위다. 묶음은 늘 두 어절(「이 기기에만」 ≤ 6글자)이라 어느 폭에서도 비용이 없다. 방법: `core/glue.ts`에 규칙 하나 — 어절로 홀로 선 「이」「그」「저」(앞이 공백·문장 첫머리·여는 괄호·「, 뒤가 공백 + 한글 어절)와 **바로 뒤 어절**을 `chain`(`.keep-phrase`, inline-block `max-width: 100%`)으로 — `nowrap`이 아니다(뒤 어절이 긴 지명·낱말일 수 있어 넘침 0을 지킨다; 묶음이 한 줄보다 길 때만 안에서 갈린다). 붙은 「이」(「세월이」「이서연의」)·조사·수관형사(「한 해」「두 번」)·사용자 글(`data-user-text`)은 대상이 아니다. 글자는 바꾸지 않는다(접근 가능한 이름·복사 글자 그대로). 적용 범위: `Glue`를 거치는 모든 글에 자동(캐러셀·출생신고 주석·인용 박스·기록 시트 안내 「이 기기에만」·자산 도움말 「그 선택만으로」…)이고, 아직 `Glue`를 거치지 않는 **고정 문장**(첫 화면 FS5 설명·가상 인구 주석, 엔딩 플레이 시간 보조 문장·다시 태어나기 안내, 나가기 확인 보조 문장, 영향 안내 한 줄)은 `Glue`로 감싼다; 제목(h1·시트 제목)은 11-8의 제목 규칙(글자 크기 상한·compact 한 줄 줄임)이 있어 감싸지 않는다. 데이터 서술 문장(이벤트 결과·연표·기록 줄 — 「그 아이는」 31어절)은 그 줄을 `Glue`로 감쌀 때 함께 적용된다(2차 가능). 11-8의 **두 글자 끝줄 허용**(문단 마지막 줄의 짧은 낱말)은 그대로다 — 이 항은 줄 **끝**의 관형사 고아만 막는다. 구현 항목 `diff-003.md` **D-97**(규칙·시험)·**D-98**(고정 문장 감싸기)·**D-99**(데이터 서술 줄, 2차 가능). 시안 생성기는 같은 함수(`glueSegments`)를 쓰므로 D-97이 들어오면 재생성만으로 따라간다. **구현 확정(2026-10-20, developer r2 — D-97·D-98 닫힘, `ai-log/2026-10-19_SPEC-003_design-M8.md` 「후속 3」)**: `core/glue.ts` `CHAIN` 맨 끝 대안 `(?<![^\s(「])[이그저] [가-힣][^\s(·/—]*(?!\S)(?! - **사슬이 한 줄보다 길면 갈리는 자리를 디자인이 정할 수 없다 — 데이터로 채우는 글의 사슬은 가장 좁은 한 줄보다 짧아야 한다**(2026-10-19 후속 3, REV-003-M7b-2 R-398 전수 실측 — `ai-log/2026-10-19_SPEC-003_design-M7b.md` 「후속 3」): Glue 묶음(`.keep-phrase`)이 안쪽 폭보다 길면 브라우저가 묶음 **안**에서 「·」 뒤(「출생아수·」 줄 끝 — 위반) 또는 괄호 앞(「(1970~)」 다음 줄 — 허용)에서 가르는데 어느 쪽인지는 폭마다 다르다(같은 305px 사슬이 223px에서는 괄호 앞, 257~297px에서는 「·」 뒤). 그러므로 인용 요약·출처 자료 이름처럼 **데이터가 채우는 글의 「·」「/」「—」 사슬은 붙은 괄호·구두점까지 합쳐 가장 좁은 한 줄(320 · 글자 200% 인라인 카드 223px)보다 짧아야 한다** — 요약(28px) 한글 7자 + 마침표(≈ 203px), 출처(24px) 한글 9자 상당(216px). 길면 표시 변환이 아니라 **데이터를 고친다**(쉼표 나열·「와/과」 — 1항): 자료 이름의 「·」는 나열(「출생아수·합계출산율」)일 수도 복합어(「방과후·돌봄 교육」)일 수도 있어 기관 나열처럼 일괄 쉼표로 바꾸면 뜻이 바뀐다. 같은 이유로 문장 끝의 「숫자+단위+서술어+마침표」 한 덩어리(「4.53명이었습니다.」 226.5px)가 216~223px 창에 들면 마침표만 다음 줄 첫머리에 남는다(`overflow-wrap: anywhere`의 비상 끊김) — 덩어리를 끊어 쓴다(「4.53명으로 집계되었습니다.」). 구현 항목 `diff-003.md` **D-66**(데이터·단위 시험)·**D-67**(상시 e2e — 연결 카드 × 세상 전부, 320 인라인 × 150·200%).

### 11-5. 강제 색상에서 상태(hover·active·focus) 색
- `forced-color-adjust: none`을 준 요소는 브라우저가 색을 대신 고쳐 주지 않으므로 **상태마다 배경·글자를 시스템 색 한 짝으로** 못 박는다: 쉬는 상태 `ButtonFace`/`ButtonText`(주 버튼) 또는 `Canvas`/`CanvasText`, hover·active `Highlight`/`HighlightText`, 키보드 포커스는 쉬는 짝 그대로(링은 `outline`이 그린다), 포커스 중 hover·active는 다시 `Highlight` 짝(특이도가 포커스 규칙에 지지 않게 `:focus-visible:hover`로).
- 보통 모드의 `:hover { background: var(--c-brand-hover) }`가 강제 색상 블록보다 특이도가 높으면 토큰 매핑(`ButtonText`)이 배경에 칠해져 글자와 같은 색이 된다 — 첫 화면 주 버튼의 글자가 사라졌던 원인(REV-003-M2-4 r6 후속). **새 hover·active·눌림 규칙을 더할 때마다 강제 색상 짝을 같은 자리에 적는다**(`tests/barRelease.test.ts`가 첫 화면 CSS의 `:hover` 수를 센다 — 새 화면도 같은 잠금을 둔다). 눌림·선택은 이중 테두리·체크 같은 모양으로(8절). `tokens.css` 강제 색상 블록의 특이도는 3절 R-251(2026-10-17 반영 — 다크 두 선택자를 함께 적어 수동 다크 + 밝은 고대비에서도 시스템 색 매핑이 이긴다).
- **시스템 색으로 매핑된 토큰을 면(배경)에 쓰는 요소**(`background: var(--c-brand)` → 강제 색상에서 `ButtonText`): 브라우저는 저자가 쓴 **시스템 색은 덮어쓰지 않으므로** 면이 검게(CanvasText 극성) 남고, 그 위 글자(`--c-on-brand` = `ButtonFace`) 뒤에는 Canvas 백플레이트가 깔려 **글자가 사라진다**(M3 출생신고 띠 — 시안·구현 강제 색상 스크린샷의 흰 상자, `diff-003.md` D-07. 구현은 r4 R-291로 고쳐 `qa/screenshots/003/dev-M3-r4-birth-top-forced-colors-light-360x740.png`에서 글자가 보이고, e2e `m3-colors`가 **렌더 픽셀**로 글자 자리의 명도 대비 ≥ 4.5:1을 잰다). 그런 요소는 강제 색상 블록에서 ① `background: Canvas; color: CanvasText` + 모양(굵은 선·테두리)으로 구분하거나(출생신고 띠 `.doc__band`), ② 주 버튼처럼 `forced-color-adjust: none` + 시스템 색 **한 짝**을 명시한다. 글자색 vs 배경색만 견주는 대비 시험은 백플레이트를 보지 못하므로 **강제 색상 스크린샷을 눈으로 확인**한다(`shootMockups` `-forced`, e2e 스크린샷).

### 11-6. 컨테이너 쿼리
- `@container (max-width: Nem)`·`cqw` 단위를 쓰는 요소의 **조상에 `container-type: inline-size`**가 있어야 한다 — 없으면 쿼리는 영원히 거짓이고(한 줄 모양 고정) `cqw`는 무시된다. 첫 화면은 `.slide`가 컨테이너다. 새 화면에서 `Pair`·칸 폭 맞춤 글자를 쓰면 그 칸을 컨테이너로 선언한다.
- 컨테이너가 된 요소는 안쪽 내용으로 폭을 정하지 못하므로(inline-size containment) **부모가 폭을 정하는 블록**에만 건다(flex·grid 칸은 `min-width: 0`과 함께). `cqw` 식은 `@supports (width: 1cqw)`로 감싼다.
- 문턱은 em으로 적어 글자 확대에 함께 커지게 한다. 지원하지 않는 브라우저(Safari 16 미만)는 한 줄 모양 + `Glue` 묶음으로 물러난다. 제품 번들에 `@container`·`container-type`·`cqw`가 살아 있는지 e2e-prod가 본다(R-243).
- **폴백 규칙(REV-003-M3-4 R-302, M3 r5에서 확정 — 새 화면도 같다)**: ① 컨테이너 단위(`cqi`·`cqw`)를 쓰는 **식**은 반드시 `@supports (width: 1cqi)`(또는 `1cqw`) 안에 둔다 — 모르는 브라우저에서는 식이 통째로 무효라 속성이 `unset`이 되어(룰렛 제목이 본문 16px가 됐다) 기본 규칙(`.t-title`의 `--fs-2xl`)으로 물러나야 한다. ② **배치 규칙을 `@media`(뷰포트 px)에서 `@container`(rem)로 옮긴 곳**은 `@supports not (container-type: inline-size)` 블록에 **예전 뷰포트 규칙을 되살린다**(비교 표 쌓기 `@media (max-width: 639px)`, 서류 3열 `@media (min-width: 640px)`) — 쌓기 본문은 `@container` 블록과 **글자 그대로 같아야** 하고(`tests/docCssFallback.test.ts`가 두 블록을 견주고 `e2e/m3-css-fallback.spec.ts`가 컨테이너 질의를 지운 CSS로 실제 화면을 잰다), 컨테이너 질의가 있어야만 뜻이 서는 규칙(서류 격자 1열 — 칸 폭 rem과 글자 크기를 함께 본다)은 되살리지 않는다. ③ 폴백 블록은 하나이고 그 안에는 되살리는 선택자(`.table--cmp`·`.doc__grid`)만 둔다 — 다른 규칙이 슬쩍 들어가지 않게 시험이 선택자 목록을 본다. 시안 `ds.css`도 같은 두 블록을 갖는다(2026-10-17). 남은 한계(R-310): 제목 폴백 `--fs-2xl`은 폭 320·360 × 글자 200%에서 「정해졌습니 / 다」가 재발할 수 있다 — iOS 15 이하 Safari 실기기 목록(TODO). M4 대시보드의 컨테이너 규칙(이름표 격자 `facts` 15.5rem 1열)은 글자 확대에만 쓰이므로 모르는 브라우저는 2열 그대로(폴백 없음 — 글자 100%는 폭 320에서도 2열이 맞다).
- `<br>`로 낱말을 가르는 곳은 컨테이너·폭과 무관한 **등록제**(`e2e/intendedBreaks.ts#FORCED_BREAKS`, R-300) — 11-8절 (b).

### 11-7. 서류 격자·칩·비교 표·FitPair — M3(룰렛·출생신고)에서 확정, M4 패널·프로필 카드가 따른다 (REV-003-M3-1~3)
- **긴 낱말이 들어가는 격자 칸**(9글자 지명 「전남광주통합특별시」, 긴 직업·주거 이름): 좁은 화면(2열)에서는 한 줄 전체, 넓은 화면(3열)에서는 **두 칸 이상**(`grid-column: span 2`) — 한 칸(폭 1280에서 205px)은 글자 150%부터 낱말이 중간에서 끊긴다(R-281 마스터 결정). 빈 칸을 메우려고 `grid-auto-flow: dense`를 쓰지 않는다(읽는 순서 = 화면 순서). 끊김 판정 기준은 칸이 아니라 **한 줄 전체 폭**(낱말이 한 줄에 들어갈 폭인데 끊기면 위반)이고, 허용은 측정과 `INTENDED_BREAKS`뿐이다(11-8절 — R-281의 「글자 200% × 폭 320·360 명시 목록」은 QM3-1이 대체했다). **열 수·쌓기는 뷰포트 px가 아니라 컨테이너 폭(rem)이 정한다**: 서류 격자는 본문 `docbody`가 11.5rem 미만이면 1열(반쪽 칸의 「단순노무직」·「서비스직」이 글자 150~200%에서 끊겼다 — 폭 320 · 150%+, 360 · 200%), 3열은 640px 이상 **그리고** 본문 17.75rem 이상일 때만; 비교 표는 카드 `cmp`가 35rem 미만이면 한 행씩(글자 200%의 폭 640대에서 출처 줄이 표 칸 안에서 끊겼다). px 미디어 쿼리는 글자 확대에 반응하지 않는다(11-6절). 새 화면도 가장 긴 내용의 **표본을 일부러 모아**(흙·다이아몬드·지난·다가올 세상, 부모 직업이 다른 표본 — R-262·QM3-1) 잰다 — 짧은 기준선 한 장으로는 못 잡는다.
- **칩 안 줄바꿈**(수저 칩): 알약은 `flex-wrap` + `max-width: 100%`, 아이콘·점은 `flex: none`, 이름은 `flex: 1 1 0; min-width: min-content; overflow-wrap: normal; word-break: keep-all` — 점이 먼저 다음 줄로 밀리고 이름은 `<wbr>`(「다이아몬드<wbr>수저」) 자리에서만 끊긴다. 전역 `overflow-wrap: anywhere`를 이름에 그대로 두면 점이 밀리기 전에 이름이 글자 하나씩 끊긴다. 짧은 칩(릴 칸)은 제외.
- **비교 표 + 한 줄 서술**: 표에는 「이 가정 형편」에 맞춘 **집단의 값만**(출처 확인 행만, 모든 단계 같은 행 구성, 행마다 출처 줄과 집단 설명, 열 머리와 칸 뜻이 어긋나는 값 금지 — 「전체 평균」 칸에 격차를 넣지 않는다). 이 가정을 겨냥할 수 없는 지표(소득 계층 간 기대수명 격차 같은 집단 평균 차이)는 **표 밖 한 줄 서술** + 「집단의 평균 차이입니다」 단서 + 모든 단계 같은 글. 통계의 기준 연도가 그 세상과 어긋나면(지난·다가올 세상) 카드 전체를 숨기고, 하단 표기의 범위를 보이는 항목으로 한정한다(R-260·R-261·R-263). 제목이 약속한 값은 눈에 보이는 글자에(11-4절 QM2-11).
- **짧은 쌍의 둘째 방식 `FitPair`**(`ui/FitPair.tsx`): 내용 길이가 **판마다 다른** 쌍(「{수저}({구간}) · {시·도}」, 「{나이}세 · {직업}」, 「수저 게임 · 가상의 서류」)은 em 문턱의 `Pair` 대신 보이지 않는 탐침(`::before { content: attr(data-text) }`, **`position: fixed`** — absolute면 한 줄 폭만큼 문서 가로 스크롤이 늘어난다)으로 한 줄 폭을 재서 칸 폭과 견주고, 넘치면 기호 없이 두 항목을 따로 줄로. 탐침 글자는 DOM 글자에 들어가지 않는다(복사·읽기에 두 번 나오지 않음). 칸이 `flex` 안이면 그 칸이 폭을 **나눠 받아야**(`flex: 1 1 8rem; min-width: 0`) 측정이 맞다(문서 띠 `.doc__tag`).
- **세상별 문구 분기**: 통계 기반 문구(지역 확률표 주석·하단 표기·지역 표기)는 세상마다 다른 상수/함수로 두고(지금 = 통계 파생, 지난·다가올 = 설계값·조정 고지, 지난 세상 지역 이름은 2025년 행정구역임을 밝힘) 한 문장이 세 세상에 억지로 맞도록 쓰지 않는다(R-263·R-264·R-187). 문구는 `copy.md` 룰렛·출생신고 행.
- **넘침 측정기 공통 규칙**: `clip: rect(0 0 0 0)`로 읽기 전용으로 접은 요소와 그 안(비교 표의 접힌 머리글)은 세지 않는다 — 시안 `shootMockups#overflowReport`와 e2e `textResize.ts`가 같은 규칙(M3). 가로 넘침 0px·요소 단위 넘침 0은 그대로다.

### 11-8. 낱말 끊김 공통 규칙 — QM3-1·QM3-2 (M3-L02, 2026-10-16 r4에서 확정, 새 화면이 그대로 따른다)
- **대상은 눈에 보이는 모든 낱말**(제목·본문·칩·표·출처·푸터·하단 띠·헤더·릴·장식 「접수」까지 — 낱말 종류로 범위를 좁히지 않는다). 낱말 = 공백·구두점으로 가른 한글·영숫자 덩어리이고 요소 경계(`<span>`·`<wbr>`)를 넘어 이어 붙은 글자는 한 낱말, `<br>`는 낱말 경계(첫 화면 띠의 「다이아몬드<br>수저」는 글쓴이가 정한 두 줄 이름표). 끊김 = 한 낱말의 글자가 두 줄 이상에 걸친 것 — 낱말 사이·구두점 뒤 줄바꿈은 끊김이 아니다.
- **허용은 둘뿐, 둘 다 손으로 적은 낱말 목록이 아니다**: (a) **측정상 한 줄 전체보다 긴 낱말** — 자연 폭(`nowrap`으로 잰 글자 상자 폭의 합) > 한 줄 전체(그 낱말에서 위로 올라가 처음 만나는, 여러 칸이 한 줄을 나눠 쓰는 상자의 내용 폭 — 격자 `dl`·또래 `li`·표·두 릴 전체; 칸 하나의 폭이 아니다) + 0.5px일 때만, 그리고 **글자 100%에서는 0건**(R-281 유지). 지금 그런 낱말은 글자 200%의 7글자 특별자치도 지명(폭 320)과 9글자 「전남광주통합특별시」(폭 375까지)뿐이다. (b) **코드에 명시한 줄바꿈 지점** — 두 등록 목록(`e2e/intendedBreaks.ts`): `INTENDED_BREAKS`의 **`<wbr>`**(폭이 모자랄 때만 갈리는 지점 — 지금은 「다이아몬드<wbr>수저」, `ui/Grade.tsx`·시안 생성기 `mockLib.mjs#gradeNameHtml` 하나)와 `FORCED_BREAKS`의 **`<br>`**(폭과 상관없이 늘 줄이 바뀌는 자리 — 지금은 첫 화면 수저 띠의 「다이아몬드<br>수저」, `TitleScreen.tsx`·`mockLib.mjs#spoonLineup` 하나, REV-003-M3-4 R-300). **`<br>`는 낱말 경계가 아니다**: 등록 없는 낱말 한가운데의 `<br>`는 감사기가 폭과 무관하게 `broken`으로 세고, 등록 낱말은 `forced`로 따로 보고해 호출하는 e2e가 화면마다 기대 집합(첫 화면 상태마다 하나, 룰렛·출생신고·캐러셀 0)과 대조한다. 목록에 없는 낱말에 `<wbr>`·`&shy;`·U+00AD·`<br>`를 쓰려면 이유와 함께 등재한다(`tests/wordBreaks.test.ts`가 `src/` 사용처(파일별 `<br>` 개수·서버 렌더의 앞뒤 낱말 포함)와 목록의 일치를 잠근다). 시안 생성기도 같은 두 자리에만 둔다 — 새 화면(M4 대시보드) 시안에는 둘 다 없다.
- **그 밖의 끊김은 결함**이고 고치는 방법은 낱말을 허용 목록에 넣는 것이 아니라 **칸을 한 줄 전체로 넓히는 것**이다 — 반쪽 칸을 1열로(서류 격자 컨테이너 11.5rem), 출처 줄을 표 칸 밖 한 덩어리로(비교 카드 컨테이너 35rem), 칩 안 점을 먼저 다음 줄로(11-7절). 문턱은 rem·컨테이너 폭으로 두어 글자 확대에 함께 커지게 한다.
- **제목(h1)에는 (a)(b)를 쓰지 않는다**: 어떤 조합에서도 제목 낱말이 끊기지 않도록 **줄 폭 기준 글자 크기 상한**을 둔다 — `font-size: max(바닥, min(기본, 100cqi ÷ (가장 긴 낱말 글자 수 + 1)))`(상자를 `container-type: inline-size`로, 글자 수는 문구 상수에서 계산해 인라인 변수로). rem 고정 상한은 루트 글자 200%에서 함께 두 배가 되어 소용이 없다. 바닥은 같은 화면 본문보다 큰 크기(룰렛 `--fs-lg`)라 제목 위계가 유지되고, 낱말 **사이**에서 여러 줄로 접히는 것은 허용한다(「태어날 곳이 / 정해졌습니다」, `roulette-result-320-text200.png`). 「정해졌습니 / 다」처럼 한 글자가 홀로 남는 것은 금지다. **M4 r2(R-321)에서 새 화면에 적용**: 엔딩 「{이름}의 인생」(컨테이너 `.ending__who`, 바닥 `--fs-lg`, `titleCharsFor(제목)`) · 밀린·오류 메시지(컨테이너 `.system .card`, **바닥 `--fs-md`** — 폭 320 · 글자 200%에서 「바뀌었습니다.」 7글자가 `--fs-lg`의 두 배 36px로는 252px > 내용 폭 246px이라 본문 크기까지 내려가고 그때만 굵기·색으로 구분한다, `SYSTEM_TITLE_CHARS`) · 대시보드 이름(기본이 본문 크기라 상한 없음 — `.who` `flex-wrap`으로 알약이 내려간다). 시안 `ending-320-text200.png`·`system-superseded-320-text200.png`, e2e `m4-titles`.

### 11-9. 항목 수가 바뀌는 「·」 사슬 — 영향 줄의 CSS 가장자리 감춤 (M5, QM2-10 규칙 4, 2026-10-17)
- 영향 줄은 항목 수가 1~6으로 바뀌는 나열인데 마스터가 「 · 」로 잇기로 확정했다(EC5·M5 EC0 승인). QM2-10 규칙 2(쉼표 나열)·3(두 줄로 나누기) 대신 **규칙 4(수단은 자유, 기준은 측정)**로 지킨다: 「·」를 글자로 넣지 않고 CSS가 그린다.
- 방법(`ds.css` 「영향 표기」 블록): 컨테이너 `.impact { display: flex; flex-wrap: wrap; column-gap: 1.25em; overflow: hidden }`, 항목 `.impact__item { position: relative; white-space: nowrap }`, 항목의 `::before { content: '·' / ''; position: absolute; left: -1.25em; width: 1.25em; text-align: center }`. 기호는 **각 항목의 왼쪽 간격 한가운데**에 놓이므로 같은 줄의 이웃 항목 사이에서만 보이고, **줄 첫머리 항목의 기호는 컨테이너 왼쪽 밖(−1.25em)에 그려져 가려진다**. 줄이 몇 번 접혀도 기호가 줄 끝·첫머리에 남지 않는다.
- 접근성: `content: '·' / ''`(대체 글자가 빈 문자열)라 접근성 트리에 없고 DOM 글자에도 없다. 줄바꿈 감사(QM2-5 (a), 텍스트 노드 기준)에는 보이지 않으므로 **기하 측정**으로 확인한다 — 모든 `.impact__item` 상자가 `.impact` 상자 안, 줄 첫머리 항목의 `::before` 상자가 컨테이너 왼쪽 밖(시안 실측: 폭 320·360·1280·320×256 × 글자 100·200% × 라이트·다크·강제 색상 46장(r2)에서 줄 첫머리 「·」 0, 항목 밖 0, 넘침 0).
- 한계: 한 항목(이름 + 기호)이 한 줄 전체보다 길면 항목 안 flex-wrap이 기호 묶음을 이름 아래로 내린다(폭 320 · 글자 200%의 「집안 살림 ▼▼▼」 하나 — 선택지 내용 폭 180px < 191px). 낱말은 끊기지 않는다(QM3-1). `overflow: hidden`은 항목이 컨테이너를 넘지 않는 한 아무것도 자르지 않는다(넘침 0은 요소 단위 점검과 CM11 e2e가 지킨다).
- 쓰는 자리는 영향 줄뿐이다. 데이터로 채우는 다른 나열(출처 기관·학원 종류 …)은 그대로 쉼표 나열(11-4절 1항)이고, 고정된 짧은 쌍은 `Pair`/`FitPair`(11-4절 3항).
- 기호의 색(톤 수식자 `.impact__step--good|bad` — 이로움 `--c-up`·해로움 `--c-down`, 부채만 ▲가 해로움; M5 r2)은 이 배치 규칙과 무관하다 — 「·」 자리·항목 접힘·가장자리 감춤은 색과 상관없이 같고, 강제 색상에서는 톤 둘 다 CanvasText다.

### 11-10. 모달 시트와 `inert`·포커스 — M7b 중대 결정 카드에서 확정, M7c 자유 기록 카드가 따른다 (2026-10-19)
- **모달은 `role="dialog" aria-modal="true"` + 바깥 전부 `inert`**(헤더·도구 줄·`main`·본문 끝 여백). `aria-modal`만으로는 Tab이 스크림 뒤로 샌다. 시트는 `max-height: 94dvh; overflow: auto; scroll-padding: var(--sp-3)`의 안쪽 스크롤 영역이라 11-1절의 자기 `scroll-padding` 규칙을 따른다. 모바일은 아래에서 올라오고(위 모서리만 둥글다) ≥ 640px은 가운데. 스크림은 `--c-scrim`(강제 색상에서는 투명 — 시트의 CanvasText 테두리가 가른다).

- **문서 스크롤 잠금(M7c T1 — REV-003-M7b-3 R-400, 두 시트 공통)**: `.overlay`·`.sheet`의 `overscroll-behavior: contain`은 시트 **안**에서 끝까지 쓴 뒤의 연쇄만 끊는다 — 스크림(시트 위쪽 바탕)에서 시작한 드래그, 짧은 시트(넘침 없음)의 휠·PageDown·Space는 그대로 뒤 문서를 움직인다(크로뮴은 넘침 없는 상자를 연쇄 대상에서 건너뛴다). 그러므로 잠금은 CSS 한 줄이 아니라 **열린 시트 수를 세는 훅**(`useScrollLock` — 첫 시트가 열릴 때 걸고 마지막 시트가 닫힐 때 푼다; 결정 시트 → 기록 시트로 이어질 때 개수가 0이 되지 않아 풀렸다 걸리지 않고 `scrollY`가 튀지 않는다)이 `<html class="sheet-open">`을 건다: `html.sheet-open { overflow: hidden; padding-right: var(--scrollbar-w, 0px) }`, `--scrollbar-w`는 잠그기 **전에 잰** `innerWidth − documentElement.clientWidth`(겹쳐 그리는 스크롤바 — 모바일·헤드리스 — 는 0, 데스크톱 고전 스크롤바는 15~17px)라 본문이 옆으로 밀리지 않는다(`clientWidth` 불변, T1 (e)); 고정 요소(헤더·진행 줄)에도 같은 보정을 둘지는 developer 선택(스크림 뒤라 눈에 띄지 않는다). **`scrollbar-gutter: stable`은 쓰지 않는다** — 헤드리스 크로뮴은 겹쳐 그리는 스크롤바인데도 15px을 비워 폭 320 · 글자 200%의 상태 바가 8px 넘쳤다(시안 감사 2026-10-19; 구현 CM11 e2e도 같은 환경이다). 시트 안 스크롤은 막지 않는다 — **구현(2026-10-19 UI 단계, D-81)**: `.overlay { touch-action: pinch-zoom }`(스크림에서 시작한 손가락 끌기 — 가장 가까운 스크롤 상자가 문서라 html 잠금만으로는 iOS 사파리가 놓칠 수 있다, T1 (d)) + `.sheet { touch-action: pan-y pinch-zoom }`. 첫 규칙 뒤의 **별도 규칙** 두 줄이고 `ds.css`도 같은 두 줄을 둔다(`tests/designAssets.test.ts`가 구현과 대조). **스크림 값은 `none`이 아니라 `pinch-zoom`(r2, REV-003-M7c-1 R-405 → D-90)**: 유효 터치 동작은 자기 값과 가장 가까운 스크롤 상자까지의 조상 값의 교집합인데, 크로뮴(`StyleAdjuster::AdjustEffectiveTouchAction`)은 스크롤 상자에서 **pan 비트만** 되살린다 — 스크림이 `none`이면 `.sheet`의 유효값이 `(pan-y | pinch-zoom) ∩ (none | pan)` = `pan-y`로 줄어 시트가 떠 있는 동안 핀치 확대·두 번 탭 확대가 화면 어디서도 안 됐다(안드로이드 크롬·삼성 인터넷; 결정 시트는 수동 모드에서 결정마다 뜨므로 출처 줄 같은 작은 글자를 확대해 읽을 길이 막히는 1.4.4 후퇴). `pinch-zoom`은 pan이 없어 스크림의 한 손가락 끌기는 여전히 막고(T1 (d) 유지) 시트 안 유효값은 `pan-y pinch-zoom`이다. 시안·규격은 이번에 바꿨고 구현 `dash.css`·핀치 e2e는 developer r2-2에서 들어왔다(**D-90 닫힘**, 후속 3) — e2e `m7c-pinch-zoom.spec.ts`는 두 손가락 `Input.dispatchTouchEvent`로 핀치를 넣어 `visualViewport.scale > 1.3`을 단언한다(`Input.synthesizePinchGesture`는 헤드리스에서 `scale`을 바꾸지 못해 변이 점검이 공허했다; T1 (a)(h) 그대로). e2e (a)~(h)와 변이 점검은 content-M7c 7-1절 T1. 시안은 `page()`의 흉내 스크립트가 `.overlay`가 있으면 폭을 재고 클래스를 건다.
