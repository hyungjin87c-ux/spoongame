# Codex 이미지 생성 요청

Claude Code(designer)가 요청서를 쓰고, 형진 님이 Codex Desktop에서 실행하고, Claude가 검수·적용한다. 검증 흐름(`docs/review/codex/README.md`)과 같은 꼴이되 산출물이 코드가 아니라 **그림**이다. 자동 동기화는 없다.

| 파일 | 작성 | 내용 |
|---|---|---|
| `IMG-<번호>-<대상>/request.md` | Claude | 목적·화풍·범위·프롬프트 틀·금지 목록·납품 형식·검수 기준·라이선스·붙여 넣을 지시문 |
| `IMG-<번호>-<대상>/out/*.webp`, `out/sheet-*.png` | Codex | 완성 이미지와 대조 시트 — **Codex가 쓰는 곳은 `out/`과 `delivery.md`뿐** |
| `IMG-<번호>-<대상>/delivery.md` | Codex | 장별 프롬프트 전문·모델·시드·크기·바이트·재시도 기록 |
| `IMG-<번호>-<대상>/review.md` | Claude | 장별 PASS/REDO와 사유, 재작업 지시, 적용 기록 |

## 흐름
1. Claude가 `request.md`를 쓴다(이미지는 만들지 않는다). 형진 님이 요청서의 「묻는 것」에 답하면 확정.
2. 형진 님이 Codex Desktop에서 요청서 끝의 지시문을 붙여 넣어 실행한다. Codex는 **첫 묶음만 만들고 멈춘다**.
3. Claude가 대조 시트를 열어 `review.md`에 판정하고, 형진 님이 화풍·대비·품위를 결정한다(디자인 게이트). 통과하면 다음 묶음.
4. 다 끝나면 Claude가 `out/`의 파일을 적용 자리(`public/…`)로 **옮기고**(복사하지 않는다 — 저장소에 두 벌 두지 않는다), `docs/design/credits.md`에 AI 생성물 행을 더하고, 적용 차이를 design 로그에 적는다. developer가 지연 로드 경계 시험과 함께 코드에 잇는다.

## 규칙
- 외부 참조 이미지(사진·연예인·다른 게임)를 Codex 입력으로 넣지 않는다. 일관성 참조는 이 요청으로 만든 우리 그림만.
- 고해상 원본·실패작은 저장소에 넣지 않는다(`IMG-*/raw/`는 커밋하지 않는다).
- 실존 인물 닮음·상표·로고·글자·워터마크 0. 피부색·체형 서열 0. 조롱 표지 0(요청서의 금지 목록이 정본).
- 라이선스: AI 생성물임과 도구·모델·날짜를 `credits.md`에 적는다. OpenAI 출력물 권리 근거는 첫 화면 일러스트 행과 같고 수익화 때 재확인한다.

## 기획·디자인 요청 (DSN)

이미지 생성과 같은 꼴이되 산출물이 **기획서·정적 시안·캡처**다(2026-11-13 형진 님 — Codex에 기획·디자인을 맡김). Codex가 쓰는 곳은 그 요청 폴더의 `plan.md`·`mockups/`·`shots/`·`delivery.md`뿐이고, Claude가 `review.md`에 검토를 적은 뒤 형진 님이 고르면 마스터가 명세(SPEC)로 옮긴다. 앱 실행이 필요해 Codex 검증 폴더(`node_modules` 있음)에서 돌린다.
