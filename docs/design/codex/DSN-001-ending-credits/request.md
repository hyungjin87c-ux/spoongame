## 0. Codex에게 — 먼저 읽기

- 이번에 너는 이 게임의 **기획자이자 디자이너**다. 「엔딩 크레딧」을 무엇으로, 어떤 순서로, 어떻게 보여 줄지 정하고 시안으로 그린다.
- **쓰는 곳은 이 폴더 안뿐**이다: `docs/design/codex/DSN-001-ending-credits/` 아래의 `plan.md`(기획서) · `mockups/`(정적 HTML 시안) · `shots/`(시안 캡처 PNG) · `delivery.md`(작업 기록). `src/`·시험·설정·다른 문서는 고치지 않고, 커밋·푸시·배포를 하지 않는다.
- 저장소를 읽고 앱을 실행해 보는 것은 자유다(`npm run dev`로 지금 엔딩을 직접 보라 — 엔딩까지 빨리 가려면 첫 화면 → 태어나기 → 인생 화면의 자동 모드와 「다음 결정으로」·배속을 쓴다). 실제 판 데이터로 문장 샘플을 만들려면 `./node_modules/.bin/vite-node`로 `src/core`를 불러 판을 끝까지 돌려도 된다(임시 스크립트는 이 폴더 밖에 두고 끝나면 지운다). `npx`는 쓰지 않는다.
- **외부 참조를 들이지 않는다**: 다른 게임·영화·방송의 크레딧 화면 캡처·문구·형식을 참고 이미지나 본보기로 쓰지 않는다. 「이름이 아래에서 위로 흐른다」「역할과 이름을 두 열로 놓는다」 같은 **장르 일반 관습**은 써도 되지만, 특정 작품의 고유한 구성·문구·배치를 재현하지 않는다. 문서에 다른 작품 이름을 쓰지 않는다.
- 막히면 지어내지 말고 `plan.md`의 「형진 님께 묻는 것」에 질문으로 남긴다.

## 1. 배경과 목적

「수저 게임」은 한국에서 태어나 한 번의 인생을 사는 웹 게임이다. 태어난 집(수저)·세대·지역·타고난 것(기질·적성·외모)이 삶에 얼마나 영향을 주는지를, 해마다 일어나는 사건과 결정으로 체감하게 한다. 한 판은 30분 남짓이고, 끝나면 엔딩 화면이 나온다.

- **지금 엔딩**(`src/screens/EndingScreen.tsx`)은 한 화면에 회고를 늘어놓는 문서다. 차례: 머리(얼굴·이름·세대·생몰) → 사망 줄·「N번의 선택」·플레이 시간 → ~~출발선 대비 자리(막대·「출발선보다 앞쪽/비슷/뒤쪽」)~~ → 최종 스탯 4종·최종 순자산·외모 글 → 생애 연표 → 「다시 태어나기」.
- **「출발선 대비 자리」를 지운다**(형진 님 결정, 이번 배포에서 삭제 진행 중). 같은 세대 시뮬레이션 분포에서 최종 순자산 백분위를 매겨 출발선 구간과 견주는 카드였다. 형진 님 판단은 「한 삶을 살아보고 와닿지 않는다」다 — **숫자·순위로 삶을 정리하는 방식이 몰입을 깨뜨렸다**는 뜻으로 읽는다.
- **목적**: 한 삶을 다 살고 난 플레이어에게 **「이 사람의 삶에 누가 있었고, 어떤 시대를 지나왔는지」가 와닿게** 하는 엔딩 크레딧. 형진 님의 원칙은 「몰입 우선 — 촘촘하고 현실적이며 감정이 담긴 내용」이다. 판마다 다른 사람·장소·시대·선택이 크레딧이 된다.

## 2. 엔딩 흐름 안의 자리 (함께 고려할 계획)

- **SPEC-017 「엔딩 첫 장면·사망 기록 문서·공유 카드」**(`docs/spec/SPEC-017-엔딩첫장면과공유.md`, 형진 님 확정, 아직 구현 전)가 엔딩 앞쪽을 바꿀 예정이다: ① 사망 직후 어두운 **첫 장면**(이름·생몰년·단상 세 줄·마무리 한 줄, 약 10초, 건너뛰기) → ② 출생신고서와 짝이 되는 **사망 기록 문서** → ③ 공유 카드(나중 배포). 이 명세는 「출발선 막대」가 남는다고 가정했는데, 이번 삭제로 그 가정이 바뀐다 — 크레딧이 그 빈자리와 어떻게 이어지는지도 제안하라.
- 크레딧을 **어디에** 둘지는 너의 제안이다. 예: 첫 장면 바로 뒤 / 문서와 연표 뒤 「다시 태어나기」 앞 / 엔딩 맨 끝에서 다시 보기 버튼으로. SPEC-017과 겹치거나 부딪히는 곳(첫 장면의 단상과 크레딧의 중복 등)을 짚고 정리안을 내라.
- 「다시 태어나기」 흐름과 새로고침·이어하기 규칙: 엔딩 상태는 저장돼 새로고침해도 엔딩이 열린다. SPEC-017은 첫 장면을 「사망 직후 한 번만」(UI 메모리) 보이고 다시 보기 버튼을 둔다. 크레딧도 **새 저장 필드 없이** 같은 방식이 되도록 설계하라(필요하면 이유와 함께 질문으로).

## 4. 지켜야 할 것 (필수)

1. **와닿음**: 사람과 시대가 주인공이다. 점수·순위·백분위·「출발선 대비」·「성공/실패」 판정을 쓰지 않는다.
2. **사실만, 판마다 다르게**: 모든 줄은 판의 데이터에서 함수로 만들 수 있어야 한다. 손으로 적은 숫자·지어낸 사실 없음. 데이터가 없는 칸은 줄을 만들지 않는다(빈 이름 대신 「어머니」 같은 호칭은 가족 카드 규칙을 따른다).
3. **어체·민감 소재**: 담담한 합쇼체. 평가어·교훈조·느낌표·이모지 없음. 가난·부를 조롱하거나 미화하지 않는다. 외모·성별로 사람을 평가하지 않는다. 자살은 통계와 109 안내로만 다루는 프로젝트 규칙이 있다(지금 사인 후보에는 없다). 정치·재난은 사실 한 줄. 「무거운 장면 가리기」를 켠 판에서는 무거운 줄을 어떻게 다룰지 정한다(`docs/design/copy.md` 12절 규칙과 맞춘다).
4. **길이와 조작**: 크레딧은 건너뛸 수 있어야 한다(보이는 버튼 + 키보드). 총 길이 후보를 제안하라(판의 길이에 따라 줄 수가 달라질 때의 상한 포함). 움직임 줄이기(`prefers-reduced-motion`·`data-motion=reduce`)에서는 흐르지 않고 정지 목록으로 보인다. 스크린리더는 전체를 한 번에 읽는다(줄마다 끊어 읽지 않는다). 키보드 초점이 보인다.
5. **화면**: 기존 색·간격·글자 토큰만 쓴다(`src/styles/tokens.css`·`docs/design/design-system.md`). 라이트·다크·강제 색상(고대비) 모두. 폭 320·360(모바일)·1280(PC), 글자 200%에서도 넘치지 않는다.
6. **성능**: 첫 로딩 한도 400,000 B(gzip)에 여유가 거의 없다(WebKit 약 1.2KB). 크레딧은 **지연 로드** 전제다. 새 글꼴을 들이지 않는다. 게임 글자는 Noto Sans KR 조각 안의 글자만 쓸 수 있다(`tests/designAssets.test.ts` — 새 고정 문구는 조각 밖 글자를 피한다. 사람 이름은 이미 조각 안이다).
7. **소리**: 기존 BGM 체계(`docs/data/bgm-spec.md`)가 있다. 새 음원은 이번 범위 밖 — 크레딧 동안 음악을 어떻게 할지 제안만.
8. **닮음 방지**: 0절의 외부 참조 규칙. 우리 정체성(수저·세대·시대·한국의 한 생애, 출생신고서와 짝이 되는 서류감)을 담는다.

## 5. 산출물

1. **`plan.md` (기획서)**
   - 컨셉 2~3안(각각 한 문단 + 장단점 + 와닿는 지점) → **추천 1안**과 이유.
   - 크레딧 구조: 섹션 순서, 섹션마다 줄의 모양, **줄마다 데이터 출처(필드)와 없을 때 처리**, 최대 줄 수.
   - 문장 샘플: 실제 판으로 뽑은 크레딧 전문 — **밀레니얼 2판(수저 1·5), 산업화 1판, 20세 미만 사망 1판, 가족이 적은 판 1판, 가림을 켠 판 1판**(시드와 만든 방법을 적는다).
   - 연출 명세: 속도·총 길이·전환·건너뛰기·다시 보기·움직임 줄이기·소리.
   - 엔딩 흐름 안의 자리(2절)와 SPEC-017과의 정리안.
   - 화면 규격: 토큰·간격·글자 크기·폭별 배치.
   - 접근성(읽기 순서·초점·스크린리더)·성능(지연 로드 경계)·저장 영향(새 필드 없이 되는지).
   - 구현 시 완료 기준·시험 제안, 위험, **형진 님께 묻는 것**(질문마다 추천안과 이유, 한꺼번에).
2. **`mockups/`**: 정적 HTML 시안 — 추천안 기준, 360×740과 1280×800, 라이트·다크. 실제 판 데이터(위 샘플 중 2판 이상)로 채운다. 저장소 CSS를 상대 경로로 불러 쓰거나 토큰 값을 그대로 옮긴다(새 색 금지).
3. **`shots/`**: 시안 캡처 PNG — 장면의 처음·중간·끝, 움직임 줄이기 정지 화면, 모바일·PC, 라이트·다크. 장마다 파일 이름에 폭·테마를 넣는다(예: `credits-360-dark-mid.png`). 고해상 원본은 넣지 않는다(장당 1MB 이하).
4. **`delivery.md`**: 읽은 파일, 돌린 명령, 쓴 시드, 시안을 만든 방법, 한계와 미확인.

## 7. 검토 기준 (Claude · 형진 님)

1. 다 살고 난 뒤 **와닿는가** — 사람·시대·선택이 이 판만의 것인가.
2. 사실성 — 모든 줄이 데이터에서 나오고 지어낸 것이 없는가.
3. 길이·리듬 — 지루하지 않고 건너뛸 수 있는가, 긴 삶(100세)·짧은 삶(10세 미만)에서도 맞는가.
4. 품위 — 평가·조롱·교훈조 없음, 민감 소재 규칙.
5. 접근성·폭·테마·성능 계획이 구현 가능한가.
6. 닮음 없음 — 특정 작품을 떠올리게 하는 고유 구성이 없는가.

## 8. 이미 정해진 것

- 「출발선 대비 자리」(엔딩 백분위·출발선 막대·이동 판정)는 삭제한다. 대체 지표를 만들지 않는다.
- 출생 쪽의 수저 구간 표시(룰렛·출생신고·프로필의 「흙수저(하위 25% 안쪽)」)는 남는다 — 출발점 정보라 엔딩 비교와 다르다.
- 엔딩 크레딧은 Codex가 기획·디자인하고, 형진 님이 고른 뒤 명세·구현한다.
