## 2. 엔딩에서의 자리

```text
사망 직후
  → SPEC-017 첫 장면 약 10초(건너뛰기 가능)
  → 사망 기록 문서 / 회고
       ├─ 이 삶의 이름들 보기
       │    → 이름·출생 사실 → 가족과 친구 → 본인 선택 → 시대
       │    → 태어나고 마칠 때 → 생애 기록 마무리
       │    → 기록으로 돌아가기 / 처음부터 보기
       ├─ 최종 스탯·순자산 / 생애 연표
       └─ 다시 태어나기
```

수저 장면은 마지막 시대 줄 다음, 「○○의 생애 기록을 마쳤습니다.」 바로 앞에 둔다. 사람과 선택이 먼저 남고 수저가 끝의 한 장면이 되게 한다. 첫 장면 뒤에 크레딧을 연속 자동 재생하지 않는다. 첫 장면 건너뛰기는 회고로, 크레딧의 보이는 「회고로」와 Escape도 회고로 간다. 새 인생을 시작하지 않는다.

끝에 도착해도 자동으로 닫지 않는다. 「기록으로 돌아가기」는 호출한 회고 버튼으로 초점을 돌리고, 「처음부터 보기」는 같은 삶·같은 문장을 다시 읽는다. 새로고침·이어하기는 저장된 회고를 열고 크레딧을 자동 시작하지 않는다. SPEC-017의 남아 있는 출발선 막대 전제와 공유 카드 후보는 후속 명세에서 삭제 결정에 맞춰 정리한다. 이번 문서는 기존 명세·구현을 수정하지 않는다.

### 4-2. 청년 이후의 시대

`eraRows`에서 다음 조건을 모두 지키는 줄을 연도 오름차순으로 본다.

1. 게임 나이 20 이상이며 출생~사망 범위 안이다.
2. `forecast === false`이고 승인된 실제 마지막 해 **2026** 이하이다. 기준은 `ERA_ACTUAL_LAST_YEAR`이며 컴퓨터 달력이 바뀌었다고 예측이 사실이 되지 않는다. 2110년 끝 안내는 예측 표지가 없어도 제외된다.
3. 청년·중년·노년마다 첫 줄을 하나 고른다. 앞 단계에서 heavy를 골랐다면 뒤 단계에서는 가장 이른 non-heavy를 고른다. 없다면 생략한다.
4. 원문 `line`만 쓰고 가구 영향 `second`는 쓰지 않는다. 거주·목격·피해와 연결하는 문장을 덧붙이지 않는다.

현재 가림 설정 때문에 선택 연도가 달라지지 않는다. heavy 한 줄을 가린 상태에서도 그 한 줄의 자리를 유지한다. 20세 전 사망판에는 시대 장이 없다. 산업화 샘플의 노년에서는 앞서 heavy를 골랐으므로 2014·2016의 무거운 줄을 지나 2018년의 가벼운 줄을 쓴다.

### 4-3. 원문과 가림

선택 결과는 `HistoryEntry.text` 전체다. 첫 문장만 떼어 반전·조건·불합격을 잃지 않는다. 기록된 질문·라벨을 현재 콘텐츠로 소급 교체하지 않는다. 직무에 지원했다는 기록을 실제 취업 직업으로 바꾸지 않는다.

`gentleUsed`는 사용 이력 안내이고 실제 가림은 현재 `settings.gentle`이다. 선택의 heavy는 사건 정의에 있는 분류를 따른다. 가릴 때 제목·질문·고른 길·결과를 함께 빼고 「무거운 일이 있었습니다 · 건강」처럼 기존 분류 이름만 남긴다. 시대는 「무거운 일이 있었습니다 · 시대의 일」이다. 닫힌 원문을 DOM·접근성 이름·투명 글자에 두지 않는다. 펼침은 해당 한 건에만 적용하고 이동을 멈추며, 접기·설정 변경·재진입·새로고침 때 원문을 다시 닫는다.

## 5. 마칠 때 수저를 정하는 법

### 5-1. 입력과 계산

태어날 때 수저는 `character.parentWealth`다. 마칠 때는 종료 `assets.net`을 사용한다. 이미 부채가 빠진 순자산이므로 `assets.debt`를 다시 빼지 않는다. 나이는 `death.age`인 게임 나이이며 표시용 한국 나이를 넣지 않는다. 단위는 자료와 맞춘 현재가치 만 원이다. 출생 세대는 시작할 때 실제로 쓰인 세대 프로필을 따른다.

기준은 [순자산 자료 4절](../../../data/networth-distribution.md)의 **안 B**다. 연령대별 구간 분포가 직접 공표된 값이라고 쓰지 않는다. 전체 가구의 누적 분포와 연령대별 평균·중위값을 합쳐 만든 추산이다.

| 게임 사망 나이 | 쓰는 공식 표 행 | 중위값 M(만 원) | 평균(만 원) |
|---|---|---:|---:|
| 20~29 | 29세 이하 | 5,000 | 10,796 |
| 30~39 | 30~39세 | 15,585 | 25,060 |
| 40~49 | 40~49세 | 28,384 | 48,389 |
| 50~59 | 50~59세 | 31,685 | 55,161 |
| 60~64 | 60세 이상(65세 이상도 포함하는 행) | 25,000 | 53,591 |
| 65 이상 | 65세 이상 | 22,100 | 49,279 |

```text
x ≤ M: F(x | 나이) = F_all(x × 23,860 / M)
x > M: F(x | 나이) = 100 × Φ( ln(x/M) / σ )
σ = √(2 × ln(평균/M))
```

F와 `F_all`의 단위는 0~100 백분율이고 Φ는 0~1 표준정규 누적함수다. `F_all`은 자료 4-1의 21개 마디 사이 선형 보간이다. P90 이상은 문서의 파레토 꼬리를 쓴다. `σ`는 표에 인쇄된 세 자리 값 대신 평균·중위값으로 다시 계산한다. 이번 장면은 11월 13일 쏠림 측정에서 사용한 P10/P25 등 성긴 분위수 표의 재보간을 쓰지 않는다. 계산 함수와 원자료·중간값은 `wealth-2.mjs`와 `samples-2.json`에 남긴다.

F를 구한 뒤 같은 세대의 출생 수저 비율 누적 경계로 1~5 이름을 붙인다. 이번 실제 판의 경계는 아래와 같다.

| 세대 | 흙/동 경계 | 동/은 경계 | 은/금 경계 | 금/다이아몬드 경계 |
|---|---:|---:|---:|---:|
| 산업화 | 40% | 72% | 92% | 99% |
| X세대 | 33% | 64% | 88% | 98% |
| 밀레니얼 | 26% | 56% | 83% | 97% |

이 표의 숫자는 설계 근거이며 크레딧 화면에 넣지 않는다. 제품에서는 `startBandOf`와 같은 세대 비율 원본을 사용하고 새 경계 표를 중복 관리하지 않는다. **정확히 경계와 같으면 아래 단계에 남기는 `p <= 경계`를 제안**한다. 예를 들어 밀레니얼 26.000…%는 흙, 그보다 크면 동이다. 반올림한 개인 백분위나 반올림한 표시 경계로 판정하지 않는다.

### 5-2. 예외와 한계

| 입력 | 처리 |
|---|---|
| 게임 사망 나이 0~19 | 출생 수저만. 종료 수저·백분위·변화는 생성하지 않는다. 게임 19는 화면 20세지만 이 규칙의 20세 전이다. |
| 게임 사망 나이 20 | 성인 추산 시작. 화면은 21세다. |
| 순자산 0 이하 | 마지막 수저를 흙으로 정한다. 음수 금액이나 빚을 강조하지 않는다. |
| 성인인데 순자산이 없거나 유한 숫자가 아님 | 출생 수저와 「마칠 때의 수저는 추산하지 못했습니다.」. 0으로 간주하지 않는다. 실제 여섯 판에는 이 사례가 없으며, 정상 유효 저장에서 발생한다고 주장하지 않는다. |
| 출생 수저·세대 경계가 유효하지 않음 | 임의의 단계로 채우지 않는다. 제품의 저장 검증·복구 경계에서 처리하고 장면을 생략한다. |

조사의 단위는 **가구**, 나이는 **가구주**다. 이 삶의 사망 나이를 그 연령대에 대응시키는 것은 설계 가정이며 실제로 가구주였다는 사실이 아니다. 60~64세의 독립 분포와 70·80대별 분포는 없다. 65세 이후는 모두 같은 행이다. 아래쪽 분포 모양을 전체와 같게, 위쪽을 로그정규로 보는 근사도 남는다. 이 추산으로 정밀한 사회적 위치나 개인의 성취를 증명하지 않는다.

태어날 때는 가족 형편의 등급이고 마칠 때는 게임의 마지막 자산을 가구 통계에 대응시킨 값이다. 수저 이름의 경계는 같지만 두 시점의 측정 대상은 같지 않다. 이를 작은 근거 줄과 선택해서 여는 「추산 기준」에 명확히 적는다.

## 6. 장면 문장과 숫자 제안

제목은 **「태어나고 마칠 때」**다. 성인 두 시점의 그림 아래에는 「태어날 때」·「마칠 때 · 추산」과 이름·점 다섯을 둔다. 그림 이름이 두 번 낭독되지 않도록 장식 묶음은 숨기고 사실 문장이 읽기를 맡는다.

| 경우 | 사실 문장 | 작은 근거 줄 |
|---|---|---|
| 올라감 — 실제 김현우 | 흙수저로 태어나 동수저로 마쳤습니다. | 가구주 연령대별 통계를 바탕으로 추산했습니다. |
| 그대로 — 실제 김나래 | 은수저로 태어나 은수저로 마쳤습니다. | 같은 근거 줄 |
| 내려감 — 실제 이상훈 | 다이아몬드수저로 태어나 금수저로 마쳤습니다. | 같은 근거 줄 |
| 내려감 — 실제 이학수·이상철 | 금수저로 태어나 은수저로 마쳤습니다. | 같은 근거 줄 |
| 20세 전 — 실제 이용수 | 동수저로 태어났습니다. | 마칠 때의 수저는 추산하지 않았습니다. |
| 성인 추산 불가 — 입력 경계 제안 | {출생 수저}로 태어났습니다. | 마칠 때의 수저는 추산하지 못했습니다. |

두 단계가 같은 경우도 같은 말투와 크기다. 「성공」「역전」「몰락」·칭찬·한숨·감탄과 상승/하락 색 기호를 넣지 않는다. 0 이하에서 흙수저가 되더라도 금액·부채 문장을 덧붙이지 않는다. 어린 삶에 아쉬움·잠재력·가정한 미래를 쓰지 않는다.

「추산 기준」을 열면 다음을 읽는다. 기본 화면에서는 접혀 있다.

> 2025년 가계금융복지조사의 가구주 연령대별 평균과 중위값을 바탕으로 분포를 추산했습니다. 가구주 연령대는 이 삶이 끝난 나이로 골랐습니다.
>
> 태어날 때는 가족의 형편을, 마칠 때는 이 삶의 마지막 순자산을 나타냅니다. 두 시점의 기준은 같지 않습니다. 수저 이름의 경계는 태어난 세대의 비율을 함께 씁니다.

**개인 백분위 숫자는 기본 화면과 접힌 설명 안 모두 숨기는 것을 추천**한다. 이 장면에서 읽을 핵심은 두 수저와 추산이라는 사실이다. 정밀하게 공표된 연령별 분포가 없는 상태에서 「아래에서 약 60%」를 크게 두면 숫자가 결론이 되기 쉽다. 금액·눈금·막대도 넣지 않는다. 이는 계산을 생략한다는 뜻이 아니며 검토용 수치·원본은 산출물에 남긴다.

형진 님이 숫자를 원하면 「추산 기준」 안의 보조 줄로만 `아래에서 약 60%`처럼 정수로 표시하는 대안을 남긴다. 1% 미만은 「아래에서 1% 안쪽」, 99% 이상은 「위에서 1% 안쪽」으로 묶는다. 표시 반올림은 수저 판정에 영향을 주지 않는다. 현재 시안은 숨김 추천안을 따른다.

## 7. 천천히 바뀌는 세 안

기존 `sp-1`~`sp-5` 실루엣만 쓴다. 새 그림·사진·재질 텍스처·래스터가 없다. 특정 게임·영화·방송의 크레딧 화면이나 문구를 참고하지 않았다.

| 안 | 처음 → 중간 → 끝 | 장점 | 판단 |
|---|---|---|---|
| **A. 같은 자리에서 겹쳐 바뀜** | 시작 수저 0.8초 → 불투명한 출생 그림 위에 마침 그림의 불투명도를 2.4초 동안 0→1 → 마지막 수저 1.6초 | 중간에 바탕이 비쳐 밝아지지 않는다. 움직이는 방향이나 중간 단계를 만들지 않고 실제 두 상태만 남긴다. 내려감에도 같은 동작이다. | **추천** |
| B. 아래에서 위로 스며듦 | 시작 수저 → 마지막 실루엣을 아래부터 위로 드러냄 → 마지막 수저 | 재질 변화가 잘 보인다. | 비추천. 아래→위의 방향이 내려간 판에서도 상승감을 주며 채움 막대로 읽힐 수 있다. |
| C. 두 그림의 밑줄을 차례로 옮김 | 두 수저 정지·시작 쪽 밑줄 → 둘 다 정지 → 마지막 쪽 밑줄 | 두 상태가 한 번에 읽히며 이미지가 겹치지 않는다. | 비추천. 두 수치의 비교 카드처럼 보이고 「천천히 바뀜」이 약하다. 움직임 줄이기에서는 밑줄 없이 두 그림만 쓴다. |

A는 **출생과 마지막 두 실루엣만** 겹친다. 1→5라도 2·3·4를 순서대로 보여 주지 않는다. 지나가지 않은 단계를 생애의 사실처럼 만들지 않기 위해서다. 중간의 두 색은 별도 등급이나 중간 수저가 아니며 이름·점은 처음과 끝의 두 사실로 고정한다. 화면 전체·배경·글자를 함께 어둡게 하거나 바꾸지 않는다.

동일 단계는 한 수저가 4.8초 그대로 머문다. 이름과 점은 태어날 때·마칠 때 두 항목으로 남는다. 20세 전은 출생 수저 한 개와 한 문장이 4.8초 머물고 변화·화살표·빈 마지막 칸이 없다. 이동 방향에 따라 축하·침묵·길이를 다르게 만들지 않는다.

**큰 실루엣의 규칙 충돌을 명시한다.** 현재 `Brand.tsx`는 32px 이상에 `sp-N-lg`를 쓰게 되어 있다. 이번 요청은 `sp-N` 다섯 실루엣을 직접 지정했으므로 시안에서는 그 지정을 우선하여 `sp-N`을 확대했다. 이 시안 한정 선택이며 기존 디자인 시스템을 개정했다는 뜻은 아니다. 제품 명세에서 예외를 명시해야 하며 원본 SVG나 `Spoon` 코드는 이번에 고치지 않는다.

## 8. 길이·정지·다시 보기

읽기와 수저 연출의 시간 예산을 분리한다.

```text
N = 기본 상태에 보이는 전문의 Unicode 문자 수
    (공백 포함, 줄바꿈·조작 단추·접힌 상세 원문 제외)
D_read = max(18, ceil(8 + N / 7))초
D_total = D_read + 4.8초
```

N에는 새 선택·시대·수저 사실 문장·기본 근거 줄·끝점 이름과 닫힌 상태에서도 보이는 「추산 기준」 제목 5자를 포함한다. 원문을 가린 판은 가림 문장을 센다. 「추산 기준」 상세나 펼친 민감 원문을 읽을 때는 재생을 멈추므로 기본 재생 N에 넣지 않는다. 초당 7자는 실제 독서 속도가 확인된 값이 아닌 첫 시안의 가설이다.

제품에서 전체 이동을 만들 경우 `D_read`의 **처음 4초와 마지막 4초 정지**는 유지한다. 마지막 4초는 수저 장면 뒤의 「생애 기록을 마쳤습니다」를 읽는 시간이다. 가운데 읽기 구간은 `D_read−8`, 수저 그림을 보는 별도 4.8초는 그 사이 끝부분에 한 번만 더한다. 수저 장면 끝의 1.6초와 최종 문장 4초는 서로 다른 화면 내용을 읽는 시간이며 같은 정지를 두 번 계산하지 않는다. 사실 문장의 읽기 시간은 N에, 추가 그림 머묾은 4.8초에 들어간다.

`D_read > 90` 또는 명단 21명 초과면 처음부터 정지 목록이다. 글·사람을 잘라내거나 빠르게 흘려 맞추지 않는다. 따라서 자동 전체 재생의 제안 상한은 **94.8초**이며, 목록에서는 시간 제한이 없다. 실제 이동거리/(D_read−8)가 36 CSS px/s를 넘는 경우도 목록으로 바꾼다. 같은 단계·20세 전의 4.8초는 고정 머묾이다.

**현재 시안은 전체 정지 목록과 명시적 버튼으로 시작하는 수저 4.8초만 작동한다.** 전체 크레딧 자동 스크롤·처음/끝 4초 상태 기계·생산용 지연 로딩은 구현하지 않았다. 아래 표의 자동 가능은 기획 규칙의 후보이지 현재 시안의 전체 자동 재생 여부가 아니다.

| 실제 판 | N | D_read | 제품 기본 제안 | 자동 후보 총길이 |
|---|---:|---:|---|---:|
| 김현우 | 568 | 90초 | 자동 후보; 속도 검사 필요 | 94.8초 |
| 이상훈 | 689 | 107초 | 정지 목록 | 없음 |
| 이학수 | 749 | 115초 | 정지 목록 | 없음 |
| 이용수 | 174 | 33초 | 자동 후보; 수저는 정지 | 37.8초 |
| 김나래 | 465 | 75초 | 자동 후보; 수저는 정지 | 79.8초 |
| 이상철 | 705 | 109초 | 정지 목록 | 없음 |

움직임 줄이기(`prefers-reduced-motion` 또는 `data-motion=reduce`)와 글자 200%는 정지 목록·정지 수저다. 성인은 두 수저를 나란히, 어린 삶은 하나만 둔다. 변화·페이드·자동 닫힘이 없다. 네이티브 스크롤은 허용한다. 글자 확대를 CSS 글자 크기 감지에만 의존하는 시안 방식은 제품의 확대·재배치 검사로 보완해야 한다.

늘 보이는 회고 복귀, 일시 정지/이어 보기, 목록 보기, 처음부터 보기를 제공한다. 수동 스크롤·방향키·PageUp/Down·Home/End·다른 조작 초점·창 폭 변경·탭 숨김·가림/근거 펼침 때 멈춘다. 돌아왔다고 임의로 재개하지 않는다. Escape는 회고로 돌아간다. Space/Enter는 초점 단추의 기본 동작을 따른다.

### 읽기와 초점

한 개의 안정된 문서로 읽는다: 인물 제목 → 가족 명단 → 선택 → 시대 → 수저 사실 → 마지막 기록. 수저 SVG·이름·점의 시각 묶음은 `aria-hidden` 장식이며 「흙수저로 태어나 동수저로 마쳤습니다.」라는 사실 문장 **한 번**이 두 시점을 설명한다. 별도의 숨은 동일 문장이나 `aria-live` 알림을 더하지 않는다. 화면 변화 프레임마다 DOM 문장을 교체하거나 초점을 움직이지 않는다.

진입 초점은 첫 제목, 복귀 초점은 회고의 호출 단추다. 끝에 도달해도 강제 초점 이동은 없다. 원문 펼침에는 나이·분류를 포함한 접근 가능한 이름과 펼침 상태를 둔다. 가린 내용을 단추 이름·설명으로 유출하지 않는다. reduced 모드도 같은 읽기 순서다. 실제 NVDA/VoiceOver 확인은 구현 완료 조건에 남기며 이번 시안으로 낭독 통과를 주장하지 않는다.

### 데이터·성능·저장

게임 상태는 읽기 전용이며 RNG를 소비하지 않는다. 이름·선택·시대·추산의 모든 결과는 원래 key/index/year와 입력값으로 역추적한다. 새 GameState·설정 저장 필드는 없다. 보기 상태·재생 위치·일시 정지·펼친 항목은 UI 메모리다.

보기 단추를 누른 뒤 크레딧 선택기·계산·스타일을 지연 로드한다. 첫 화면·생애 엔진에서 정적으로 따라오게 하지 않는다. 샘플 JSON은 검토용 산출물이며 앱에 탑재하지 않는다. 초기 gzip 400,000B, Chromium·WebKit 여유는 실제 제품 번들에서 다시 잰다. 청크 로드 실패는 회고·다시 태어나기를 유지하고 재시도 경로를 제공한다. 저장 덮어쓰기·인생 초기화로 처리하지 않는다.

고정 화면 명칭은 「이 삶의 이름들」·「이름과 시간」이다. 1회차에서 글꼴 조각 밖으로 확인한 「크레딧」의 ‘딧’을 새 UI에 넣지 않는다. 새 고정 문구는 400·700 기존 조각에 모두 있는지 구현 때 확인한다.

선택 수가 늘어 일부 판이 정지 목록으로 바뀌는 것은 의도한 상한 처리다. 이름·사건을 줄여 원래 재생 길이에 맞추지 않는다. 큰 결정 whitelist는 편집 제안이므로 후속 명세에서 승인하고 콘텐츠 추가 때 갱신 책임을 정한다. 그때도 학창·청년·중년·노년을 억지로 채우지 않는다.

## 12. 형진 님께 묻는 것

1. **수저 연출은 A 「같은 자리에서 겹쳐 바뀜」과 4.8초로 정할까요?** 추천은 A다. 실제 처음·끝만 사용하며 올라감·내려감에 같은 동작을 적용한다. 0.8초 시작, 2.4초 변화, 1.6초 끝을 읽고 동일 단계·어린 삶은 같은 시간 정지한다.
2. **개인 백분위 숫자는 숨길까요?** 추천은 숨김이다. 이름·점·추산 근거가 장면의 뜻을 전하며 불확실한 분포를 정밀한 개인 순위처럼 보이지 않게 한다. 원하면 접힌 「추산 기준」 안에 정수 근사치 한 줄만 두는 대안이 있다.

이미 정해진 일곱 결정과 경제 보정 후 배포를 다시 묻지 않는다. 위 두 제안 확인 전에는 제품에 구현하지 않는다.
