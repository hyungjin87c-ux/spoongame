# DSN-001 엔딩 크레딧 기획 — 이 삶의 이름들

- 상태: **기획·디자인 제안. 형진 님 선택 전 구현하지 않음.**
- 기준: 2026-11-13, `41521a1cb256a575ba4c0a216334891c6b6486f5`.
- [시안 목록](mockups/index.html) · [엔딩 안의 진입 위치](mockups/ending-entry.html) · [모바일 첫 장면](shots/credits-360-light-start.png) · [PC 첫 장면](shots/credits-1280-dark-start.png).
- 추천: **사망 기록 문서 아래에서 선택해 여는, 이름 중심의 한 장 크레딧**. 가족과 친구의 이름, 실제 선택 두 건, 역사적 시대 줄 두 건을 담는다. 마지막에는 기록 화면으로 돌아간다.

## 1. 무엇을 남길 것인가

플레이 중 가족 카드 가장자리에 있던 이름을 엔딩의 가운데로 옮긴다. 어머니와 아버지, 형제와 배우자, 친구를 호칭과 이름으로 다시 본다. 그 뒤에 가족이 정했던 일과 본인이 골랐던 일을 한 장씩, 그 삶의 시간 안에 있었던 사회 사실을 짧게 놓는다. 감정의 결론을 대신 내리지 않고 구체적인 이름과 장면을 남긴다.

현재 엔딩은 실제 Chrome에서 확인했다. 머리와 사망 요약 다음에 비교 막대가 크게 놓이고, 스탯과 연표가 이어진다. [확인한 현재 화면](shots/current-ending-1280-light.png). 이 비교 카드가 빠지는 자리에는 새 지표 대신 **이름과 기록을 여는 진입부**를 둔다. 기존 숫자 카드의 크기를 그대로 채울 필요는 없다.

## 2. 컨셉 세 안과 추천

### A. 이 삶의 이름들 — 추천

작은 호칭과 큰 이름으로 시작하는 한 장의 명단이다. 이름 다음에 실제 질문·고른 길·결과 원문, 마지막에 시대 사실과 주인공 이름이 온다. 출생신고서의 종이 면과 정렬, 인생 기록의 시대 색을 이어 쓴다. **와닿는 지점은 익숙했던 이름들이 처음으로 주된 내용이 되는 순간**이다.

- 장점: 현재 가족 카드와 연표에서 바로 만들 수 있다. 긴 삶·짧은 삶·가족이 적은 삶 모두 같은 규칙을 쓴다. 종이 한 장의 읽기 순서가 정지 목록에서도 유지된다.
- 단점: 이름만 길어지면 장부처럼 느껴질 수 있다. 그래서 이름 뒤에 해당 판의 구체적인 선택과 시대 줄을 넣고, 자동 재생을 강제하지 않는다.

### B. 그해의 사람들

출생, 가족 변화, 진로 같은 실제 발생 시점을 세네 장으로 나눠 보여 준다. 연도와 사건 옆에 기록으로 확인되는 인물을 둔다. **와닿는 지점은 어떤 사람이 삶에 들어온 때를 다시 만나는 것**이다.

- 장점: 사람과 사건의 연결이 선명하고 장면마다 여백을 충분히 줄 수 있다.
- 단점: 현재 가족 모델은 과거 동거·관계 상태 전체를 복원하지 못한다. 장면을 채우려는 압력이 추정을 부르고, SPEC-017의 첫 단상과 반복된다. 이번 추천에서 제외한다.

### C. 두 줄의 시간

개인의 선택과 같은 시기 사회 사실을 두 줄로 병치한다. PC에서는 두 열, 휴대폰에서는 위아래로 읽는다. **와닿는 지점은 한 사람의 일상과 사회의 시간이 나란히 놓이는 것**이다.

- 장점: 가족이 적은 판에서도 내용이 성립하며 세대 차이를 드러내기 쉽다.
- 단점: 같은 때 일어났다는 이유만으로 인과관계가 있는 것처럼 읽힐 수 있다. 기존 시대 연표의 축약판이 되기 쉬우며 이름의 비중도 줄어든다.

**A를 추천한다.** 검증된 이름을 가장 크게 두고, 의미를 과장하지 않는 편집으로 사람과 시대를 연결할 수 있다. 특정 작품의 화면·문구·구성을 참고하지 않았다. 역할과 이름을 배열하고 글이 천천히 이동하는 일반 관습만 사용했다.

## 3. 엔딩 흐름과 SPEC-017 정리

```text
사망 직후
  → SPEC-017 첫 장면 약 10초(기존 계획, 건너뛰기 가능)
  → 사망 기록 문서 / 회고
       ├─ 이 삶의 이름들 보기 → 크레딧 → 회고로 돌아가기
       ├─ 스탯 / 생애 연표
       └─ 다시 태어나기(기존 안내·확인 규칙)
```

- **진입 위치**: 사망 기록 문서의 바로 아래, 스탯과 긴 연표보다 앞. 제목 `이 삶의 이름들`, 설명 `이름과 시간을 다시 펼칩니다.`, 버튼 `이 삶의 이름들 보기`. 단추를 눌러야 시작한다. [진입부 부분 시안](mockups/ending-entry.html)은 위치와 정보 위계를 보여 주며 SPEC-017 사망 서류 전체를 새로 디자인한 것은 아니다.
- **첫 장면**은 사망 직후의 짧은 전환, **크레딧**은 사람·선택·시대의 구체적인 기록, **서류·연표**는 자세히 확인하는 기록으로 역할을 나눈다. 두 긴 연출을 연속 자동 재생하지 않는다.
- SPEC-017 E1-1의 출발선·시대 마무리는 이번 삭제와 중복을 함께 검토해야 한다. 추천 수정 방향은 첫 장면의 끝을 `생애 기록을 펼칩니다.` 같은 전환 문장으로 줄이고, 구체적인 시대 사실은 크레딧에 맡기는 것이다. 이 문서는 기존 명세를 고치지 않는다.
- SPEC-017 E2의 “출발선 막대 유지”, E3 공유 카드의 출발선 후보도 후속 명세에서 삭제 결정과 정합성을 맞춰야 한다. 공유 카드의 대체안은 이번 범위 밖이다.
- 첫 장면을 건너뛰면 곧바로 회고로 간다. 크레딧을 뒤이어 자동 시작하지 않는다. 크레딧의 `건너뛰기`·Escape 역시 회고로 돌아갈 뿐 새 판을 만들지 않는다.
- 끝은 자동 닫힘 없이 멈춘다. 주 버튼은 `기록으로 돌아가기`, 보조는 `처음부터 보기`. 다시 태어나기는 돌아간 회고 화면의 기존 경로를 쓴다. 연출을 닫는 조작과 인생 기록 삭제를 분리한다.

## 4. 전문의 구조와 데이터 계약

아래의 “줄”은 줄바꿈에 따라 늘어나는 화면 줄 수가 아니라 **논리 항목**이다. 최종 시안과 12절 전문은 같은 `mockups/model.mjs`로 만들었다. `credits.json`에는 표시할 결과와 원문 위치를, `samples.json`에는 실제 생성 상태와 파생 근거를 보존했다. 이 파일들은 시안용이며 제품의 런타임 데이터로 가져오지 않는다.

시대 필터의 제품 구현에는 **`forecast:false`뿐 아니라 실제 역사 연도 상한과 event 줄인지도 검사**해야 한다. 이번 6개 샘플은 2110년 이전에 끝나므로 끝 안내를 만나지 않는다. 달력 현재 시각을 기준으로 미래 줄이 자동으로 역사 사실이 되게 하지 않는다. 승인된 시대 데이터의 실제 마지막 해를 사용한다.

**명단 순서**는 어머니 → 아버지 → 조부모 기존 자리 순 → 손위·손아래 형제의 기존 key 순 → 배우자/연인 → 자녀 → 친구다. 별세·동거·재산·관계 점수로 이름의 크기나 순서를 바꾸지 않는다. 같은 이름이 두 사람에게 있으면 key가 다르므로 둘 다 남긴다. 성인기에 같은 key의 과거 인연을 모두 복원했다고 주장하지 않는다.

**최대 본문은 사람21 + 선택2 + 시대2 = 25항목**이다. 부모2·조부모4·형제7·배우자1·자녀4·친구3을 기준으로 한 현재 모델의 상한이다. 미래 모델에서 더 많아지면 사람을 임의로 잘라내지 않고 전체 정지 목록으로 전환한다. 서문·끝·장 제목은 별도다. 선택 장과 시대 장이 빈 경우 제목·빈 칸·“없음”을 모두 만들지 않는다.

### 사람을 해석하지 않는 경계

- 가족 명단은 **기존 카드가 확인해 주는 관계와 이름**이다. 모든 과거 만남의 완전한 명부가 아니다. `familyViewOf(game, at)`에 옛 나이를 넣어도 현재 flags를 읽으므로 과거 동거·친밀도 전체를 복원할 수 없다.
- 출생 전 별세 조부모는 명단에서 제외한다. 별세한 나머지 사람은 같은 호칭·이름으로 포함하되 사인·추모 표식·검은 띠·별세 나이를 덧붙이지 않는다. 생존자로 표현하지도 않는다.
- 사이가 먼 사람도 지우지 않는다. 기존 카드의 `전 배우자`, `멀어진 친구` 등 확정 호칭만 따른다. 관계 수치로 “사랑한”, “돌봐 주신”, “끝까지 곁을 지킨”을 만들지 않는다.
- 플레이어가 그 사회 사건을 직접 목격하거나 피해를 입었다고 쓰지 않는다. 어린 나이의 시대 줄도 기억이나 경험담이라고 부르지 않는다.
- 수저·외모·성별·기질을 이름 앞의 평가 수식어로 쓰지 않는다. 자산·스탯·백분위·순위는 전문에 들어가지 않는다. 직업 지원 라벨을 실제 취업 직업으로 바꾸지 않는다.

## 5. 가림·짧은 삶·사용자 글

- 원문 가림은 현재 `settings.gentle`로 결정한다. `gentleUsed`는 사용 이력 안내만 결정한다. 사용 이력이 있어도 현재 설정이 off면 원문을 보여 주는 기존 규칙을 따른다.
- 선택 항목이 heavy면 제목·질문·선택·결과를 함께 가리고 `무거운 일이 있었습니다 · {HEAVY_KIND_TEXT}`만 남긴다. 시대는 기존 `SCENE_TEXT.eraVeilKind`인 `시대의 일`을 쓴다. 시각 출력과 접근성 출력에 같은 변환 결과를 전달한다.
- `펼쳐 보기`로 요청한 항목만 읽을 수 있다. 열 때 자동 이동을 멈춘다. `aria-expanded`와 해당 본문 연결을 제공하며 버튼 이름에 나이·분류를 붙인다. 닫힌 원문을 투명 글자나 스크린리더 전용 글자로 남기지 않는다. 가림 설정 변경·다시 진입·새로고침 시 펼침은 초기화한다.
- 사인과 가족의 별세 원문은 크레딧에서 반복하지 않는다. 새 사인을 만들지 않는다. 민감 소재의 기존 분류·정치/재난의 사실 한 줄 원칙을 유지한다. 새로운 자살 서술은 만들지 않는다.
- 실제 6세 사망 샘플은 이름·가족6명·1945년 시대1줄로 끝난다. 학업·직업 장은 없다. “피우지 못한 꿈”이나 가정한 미래를 붙이지 않는다.
- 가족4명인 샘플도 같은 여백과 이름 크기를 쓴다. 배우자·친구의 빈 자리를 표시하거나 외로움을 단정하지 않는다. 가족 데이터가 없는 옛 판은 이름·실제 선택·확인된 시대 줄로 성립한다.
- **사용자가 남긴 글은 첫 버전에서 제외를 추천**한다. 해석·요약·감정 추론을 하지 않는다. 포함 여부는 11절 질문으로 남긴다. 이후 포함한다면 본인이 선택한 원문 한 건만, 순수 텍스트와 `bdi dir=auto`, 줄바꿈·긴 단어·양방향 글 처리를 그대로 적용한다.

## 6. 길이·속도·조작

길이 후보는 **짧게25~40초 / 기본60~90초 / 느리게90~120초**다. 추천은 **본문에 따라 18~90초**, 현재 일반 샘플은66~83초다. 30분 남짓의 판 뒤에 읽는 별도 콘텐츠인 만큼 선택 진입을 전제로 한다. 짧은 삶을 기본 길이까지 빈 화면으로 늘이지 않는다.

- 초기 길이 가설은 `D = max(18, ceil(8 + N/7))초`. N은 내비게이션을 제외한 표시 전문의 Unicode 문자 수이며, 문서에서 보이는 공백도 포함한다. **초당7자는 실측 독서 속도가 아니라 첫 시안의 조정 가능한 가설**이다. 긴 문자열의 UTF-16 코드 단위 수를 쓰지 않는다.
- D가90초를 넘거나 명단이 현재 상한을 넘으면 처음부터 정지 목록. 빠르게 흘려 상한에 억지로 맞추거나 사람을 삭제하지 않는다. 200% 글자 확대에서는 정지 목록을 추천한다.
- 초기4초·마지막4초는 정지해 이름과 버튼을 읽는 시간으로 둔다. 가운데 D−8초에 이동한다. 구현에서는 실제 이동거리/(D−8)로 속도를 계산하되 36 CSS px/s를 넘으면 정지 목록으로 전환한다. 시안의 선택 재생은 이 중간 이동 감각을 확인하는 보조 기능이며 4초 정지와 완료 안내의 정식 상태 기계는 구현하지 않았다.
- 이동은 선형, 가속·페이드·확대·검은 화면 전환 없음. 배경과 글자 색을 도중에 바꾸지 않는다. 이름과 호칭이 한 묶음으로 지나간다.
- 항상 보이는 `건너뛰기` + Escape는 회고로 복귀한다. `멈추기/이어 보기`, `목록으로 보기`, `처음부터 보기`를 제공한다. Space/Enter는 현재 초점 단추의 기본 조작을 따른다. 본문에서 방향키·PageUp/Down·Home/End·직접 스크롤을 쓰면 자동 이동을 멈추고 사용자 스크롤을 따른다.
- 탭이 가려지면 멈추고, 돌아왔을 때 임의로 재개하지 않는다. 버튼으로 재개할 때 같은 위치에서 계속한다. 다른 컨트롤에 키보드 초점이 가거나 창 폭이 바뀌어도 멈춘다.
- `prefers-reduced-motion:reduce` 또는 `data-motion=reduce`는 **이동·페이드·자동 종료가 없는 전체 정지 목록**이다. 긴 목록의 네이티브 스크롤은 허용한다. 재생 버튼을 숨기고 읽기 순서를 유지한다.
- **소리 추천은 무음**이다. 현재 앱은 엔딩에서 BGM을 정지한다(`App.tsx:351`, `useBgm.ts:28`). 새로운 음악·음량 상승·자동 음원 로드는 제안하지 않는다. 기존 곡 사용 여부는 별도 질문이다.

## 8. 접근성·성능·저장

### 접근성

- 한 개의 안정된 의미 문서: 이름 h1 → 가족과 친구 h2/dl(호칭과 이름 한 항목) → 선택 h2/article → 시대 h2/article → 끝/버튼. 화면 밖의 다음 줄도 처음부터 문서에 존재한다. 가림 원문만 닫힌 상태에서 읽기 트리에서 제외한다.
- 진입 시 첫 제목에 초점을 둔다. **줄마다 aria-live로 낭독하지 않는다.** 스크린리더는 전체를 한 문서로 순서대로 읽거나 탐색할 수 있다. 시각 연출용 텍스트를 별도로 복제해 두 번 읽게 하지 않는다. “전체를 한 번에”는 자동 장문 방송을 뜻하지 않는다.
- 자동 이동 중 컨트롤에 초점이 가면 멈춘다. 초점 위치를 따라가는 자동 전환·가상 목록 없음. 닫을 때 호출한 회고 버튼으로 초점을 돌린다. 끝에 도달했다고 초점을 강제로 이동하지 않는다.
- 접근성 점검은 이 시안에서 DOM·키보드·미디어 에뮬레이션까지 했다. 실제 NVDA/VoiceOver 낭독은 미확인이며 구현 완료 기준에 둔다.

### 성능

- 첫 화면·생애 엔진에는 크레딧 본문 선택기·CSS·시대 자료를 정적 import하지 않는다. **보기 버튼을 누른 뒤 동적 import**하는 별도 UI 경계다. 기존 EndingScreen이 정적 import되어 있어도 그 파일에서 크레딧의 구현·데이터를 정적으로 따라오게 하지 않는다.
- lazy 모듈이 받아야 할 입력은 기존 종료 GameState와 현재 gentle, 이미 설치된 데이터/공개 조회 함수다. 새로운 전체 가족/시대 JSON 사본을 앱에 넣지 않는다. 생산용 출력은 현재 상태에서 파생하며 새 RNG 소비0.
- 시안의 samples.json은 검토 근거용이고 제품 첫 로딩과 무관하다. credits.json도 앱에 포함시키지 않는다. 기존 폰트 파일만 사용하며 새 음원·이미지·외부 요청0.
- 청크 로드 실패 시 회고 화면과 다시 태어나기 기능을 유지한다. 실패 안내와 재시도를 제공한다. 크레딧 실패가 종료 저장을 덮어쓰거나 인생을 초기화하지 않는다.
- 첫 로딩400,000B는 **실제 production 번들의 Chromium·WebKit에서 재측정**해야 한다. 이번 정적 시안의 크기로 제품 한도 통과를 주장하지 않는다. 필요 모듈을 이미 확보하지 못했을 때 era 청크만 선택 진입 뒤 받는다.

### 저장과 복원

새 GameState·설정 필드0. `view:review|credits`, 재생 위치, 멈춤, 펼친 항목 key는 UI 메모리만 쓴다. 엔딩 데이터는 읽기 전용이다. 새로고침·이어하기는 항상 저장된 엔딩의 회고 화면을 열고, 첫 장면/크레딧을 자동 재생하지 않는다. 명시적으로 다시 보기 하면 동일한 자료·순서로 처음부터 표시한다. 다른 탭이 새 판을 시작한 경우에는 기존 세션 충돌 처리를 그대로 따른다.

## 9. 실제 샘플과 재현

## 11. 형진 님께 묻는 것

선택을 기다리는 항목을 한꺼번에 모았다. 나머지는 위 추천안으로 구체화했다.

1. **회고에서 선택해 여는 배치로 할까요?** 추천은 사망 기록 문서 바로 아래 버튼이다. SPEC-017 첫 장면 뒤에 긴 연출을 또 강제하지 않으면서, 긴 연표보다 먼저 발견할 수 있다.
2. **SPEC-017 첫 장면의 출발선·시대 마무리를 전환 문장으로 정리할까요?** 추천은 `생애 기록을 펼칩니다.` 방향이다. 비교 삭제와 맞추고 사람·시대의 구체적인 줄을 크레딧에 맡긴다. 확정 명세의 문구 변경이므로 확인이 필요하다.
3. **사용자의 생각 남기기 글을 포함할까요?** 추천은 첫 버전 제외다. 이후 원한다면 플레이어가 직접 고른 원문 한 건만 넣고 자동 해석·요약은 하지 않는다.
4. **크레딧에 기존 BGM을 이어 붙일까요?** 추천은 현재 엔딩과 같은 무음이다. 음악을 택하면 기존 켜짐·음량을 존중하는 별도 재생 조작을 명세에 넣어야 한다. 새 곡은 이번 범위 밖이다.
5. **명단은 기존 가족 카드가 확인하는 이름만으로 시작할까요?** 추천은 그렇다. 과거의 모든 인연이나 동거 기간을 완전하게 복원하는 기능은 별도 데이터 설계가 필요하다. 그 범위를 이번에 넓히지 않으면 새 저장 필드 없이 구현할 수 있다.

표시 문구와 길이는 시안 단계다. 실제 읽기 속도·감정의 와닿음은 형진 님의 샘플 확인 뒤 조정하며, 데이터가 없는 내용으로 빈 부분을 채우지 않는다.
