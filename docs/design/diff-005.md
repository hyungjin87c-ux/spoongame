## 9. REV-005-QI3-1 후속 — 낮은 창의 그림 높이 (R-447, designer 판단 2026-10-20)

**문제**(reviewer): `title.css:368` 그림 높이 420px 고정이라 1280 폭에서 창 높이가 낮으면 스크롤 0에서 값 줄이 띠에 가린다. 형진 님 메인 플랫폼(FHD 150% 노트북)의 브라우저 안쪽 높이가 약 600~650이라 **기본 환경에서 HS3 ④의 뜻(표제어·값이 스크롤 0에 보임)이 깨진다.** 시안 재측정(9-1): 1280×620은 새 판·이어서 살기 모두 가림(값 아래 558 > 열 끝 546·494), 1366×657은 새 판 한 줄 표제어만 보임(25px 여유)이고 두 줄 표제어·이어서 살기는 가림(−5·−27·−57).

**판단**: 높이 조건으로 **그림만** 줄인다(카드·슬롯·여백은 그대로 — 그림은 장식이고 통계 카드가 내용이다). 단계(`max-height` 미디어 쿼리)가 아니라 **연속 `clamp()`** — 단계는 경계 바로 위 높이에서 다시 가리는 틈이 생기고(예: 699에서 420이면 이어서 살기 −8), 식 하나면 어느 높이에서나 같은 여유(8px)를 지킨다. 띠 높이 변수 `--bar-h`는 식에 넣지 않는다 — JS가 재기 전 첫 그림에서 그림이 한 번 뛰고(CLS), 확인 단계(156px)로 들어갈 때마다 그림이 움직인다. 대신 **이어서 살기 띠(120px)와 두 줄 표제어(24자)** 를 설계 기준으로 잡아 가장 흔한 두 상태를 모두 덮는다(확인 단계는 과도 상태라 열 안쪽 스크롤에 맡긴다).

| ID | 곳 | 지금 구현 | 시안(제안) | 상태 · 근거 |
|---|---|---|---|---|
| D5-34 | 넓은 화면 그림 높이·겹침(낮은 창) | `.illust--top { --illust-h: 420px; --illust-tuck: 32px }`, ≥ 1600 `500px`·`36px` 고정 | 아래 CSS 원문 — `--illust-h`는 `clamp(224px, calc((100vh - 334px) / 0.924), 420px)`(≥ 1600 상한 500px), `--illust-tuck`은 `min(32px, calc(var(--illust-h) * 0.0762))`(≥ 1600 `min(36px, …)`). 창 높이 ≥ 722 → 420(지금 그대로, 1280×800·1920×1080 수치 불변), 541 이하 → 바닥 224(모바일 배너와 같은 최소), 그 사이는 비례. 겹침도 비례(7.62%)라 그림이 줄어도 제주 타일은 아래 30%만 가려진다 | **시안 제안(designer 판단, R-447)** — 구현은 `src/styles/title.css` 「넓은 화면」 블록의 `.illust--top` 두 줄과 1600 블록 한 줄을 아래로 바꾼다. 시안 `title-005.css` 같은 블록에 적용(2026-10-20). e2e 제안은 아래 |

**CSS 원문**(`src/styles/title.css` — `@media (min-width: 960px)` 블록 안의 `.illust--top` 규칙과 `@media (min-width: 1600px)` 블록을 이것으로; 시안 `title-005.css`는 `html[data-hero='illust']` 접두만 다르다):

```css
@media (min-width: 960px) {
  .illust--banner { display: none; }
  /* 겹침(--illust-tuck)은 그림 높이의 7.62%(420px일 때 32px) — 낮은 창에서 그림이 줄어도 제주 타일이 카드 뒤로 더 들어가지 않는다(D5-34). 420·500px에서는 32·36 그대로 */
  .illust--top { display: flex; justify-content: center; --illust-h: 420px; --illust-tuck: min(32px, calc(var(--illust-h) * 0.0762)); margin-bottom: calc(-1 * var(--illust-tuck)); }
  /* 낮은 창(REV-005-QI3-1 R-447, diff-005 D5-34): 그림 높이를 창 높이에 맞춰 줄여 이어서 살기 띠(120px)에서도, 표제어가 두 줄인 슬라이드에서도 값 줄 아래끝이 열의 보이는 끝 위(여유 8px)에 있게 한다.
     예산 334px = 띠 120 + 열 아래 간격 6 + 여유 8 + 위 여백 24 + 카드 위끝→값 아래끝 176(표제어 두 줄). ÷ 0.924 = 겹침(7.62%)을 뺀 그림 높이 비율. 창 높이 ≥ 722면 420(지금 그대로), 541 이하는 바닥 224(모바일 배너와 같은 최소).
     clamp()를 모르는 엔진은 위 420px 그대로(@supports). --bar-h를 쓰지 않는 이유: JS가 재기 전 첫 그림과 확인 단계(156px)에서 그림이 뛴다(CLS·움직임). */
  @supports (height: clamp(1px, 2px, 3px)) {
    .illust--top { --illust-h: clamp(224px, calc((100vh - 334px) / 0.924), 420px); }
  }
}
@media (min-width: 1600px) {
  .illust--top { --illust-h: 500px; --illust-tuck: min(36px, calc(var(--illust-h) * 0.0762)); }
  @supports (height: clamp(1px, 2px, 3px)) {
    .illust--top { --illust-h: clamp(224px, calc((100vh - 334px) / 0.924), 500px); }
  }
}
```

식의 유래: 값 줄 아래끝 = 위 여백 24 + (그림 h − 겹침 0.0762h) + 카드 위끝→값 아래끝(한 줄 147 / 두 줄 176) ≤ 열의 보이는 끝(창 높이 − 띠 − 6) − 여유 8 → `0.924h ≤ 100vh − 334`(띠 120·두 줄 기준). `0.0762 = 32/420`, `0.924 = 1 − 0.0762`. 1280×800·1920×1080은 clamp 상한에 걸려 **지금 측정값(카드 위 412/488, 값 아래 558/634, 겹침 32/36) 그대로** — `e2e/first-screen-layout.spec.ts` 「배치 1280x800·1920x1080」 단언은 바뀌지 않는다.

**e2e 제안**(developer): `first-screen-layout.spec.ts` 배치 시험의 뷰포트 표에 `{1280×620, 1366×657} × {새 판, 이어서 살기(저장 있음)}`를 더해 (ⅰ) `.illust--top img` 높이 = 310 / 350(±1) (ⅱ) 그림 아래끝 − 카드 위끝 = 24 / 27(±1) (ⅲ) 활성 슬라이드의 `[data-testid="slide-value"]` 아래끝 ≤ `.title__side` 아래끝(`getBoundingClientRect().bottom`, = 띠 위끝 − 6) — 첫 슬라이드와 두 줄 표제어 슬라이드(cdr, 24자) 둘 다 (ⅳ) 1280×800·1920×1080 수치 불변.
