# 첫 화면 CI 시안 세 안 · 로고 링크 규격 (SPEC-016 후보, 2026-11-10 designer)

형진 님 요청(2026-11-10): ① 첫 화면에 수저 게임 CI(한반도+수저 심볼)가 없다 — 시안 2~3개를 보고 고른다. ② 모든 화면의 로고를 누르면 **확인 없이** 첫 화면으로 간다 — 링크의 모양(기본·호버·포커스·누름)과 접근 이름을 정한다.

> **확정(2026-11-10 형진 님·마스터, SPEC-016 후속)**: ① 첫 화면 CI = **안 B 가로 결합 로고**(1절 B 행 규격 그대로). ② 판 도중(룰렛·출생신고·인생) 로고는 확인 없이 첫 화면, **엔딩 로고는 한 번 묻고** 첫 화면(= 새 판, 그 엔딩은 다시 볼 수 없다) — 확인 단계 규격은 **3-6절**. 마스터 결정: 접근 이름 쉼표형 「수저 게임, 첫 화면으로」 · **밀린 화면 로고는 링크 아님**(developer 실측 — 다른 탭을 밀어내는 부작용) · 로고 링크 **입력 가드 없음** · 320px 획 상자 39px 허용. 8절의 판단 항목은 모두 닫혔다. 새 소식 확정안은 4절.

## 0. 한 줄 요약과 추천

| 안 | 한 줄 | 좁은 화면(360) 머리 높이 → 세대 목록 시작 | 넓은 화면(1280) |
|---|---|---|---|
| **A 세로 로고** | 큰 워드마크 자리에 `logo-stacked.svg`(정식 심볼 위, 워드마크 아래) | 176px → 목록 330px(지금 291) | 236px → 382px(지금 303) |
| **B 가로 결합 로고(추천)** | 큰 워드마크 자리에 `logo-a.svg`(정식 심볼 왼쪽 + 워드마크) — 다른 화면 머리글 로고와 **같은 짜임을 크게** | 88px → 목록 242px(지금보다 49px 위) | 108px → 254px(49px 위) |
| **C 머리글 + 워드마크** | 맨 위에 다른 화면과 같은 머리글(`logo-header.svg` 40px + 「첫 화면」), 큰 워드마크는 그대로 | 73px 머리글 + 64px → 목록 364px(73px 아래) | 73 + 84px → 376px |

**추천 B.** 이유 넷:
1. **CI가 첫 화면 첫 줄에 있다** — 심볼 88px(≥ 48 정식 심볼 기준)이 워드마크와 한 덩어리라 「한반도를 담은 숟가락」이 제목과 함께 읽힌다. A도 CI는 있지만 심볼이 워드마크 위에 따로 서서 둘로 읽히고, 좁은 화면에서 머리가 176px이라 세대 목록이 지금보다 39px 더 내려간다(목록은 선택의 자리라 첫 화면의 중심이다).
2. **모든 화면의 로고가 한 짜임**이다 — 머리글 로고(`logo-header.svg`, 단순화 심볼 + 워드마크 0.64H)와 B(`logo-a.svg`, 정식 심볼 + 워드마크 0.768H)는 심볼–워드마크의 자리·비율이 같은 계열이라, 로고를 누르면 첫 화면으로 간다는 규칙이 「같은 그림이 큰 자리로 돌아온다」로 체감된다. 
3. **가장 작은 변화로 가장 큰 효과** — 머리 높이가 64 → 88px(24px)로 늘 뿐이고 왼쪽 정렬·부제·체험 한 줄·목록 배치는 그대로다(디자인 시스템 1절 로고 규칙의 「첫 화면 ≥ 40px」도 지킨다: 워드마크 획 상자 실측 42px).
4. C는 「수저 게임」이 한 화면에 두 번(머리글 40px + 제목 64px) 보여 **되풀이로 읽힌다**(`screens/016` 샷에서 바로 보인다). 머리글의 「첫 화면」 이름도 첫 화면에서는 자기 이름이라 정보가 없다. C의 장점(링크 자리가 모든 화면에서 같다)은 첫 화면에서 로고가 링크가 아니므로(3-4) 쓸 데가 없다.

- B의 흠: 320px 폭에서는 로고가 칸 폭 288px에 맞춰 83px로 줄어 워드마크 획 상자가 **39px**(≥ 40에 1px 모자람). DS1의 기준 폭은 360이고 320은 CM11의 「넘침 없음」 기준만 보므로 허용 범위로 본다. 더 지키고 싶으면 88 → 92px(360에서 폭 319px, 320에서 똑같이 288px로 줄어 39px — 바뀌지 않는다)이 아니라 **320px 아래에서만 심볼을 빼고 워드마크만** 두는 길이 있으나 CI가 사라지므로 권하지 않는다.

## 3. 머리글 로고 링크 — 규격 제안 (첫 화면 밖 모든 화면)

### 3-1. 구조와 접근 이름

- **developer가 같은 날 구현 중인 것과 맞춘다**(작업 트리 `src/ui/Brand.tsx` SPEC-016 H1, 커밋 전 — 읽기만 했다): `HeaderLogo({ onHome })`이 그림을 `<button type="button" class="logo-link" aria-label={LOGO_HOME_LABEL}>`로 감싸고 안쪽 `span`은 `aria-hidden`, `title.css`에 `.logo-link { … margin: -2px 0; min-width/min-height: var(--hit) … }`. 이 문서의 상태 CSS(3-2)는 **그 규칙 뒤에 덧붙이는 블록**이고 클래스 이름이 같다. 버튼(동작은 앱 안의 화면 전환)이라 `href`는 없다 — 뜻은 같다. 가로 여백은 developer 규칙(`margin: -2px 0; padding: 0`, 최소 폭 44px)을 그대로 두어도 되고, 호버 면이 로고에 꼭 붙는 것이 거슬리면 `padding: 0 4px; margin: -2px -4px`로.
- 접근 이름 문구는 `LOGO_HOME_LABEL` 한 상수 — developer 자리표시 「수저 게임 — 첫 화면으로」를 아래 추천 문구로 바꾼다(둘 다 글꼴 조각 안, 「—」 U+2014는 s0).
- 접근 이름 **「수저 게임, 첫 화면으로」**(13자, 글꼴 조각 안). 게임명이 먼저 오는 이유: DS1 「게임명이 모든 화면 헤더에 읽힌다」를 링크 이름이 그대로 맡는다. 쉼표는 낭독의 쉼이고 「—」·「·」는 낭독기마다 읽는 법이 달라 쓰지 않았다(마스터 예시 「수저 게임 — 첫 화면으로」의 뜻 그대로). 대안 「수저 게임 첫 화면으로」(12자 — 「수저 게임의 첫 화면」으로 들려 뜻은 같고 쉼이 없다).
- `title` 속성은 두지 않는다(마우스 툴팁은 접근 이름과 같은 글이라 더할 정보가 없고, 터치에서는 보이지 않는다). 보이는 글자가 없는 그림 링크라 WCAG 2.5.3(보이는 이름 포함)은 해당 없음.
- 쓰는 자리: `SiteHead`(룰렛·출생신고·엔딩·오류 화면)와 `DashHead`(인생 화면 sticky 머리글) — `HeaderLogo` 한 곳을 바꾸면 모두 바뀐다. 오류 화면에서도 링크다(첫 화면으로 가는 길이 하나 더 생겨 안전하다 — 주 버튼은 그대로). **밀린 화면은 링크가 아니다**(마스터 결정 2026-11-10 — developer 실측에서 새로 열면 다른 탭을 밀어내는 부작용이 있어 `onHome`을 주지 않는다: 눌러도 아무 일 없는 그림, 지금과 같다). 엔딩은 링크이되 **한 번 묻는다**(3-6).

### 3-2. 네 상태 (시안 `?v=link`, 라이트·다크·강제 색상 샷)

| 상태 | 모양 | 토큰 |
|---|---|---|
| 기본 | 로고 40px 그대로, 밑줄 없음(그림 링크), 커서 손 모양 | `--c-logo` |
| 호버 | 로고 뒤에 **면 한 단**(모서리 `--r-sm` 6px, 로고 둘레 위아래 2px·좌우 4px) — 로고 색은 바꾸지 않는다(R-130) | `--c-surface-2`(라이트 #f1ede4 · 다크 #262c3a) |
| 키보드 포커스 | 공통 포커스 링 3px, 간격 2px | `--c-focus`(#1d5bd6 / #8ab4ff, 바탕과 3:1 ↑) |
| 누름(`:active`) | 호버 면보다 한 단 진한 **쪽빛 옅은 면** — 눌린 순간이 보인다 | `--c-brand-soft`(#e4e8f1 / #262f47) |
| 강제 색상 | 면이 지워지므로 호버 = **2px 점선** CanvasText, 누름 = 2px 실선, 포커스 = 3px Highlight(공통 링). 로고는 `forced-color-adjust: none` + `--c-logo: CanvasText`(지금 규칙) | 시스템 색 |

- 전환 `background var(--dur) var(--ease)`(200ms, `.btn`과 같다). 움직임 줄이기에서는 토큰이 0.01ms라 즉시.
- 누르는 영역: 로고 40px + 패딩 2px·4px = **44px**(WCAG 2.5.8) — 음수 바깥 여백(`margin: -2px -4px`)이라 머리글 배치·`--head-h`는 그대로다.
- 대비: 상태 면은 **뜻을 나르지 않는 보조**(링크임은 로고 모양·커서·포커스 링·낭독 이름이 전한다)라 1.4.11 대상이 아니다. 로고/면 대비는 라이트 `--c-logo`/`--c-surface-2` 10.98:1 · 누름 면 `--c-brand-soft` 10.45:1, 다크 10.99 / 10.46(토큰 쌍 계산, `contrast-report.md`의 로고/바탕 행과 같은 급). 면/바탕은 라이트 1.09·1.15, 다크 1.28·1.35 — 「한 단」이라 상태는 보조이고 포커스 링·커서·낭독 이름이 뜻을 맡는다.

```css
/* 머리글 로고 링크 상태 (SPEC-016, title-ci.md 3-2) — title.css의 developer `.logo-link` 기본 규칙 바로 뒤에 덧붙인다(기본 규칙은 그대로, 전환만 더한다) */
.logo-link { transition: background var(--dur) var(--ease); }
.logo-link:hover { background: var(--c-surface-2); }
.logo-link:active { background: var(--c-brand-soft); }
.logo-link:focus-visible { outline: 3px solid var(--c-focus); outline-offset: 2px; }
@media (forced-colors: active) {
  .logo-link:hover { outline: 2px dashed CanvasText; outline-offset: 2px; }
  .logo-link:active { outline: 2px solid CanvasText; outline-offset: 2px; }
  .logo-link:focus-visible { outline: 3px solid Highlight; }
}
```

### 3-3. 동작 — 누르면 확인 없이 첫 화면으로

- 결과는 인생 화면 도구 줄 **「나가기」의 확인 뒤와 같다**(판은 한 해마다 저장돼 있고, 첫 화면은 「이어서 살기」 띠로 열린다). 다른 점은 **확인 단계가 없다**는 것뿐(형진 님 지시). 「나가기」의 확인 단계는 그대로 둔다 — 두 길이 있는 것은 자연스럽다(머리글 로고 = 누리집 관습, 나가기 = 게임 관습).
- 룰렛·출생신고에서 누르면: 판이 아직 시작되지 않은 상태라 첫 화면(새 판)으로. 룰렛이 도는 중이면 돌기를 멈추고 간다(developer 판단 — 룰렛 결과를 저장하지 않는 지금 구조면 그대로 버려진다).
- ~~입력 가드 0.4초를 링크에도 건다~~ → **걸지 않는다**(마스터 결정 2026-11-10). 첫 화면 「태어나기」 띠와 자리가 겹치지 않아 더블탭의 둘째 입력이 화면을 또 바꾸는 길이 없고, 판 도중의 결과는 되돌릴 수 있다(「이어서 살기」). 엔딩만 확인 단계가 막는다(3-6).
