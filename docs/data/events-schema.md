# 이벤트 데이터 작성법 (SPEC-001 M3 → M4에서 갱신)

이벤트는 `src/data/events/*.json` 에 쓴다. **코드는 고치지 않는다** — 파일을 추가/수정하기만 하면 로드할 때 자동으로 풀에 들어간다(`src/data/events/index.ts`가 `*.json`을 전부 읽는다).
잘못된 데이터는 앱(개발 서버)을 처음 열 때, `npm test`, 그리고 **`npm run build`에서 문제 목록과 함께 바로 드러난다**. 점검은 두 겹이다.

1. **스키마 검증** — 데이터가 형태에 맞는가(`src/core/events.ts#validateEventFiles`). 앱이 읽을 때마다 한다.
2. **문구 점검** — 글이 이 게임의 규칙을 지키는가: 어조·길이·시대 소재, **상태 어휘**(가족·부모님·일터·혼자 같은 말이 그 상태를 요구하는 조건 없이 쓰이지 않는가), **선택지 균형**(한쪽이 모든 수치에서 낫기만 한 선택지가 없는가), 영유아 3인칭(`src/core/eventLint.ts#lintEventData`, 7절). **빌드와 `npm test`가 같은 함수를 쓴다.**

빌드는 번들을 만들기 전에 `scripts/validateEvents.ts`(`npm run check:events`로 따로 돌릴 수도 있다)로 두 겹을 모두 검사하고, 문제가 있으면 종료 코드 1로 **빌드를 중단**한다 — 잘못된 데이터가 담긴 번들이 만들어져 배포본이 빈 화면이 되는 일은 없다(R-043). 느낌표 하나, 시대에 어긋난 단어 하나도 빌드에서 걸린다(QA 사용감 8).
이벤트를 고친 뒤에는 `npm run check:events`(수 초)나 `npm test`로 바로 확인한다.

## 1. 파일 모양

```json
{
  "note": "자유 메모(필수 문구 포함). '커뮤니티 사연을 모티브로만 새로 쓴 글이다'라고 적는다.",
  "events": [ { ...이벤트... }, { ...이벤트... } ]
}
```
- 파일 이름은 자유(현재는 생애 단계별 5개). 이벤트 `id`는 **모든 파일을 통틀어 하나뿐**이다.
- 최상위에는 `events`(필수)와 `note`만 쓸 수 있다. 오타(알 수 없는 항목)는 오류다. `note`에 "모티브로만 새로 쓴 글"이 없으면 문구 점검이 실패한다.

## 2. 이벤트 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | O | 소문자로 시작, 소문자·숫자·하이픈 2~48자 (`school-exam`). 저장 파일에 남으므로 **한 번 쓴 id는 바꾸지 않는다**. 예약어(`constructor`·`prototype` 등 `Object.prototype`의 속성 이름)는 쓸 수 없다(R-046). |
| `title` | O | 1~30자(권장 16자 이하, 7절). 연표·선택지 제목에 쓰인다. |
| `text` | O | 10~400자(권장 70자 이하, 7절). 서술 이벤트는 사건 문구, 선택지 이벤트는 상황 설명. |
| `stages` | O | `infant`(영유아 0~6) · `school`(학창 7~19) · `youth`(청년 20~39) · `middle`(중년 40~64) · `senior`(노년 65~) 중 하나 이상. |
| `ageRange` | | `{ "min": 10, "max": 16 }` 단계 안에서 나이를 더 좁힌다. `stages`와 겹치지 않으면 오류(영원히 안 일어나므로). |
| `eras` | | `past`·`present`·`future` 중 일부. 없으면 모든 시대. **시대 차이는 이 필터와 `ERA_CONFIG` 계수로만** 만든다. 시대 소재 규칙은 7절. |
| `weight` | O | **0.1 이상 100 이하**. 같은 해에 후보가 여럿일 때의 상대적 확률. 0에 가까운 값은 모디파이어를 곱할수록 언더플로해 확률이 사라지므로 하한을 둔다(R-046). |
| `once` | O | `true`면 한 판에 한 번만. `false`면 반복되고 `cooldown`년 동안 쉰다. **출시 데이터는 모두 `true`다** — 같은 문구가 한 판에서 되풀이되지 않게(QA 사용감 7). 반복이 필요하면 문구가 다른 별도 이벤트로 나눈다. `false`를 쓰려면 `cooldown` 15년 이상이 필요하다(문구 점검). |
| `cooldown` | | `once:false`일 때 다시 나오기까지 최소 년수(1~60, 기본 10). |
| `conditions` | | 발생 조건(아래 3절). 모두 맞아야(AND) 후보가 된다. |
| `modifiers` | | `[{ "when": 조건, "weight": 배수 }]` 조건이 맞으면 가중치에 배수를 곱한다(**0.1 이상 10 이하**, 이벤트당 **최대 6개**, 모두 맞거나 모두 안 맞는 최악의 곱도 0.01~10000 안). **외모 → 연애·결혼·사업 이벤트 확률**, 부모 재력·교육방식 → 노출 확률은 이렇게 반영한다. |
| `effects`, `bonuses` | | **서술 이벤트(선택지 없음)** 의 효과(4절). `bonuses`는 최대 8개. |
| `choices` | | **선택지 이벤트**. 2~3개. 아래 5절. `choices`를 쓰면 이벤트 단위 `effects`/`bonuses`는 쓰지 않는다. |

## 3. 조건(`conditions` · `modifiers[].when` · `bonuses[].when` · `choices[].requires`)

적은 항목이 **모두** 맞아야 한다. 빈 객체는 오류.

```json
{
  "stats": { "wealth": { "min": 30 }, "health": { "max": 60 } },
  "looks": { "min": 70 },
  "parentWealth": { "min": 4 },
  "birthOrder": { "max": 1 },
  "parentAge": { "min": 60, "max": 100 },
  "motherAge": { "max": 45 },
  "parenting": ["strict", "helicopter"],
  "gender": ["male"],
  "flags": ["has_partner"],
  "notFlags": ["married"]
}
```
- `stats`: `wealth` `education` `health` `happiness` `relationships`(0~100), `{min, max}` 중 하나 이상(경계 포함).
- `looks`: 외모 0~100. `parentWealth`: 1~5. `parenting`: `neglect`(방임) `free`(자유) `helicopter`(헬리콥터) `strict`(엄격) 중 하나라도. `gender`: `male` `female`.
- `flags`: 모두 켜져 있어야. `notFlags`: 하나도 켜져 있지 않아야.
- `birthOrder`: 형제 순서 1(첫째)~5(다섯째). 출생신고에서 정해진 값이다(SPEC-003 BR6). 예: `{ "max": 1 }`은 첫째인 판에서만.
- `parentAge`: **두 부모 중 나이가 많은 쪽의 지금 나이**(태어났을 때 나이 + 아이의 지금 나이) 0~130. 부모의 병환·임종처럼 부모 나이와 어긋나면 안 되는 사건에 쓴다(BR6).
- `motherAge`: **어머니의 지금 나이**(태어났을 때 어머니 나이 + 아이의 지금 나이) 0~130. 어머니 나이가 한계를 넘으면 말이 안 되는 사건에 쓴다(BR6, R-268). 예: `infant-new-sibling`(동생이 생겼다)은 `{ "max": 45 }` — 출생 때 어머니가 47~51세였던 판에서 49~57세에 동생을 낳는 일이 없게.
- 출생 가족 정보를 모르는 상태에서는 `birthOrder`·`parentAge`·`motherAge` 조건이 맞지 않는 것으로 본다(사건이 일어나지 않는 쪽이 안전하다).

## 4. 효과(`effects`)와 보너스(`bonuses`)

```json
{ "stats": { "wealth": -3, "happiness": 2 }, "setFlags": ["married"], "clearFlags": ["has_partner"] }
```
- 스탯 변화량은 0이 아닌 정수(절댓값 50 이하). 결과는 항상 0~100으로 잘린다(`src/core/stats.ts` 한 곳).
- **한 스탯에 더해질 수 있는 변화량의 최악의 합(기본 효과 + 모든 보너스를 조건과 무관하게 전부 더한 값)은 ±50 이내**여야 한다(R-046). 자동 모드가 점수의 지수(`Math.exp`)를 가중치로 쓰므로 합이 한없이 커지면 `Infinity`가 된다. 런타임도 지수를 ±40으로 제한해 이중으로 막는다(`src/core/life.ts#AUTO_EXPONENT_LIMIT`).
- `setFlags` 플래그 켜기, `clearFlags` 끄기(같은 효과에서 같은 플래그를 켜고 끄면 오류).
- **보너스**: `"bonuses": [{ "when": 조건, "effects": 효과 }]` — 조건이 맞을 때 효과를 더한다. 부모 재력·교육방식·외모 같은 **캐릭터 속성을 효과에 반영**하는 방법이다. 보너스 조건은 효과를 적용하기 **전** 상태로 판정하며 보너스끼리 연쇄하지 않는다.

## 5. 선택지(`choices`)

```json
{
  "id": "academy",
  "label": "방과 후에 따로 배운다",
  "result": "방과 후마다 따로 공부를 더 했다. 숙제가 늘었고, 성적도 천천히 올랐다.",
  "effects": { "stats": { "education": 6, "happiness": -3 } },
  "bonuses": [ { "when": { "parenting": ["strict"] }, "effects": { "stats": { "education": 2 } } } ],
  "requires": { "parentWealth": { "min": 4 } }
}
```
- `id`(소문자로 시작, 소문자·숫자·하이픈 1~32자, 이벤트 안에서 유일) · `label` 1~40자(권장 24자 이하) · `result` 6~300자(권장 80자 이하, 고른 뒤 사건 기록에 남는 문구)는 필수.
- `requires`가 있으면 조건을 만족할 때만 선택지가 **보인다**. 화면에는 항상 2~3개가 보여야 하므로 **`requires`가 없는 선택지가 2개 이상** 있어야 한다.
- 선택지는 이벤트가 일어난 순간 보이는 목록이 정해져 **저장 상태에 들어간다**(새로고침해도 같은 선택지).

## 6. 플래그 (이후 이벤트를 여닫는다)

- 이름: 소문자로 시작, 소문자·숫자·밑줄 (`has_career`, `first_love`).
- 한 이벤트가 `setFlags`로 켠 플래그를 다른 이벤트가 `conditions.flags`/`notFlags`/`requires`/`bonuses`/`modifiers`로 읽는다. 예: `youth-meeting`이 `has_partner`를 켜고 `youth-marriage`가 그 플래그를 요구한다.
- **읽는 플래그는 어딘가에서 켜져야 한다**(오타 방지): 켜는 이벤트가 어디에도 없으면 로드할 때 오류다. 켜기만 하고 안 읽는 플래그는 허용된다(엔딩에서 쓸 수 있다).
- **흐름이 막히지 않게** 설계한다(R-045 e): 선택으로 길이 닫히면 다른 길이 열리게 한다. 예) 결혼 "기다리자" → `marriage_waited` → `youth-marriage-again`(다시 꺼낸 이야기) → 또 기다리면 `youth-partner-leaves`; 헤어짐 → `broke_up` → `youth-reunion`; 아이를 갖는 선택 → `has_child` → 중년의 아이 이벤트·노년의 손주 이벤트(아이를 두지 않은 판에는 열리지 않는다); 검진을 미룸 → `health_ignored` → `middle-health-crisis`.
- **현재 켜는 플래그와 켜고 읽는 이벤트의 전체 표는 `docs/data/events-distribution.md` 4절**(데이터에서 자동으로 만든다)에 있다. `tests/events.test.ts` "플래그 연결"과 `tests/flow.test.ts`가 연결이 실제로 이어지는지 확인한다.
- **한 판 안에서 이미 일어난 일과 모순되는 이벤트가 나오지 않게** 한다(REV-001-M4-1 R-057~R-060, R-062, R-065). 이벤트는 "그 사건이 일어난 판의 상태"를 플래그로 닫고 열어 쓴다:
  - 부모님의 임종(`middle-parents-farewell`)은 `parents_gone`을 켜고, 부모님이 나오는 중년·노년 이벤트(병환)는 `notFlags: ["parents_gone"]`으로 닫는다.
  - 아이는 `has_child`(+ 늦게 맞았으면 `child_late`)로 시작하고, 독립(`middle-child-leaves`)이 `child_left`를 켜서 자라난 아이·아이의 앞날을 닫는다. 아이가 어린 시점에 "진로·독립"이 나오지 않게 창은 아이를 맞은 나이(청년 27~39세)에서 가장 이른 경우로 잡고, 늦게 맞은 아이(`child_late`)는 별도 이벤트(`middle-late-child`)로 시점을 옮긴다. 손주 이야기는 `child_distant`(연락이 끊긴 자식)일 때 닫히고, 먼저 연락해 화해하면(`senior-estranged-child`) 풀린다.
  - 학업을 접으면(`school-family-priority` "집안의 결정을 따른다") `left_school`이 켜져 입시·학교 생활 이벤트가 닫힌다. 집은 `renting`(월세방)·`own_home`(자가)으로 갈라, 월세 인상은 월세방을 구한 판에서만 나온다.
  - 이혼(`middle-marriage-crisis` "따로 살기로 한다")은 `married`뿐 아니라 `has_partner`도 끈다. 헤어졌다 다시 만난 사이는 `reunited`로 표시해 결혼 이야기(`youth-second-chance`)가 다시 열린다.
  - **문구가 상태를 말하면 조건에 그 플래그를 건다** — 이것은 문구 점검(7절 "상태 어휘")이 빌드에서 강제한다. 상태와 무관하게 쓰려면 문구를 중립으로 바꾼다("자식에게 남길지" → "남길지").

## 7. 문구 규칙과 길이 권장 최대 (SPEC-001 '안 할 것' 포함 — `npm run check:events`와 `npm test`가 점검한다)

문구 점검(`src/core/eventLint.ts`)이 이벤트의 제목·본문·선택지 라벨·결과 문구에 모두 적용한다. 어기면 **빌드가 실패**한다.

**내용**
- 커뮤니티 사연을 **모티브로만** 새로 쓴 글. 실제 글 원문·실존 인물·실제 상호·실제 사건 이름 금지(상호·사건·제도 이름 목록 점검, "출처·원문·퍼옴·링크" 같은 인용 표지 점검).
- **특정 달력 연도·실제 사건을 가정하지 않는다**(R-033: 지금 세상은 2008~2025년생이라 성인기 전체가 미래다). 기준은 나이뿐. `2031년`·`1990년대`·`80년대` 형태가 걸린다.

**어조** — 담담한 회고(원작 '80억분의 1')
- 느낌표·물음표·말줄임표·이모지·그림 기호·URL·"ㅋㅋ"·과장 표현(`엄청`·`대박`·`충격` …) 금지.
- 본문(`text`)과 결과(`result`)는 `~다.`로 끝나는 서술체, 선택지 라벨은 `~다`로 끝난다. 제목·라벨 끝에 마침표를 찍지 않는다. `~요`·`~죠` 같은 구어체 종결 금지.
- 지나온 일을 짧게 되돌아보는 문장으로 쓴다: "~했다", "~였다", "~이 남았다". 감정을 설명하기보다 장면을 적는다.

**길이 권장 최대 (R-042)** — 넘으면 점검이 실패한다 (`src/core/eventLint.ts#TEXT_LIMITS`, 스키마의 하드 한도보다 훨씬 짧다)

| 항목 | 최대 | 화면에서 | 지금 데이터의 평균 / 최대 |
|---|---|---|---|
| 제목 `title` | 16자 | 선택지 패널 제목(한 줄) | 8 / 15 |
| 본문 `text` | 70자 (한 문장 50자) | 선택지 패널 설명 | 48 / 63 |
| 선택지 라벨 `label` | 24자 | 선택지 버튼 | 12 / 22 |
| 결과 `result` | 80자 (한 문장 50자) | 선택한 뒤 사건 기록 한 줄 | 43 / 58 |

근거(`e2e/layout.spec.ts`, 실제 `LifeScreen`·실제 CSS를 담은 하니스 `harness/layout.html`):
- 풀의 **모든 선택지 이벤트**(선택지 전부를 보인 최악의 경우)를 360×568·640·740에서 재어, 선택지 버튼 전부와 컨트롤 6개가 첫 화면에서 서로 가려지지 않고 가로로 넘치지 않는다.
- 위 최대값으로 만든 "최악의 이벤트"(제목 16·본문 70·라벨 24자 × 3)는 360×640·740에서 선택지 3개가 첫 화면에 다 들어오고, **360×568에서는 약 33px 넘쳐 스크롤이 필요하다**(스크롤하면 고정 컨트롤 바에 가려지지 않고 모두 닿는다). 높이가 낮은 화면의 고정 컨트롤 바 문제는 M5 화면 정리 몫이다.
- 그래서 360×568에서도 현재 이벤트는 모두 첫 화면에 들어오지만, 새 이벤트가 이를 어기면(본문이 길고 라벨이 두 줄인 3지선다 등) 테스트가 실패한다 — 문구를 줄인다.
- 읽는 시간 가정(`src/data/timingTable.ts#READ_SEC`)은 QA가 잰 "선택지 이벤트 본문+라벨 평균 75.6자"를 기준으로 한다. 지금 데이터는 평균 약 81자로 ±25% 안이다(`tests/simulation.test.ts`가 확인). 글이 훨씬 길어지면 시간 모델을 다시 잰다.

**시대 소재 (R-045 d)** — 시대마다 어울리지 않는 말은 금지어 표(`ERA_BANNED_WORDS`)로 점검한다. `eras`를 쓰면 그 시대들의 금지어만 적용되고, 생략하면(모든 시대) **세 시대의 금지어를 모두** 피해야 한다.

| 시대 | 쓰면 안 되는 말 |
|---|---|
| 지난 세상 | 새 소재: 학원·급식(학창 소재, 모든 단계에서 금지) / 스마트폰·휴대전화·메신저·대화방·온라인·인터넷·앱·플랫폼·화면·화상·원격·노트북 …(새 기기 소재, **노년 전용 이벤트에서는 허용**) / 미래 소재: 로봇·인공지능·자동화 … |
| 지금 세상 | 옛 소재: 연탄·흑백·라디오·텃밭·공중전화·장터·품앗이·아궁이·월급봉투 … / 미래 소재 |
| 다가올 세상 | 옛 소재 |

QA가 지적한 "학원 버스"(시대 중립 문구)·"텃밭과 라디오"(다가올 세상)는 이 점검이 실제로 잡는다. 시대마다 다르게 쓰려면 `eras`로 이벤트를 나눈다(예: `school-academy-night`는 지금·다가올 세상 전용, 지난 세상에는 `school-long-walk`·`school-family-priority`·`school-lunch`(도시락)).

**생애 단계별 면제 (R-067)**: 지난 세상(1950~89년생)의 노년(65세 이후)은 이미 휴대전화·인터넷이 있는 세상에서 산다. 그래서 이벤트의 모든 단계가 노년이면 지난 세상에서도 새 기기 소재를 쓸 수 있다(`bannedWordsFor(eras, stages)`). 학창 소재(학원·급식)와 미래 소재는 노년에도 계속 금지다. 이 덕에 `senior-new-device`("낯선 기계")가 지난 세상에도 열려 있다(노년 선택지 평균이 다른 시대보다 낮던 지난 세상에 선택지 하나가 늘었다).

**오탐 예외 (R-067)**: 규칙이 정상 표현을 잘못 잡지 않도록, 검사 전에 `SAFE_PHRASES`에 적힌 표현을 글에서 지운다 — 헐값·헐렁("헐"), 영향을 미친·미친 영향("미친"), 펌프("펌"), 우물쭈물("우물"), 폭풍우("폭풍"), 현대적·현대인("현대"). "~니까"는 문장 끝일 때만 구어체로 본다("비가 오니까 우산을 챙겼다"는 정상). 새 예외를 넣으면 `tests/eventLint.test.ts` "오탐 예외"에 문장을 하나 더한다.

**상태 어휘 (R-067)** — 문구가 어떤 상태를 말하면 조건이 그 상태를 요구해야 한다(`STATE_WORD_RULES`). 성인기(청년·중년·노년) 이벤트의 제목·본문·선택지 라벨·결과 문구에 적용하고, 선택지 글은 그 선택지의 `requires`로도 충족할 수 있다.

| 말 | 이벤트(또는 선택지)에 필요한 조건 | 예외 |
|---|---|---|
| 자식·손주·아들·딸·아이 | `flags: ["has_child"]` | `youth-child`·`youth-child-again`(아이를 가질지 정하는 이벤트) |
| 배우자·남편·아내·부부 | `flags: ["married"]` | - |
| 부모님(중년·노년) | `notFlags: ["parents_gone"]` | `middle-parents-farewell`(임종 이벤트) |
| 일터·출근·퇴근·직장·회사·상사·동료 | `flags`에 `has_career` 또는 `own_business` | - |
| 혼자 | `notFlags: ["married"]` | - |

영유아·학창기의 "아이"는 나 자신이나 또래라 가족어가 아니다. "받아들이다·잦아들다"의 "아들", "딸기"의 "딸", "아이디어"의 "아이", "학부모"의 "부모"도 걸리지 않는다.

**선택지 균형 (R-069)** — 같은 이벤트의 두 선택지에서 한쪽이 **모든 스탯에서 낫거나 같고** 어딘가는 확실히 낫다면 '정답형'이라 걸린다(보너스는 최악·최선으로 쳐서 비교한다: 보너스로 뒤집힐 수 있는 위험 선택은 통과). 효과가 완전히 같은 두 선택지도 걸린다. 소극적 선택(미루기·사양·모른 척·넘기기)에는 작은 이득을 준다 — 시간·돈·몸을 아끼는 쪽(재산 +1, 건강 +1, 학력 +1)으로. 예외 목록(`DOMINANCE_EXCEPTIONS`)은 비어 있다.

**영유아 문구는 3인칭 (R-070)** — 영유아 이벤트는 "아이"로 쓰고 "나·내"를 쓰지 않는다(학창기부터는 회고하는 "나").

## 9. 상태에 남는 것 (참고)

저장 상태(`GameState`, 스키마 v4)에는 `flags`(켜진 플래그) · `seen`(이벤트 id → 마지막으로 일어난 나이) · `pending`(대기 중인 선택지: 이벤트 id, 인스턴스 키 `id@나이`, 보이는 선택지 id) · `lastChoiceAge` · `death`가 있고, `history`에 연표(나이·종류·문구·고른 선택)가 쌓인다(상한 160개, `HISTORY_LIMITS`). 엔딩(M5)은 이 연표를 읽는다.

**콘텐츠를 갱신해도 저장이 날아가지 않는다 (R-046).** 대기 중이던 선택지가 가리키는 이벤트가 풀에서 사라졌거나, 선택지가 바뀌었거나, 선택지 이벤트가 아니게 되었으면 저장 전체를 버리지 않고 **대기만 풀어** 이어간다(그 해는 다시 진행된다). 저장의 모양이 어긋난 것(키·나이·본 이벤트 기록·선택지 개수 불일치 — 손상·변조)만 새 게임이 된다(`src/core/storage.ts#parseGame`). 저장 형식은 그대로라 `SCHEMA_VERSION`은 4이다. 그래도 **이미 쓴 이벤트·선택지 id는 바꾸지 않는다** — 바꾸면 그 이벤트가 `seen`에서 맥락을 잃고 대기 중이던 사용자는 그 선택지를 잃는다. M3의 표본 20개 id는 모두 그대로 남아 있다(`tests/events.test.ts`가 확인).

## 10. 이벤트·밸런스를 고친 뒤 다시 만들 것 (분포표, R-085)

엔딩의 "출발선 대비"는 같은 시대의 헤드리스 시뮬레이션 판들이 남긴 **최종 재산 분포표**(`src/data/finalDistribution.ts`)에서 도착 자리를 구한다. 이 표는 **현재 이벤트·진행 규칙·밸런스 표로 돌린 결과**라서, 아래를 고치면 낡는다.

- 이벤트 데이터(`src/data/events/*.json`)의 효과·조건·가중치·플래그, 이벤트 추가·삭제
- 진행 규칙과 표: `src/core/life.ts`, `src/data/lifeTable.ts`, `src/data/birthTable.ts`의 값 (`timingTable.ts`는 시뮬레이션 결과에 영향이 없다)

**절차 — 위를 고쳤다면 이 순서로:**

1. `npm run check:events` — 데이터 검증(빌드가 먼저 돌리는 것과 같다)
2. `npx vite-node scripts/eventDistribution.ts` — 이벤트 분포 문서(`docs/data/events-distribution.md`) 다시 만들기
3. `npx vite-node scripts/finalDistribution.ts` — 최종 재산 분포표 다시 만들기 (시대별 4000판, 약 12초)
4. `npm test` — 표가 낡았는지는 `tests/ending.test.ts` "현재 엔진·이벤트로 같은 시드·판 수로 다시 만들면 같은 표다"가 잡는다. 점검만 따로 하려면 `npm run check:dist`

`npm run build`에는 넣지 않았다: 표를 다시 만들어 견주는 데 10초대가 걸려 빌드가 느려지기 때문이다(`check:events`는 수 초). 배포 전에는 `npm test`(필수)가 같은 것을 잡는다. SPEC-002로 이벤트를 +50 추가하면 반드시 3번을 한다.

표는 **무작위 선택 전략**(수동 플레이 흉내)으로 만든다. 자동 모드(성향 선택) 판은 같은 표와 견준다 — 지난 세상은 자동 판이 평균 4~5점 더 벌어(중앙값 37 → 42) 같은 재산이 표에서 최대 14%p 다른 자리로 읽힌다(지금·다가올 세상은 최대 6~7%p). 측정과 제안은 `docs/review/REV-001-M5-1.md` 하단 "반영 내역" R-085.
