# 이벤트 데이터 작성법 (SPEC-001 M3 → M4에서 갱신)

이벤트는 `src/data/events/*.json` 에 쓴다. **코드는 고치지 않는다** — 파일을 추가/수정하기만 하면 로드할 때 자동으로 풀에 들어간다(`src/data/events/index.ts`가 `*.json`을 전부 읽는다).
잘못된 데이터는 앱(개발 서버)을 처음 열 때, `npm test`, 그리고 **`npm run build`에서 문제 목록과 함께 바로 드러난다**. 점검은 두 겹이다.

1. **스키마 검증** — 데이터가 형태에 맞는가(`src/core/events.ts#validateEventFiles`). 앱이 읽을 때마다 한다.
2. **문구 점검** — 글이 이 게임의 규칙을 지키는가: 어조(본문·결과는 **합쇼체** 「~했습니다.」, SPEC-003 M7e-1)·길이·시대 소재, **상태 어휘**(가족·부모님·일터·혼자 같은 말이 그 상태를 요구하는 조건 없이 쓰이지 않는가), **선택지 균형**(한쪽이 모든 수치에서 낫기만 한 선택지가 없는가), 영유아 3인칭(`src/core/eventLint.ts#lintEventData`, 7절). **빌드와 `npm test`가 같은 함수를 쓴다.**

빌드는 번들을 만들기 전에 `scripts/validateEvents.ts`(`npm run check:events`로 따로 돌릴 수도 있다)로 두 겹을 모두 검사하고, 문제가 있으면 종료 코드 1로 **빌드를 중단**한다 — 잘못된 데이터가 담긴 번들이 만들어져 배포본이 빈 화면이 되는 일은 없다(R-043). 느낌표 하나, 시대에 어긋난 단어 하나도 빌드에서 걸린다(QA 사용감 8).
이벤트를 고친 뒤에는 `npm run check:events`(수 초)나 `npm test`로 바로 확인한다.

## 1. 파일 모양

```json
{
  "note": "자유 메모(필수 문구 포함). '커뮤니티 사연을 모티브로만 새로 쓴 글이다'라고 적는다.",
  "events": [ { ...이벤트... }, { ...이벤트... } ]
}
```
- 파일 이름은 자유(현재는 생애 단계별 5개). 이벤트 `id`는 **모든 파일을 통틀어 하나뿐**이다.
- 최상위에는 `events`(필수)와 `note`만 쓸 수 있다. 오타(알 수 없는 항목)는 오류다. `note`에 "모티브로만 새로 쓴 글"이 없으면 문구 점검이 실패한다.

## 2. 이벤트 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | O | 소문자로 시작, 소문자·숫자·하이픈 2~48자 (`school-exam`). 저장 파일에 남으므로 **한 번 쓴 id는 바꾸지 않는다**. 예약어(`constructor`·`prototype` 등 `Object.prototype`의 속성 이름)는 쓸 수 없다(R-046). **`note-`로 시작하는 id도 쓸 수 없다** — 기록 카드(`src/data/notes.json`, SPEC-003 M7c)가 본 이벤트 기록 `seen`에 같은 접두의 키를 쓴다(`tests/noteCards.test.ts`). |
| `title` | O | 1~30자(권장 16자 이하, 7절). 연표·선택지 제목에 쓰인다. |
| `text` | O | 10~400자(권장 74자 이하, 7절). 서술 이벤트는 사건 문구, 선택지 이벤트는 상황 설명. |
| `stages` | O | `infant`(영유아 0~6) · `school`(학창 7~19, 7세는 학창 단계지만 영유아 빈도표를 쓴다 — M7a, `EARLY_YEARS_MAX_AGE`) · `youth`(청년 20~39) · `middle`(중년 40~64) · `senior`(노년 65~) 중 하나 이상. |
| `ageRange` | | `{ "min": 10, "max": 16 }` 단계 안에서 나이를 더 좁힌다. `stages`와 겹치지 않으면 오류(영원히 안 일어나므로). |
| `eras` | | `past`·`present`·`future` 중 일부. 없으면 모든 시대. **시대 차이는 이 필터와 `ERA_CONFIG` 계수로만** 만든다. 시대 소재 규칙은 7절. |
| `weight` | O | **0.1 이상 100 이하**. 같은 해에 후보가 여럿일 때의 상대적 확률. 0에 가까운 값은 모디파이어를 곱할수록 언더플로해 확률이 사라지므로 하한을 둔다(R-046). |
| `once` | O | `true`면 한 판에 한 번만. `false`면 반복되고 `cooldown`년 동안 쉰다. **출시 데이터는 모두 `true`다** — 같은 문구가 한 판에서 되풀이되지 않게(QA 사용감 7). 반복이 필요하면 문구가 다른 별도 이벤트로 나눈다. `false`를 쓰려면 `cooldown` 15년 이상이 필요하다(문구 점검). |
| `cooldown` | | `once:false`일 때 다시 나오기까지 최소 년수(1~60, 기본 10). |
| `conditions` | | 발생 조건(아래 3절). 모두 맞아야(AND) 후보가 된다. |
| `modifiers` | | `[{ "when": 조건, "weight": 배수 }]` 조건이 맞으면 가중치에 배수를 곱한다(**0.1 이상 10 이하**, 이벤트당 **최대 6개**, 모두 맞거나 모두 안 맞는 최악의 곱도 0.01~10000 안). **외모 → 연애·결혼·사업 이벤트 확률**, 부모 재력·교육방식 → 노출 확률은 이렇게 반영한다. |
| `effects`, `bonuses` | | **서술 이벤트(선택지 없음)** 의 효과(4절). `bonuses`는 최대 8개. |
| `choices` | | **선택지 이벤트**. 정의 2~4개, 같은 상태에서 보이는 것은 2~3개(M7a r3 — 아래 5절). 아래 5절. `choices`를 쓰면 이벤트 단위 `effects`/`bonuses`는 쓰지 않는다. |
| `milestone` | | `true`면 **마일스톤 이벤트**(SPEC-003 IN3, M7a): 첫 예방접종·첫 걸음마·첫 말처럼 정한 나이 창(`ageRange`) 안에서 **모든 판에** 일어난다. **서술 이벤트·`once:true`·`ageRange`의 `min`과 `max`가 모두 있어야 한다**(어기면 로드할 때 오류). 일반 추첨과 **별개 슬롯**이라 그 해의 일반 사건과 함께 연표에 한 줄을 남기고(한 해 두 줄), 창의 마지막 해에는 100%다 — 아래 「마일스톤 슬롯」. |
| `citation` | | **중대 결정 카드의 인용 연결**(SPEC-003 MD2, M7b — 선택지 이벤트만). 인용 id 문자열 `"c-006"` = 이 카드가 뜨는 모든 세상에서 같은 인용, 객체 `{ "past": "c-033", "present": "c-006", "future": "c-006" }` = 세상마다 다른 인용(적히지 않은 세상은 인용 없음, 키는 이 이벤트가 뜨는 세상만). id는 `src/data/citations.json`의 `verified`·`usable` 인용이어야 하고(`check:events`가 점검) 그 인용의 `eras`에 그 세상이 있어야 화면에 보인다. 다가올 세상은 인용의 머리말 「지금 기준으로는」, 지난 세상의 시대 무관 연구는 「지금의 연구로는」이 붙고, 지난 세상 통계는 인용의 `validFromYear`보다 이른 게임 속 연도에서는 보이지 않는다. `citations.json`의 `usedBy`는 이 필드의 **역색인**이라 사람이 쓰지 않는다(`npm run gen:citations`, 어긋나면 `npm run check:citations`가 실패). |
| `noCitation` | | 이 카드에 **어느 세상에서도 인용을 붙이지 않는** 사유 코드 — `X1` 의료·응급·진단 / `X2` 임종·가족 갈등의 존엄 / `X3` 재무·법률 행위 / `X4` 낙인 위험 / `X5` 다가올 세상 상상 전용 / `X6` 양육 방식 가치판단 유도(**원칙적 무인용 X1~X6**, 시대별 등장 카드의 25% 이하, 목록 변경은 마스터 승인) / `D` 맞는 자료가 없어 서술 장면으로 둔 카드. `citation`과 함께 쓰지 않는다. 선택지 이벤트 90개는 `citation`·`noCitation` 중 하나를 가져야 한다 — 단 2차 수집 대기 카드(T-01~T-13 정서·관계)는 `src/data/citationPending.ts`에 칸 단위로 적어 두고 두 필드를 아직 쓰지 않는다(`tests/citationLink.test.ts`가 90개 전수를 점검). |

**마일스톤 슬롯** (`src/core/life.ts#stepYear`): 해마다 일반 추첨(선택지 → 서술)과 별개로, 그 나이·시대에 일어날 수 있는 `milestone: true` 이벤트를 **한 해에 여러 개(칸 `MILESTONES_PER_YEAR_MAX` = 3개까지)** 일으킨다(M7a r3 — 걸음마와 첫 말이 모두 1세). 창이 일찍 끝나는(급한) 것부터, 끝이 같으면 id 오름차순으로 확률 1 ÷ (창 끝 나이 − 나이 + 1)로 따지고, 창의 마지막 해는 난수 없이 100%다(난수는 확률이 1보다 작은 후보를 따질 때만 쓴다). 연표에는 **id 오름차순**으로 남는다(같은 해 걸음마 → 첫 말, 그 뒤 일반 사건 — 한 해 세 줄). 마일스톤은 일반 추첨 후보에서 빠지고, 그 해의 일반 사건이 선택지여도 마일스톤 줄은 이미 연표에 남는다(`TickInfo.milestoneIds`). **한 해에 마감되는 마일스톤이 칸 수를 넘으면**(같은 시대에서 창 끝이 같은 마일스톤이 4개 이상) 그 해에 일부가 못 일어나 100% 보장이 깨지므로 풀 점검(`milestoneWindowProblems`, `npm run check:events`)이 잡는다 — 둘·셋이 같은 해에 끝나는 것은 괜찮다(r2까지의 「창 끝이 같으면 안 된다」는 사라졌다). **창의 모든 나이가 `stages`에 덮여야 한다**(스키마 검증 — 6~7세 창에 `stages: ["infant"]`이면 7세가 비어 100%가 조용히 깨진다). 지금 마일스톤: `infant-vaccine`(0세) · `infant-first-steps`(1세) · `infant-first-word`(1세). 그 전에 사망한 판은 제외한다.

## 3. 조건(`conditions` · `modifiers[].when` · `bonuses[].when` · `choices[].requires`)

적은 항목이 **모두** 맞아야 한다. 빈 객체는 오류.

```json
{
  "stats": { "education": { "min": 30 }, "health": { "max": 60 } },
  "assets": { "netMin": 0, "debtMax": 5000 },
  "looks": { "min": 70 },
  "parentWealth": { "min": 4 },
  "birthOrder": { "max": 1 },
  "parentAge": { "min": 60, "max": 100 },
  "motherAge": { "max": 45 },
  "parenting": ["strict", "helicopter"],
  "gender": ["male"],
  "housing": ["rent", "free"],
  "flags": ["has_partner"],
  "notFlags": ["married"]
}
```
- `stats`: `education` `health` `happiness` `relationships`(0~100), `{min, max}` 중 하나 이상(경계 포함). **재산(`wealth`) 스탯은 없어졌다**(SPEC-003 M5, 저장 v8).
- `assets`: 자산 조건 `{ netMin, netMax, debtMax, incomeMin, dwelling }`(하나 이상; 앞의 넷은 만 원 정수). 순자산·부채·연 소득과 **지금 사는 집**을 본다. `dwelling`은 주거 형태 `family`(가족 집)·`rent`(월세)·`jeonse`(전세)·`own`(자가)·`care`(돌봄 시설) 중 **하나라도**(배열, `parenting`·`gender`와 같은 규칙; 빈 배열·중복·다른 값은 로드할 때 오류) — 출생신고의 `housing`(태어난 때의 집)과 다른 값이다(M7e-3, 마스터 결정 E-4: `youth-lonely-city`는 `{ "dwelling": ["rent", "jeonse", "own"] }`라 가족 집에 사는 판에서는 「혼자 먹는 저녁」이 일어나지 않는다. M7e-4: 같은 조건을 `middle-lonely-holiday`(「혼자 맞는 명절」)·`senior-alone`(「혼자 사는 집」)에도 걸었고, **선택지의 `requires.assets.dwelling`**으로 `youth-housing`의 「부모님 집에 머문다」(`["family"]`)와 「부모님 집으로 돌아간다」(`["rent","jeonse","own"]` + `notFlags: [lives_alone]`)를 서로 배타로 갈랐다 — `eventLint#conditionsCompatible`이 `housing` 목록처럼 `assets.dwelling` 목록의 겹침을 판정해 정의 4개·같이 보이는 것은 3개 이하 규칙을 지킨다). **20세 이상으로만 일어나는 이벤트(청년·중년·노년)에서만** 쓸 수 있다(20세 미만에는 자산이 없다). 20세 미만의 돈 조건은 `parentWealth`(부모 재력)를 쓴다. 값의 범위는 `src/data/economyTable.ts#LIMITS`.
- `looks`: 외모 0~100. `parentWealth`: 1~5. `parenting`: `neglect`(방임) `free`(자유) `helicopter`(헬리콥터) `strict`(엄격) 중 하나라도. `gender`: `male` `female`.
- `flags`: 모두 켜져 있어야. `notFlags`: 하나도 켜져 있지 않아야.
- `housing`: **출생신고의 「사는 집」** — `own`(자가) · `rent`(임차: 전세·월세) · `free`(무상 거주) 중 **하나라도**(배열, `parenting`·`gender`와 같은 규칙). 빈 배열·중복·다른 값은 로드할 때 오류다(M7a r3, T05 — QA-003-M7a: 자가 판에서 「집을 산다」가 보이던 문제). 예: `infant-moving`(이삿짐을 싸던 날)은 `{ "parentWealth": { "max": 3 }, "housing": ["rent", "free"] }`. **근사의 한계**: 값은 **태어난 때의 집**이라 3~6세에 이사로 달라졌을 수 있고, 그 이벤트가 `buy`로 집을 사도 이후 이벤트의 `housing`은 바뀌지 않는다. 건물 유형(아파트·연립)은 데이터가 없어 조건으로 쓸 수 없다(M-14, 2차).
- `birthOrder`: 형제 순서 1(첫째)~5(다섯째). 출생신고에서 정해진 값이다(SPEC-003 BR6). 예: `{ "max": 1 }`은 첫째인 판에서만.
- `parentAge`: **두 부모 중 나이가 많은 쪽의 지금 나이**(태어났을 때 나이 + 아이의 지금 나이) 0~130. 부모의 병환·임종처럼 부모 나이와 어긋나면 안 되는 사건에 쓴다(BR6).
- `motherAge`: **어머니의 지금 나이**(태어났을 때 어머니 나이 + 아이의 지금 나이) 0~130. 어머니 나이가 한계를 넘으면 말이 안 되는 사건에 쓴다(BR6, R-268). 예: `infant-new-sibling`(동생이 생겼다)은 `{ "max": 45 }` — 출생 때 어머니가 47~51세였던 판에서 49~57세에 동생을 낳는 일이 없게.
- 출생 가족 정보를 모르는 상태에서는 `birthOrder`·`parentAge`·`motherAge`·`housing` 조건이 맞지 않는 것으로 본다(사건이 일어나지 않는 쪽이 안전하다).

## 4. 효과(`effects`)와 보너스(`bonuses`)

```json
{ "stats": { "happiness": 2 }, "assets": { "net": -1200 }, "setFlags": ["married"], "clearFlags": ["has_partner"] }
```
- 스탯 변화량은 0이 아닌 정수(절댓값 50 이하). 결과는 항상 0~100으로 잘린다(`src/core/stats.ts` 한 곳).
- **한 스탯에 더해질 수 있는 변화량의 최악의 합(기본 효과 + 모든 보너스를 조건과 무관하게 전부 더한 값)은 ±50 이내**여야 한다(R-046). 자동 모드가 점수의 지수(`Math.exp`)를 가중치로 쓰므로 합이 한없이 커지면 `Infinity`가 된다. 런타임도 지수를 ±40으로 제한해 이중으로 막는다(`src/core/life.ts#AUTO_EXPONENT_LIMIT`).
- **돈 효과 (SPEC-003 M5, docs/data/economy-model.md 5절)**: 20세 이상 이벤트는 `assets: { net, income, debt }`(만 원 정수, 하나 이상)를, 20세 미만 이벤트는 `family`(집안 살림, 만 원 정수)를 쓴다. `net`은 순자산의 일회성 변화(거래·지출), `income`은 연 소득 보정(`incomeAdj`)의 변화, `debt`는 부채의 변화다. 한 효과의 절댓값 상한은 `net` 50000 · `income` 5000 · `debt` 50000 · `family` 3000이고(`src/core/events.ts#ASSET_DELTA_CAP`·`FAMILY_DELTA_CAP`), 스탯과 같이 **기본 효과 + 모든 보너스의 최악의 합**도 그 안이어야 한다. `assets`는 20세 이상으로만, `family`는 20세 미만으로만 일어나는 이벤트에서만 쓸 수 있다.
- `setFlags` 플래그 켜기, `clearFlags` 끄기(같은 효과에서 같은 플래그를 켜고 끄면 오류).
- 주거 형태(`dwelling`)는 효과가 아니라 **플래그**로 바뀐다: `in_care`→돌봄, `own_home`→자가, `renting`→월세, `lives_with_parents`·`moved_home`→집안 얹혀 삶(economy-model.md 3-2). 결혼(`married`)은 집안에서 나올 때 부모 재력에 따라 자가·전세·월세로 정해진다.
- **보너스**: `"bonuses": [{ "when": 조건, "effects": 효과 }]` — 조건이 맞을 때 효과를 더한다. 부모 재력·교육방식·외모 같은 **캐릭터 속성을 효과에 반영**하는 방법이다. 보너스 조건은 효과를 적용하기 **전** 상태로 판정하며 보너스끼리 연쇄하지 않는다.

## 5. 선택지(`choices`)

```json
{
  "id": "academy",
  "label": "방과 후에 따로 배운다",
  "result": "방과 후마다 따로 공부를 더 했다. 숙제가 늘었고, 성적도 천천히 올랐다.",
  "effects": { "stats": { "education": 6, "happiness": -3 }, "family": -450 },
  "bonuses": [ { "when": { "parenting": ["strict"] }, "effects": { "stats": { "education": 2 } } } ],
  "requires": { "parentWealth": { "min": 4 } }
}
```
- `id`(소문자로 시작, 소문자·숫자·하이픈 1~32자, 이벤트 안에서 유일) · `label` 1~40자(권장 24자 이하, **라벨의 어절은 5음절 이하** — 번호 원 옆 라벨 칸이 약 164px이고 글자 200%에서 음절당 약 32px라 6음절 어절이 칸을 넘는다, QA-003-M7e L02·M7e-4: `tests/m7eContent.test.ts` 「M7e-4 L02」가 풀 전체를 점검하고 5음절 어절 라벨 감시 목록 20개를 지키며, `e2e/m7e4-labels.spec.ts`가 모든 선택지 이벤트를 320×568·360×740 × 글자 150·200%로 낱말 끊김 감사한다) · `result` 6~300자(권장 84자 이하, 고른 뒤 사건 기록에 남는 문구)는 필수.
- `requires`가 있으면 조건을 만족할 때만 선택지가 **보인다**. 화면에는 항상 2~3개가 보여야 하므로 **`requires`가 없는 선택지가 2개 이상** 있어야 한다.
- **정의는 최대 4개, 같은 상태에서 보이는 것은 최대 3개**(M7a r3, 마스터 결정 13-M ①): 정의가 3개를 넘는 이벤트는 서로 **같이 보일 수 없는** 선택지가 있어야 한다 — `infant-new-sibling`의 `grandma`(`requires.flags: ["grandparent_close"]`)와 `notice`(`requires.notFlags: ["grandparent_close"]`)가 서로 배타라 플래그가 있으면 help·sulk·grandma, 없으면 help·sulk·notice가 늘 3개 보인다. lint(`eventLint#visibleChoiceProblems`)가 「같은 상태에서 동시에 보일 수 있는 선택지의 최대 수 ≤ 3」을 점검한다(플래그 flags/notFlags 충돌·재력·형제 순서·나이·스탯·순자산 범위·양육 방식·성별·사는 집의 허용 목록이 겹치지 않을 때만 함께 못 보인다고 본다 — 확실하지 않으면 함께 보일 수 있는 것으로 센다). 선택지 균형(지배) 점검은 정의된 모든 쌍을 비교한다.
- **돈이 드는 선택지 게이팅 (SPEC-003 EC4)**: 큰돈이 드는 선택지는 `requires`에 자산·부모 재력 조건을 건다 — 지금 10개 — 부모 재력 조건 5개(`infant-care/home` · `infant-stories/book` · `school-tutoring/tutor` · `school-exam/retry` · `youth-first-job/family`)와 순자산 조건 5개(`youth-exam-prep/persist` 순자산 −5000 이상 · `middle-parents-care/facility` · `middle-child-school/fund` · `middle-layoff/open` 0 이상 · `senior-travel/go` 5000 이상, 만 원). 근거는 `docs/data/economy-model.md` 6절(EC4)이다. 게이트가 닫혀도 `requires` 없는 선택지가 2개 이상 남는다.
- 선택지는 이벤트가 일어난 순간 보이는 목록이 정해져 **저장 상태에 들어간다**(새로고침해도 같은 선택지).

## 6. 플래그 (이후 이벤트를 여닫는다)

- 이름: 소문자로 시작, 소문자·숫자·밑줄 (`has_career`, `first_love`).
- 한 이벤트가 `setFlags`로 켠 플래그를 다른 이벤트가 `conditions.flags`/`notFlags`/`requires`/`bonuses`/`modifiers`로 읽는다. 예: `youth-meeting`이 `has_partner`를 켜고 `youth-marriage`가 그 플래그를 요구한다.
- **읽는 플래그는 어딘가에서 켜져야 한다**(오타 방지): 켜는 이벤트가 어디에도 없으면 로드할 때 오류다. 켜기만 하고 안 읽는 플래그는 허용된다(엔딩에서 쓸 수 있다).
- **흐름이 막히지 않게** 설계한다(R-045 e): 선택으로 길이 닫히면 다른 길이 열리게 한다. 예) 결혼 "기다리자" → `marriage_waited` → `youth-marriage-again`(다시 꺼낸 이야기) → 또 기다리면 `youth-partner-leaves`; 헤어짐 → `broke_up` → `youth-reunion`; 아이를 갖는 선택 → `has_child` → 중년의 아이 이벤트·노년의 손주 이벤트(아이를 두지 않은 판에는 열리지 않는다); 검진을 미룸 → `health_ignored` → `middle-health-crisis`.
- **현재 켜는 플래그와 켜고 읽는 이벤트의 전체 표는 `docs/data/events-distribution.md` 4절**(데이터에서 자동으로 만든다)에 있다. `tests/events.test.ts` "플래그 연결"과 `tests/flow.test.ts`가 연결이 실제로 이어지는지 확인한다.
- **한 판 안에서 이미 일어난 일과 모순되는 이벤트가 나오지 않게** 한다(REV-001-M4-1 R-057~R-060, R-062, R-065). 이벤트는 "그 사건이 일어난 판의 상태"를 플래그로 닫고 열어 쓴다:
  - 부모님의 임종(`middle-parents-farewell`)은 `parents_gone`을 켜고, 부모님이 나오는 중년·노년 이벤트(병환)는 `notFlags: ["parents_gone"]`으로 닫는다.
    **`parents_gone`을 켜는 선택은 해 끝에 간이 상속(M5 r3, `src/core/inherit.ts`·`life.ts#finishYear`)을 일으킨다**: 부모가 처음 모두 떠나는 해의 끝에 `INHERIT[재력 단계] ÷ (형제 수 + 1)`이 순자산에 더해지고 인생 기록에 한 줄이 남는다. 상속은 **선택의 효과가 아니라 해마다 규칙**이므로 효과 목록에도, `previewChoice`·영향 줄에도 들어가지 않는다(r2에서는 영향 줄에 「자산 ▲▲▲」가 보였으나 r3에서 뺐다 — economy-model.md 4-1절·5-C). 나이 상한(어머니·아버지 모두 100세 초과)으로도 같은 자리에서 같은 상속이 일어난다. **새 이벤트는 같은 이벤트 안에서 `parents_gone`을 켜는 선택지와 안 켜는 선택지를 섞지 않는다**(섞으면 선택에 따라 상속 여부가 갈리는데 영향 줄은 이를 말하지 않는다) — `tests/inherit.test.ts`의 점검 시험이 막는다.
  - 아이는 `has_child`(+ 늦게 맞았으면 `child_late`)로 시작하고, 독립(`middle-child-leaves`)이 `child_left`를 켜서 자라난 아이·아이의 앞날을 닫는다. 아이가 어린 시점에 "진로·독립"이 나오지 않게 창은 아이를 맞은 나이(청년 27~39세)에서 가장 이른 경우로 잡고, 늦게 맞은 아이(`child_late`)는 별도 이벤트(`middle-late-child`)로 시점을 옮긴다. 손주 이야기는 `child_distant`(연락이 끊긴 자식)일 때 닫히고, 먼저 연락해 화해하면(`senior-estranged-child`) 풀린다.
  - 학업을 접으면(`school-family-priority` "집안의 결정을 따른다") `left_school`이 켜져 입시·학교 생활 이벤트가 닫힌다. 집은 `renting`(월세방)·`own_home`(자가)으로 갈라, 월세 인상은 월세방을 구한 판에서만 나온다.
  - 이혼(`middle-marriage-crisis` "따로 살기로 한다")은 `married`뿐 아니라 `has_partner`도 끈다. 헤어졌다 다시 만난 사이는 `reunited`로 표시해 결혼 이야기(`youth-second-chance`)가 다시 열린다.
  - **문구가 상태를 말하면 조건에 그 플래그를 건다** — 이것은 문구 점검(7절 "상태 어휘")이 빌드에서 강제한다. 상태와 무관하게 쓰려면 문구를 중립으로 바꾼다("자식에게 남길지" → "남길지").
  - **동생 맞이 (M7a, IN4)**: `infant-new-sibling`(첫째에게만, 2~4세)은 선택지 네 개(help·sulk·grandma·notice — 보이는 것은 늘 3개) 모두 `younger_sibling`을 켜고 그 뒤에야 후속 `infant-sibling-toy`(3~6세, `conditions.flags: ["younger_sibling"]`)가 열린다. `family.ts`의 아래 동생 표시는 `seen["infant-new-sibling"]`을 읽어 나이 차를 사건이 일어난 나이로 둔다 — 플래그와 표시는 늘 같이 켜진다(`tests/infantContent.test.ts`가 확인). `infant-new-sibling`의 `grandma` 선택지는 `grandparent_close`(`infant-care/grandparents`나 `infant-daycare-wait/grandparents`가 켠다)가 있을 때만 보인다.
  - **맡김 장면 (M7a r3, R-363)**: 낮 동안 아이를 맡길 곳을 정한 선택은 `childcare_set`을 켠다 — `infant-parental-leave/back`(일터로 돌아가고 맡길 곳을 찾는다), `infant-daycare-wait`의 세 선택지, `infant-care`의 세 선택지. `infant-daycare-wait`와 `infant-care`는 `conditions.notFlags: ["childcare_set"]`으로 닫혀 맡김 장면이 한 판에 두 번 나오지 않고(어느 쪽이 먼저든), 육아휴직 복귀 뒤 「맡길 곳은 정해지지 않았습니다」가 나오지 않는다. 일을 쉬는 쪽(one·share)을 고른 판은 일터로 돌아갈 때가 오므로 어린이집 대기가 그대로 열린다(`tests/flow.test.ts` 「영유아 맡김·취학 전」).
  - **집 구하기와 이삿짐 (M7a r3, T05)**: `infant-moving`(이삿짐을 싸던 날, 3~6세)은 `conditions.housing: ["rent", "free"]`로 **출생신고의 사는 집이 자가인 판에는 나오지 않는다**(`tests/flow.test.ts` 「자가 판의 이사」). 「빚을 내어 작은 집을 산다」(`buy`)는 재력 3에서만 보인다.

## 7. 문구 규칙과 길이 권장 최대 (SPEC-001 '안 할 것' 포함 — `npm run check:events`와 `npm test`가 점검한다)

문구 점검(`src/core/eventLint.ts`)이 이벤트의 제목·본문·선택지 라벨·결과 문구에 모두 적용한다. 어기면 **빌드가 실패**한다.

**내용**
- 커뮤니티 사연을 **모티브로만** 새로 쓴 글. 실제 글 원문·실존 인물·실제 상호·실제 사건 이름 금지(상호·사건·제도 이름 목록 점검, "출처·원문·퍼옴·링크" 같은 인용 표지 점검).
- **특정 달력 연도·실제 사건을 가정하지 않는다**(R-033: 지금 세상은 2008~2025년생이라 성인기 전체가 미래다). 기준은 나이뿐. `2031년`·`1990년대`·`80년대` 형태가 걸린다.

**어조** — 담담한 회고(원작 '80억분의 1'), 본문·결과는 **합쇼체**(SPEC-003 마스터 결정 C1·R2, M7e-1)
- 느낌표·물음표·말줄임표·이모지·그림 기호·URL·"ㅋㅋ"·과장 표현(`엄청`·`대박`·`충격` …) 금지. 제목·라벨 끝에 마침표를 찍지 않는다. **제목·라벨에는 한글과 공백만 쓴다**(M7e-4 C20, QA-003-M7e 2회차: 가운뎃점·쉼표·괄호·슬래시·숫자·영문 금지 — 버튼의 접근성 이름에 그대로 들어간다. 잇는 말은 「이나·와/과」로 쓴다; `eventLint.ts`의 `/[^가-힣 ]/` 검사, 시험 `tests/eventLint.test.ts` 「라벨·제목은 한글과 공백만」). **구어체(해요체) 금지**: 낱말이 「요」로 끝나면 문장 안에서도 걸린다 — 「어요·아요·에요·예요·해요·네요·세요」뿐 아니라 「가요·와요·봐요·줘요·서요·써요·돼요」, 「~ㄹ게요·~ㄹ까요·~는데요·~거든요·~군요」, 「~죠」까지(M7a에서 「가요」 같은 꼴을 못 잡던 결함을 고쳤다). 「필요·중요·주요·수요·소요·강요·동요·민요·개요·풍요」 같은 한자어 명사는 걸리지 않는다(`SAFE_PHRASES`). 인용 부호 안의 대사에도 해요체·반말은 쓰지 않는다 — 대사는 간접화법으로 풀어 쓴다(마스터 결정, 2026-10-18).
- **본문(`text`)과 결과(`result`, 서술 이벤트는 본문)는 문장마다 합쇼체 「~습니다.」「~ㅂ니다.」로 끝난다**(「했습니다.」「였습니다.」「합니다.」「입니다.」). 해라체 「~했다.」는 걸린다. 사건 본문·선택 결과·카드 본문·엔딩이 이 어체이고, **제목·선택지 라벨·버튼·첫 화면 문구·시스템 안내는 현행 그대로**다(마스터 결정 R2) — 선택지 라벨은 지금처럼 `~다`로 끝난다(「창문을 연다」).
- 지나온 일을 짧게 되돌아보는 문장으로 쓴다: "~했습니다", "~였습니다", "~이 남았습니다". 감정을 설명하기보다 장면을 적는다.
- **해설 종결 금지 (M7e-3, 마스터 결정 E-11)**: 본문·결과의 문장이 「~것입니다」「~것이었습니다」「~때문입니다」로 끝나면 걸린다(`eventLint.ts#EXPLANATORY_ENDING`) — 이유를 설명하지 말고 장면을 사실로 적는다(「말하지 않았던 것입니다」 ✕, 「말하지 않았습니다」 ○). 대상을 가리키는 명사 「것」(「그것입니다」「이것입니다」「저것입니다」)은 해설이 아니라 통과한다. 시험: `tests/eventLint.test.ts` "해설 종결 금지".

예시 (`infant-care`, 해라체 → 합쇼체 — 뜻과 담담한 어조는 그대로, 끝맺음만 바뀐다):

| | 해라체 (예전 글 — 지금은 걸린다) | 합쇼체 (규칙) |
|---|---|---|
| 본문 | 부모님이 일하러 나가는 낮 동안 아이를 어디에 맡길지 정해야 했다. 집안 사정에 따라 고를 수 있는 길이 달랐다. | 부모님이 일하러 나가는 낮 동안 아이를 어디에 맡길지 정해야 했습니다. 집안 사정에 따라 고를 수 있는 길이 달랐습니다. |
| 결과 | 낮에는 조부모님 곁에서 지냈다. 끼니와 낮잠 시간이 일정했고, 옛이야기를 많이 들었다. | 낮에는 조부모님 곁에서 지냈습니다. 끼니와 낮잠 시간이 일정했고, 옛이야기를 많이 들었습니다. |
| 라벨 | 조부모님 곁에서 지낸다 | (그대로) |

**어체 판정 (`src/core/eventLint.ts#splitSentences·toneOf`, 시험 `tests/eventLint.test.ts` "어체 판정")** — 문장 단위로 문장 끝(마지막 마침표 앞)의 종결만 본다. 합쇼체 = 「니다」 앞 글자의 받침이 ㅂ(「~습니다」「~ㅂ니다」), 해라체 = 그 밖의 「~다.」, 그 밖(「~요.」「~어.」「~음.」, 마침표 없음, 받침 없는 「~니다」)은 합쇼체 서술체가 아니라서 걸린다. 연결 어미는 보지 않는다(「~했다고 합니다.」는 합쇼체, 「~했습니다만 ~없었다.」는 해라체).
- **본문·결과에서 인용 부호를 쓰지 않는다**(M7a r3, REV R-360 (a)안 — 마스터 결정 47: 대사의 해요체·반말 불허): 큰따옴표(`" "` `“ ”`)·작은따옴표(`' '` `‘ ’`)·낫표(`「 」` `『 』`)가 하나라도 있으면 걸린다. 대사는 「~라고 했습니다」 같은 **간접화법**으로 쓴다. 인용 부호로 감싼 말이 어체 판정을 건너뛰어 해라체·반말 대사가 통과하고 본문 전체를 따옴표로 감싸면 어체·마침표 요구를 모두 건너뛰던 구멍(r2까지, 지금 풀에는 0건)을 막는 가장 단순한 길이다. 제목·선택지 라벨은 이 금지의 대상이 아니다. (문장 분리 함수 `splitSentences`·`toneOf`는 인용을 가리는 순수 계산으로 남아 있고 `tests/eventLint.test.ts`가 그 동작을 따로 본다 — lint는 부호가 있는 글 자체를 막는다.)
- **옛 철자 「~읍니다」와 금액 문장**(QA O10, M7a r3): 합쇼체는 「~습니다」다 — 「읍니다」는 걸린다. 본문·결과의 **금액(숫자 + 원·만 원·억 원·달러, 「3억」)**은 걸린다 — 금액은 영향 줄(집안 살림 ▲▼)이 말하고 문장은 숫자 없이 쓴다(「몇 만 원」은 통과). **마침표 바로 뒤에 한글이 붙은 글**(「울었다.어른이 달랬습니다.」)도 걸린다 — 문장이 안 갈려 어체 판정이 끝 문장만 보게 된다(R-371 ③). **영유아 문구의 1인칭 금지**는 단계가 영유아뿐인 이벤트와 **나이 창이 7세 안에서 끝나는 이벤트**(7세 `school-*` 포함)에 적용된다(R-371 ②). 구어체 점검의 한자어 명사 예외는 「필요·중요·주요·수요·소요·강요·동요·민요·개요·풍요」에 「고요·요요·긴요·불요·연요·대요」와 노래 「(대중|민중|유행|옛) 가요」를 더했다 — 「그만 가요」(가다)는 계속 걸린다.
- 인용 부호가 금지이므로 짝이 맞지 않는 부호(`"가자 하고 …`, 홀로 선 닫는 부호)도 같은 이유로 걸린다(짝 점검 메시지는 남아 있다).
- 소수점·번호의 마침표(`3.2kg` `1.5배`)는 문장 끝이 아니다(마침표 뒤가 공백이나 글 끝일 때만 문장을 가른다). 문장 끝 마침표 뒤의 닫는 괄호(`…입니다.)`)는 문장에 붙여 본다.

**생애 단계별 면제 (R-067)**: 지난 세상(1950~89년생)의 노년(65세 이후)은 이미 휴대전화·인터넷이 있는 세상에서 산다. 그래서 이벤트의 모든 단계가 노년이면 지난 세상에서도 새 기기 소재를 쓸 수 있다(`bannedWordsFor(eras, stages)`). 학창 소재(학원·급식)와 미래 소재는 노년에도 계속 금지다. 이 덕에 `senior-new-device`("낯선 기계")가 지난 세상에도 열려 있다(노년 선택지 평균이 다른 시대보다 낮던 지난 세상에 선택지 하나가 늘었다).

**오탐 예외 (R-067)**: 규칙이 정상 표현을 잘못 잡지 않도록, 검사 전에 `SAFE_PHRASES`에 적힌 표현을 글에서 지운다 — 헐값·헐렁("헐"), 영향을 미친·미친 영향("미친"), 펌프("펌"), 우물쭈물("우물"), 폭풍우("폭풍"), 현대적·현대인("현대"). "~니까"는 문장 끝일 때만 구어체로 본다("비가 오니까 우산을 챙겼다"는 정상). 새 예외를 넣으면 `tests/eventLint.test.ts` "오탐 예외"에 문장을 하나 더한다.

**상태 어휘 (R-067)** — 문구가 어떤 상태를 말하면 조건이 그 상태를 요구해야 한다(`STATE_WORD_RULES`). 성인기(청년·중년·노년) 이벤트의 제목·본문·선택지 라벨·결과 문구에 적용하고, 선택지 글은 그 선택지의 `requires`로도 충족할 수 있다.

| 혼자 | `notFlags: ["married"]` | - |

영유아·학창기의 "아이"는 나 자신이나 또래라 가족어가 아니다. "받아들이다·잦아들다"의 "아들", "딸기"의 "딸", "아이디어"의 "아이", "학부모"의 "부모"도 걸리지 않는다.

**선택지 균형 (R-069)** — 같은 이벤트의 두 선택지에서 한쪽이 **모든 축(스탯 4개 + 돈)에서 낫거나 같고** 어딘가는 확실히 낫다면 '정답형'이라 걸린다(보너스는 최악·최선으로 쳐서 비교한다: 보너스로 뒤집힐 수 있는 위험 선택은 통과). 효과가 완전히 같은 두 선택지도 걸린다. 소극적 선택(미루기·사양·모른 척·넘기기)에는 작은 이득을 준다 — 시간·돈·몸을 아끼는 쪽(돈 +, 건강 +1, 학력 +1)으로. **돈 축**은 `assets.net + 3 × assets.income + family`(만 원)로 센다(`src/core/eventLint.ts#moneyOf`) — 부채는 빼고 본다. 예외 목록(`DOMINANCE_EXCEPTIONS`)은 비어 있다.

**영유아 문구는 3인칭 (R-070)** — 영유아 이벤트는 "아이"로 쓰고 "나·내"를 쓰지 않는다(학창기부터는 회고하는 "나").

## 9. 상태에 남는 것 (참고)

저장 상태(`GameState`, 스키마 v8 — SPEC-003 M5에서 재산 스탯이 없어지고 `assets`·`familyFund`가 더해졌다)에는 `flags`(켜진 플래그) · `seen`(이벤트 id → 마지막으로 일어난 나이) · `pending`(대기 중인 선택지: 이벤트 id, 인스턴스 키 `id@나이`, 보이는 선택지 id) · `lastChoiceAge` · `death`가 있고, `history`에 연표(나이·종류·문구·고른 선택)가 쌓인다(상한 160개, `HISTORY_LIMITS`). 엔딩(M5)은 이 연표를 읽는다.

**콘텐츠를 갱신해도 저장이 날아가지 않는다 (R-046).** 대기 중이던 선택지가 가리키는 이벤트가 풀에서 사라졌거나, 선택지가 바뀌었거나, 선택지 이벤트가 아니게 되었으면 저장 전체를 버리지 않고 **대기만 풀어** 이어간다(그 해는 다시 진행된다). 저장의 모양이 어긋난 것(키·나이·본 이벤트 기록·선택지 개수 불일치 — 손상·변조)만 새 게임이 된다(`src/core/storage.ts#parseGame`). (이 절의 대기 풀기 규칙은 v8에서도 그대로다. 저장 모양이 바뀌는 M5 개편은 `SCHEMA_VERSION`을 올려 옛 저장을 새 게임으로 보낸다.) 그래도 **이미 쓴 이벤트·선택지 id는 바꾸지 않는다** — 바꾸면 그 이벤트가 `seen`에서 맥락을 잃고 대기 중이던 사용자는 그 선택지를 잃는다. M3의 표본 20개 id는 모두 그대로 남아 있다(`tests/events.test.ts`가 확인).

## 10. 이벤트·밸런스를 고친 뒤 다시 만들 것 (분포표, R-085)

엔딩의 "출발선 대비"는 같은 시대의 헤드리스 시뮬레이션 판들이 남긴 **최종 순자산 분위수표**(`src/data/finalDistribution.ts`, 만 원 0~100번째 백분위 101칸)에서 도착 자리를 구한다. 이 표는 **현재 이벤트·진행 규칙·밸런스 표로 돌린 결과**라서, 아래를 고치면 낡는다.

- 이벤트 데이터(`src/data/events/*.json`)의 효과·조건·가중치·플래그, 이벤트 추가·삭제
- 진행 규칙과 표: `src/core/life.ts`, `src/data/lifeTable.ts`, `src/data/birthTable.ts`의 값 (`timingTable.ts`는 시뮬레이션 결과에 영향이 없다)

**절차 — 위를 고쳤다면 이 순서로:**

1. `npm run check:events` — 데이터 검증(빌드가 먼저 돌리는 것과 같다)
2. `npx vite-node scripts/eventDistribution.ts` — 이벤트 분포 문서(`docs/data/events-distribution.md`) 다시 만들기
3. `npx vite-node scripts/finalDistribution.ts` — 최종 순자산 분위수표 다시 만들기 (시대별 4000판, 약 12초)
4. `npm test` — 표가 낡았는지는 `tests/ending.test.ts` "현재 엔진·이벤트로 같은 시드·판 수로 다시 만들면 같은 표다"가 잡는다. 점검만 따로 하려면 `npm run check:dist`

`npm run build`에는 넣지 않았다: 표를 다시 만들어 견주는 데 10초대가 걸려 빌드가 느려지기 때문이다(`check:events`는 수 초). 배포 전에는 `npm test`(필수)가 같은 것을 잡는다. SPEC-002로 이벤트를 +50 추가하면 반드시 3번을 한다.

표는 **무작위 선택 전략**(수동 플레이 흉내)으로 만든다. 자동 모드(성향 선택) 판은 같은 표와 견준다 — 지난 세상은 자동 판이 평균 4~5점 더 벌어(중앙값 37 → 42) 같은 재산이 표에서 최대 14%p 다른 자리로 읽힌다(지금·다가올 세상은 최대 6~7%p). 측정과 제안은 `docs/review/REV-001-M5-1.md` 하단 "반영 내역" R-085.
