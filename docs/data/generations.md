- 겹침(GD2): 1960~1963년은 베이비붐과 86 양쪽에서 나온다. 저장되는 `generation`이 BGM 참고·엔딩 표기·카드 소개·`track`을 정하고, 출생 연도 자체가 달력 연표를 정한다. 같은 출생 연도라도 고른 세대가 다르면 연표는 같다. 엔딩에는 「베이비붐 세대 · 1961년생」처럼 세대 이름과 연도를 함께 적는다. 출생 연도 가중은 **고른 세대 범위 안의 비율**로 센다(GS7).
- 「BGM 참고 장르」는 그 세대가 청소년기를 보낸 시대의 대표 장르를 가리키는 **표시·문서용**이다. 판의 음악 전환은 달력 연도만 입력으로 한다(BG3, 세대·나이는 입력이 아님).
- `2026년 나이`: 이 판들의 2026년 이후는 모두 공식 전망 구간이다(PJ1). 알파는 6~13세에 전망 구간에 들어선다(출생 해~2025년의 어린 시절만 실제 구간).
- 검산: 15 + 9 + 10 + 11 + 16 + 16 + 8 = **85**. 겹침 연도 1960·61·62·63 = 4. 서로 다른 연도 85 − 4 = **81** = 2020 − 1940 + 1. 구간 이어짐: 1940~54 | 55~63 | 60~69(겹침) | 70~80 | 81~96 | 97~2012 | 2013~20 — 빈 해 0.
- 카드의 접이식 설명(뜻 유지): 「세대 범위는 자료마다 조금씩 달라요. 이 게임은 위 범위를 씁니다」. `MZ`는 범위가 겹쳐 라벨에 쓰지 않는다(GS2).

## 3. `GENERATION_CONFIG` 초안 (NR6 — 세대별 값을 한 곳에)

### 3-1. 형식

```ts
type GenerationId = 'industrial' | 'boomer' | 'g86' | 'genx' | 'millennial' | 'genz' | 'alpha';

interface GenerationConfig {
  id: GenerationId;
  label: string;                                      // 표시 이름 (GD1)
  birth: { from: number; to: number };                // 포함. 알파 to = LAST_BIRTH_YEAR = 2020
  bgmReference: GenreId;                              // 참고(표시용). 전환 입력 아님 (BG3)
  wealthWeights: readonly [number, number, number, number, number]; // 1~5단계 출생 비율(%), 합 100 (NR1)
  parentingWeights: Record<'neglect' | 'free' | 'helicopter' | 'strict', number>; // 합 100
  namePool: NamePoolRule;                             // 4절
  introMeaning: string;                               // 5절 (뜻만; 문장은 designer·copy.md)
  trackMode: 'standard-capable' | 'assembled';        // 알파만 'assembled' — standard 이벤트를 변형/닫음 (AL3)
  randomWeight: number;                               // 랜덤 세대 확률. 7세대 모두 1/7 (GS3, 인구 비례 아님)
}
// 출생 연도 가중(GS7)은 별도 표 birthYearWeights(DC2): 해마다 {weight, basis: 'births' | 'uniform'}
```

지금 `ERA_CONFIG`에서 **없어지는 것**: `birthYears`(→ `birth`), `label`·`blurb`(시대 이름 → 세대 이름), `priceIndex`(→ 연도 축 소비자물가, 문서 B), `life.mortalityScale`·`life.maxAge`(→ 연도별 기대수명·사망률 표 NR5, 문서 B). `parentingWeights`와 `wealthWeights`는 세대로 옮긴다. 단위 테스트: 7종 · 수저 5단계 × 7세대 합 100 · 교육방식 7세대 합 100 · 경계 연도.

### 3-2. 수저 가중치 (NR1)

| 단계 | 수저 | 산업화·베이비붐·86 | **X** | 밀레니얼·Z·알파 |
|---:|---|---:|---:|---:|
| 1 | 흙수저 | 40 | 33 | 25 |
| 2 | 동수저 | 32 | 31 | 30 |
| 3 | 은수저 | 20 | 24 | 28 |
| 4 | 금수저 | 7 | 10 | 14 |
| 5 | 다이아몬드수저 | 1 | 2 | 3 |
| 합 | | 100 | 100 | 100 |
| 금수저 이상 | | 8 | 12 | 17 |

- 출발값 근거: SPEC NR1 그대로 — 산업화·베이비붐·86은 SPEC-003 「지난 세상」 표 [40,32,20,7,1], 밀레니얼·Z·알파는 「지금 세상」 표 [25,30,28,14,3](이름만 R1 표 이름이고 2026년생은 없다, 출발값으로만 쓴다).
- **X는 두 표의 평균을 정수 합 100으로 맞춘 값**이다: 평균 [32.5, 31, 24, 10.5, 2] → 반올림 규칙(.5는 위·아래 한 번씩)으로 [33, 31, 24, 10, 2]. 세대 안에서 출생 연도별로 보간하는 안(1970년생은 지난 표 쪽, 1980년생은 지금 표 쪽)은 단순함 때문에 쓰지 않았다 — G-01.
- 모든 값은 **설계값**이다(RL3 방식으로 「설계값」 표기). 근거(소득분배·계층 이동 지표, DC10)가 확보되면 조정한다. 표는 마스터 승인 게이트를 거친다(EC0 방식). 「누가 많이 태어났나」일 뿐이며 수저가 결과를 얼마나 가르는지는 WS(`SPOON_SPREAD`, 문서 B 범위)가 따로 정한다.
- 이 표는 세 계단(산업화~86 / X / 밀레니얼~알파)이다: 1단계가 40 → 33 → 25로 줄고 금수저 이상이 8 → 12 → 17로 늘어, 「지금 세대일수록 부모 재력의 구성이 위쪽으로 옮겨 왔다」는 방향을 단순하게 표현한다. 이 방향이 DC10과 어긋나면 N7에 따라 형진 님께 보고한다.

## 4. 이름 풀 규칙 (NR4)

- **주의**: 법원 풀은 「등록 연도」 기준이라 출생 연도와 정확히 1:1이 아니다(연말 출생 → 이듬해 등록). 풀 이름 `court-YYYY`는 「등록 연도 YYYY」다. 출처 표기에 이 점을 적는다 [확인 필요: 출생 연도로 재집계된 공식 통계가 있는지, DC6].
- 이름 풀 위치·형식(MG7): 연대 풀은 `names.json`의 `decades`에 1940·1990·2000 키를 더한다(키 = 연대 첫 해, 2000은 2000~2007). 법원 풀은 `sources/scourt-birth-names.json`(원자료)을 그대로 읽는다. `tests/names.test.ts`의 연도 범위 기대를 7세대 범위로 갱신한다.

## 5. 소개 문구의 뜻 (GS2)

카드 소개 한 줄은 **사실 기반**이다: 연표 DB의 사건 이름(timeline-schema.md 8절 후보)만 쓰고, 우열·평가어 0, 비하어 0, 7장이 같은 문장 구조(병렬)다. 아래는 **뜻**이고 최종 문장은 designer가 `copy.md`에 쓴다(합쇼체).

| 산업화·전후 | 한국전쟁, 전후 복구, 산업화의 시기를 지나온 세대 |

| 밀레니얼 | 개인 홈페이지, 스마트폰, 글로벌 금융위기의 시기를 지나온 세대 |
| Z | 스마트폰, 숏폼 영상, 코로나19의 시기를 지나온 세대 |
| 알파 | 대화형 인공지능, 학령인구 감소, 고교학점제의 시기에 자라는 세대. 성인기부터는 공식 전망을 바탕으로 한 가상의 이야기 (PJ7·AL8: 전망 표시) |

- 사건 이름은 해당 `officialName`이거나 일반 명사 표기만 쓴다. 상호·서비스·작품 이름 0(「개인 홈페이지」「스마트폰」은 일반 명사).
- 카드의 부 라벨은 출생 연도 범위 숫자(「1960~1969년생」)이고 이 숫자는 UI 표기로 TL9의 「연표 문장 안 달력 연도 금지」와 무관하다(GS2).
- 「~한 세대입니다」 꼴의 형용(「열정적인 세대」)은 6절 목록에 걸린다. 「지나온/자라는 세대」는 관형어이지 평가가 아니라서 허용 패턴이다(6-3절).

## 6. 평가어 금지 목록 초안 — `GENERATION_EVAL_WORDS` (GD6)

형진 님 표의 「주요 특징 및 정체성」 칸에 있던 평가·서열 표현을 게임 문구(카드 소개·이벤트·연표·전망·엔딩·안내·UI 문구 전체)에 옮기지 않는다. 목록은 `src/data/generationWords.ts`에 두고 reviewer·마스터가 판독해 확정한다. 이 문서의 목록은 **시드**이며 낱말을 늘리는 것은 판독의 몫이다.

### 6-1. 묶음

| 묶음 | 뜻 | 낱말 시드 ▲ | 적용 방식 |
|---|---|---|---|
| **E1** 형진 님 표 유래 | 표에 있던 평가·서열 표현 | 기득권층 · 신인류 · 중간 관리자층 · 희생 의식 · 희생 세대 | 위치 무관(어디서든 걸림) |

세대 이름 집합(결합 규칙의 기준): 산업화 세대 · 전후 세대 · 베이비붐 세대 · 베이비부머 · 86세대 · X세대 · 밀레니얼(세대) · Z세대 · 알파 세대 · 알파 · MZ. 세대 비하·낙인어(GC2)는 이 목록이 아니라 `GENERATION_SLUR_WORDS`가 맡는다(`quote` 안에서만 통과).

### 6-2. 결합 규칙 (GC4)

- E2·E3·E4는 **세대 이름의 앞뒤 12자 안**에 있을 때 걸린다(「서열·성격을 세대에 붙이는 문장」만 잡고, 세대 이름이 없는 일반 문장은 건드리지 않는다).
- E1·E5는 **어디서든** 걸린다.
- 걸린 문장은 빌드(연표·이벤트·전망·엔딩 문구)와 `npm test`(UI 문구)가 모두 실패시킨다.

### 6-3. 허용 패턴 (오탐 방지)

- 「~의 시기를 지나온 세대」「~의 시기에 자라는 세대」(관형어 + 세대 이름)는 허용한다. 5절 소개 문구의 틀이다.
- 세대 이름 + 연도 범위(「1960~1969년생」), 세대 이름 + 사건 이름(「외환위기를 겪은 X세대」)은 허용한다. 사실 서술이다.
- 평가어 낱말이 세대 이름과 무관한 일반 문장(예: 「열정적인 응원이 이어졌습니다」)은 걸리지 않는다(12자 안에 세대 이름이 없을 때).

## 9. DC8 대조 기록 자리 (아직 비어 있음)

한국민족문화대백과사전 「세대」 항목(`encykorea.aks.ac.kr/Article/E0029780`)의 개념·분류와 이 문서의 7세대 범위를 대조한 결과는 DC8 수행 때 여기에 적는다: 항목명·열람일·세대별 범위 차이·한국 공식·연구 기관 대 해외 연구 기관(Pew Research·McCrindle 등) 범위 병기. **문장 복사 금지, 우리 말 요약, 출처 표기**(R-149 접근 규칙). 차이가 있어도 형진 님 표를 우선하고 차이만 기록한다(GD1).
