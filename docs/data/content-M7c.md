## 0. 먼저 읽을 것 — 마스터가 알아야 할 발견 10가지

1. **지금 코드에 사용자 글을 연표로 넣으면 이모지 한 개로 인생 전체가 날아간다.** `validHistoryEntry`(storage.ts:131~144)가 연표 `text`에 `cleanText` = `!hasHiddenControl`(U+200B~200F · 202A~202E · 2066~2069 · FEFF)을 쓰는데 ZWJ(U+200D)가 그 범위 안이다. 가족 그림 문자(U+1F468 U+200D U+1F469 U+200D U+1F467)를 적은 기록이 연표에 있으면 `checkGameState`가 `invalid` → `parseGame`이 null → 새로고침하면 새 게임이다. 마스터 방침(사용자 글에 거부 재사용 금지)이 필요한 이유이고, 3-6절이 규칙을 정한다.
2. **「140자」는 UTF-16 길이가 아니다.** `clipEntry`(history.ts:12~22)는 `slice`라서 서러게이트 쌍·ZWJ 시퀀스를 한가운데서 자른다. 그래핌 하나가 수십 코드 포인트일 수도 있으므로(결합 문자 범람) 그래핌 상한만으로는 저장 크기를 막지 못한다. **그래핌 140 + 단위 400(= `HISTORY_LIMITS.maxTextLength`) + 그래핌당 코드 포인트 상한** 세 겹이 필요하다(3-1절).
3. **기록 카드가 인생 결과를 바꾸지 않게 만든다.** 카드가 뜰 차례는 RNG를 쓰지 않는 순수 판정(`seed`·나이·플래그·본 이벤트의 함수)이고 기록은 스탯·자산을 바꾸지 않는다. 그래서 「카드를 모두 쓴 판 / 모두 건너뛴 판 / 자동 모드 / 끈 판」의 인생이 같다(R-039 계열 불변식, 완료 기준 2).
4. **FR1의 「판당 6~8회」는 7종 × 1회로 최대 7이다.** 8은 구조상 나오지 않는다. LM2의 1시간 모드 10~12도 종류를 늘리거나 반복해야 하므로 2차 과제다(NC-4).
5. **기록 카드와 중대 결정 카드는 같은 순간에 겹치지 않는다.** 결정 카드는 해의 **끝**(진행률 100%에서 `stepYear`)에 뽑히고, 기록 카드는 해의 **첫머리**(나이가 오른 직후)에 적격이 된다. 같은 해에 둘이 걸리면 「기록 카드 → 진행률 → 결정 카드」로 이어지고 시트가 동시에 열리는 일은 없다(5-4절).
6. **c-036·c-038은 기억 질문 바로 위에 두기에 부적절하다.** 둘 다 「역경·부정적 경험」 인용이라 「기억나는 장면이 있습니까?」를 역경 쪽으로 몰아간다(안전 기준 S2). 7장 중 **자료가 맞는 카드는 ① 하나(c-037)** 뿐이고 나머지는 인용 박스 없이 둔다(2절, NC-9).
7. **가상 키보드는 지금 시트 틀이 모른다.** `.sheet { max-height: 94dvh }`(dash.css:192)의 `dvh`는 키보드를 반영하지 않고, iOS는 키보드가 올라와도 레이아웃 뷰포트가 줄지 않아 아래에 붙은 시트의 버튼이 키보드 밑에 깔린다. `visualViewport` 추적이 필요하고, 입력란 글자 크기가 16px 미만이면 iOS가 화면을 확대한다(6절).
8. **수동 기록 한 줄이 올해 진행률을 되감는다.** 시계 `resetKey`(App.tsx:255)에 `game.history.length`가 들어 있어 연표가 한 줄 늘면 시계가 새로 시작한다. note 행은 이 키에서 빼야 한다(5-3절).
9. **전역 `word-break: keep-all`(styles.css:14~15)이 사용자 글에는 맞지 않는다.** 띄어쓰기 없는 긴 한글은 낱말 하나로 취급되어 마지막 수단(`overflow-wrap`)으로만 끊긴다. 사용자 글은 `word-break: normal`로 풀고, 낱말 끊김 감사(QM3-1)에서 사용자 글 영역을 표식으로 뺀다(4절).
10. **기존 시험이 영향을 받는다.** 시트가 해마다 뜨므로 시계를 실제로 돌리는 기존 e2e는 `noteCards: false`로 시작해야 하고, 「생각 남기기 준비 중」을 단언하는 시험(`tests/dashboard.test.tsx` · `tests/dashText.test.ts` · `e2e/m4-unavailable.spec.ts` 등)이 바뀐다(7-2절).

### 1-5. `notes.json` 형식 (제안 — SPEC 363~368행의 확장)

SPEC의 단일 `citationId`·`conditions`로는 변형·「하나라도」 조건·흔들림을 표현할 수 없고, 인용을 이벤트와 같은 모양으로 두면 `citationFor`·`usedBy` 역색인을 그대로 쓸 수 있다.

```
{ "cards": [ {
    "id": "note-first-love",                 // ^note-[a-z0-9-]{3,40}$ — 이벤트 id는 note- 로 시작하지 못한다(시험)
    "topic": "첫사랑의 추억",                  // 연표 라벨 「나의 기록 · {topic}」, ≤ 12자
    "order": 3,
    "ageRange": { "min": 15, "max": 25 },
    "eras": ["past", "present", "future"],   // 없으면 세 시대 모두
    "conditions": { },                       // 적격(모두 맞아야) — events.ts Condition 그대로
    "triggers": [ { "conditions": {}, "seenAny": ["middle-health-crisis"] } ],   // 있으면 하나라도 맞아야 적격(⑤)
    "timing": { "jitter": { "min": 18, "max": 22 } },   // 또는 "asap"
    "prompt": "처음 누군가에게 … {이름}에게 … 있습니까?",
    "variants": [ { "when": { "flags": ["first_love"] }, "prompt": "마음을 전했던 그때를 …" } ],   // 첫 일치, 변형이 맞으면 흔들림 대신 바로(early)
    "citation": "c-037",                     // 이벤트와 같은 모양(문자열 또는 { past, present, future })
    "noCitation": "D"                        // citation과 함께 쓰지 않는다. 코드는 events의 NO_CITATION_CODES(X1 의료, D 자료 없음)
} ] }
```

- `triggers`와 `variants[].when`은 **조건 배열이면 하나라도 맞을 때(any-of), 단일 조건이면 모두 맞아야(all-of)** 한다. ④의 「`has_partner` 또는 `married`」 변형은 `when`을 두 조건의 배열로 적는다.
- 한도 상수(`NOTE_LIMITS`: 그래핌 140 · 단위 400 · 줄 3 · 자동 카드 7 · 전체 40 · 간격 2)는 JSON이 아니라 코드에 둔다. 카드별 `maxLength`는 140 이하만 허용하는 선택 필드로 남긴다(SPEC `maxLength: 140` 호환).
- 검증(`tests/noteCards.test.ts`, 빌드 `check:events` 옆 `check:notes` ▲): id 형식·유일성, 7종 존재, `ageRange` ⊂ 0~이 시대 최대 나이, `variants[].when`이 `meetsCondition` 입력으로 유효, `citation`이 `citations.json`에 있고 `verified`·`usable`, `noCitation` 코드 유효, lint(1-1 R7·1-2 S1~S4), `{이름}` 뒤 조사가 허용 목록, 문장 길이.

1. 카드 정의에 `noCitation`(D 또는 X1)을 적고 시트에 **인용 박스 요소를 만들지 않는다**(빈 박스·자리표시 문구 0). 시트는 인용이 없으면 질문과 입력란이 바로 이어진다.
2. 시트 높이가 인용 유무에 따라 달라지는 것은 정상이다(M7b와 같다). 가상 키보드 compact 상태는 인용 박스를 숨기므로 유무에 상관없이 같은 높이가 된다(6절).
3. 약한 인용으로 비율을 채우지 않는다. 못 구한 자료는 D로 확정한다.

| 단위(UTF-16) | 400 = `HISTORY_LIMITS.maxTextLength` | 그래핌만으로는 저장 크기가 안 막힌다. 400이면 `clipEntry`가 note 행을 자르지 않는다. 가족 그림 문자(8단위)로만 채우면 50개, 깃발(4단위)은 100개까지 |
| 그래핌당 코드 포인트 | 비이모지 8 · 이모지 시퀀스 12 | 결합 문자 범람(글자 위로 쌓이는 장식)과 줄 높이 침범을 막는다. 실제 이모지 시퀀스는 최대 11(4인 가족 + 피부색) |
| 줄 | **3줄**(줄바꿈 문자 2개) | NC-3. 4번째 줄부터는 앞 줄 끝에 공백 하나로 이어 붙인다 |
| 읽는 양 | 입력의 **앞 20,000단위**만 읽는다 | 1MB 붙여넣기가 화면을 멈추지 않게. 나머지는 버린다 |
| 화면 입력란 `maxLength` | 4000 (**안전망일 뿐 화면의 한도가 아니다**) | 브라우저의 `maxlength`는 그래핌이 아니라 단위로 세고 IME 조합 중에 글자를 자른다. 시안(note.html)의 `maxlength="140"`은 구현에 옮기지 않는다 |
| 전체 | 한 인생의 note 행 ≤ 40 | FR5 (자동 카드 최대 7 + 수동 기록) |

### 3-2. 정규화 파이프라인 `finalizeNote(raw)` (제출·저장 시)

순수 함수. 결과는 `{ text, graphemes, truncated, empty }`. 같은 입력 → 같은 출력, **멱등**(`finalizeNote(finalizeNote(x).text).text`가 같다).

1. **읽는 양 제한**: 앞 20,000단위만 취한다(끝이 서러게이트 쌍 중간이면 홀로 남은 앞쪽을 버린다). 넘겼으면 `truncated`.
2. **NFC 정규화**(NFKC가 아니다 — 전각·기호의 뜻이 바뀌므로). 분리된 한글 자모(U+1100대 초성·중성·종성)가 음절로 합쳐진다. 호환 자모(ㅎ U+314E 등)는 합쳐지지 않고 그대로다.
3. **그래핌 분할**(`Intl.Segmenter`, 없으면 3-5절 대체 경로) 뒤 **그래핌마다**:
   - 유효한 **이모지 시퀀스**(3-4절)이면 코드 포인트 12개 이하일 때 그대로 둔다.
   - 아니면 3-3절 처분표로 글자를 걸러 낸다. 비이모지 그래핌이 코드 포인트 8개를 넘으면 뒤의 결합 문자부터 버린다.
4. **줄바꿈 통일**: 모든 줄 구분(`\r\n`·`\r`·U+0085·U+2028·U+2029·`\v`·`\f`)을 `\n` 하나로.
5. **공백 정규화**: 모든 가로 공백류(3-3)를 U+0020으로, 줄마다 앞뒤 공백 제거 + 안쪽 연속 공백을 1개로, 빈 줄 제거(연속 줄바꿈 → 1개), 글 전체 앞뒤 줄바꿈 제거.
6. **줄 수**: 3줄을 넘으면 4번째 줄부터를 3번째 줄 끝에 공백 하나로 잇는다.
7. **상한 자르기**: 그래핌 140개를 넘으면 140번째에서 자르고, 이어서 단위 400을 넘으면 그래핌 단위로 더 줄인다. 자를 때는 그래핌 경계에서만 자르므로 이모지 시퀀스가 중간에서 끊기지 않는다. 자르면 `truncated`.
8. **빈 입력 판정**: 결과가 빈 문자열이면 `empty`(공백만·보이지 않는 글자만·제어 문자만 포함). 쉼표·마침표만 있는 글은 빈 입력이 **아니다**(보이는 표현이다).

**실시간 입력 `sanitizeLive(raw)`** (입력란 `onChange`): 위 1·2·3(걸러 내기)·4·상한 자르기(줄 3 · 그래핌 140 · 단위 400)만 하고, **앞뒤 공백 제거와 공백 접기는 하지 않는다.** 입력 중 공백을 지우면 낱말 사이에 띄어쓰기를 칠 수 없다. 4번째 줄을 만드는 Enter는 무시한다. `finalizeNote(sanitizeLive(x))` = `finalizeNote(x)`가 성립해야 한다(시험).

**글자 수 표시**는 `sanitizeLive` 결과의 그래핌 수다(제출 시 공백 정리로 줄어들 수 있다 — 보수적인 쪽).

### 3-4. 이모지를 깨지 않는 규칙

「제어 문자·제로폭 문자 제거」는 **글자 단위가 아니라 그래핌 단위**로 판정한다. 그래핌이 아래 넷 중 하나로 **통째로** 맞으면 그 안의 ZWJ·변이 선택자·태그 문자·피부색 수식어는 그대로 둔다.

| 종류 | 모양 | 예(코드 포인트) |
|---|---|---|
| 그림 문자 시퀀스 | 그림 문자 + (U+FE0E/FE0F) + (피부색 U+1F3FB~1F3FF) 를 U+200D로 이은 열 | 가족 U+1F468 U+200D U+1F469 U+200D U+1F467 · 악수 U+1F44D U+1F3FD |
| 깃발 | 지역 표시 글자 2개(U+1F1E6~1F1FF) | 대한민국 U+1F1F0 U+1F1F7 |
| 키캡 | [0-9#*] + (U+FE0F) + U+20E3 | 숫자 1 키캡 |
| 하위 지역 깃발 | U+1F3F4 + 태그 문자(U+E0020~E007E)들 + U+E007F | 잉글랜드 등 |

- 맞지 않는 그래핌(예: 글자 뒤에 붙은 ZWJ, 홀로 있는 ZWJ, 끝에 ZWJ가 매달린 그림 문자 U+1F468 U+200D)은 3-3 처분표대로 걸러진다 — 끝에 매달린 ZWJ만 지워지고 그림 문자는 남는다.
- 지역 표시 글자가 **홀수 개**(깃발이 반쪽)이면 홀로 남은 글자는 그림 문자로 보여 유지한다(보이는 글자이다).
- 그래핌 하나가 1로 센다. 4인 가족은 1글자이고 140자 한도에 그대로 센다.
- 브라우저가 새 이모지를 모르면 `Intl.Segmenter`가 둘로 나눌 수 있다. 그 경우 글자 수가 약간 달라질 뿐이고, **저장된 글을 다시 불러올 때는 길이를 다시 자르지 않는다**(3-6절 H4).

### 3-5. IME·붙여넣기·초장문

| 상황 | 규칙 |
|---|---|
| IME 조합 중(`compositionstart`~`compositionend`) | 입력란 값을 **다시 쓰지 않는다**(React 제어 컴포넌트가 값을 바꾸면 한글 조합이 깨진다). 글자 수 표시는 조합이 끝나면 갱신하고, 상한 초과는 `compositionend`에서 한 번에 자른다 |
| 조합 중 「적어두고 살기」 탭 | 제출은 한 박자(`setTimeout 0`) 뒤 DOM의 값을 읽어 마지막 글자가 빠지지 않게 한다. 조합 상태에서도 클릭 핸들러가 `isComposing`을 확인한다 |
| Esc | `event.isComposing`이면 무시한다(조합 취소가 시트 닫기로 이어지지 않게) |
| 붙여넣기·끌어다 놓기 | `onChange`가 받은 전체 값에 `sanitizeLive`를 적용한다. 한도를 넘으면 자르고 입력란 아래 알림(`role="status"`)을 띄운다 |
| 1MB 붙여넣기 | 브라우저가 `maxLength=4000`에서 자르고, 우리 쪽은 앞 20,000단위만 읽는다. 처리 중 화면이 멈추지 않는다(시험은 입력 읽은 양 ≤ 20,000을 단언하고 시간은 보고만) |
| `Intl.Segmenter` 없음 | 코드 포인트 단위로 세고 ZWJ·변이 선택자·태그 문자를 모두 지운다(이모지 시퀀스가 흩어지지만 안전하고 한도는 더 보수적). 시험은 `Intl.Segmenter`를 지운 환경으로도 돈다 |
| 캐럿 | 정규화로 값이 바뀌지 않은 입력에서는 캐럿이 끝으로 튀지 않는다. 값이 바뀐 경우(잘림·삭제)만 바뀐 위치 뒤로 보정 |

### 3-6. 저장 검증 `hasHiddenControl`과의 관계 (충돌 정리)

**현재 사용처(모두 게임이 만든 글)**: 이름(`validCharacter`), 연표 `text`·`title`·`choice`(`cleanText`·`optString`), 사망 원인(`cleanText`). 사용자가 직접 칠 수 있는 글은 지금까지 없었다.

**결정 규칙** (마스터 방침: 사용자 글에는 거부를 재사용하지 않는다)

| # | 규칙 |
|---|---|
| H1 | **`hasHiddenControl`·`cleanText`·`optString`을 note 행의 `text`에 적용하지 않는다.** `validHistoryEntry`가 `kind === 'note'`를 갈라 note 전용 검사로 보낸다. 규칙 자체(범위·함수)는 바꾸지 않는다 — 게임이 만든 글(이름·사건·사망 원인)에는 그대로다 |
| H2 | note 행의 `title`(주제)과 `eventId`(카드 id)는 **게임이 만든 글**이라 기존 검사를 그대로 받는다(카드 id는 ASCII, 주제는 `notes.json`) |
| H3 | **로드 때는 거부하지 않고 복구한다.** note 행의 `text`가 **문자열이 아니면** 모양 위반으로 손상(저장 전체 새 게임, 나머지 필드와 같은 규칙). 문자열이면 `cleanNoteForLoad`로 **위험한 글자만 걷는다**(3-3 처분표의 제어·방향·제로폭·서러게이트·개인 사용 영역, 이모지 안의 ZWJ는 유지). 걷고 나서 비면 그 행만 버린다. 20,000단위를 넘는 변조 값은 그래핌 경계에서 자른다 |
| H4 | 로드 때 **그래핌 140·단위 400·줄 3은 다시 적용하지 않는다.** 기기·브라우저마다 그래핌 셈이 다를 수 있어(새 이모지 등) 정상 기록이 잘리는 일을 막는다. 상한은 쓰는 순간(`finalizeNote`)에만 지킨다 |
| H5 | 방어는 세 겹이다: ① 입력 단계에서 제거(3-2) ② 표시 단계에서 격리(`<bdi>` + `unicode-bidi: isolate`, 4절) ③ 로드 단계에서 복구(H3). 하나가 뚫려도 UI 순서 뒤집기·저장 거부는 일어나지 않는다 |
| H6 | **시험**: (a) 가족 그림 문자·깃발·피부색·결합 문자·RTL 글을 담은 note 행이 저장→`parseGame`→같은 글 (b) 같은 가족 그림 문자를 **이름**에 넣은 저장은 여전히 null (c) note 행에 RLO(U+202E)를 직접 심은 저장은 null이 아니고 RLO만 없는 글 (d) `text`가 숫자인 note 행은 null (e) 20,000단위 초과 변조 값이 null이 아니고 잘린 글 (f) 이름·사망 원인·연표 글(non-note)의 숨은 문자 거부는 지금처럼 null |

### 3-7. 사용자 글을 어디에 저장하는가 · 스키마 · 호환 (NC-1 추천안)

### 4-2. 개인정보 (FR5·FR8)

**안내 문장의 뜻** (입력란 아래, 카드 안 문구라 합쇼체; 최종 문구는 designer — 현재 `copy.md` 80행의 「실명·연락처 같은 개인정보는 적지 마십시오. 이 기기에만 저장됩니다.」 유지):

1. 실명·연락처·주소·계정 같은 **개인정보를 적지 않는다.**
2. 적은 글은 **이 브라우저(기기)에만** 저장되고 서버로 가지 않는다.

권장(결정 불필요, designer 판단): 새 인생을 시작하면 지워진다는 뜻은 기존 안내(첫 화면 확인 단계의 「이전 판이 사라집니다」, 엔딩의 `REBIRTH_NOTE` 「다시 태어나면 이 인생의 기록은 사라집니다.」)가 이미 지고 있다. 그 위에 한 줄을 더 얹지 않는다.

**기술 보증**

| # | 보증 | 시험 |
|---|---|---|
| P1 | 서버·외부로 가지 않는다. 입력·저장·표시 중 외부 도메인 요청 0건(CM3) | Playwright 요청 감시 |
| P2 | 의견 보내기 주소에 글이 없다. `buildFeedbackUrl`은 이미 허용 목록(빌드 버전·화면·세상·인생 길이)뿐이다. **회귀 시험**: 상태에 note 행(특수문자·긴 글·그림 문자)이 있어도 주소에 글의 어떤 조각도 없다 | `tests/feedbackUrl.test.ts` 확장 |

## 5. 동작 (FR5~FR7 · FR9 · DB5)

### 5-1. 한 시트, 두 진입 경로

자동 카드와 「생각 남기기」 버튼은 **같은 시트 컴포넌트**(`NoteSheet`)다. 틀·입력 규칙·두 버튼·확인 단계·접근성·저장이 모두 같고 아래만 다르다.

| | 자동 카드 | 「생각 남기기」 수동 |
|---|---|---|
| 여는 것 | 시스템(적격 판정, 파생 상태) | 사용자(도구 줄 버튼, App 수준 UI 상태) |
| 질문 | 카드 질문(1-4절) | 고정 질문 「지금 {이름}에게 마음에 남아 있는 장면이나 생각이 있습니까?」 |
| 인용 | 카드에 있으면 | 없음 |
| 연표 줄 | 라벨 = 카드 주제, `eventId` = 카드 id | 라벨 = 「지금의 생각」 ▲, `eventId` = `note-manual` |
| 2번(담아 두기) | 카드 소비(`seen` 표시, 다시 안 뜬다) | 그냥 닫힘 |
| 닫은 뒤 포커스 | 인생 화면 제목 | 「생각 남기기」 버튼 |
| 새로고침 | 같은 카드가 다시 뜬다(적격이 유지되므로), 입력한 글은 사라진다 | 닫힌다, 글은 사라진다 |
| 자동 모드 | 뜨지 않는다(소비) | 자동 모드에서도 연다 |
| 한 해 안 횟수 | 1 | 제한 없음(전체 상한 40만) |

### 5-2. 시트의 상태 흐름

```
열림 ─ 입력 ─┬─ 「적어두고 살기」 ─ 빈 입력 → 안내(카드 열린 채, 포커스 입력란)
             │                  └ 글 있음 → 저장(연표 줄 + 소비 표시) → 닫힘
             ├─ 「마음속에 담고 살기」 ─ 글 없음 → 닫힘(자동 카드는 소비)
             │                        └ 글 있음 → 확인 1번 ─ 「돌아가서 이어 쓰기」 → 입력(글 유지)
             │                                             └ 「글을 지우고 담아 두기」 → 닫힘(저장 없음)
             ├─ Esc ─ 「마음속에 담고 살기」와 같다(글이 있으면 같은 확인), IME 조합 중에는 무시
             └─ 「자동 기록 카드 끄기/켜기」 ─ 설정만 바꾸고 시트는 그대로 열려 있다
```

- 확인 단계의 버튼 이름은 방금 누른 「마음속에 담고 살기」와 달라야 하고 결과가 드러나야 한다(QM2-6 규칙). 이름·안내 문구는 designer가 정하며, 안내는 SPEC 인용문 「적은 글은 저장되지 않습니다」의 뜻을 유지한다. **안전한 쪽(돌아가서 이어 쓰기)이 먼저 포커스를 받고 기본 버튼**이다. 확인이 열린 동안 입력란은 읽기 전용이고 글은 그대로 보인다.
- 1번 빈 입력 안내는 `aria-invalid` + 입력란 `aria-describedby`로 연결하고 포커스를 입력란으로 돌려준다(키보드가 내려가지 않게).
- 확인 단계를 거치지 않는 2번은 글이 없을 때뿐이다.
- 제출 멱등: 수동 기록은 열 때의 note 행 수(`expectCount`)를 들고 가서, 이미 늘어난 상태면 두 번째 제출을 무시한다(연타·더블탭 → 1건). 자동 카드는 적격이 사라지면(소비됨) 무시된다.

### 5-3. 정지와 시간 목표 (LM5)

- 시트(자동·수동)가 열린 동안: 연출 시계(`useYearClock`)·자동 선택 타이머(`autoChooseArmed`에 `noteOpen` 조건 추가)·`advance`·`skip`이 멈춘다. 열기 전의 `paused`는 건드리지 않는다 — 닫으면 이전 상태로 돌아간다(DB5). 일시정지 중에도 수동 기록을 열 수 있다.
- **`noteOpen`은 App 수준 한 곳**(M7b U10 상태 옆)에 둔다. M8의 플레이 시간 타이머(LM6)가 같은 값을 읽어 카드 열람 시간을 시간 목표에서 뺀다(LM5). M7c는 값을 내놓고 정지를 시험한다. 플레이 시간 표시·집계는 M8이다.
- **시계 되감김 버그 방지**: `useYearClock`의 `resetKey`(App.tsx:255)에서 `history.length` 대신 note 행을 뺀 줄 수를 쓴다. 수동 기록이 진행률을 0으로 되돌리지 않는다(시험: 진행률 50%에서 기록 저장 → 진행률 유지).
- 자동 카드는 해의 **첫머리**에 뜨므로 진행률은 0%에서 멈춰 있고, 닫으면 그 해가 처음부터 채워진다.
- 사용자가 `showTitle`(나가기)로 나가 있거나 `superseded`이면 시트를 그리지 않는다. 돌아오면 적격이 유지되어 다시 뜬다.

### 5-4. 두 시트의 우선순위 · 동시 열림 금지 (M7b U10)

| 상황 | 결과 |
|---|---|
| 자동 카드가 적격인 해의 결정 카드 | 기록 카드가 **먼저**. 닫으면 연출 시계가 해를 채우고 해의 끝에 결정 카드가 (뽑히면) 뜬다. 동시 열림 없음 |
| 결정을 고른 직후 다음 해의 기록 카드 | 결정 시트가 닫히고 곧바로 기록 시트가 뜬다. 새 시트의 버튼에는 입력 가드 400ms가 걸려 더블탭의 둘째 입력이 떨어지지 않는다. 포커스는 기록 시트 질문 제목이 이긴다(`choiceResolved`보다 나중) |
| 수동 모드 + 결정 시트 열림 + 도구 줄 | 도구 줄이 `inert`라 「생각 남기기」를 누를 수 없다 |
| 수동 모드 + 결정 **접힌 띠** + 「생각 남기기」 | 기록 시트가 열린다. 결정 카드는 접힌 채 그대로이고 닫아도 저절로 다시 열리지 않는다. 포커스는 「생각 남기기」 버튼으로 |
| 자동 모드 + 결정 인라인 카드 + 「생각 남기기」 | 기록 시트(모달)가 열린다. 자동 선택 타이머는 멈추고 닫으면 `AUTO_CHOICE_MS`부터 다시 센다(접기와 같은 규칙). 인라인 카드는 그대로 |
| 기록 시트가 열린 채 자동 모드가 켜지는 경로 | 없다(도구 줄 `inert`) |
| 나가기 확인 단계가 열린 채 「생각 남기기」 | 확인 단계를 닫고 시트를 연다 |
| 기록 시트가 열린 채 탭 가림 | 그대로 유지(시계는 어차피 멈춰 있다) |
| 기록 시트가 열린 채 다른 탭이 저장을 바꿈 | 기존 「밀린 화면」(R-011) |
| 일시정지 중 | 수동 기록 가능, 닫아도 일시정지 유지 |

### 5-5. 40개 상한 · 저장 실패

- 기록(note 행) 40개 도달 뒤에 「생각 남기기」를 열면 시트는 입력란 대신 안내(「이 인생에서 남길 수 있는 기록은 40개까지입니다.」 ▲)와 닫기 버튼만 보인다. 자동 카드는 7장이라 이 한도에 닿지 않는다. 연타해도 41번째 줄은 생기지 않는다(reducer가 막는다).
- **저장 실패(쿼터)** (FR5): 기록은 reducer로 메모리 상태에 들어가 인생 기록에 그대로 보이고 입력 내용을 지우지 않는다. 저장 effect가 실패하면 기존 배너(「저장하지 못했습니다. 이 화면을 닫으면 진행이 사라질 수 있습니다.」, `save-notice`)가 뜬다. 이 배너가 기록 카드에 특화된 별도 안내를 대신한다(NC-11, 대안은 「저장해 보고 닫기」).

### 5-6. 「다음부터 띄우지 않기」와 자동 모드 (FR7 [가정] 두 항목)

**설정**: `Settings.noteCards`(기본 true, 설정 키에 저장, 새 인생으로 넘어가도 유지).

**시트 아래 한 칸**(자동·수동 시트 모두): 버튼 이름이 **하는 일**을 말한다 — 켜져 있으면 「자동 기록 카드 끄기」, 꺼져 있으면 「자동 기록 카드 켜기」(`aria-pressed`를 쓰지 않는다 — 이름이 상태를 전한다, 일시정지 버튼과 같은 방식). 누르면 설정만 바뀌고 **시트와 입력 중인 글은 그대로**이며(글이 사라질 위험 0) 알림이 한 줄 나온다(「이제 기록 카드가 저절로 뜨지 않습니다. 생각 남기기 버튼으로는 언제든 적을 수 있습니다.」 / 「기록 카드가 다시 뜹니다.」 ▲, 최종 문구는 designer). 이름의 「자동」이 **자동 모드**와 헷갈리지 않는지 designer가 확인한다.

**다시 켜는 길**: 꺼진 뒤에도 「생각 남기기」 버튼은 늘 있고, 거기서 연 시트 아래 같은 자리가 「켜기」로 바뀐다. 별도 설정 화면은 만들지 않는다.

**효과 범위**: 자동 카드만. 「생각 남기기」 버튼은 영향 없음.

**꺼져 있거나 자동 모드인 동안 적격이 된 카드**: 시트 없이 **소비**한다(`seen` 표시). 나중에 켜도 이미 지나간 카드는 돌아오지 않고 이후 카드부터 뜬다 — 규칙이 한 줄이고 예측 가능하다. 소비는 간격(R3)에는 센다.

### 5-7. 엔딩 · 다시 태어나기 (FR9)

- 엔딩 연표(`buildTimeline`)는 이미 모든 줄을 단계별로 묶으므로 note 행이 시간순으로 함께 나온다(Q5). `TimelineItem`은 `kind === 'note'`일 때 라벨 「나의 기록 · {주제}」 + `NoteText`로 그린다. 연표 줄 수 상한(300)·기록 상한(40) 안이다.
- `REBIRTH_NOTE` 「다시 태어나면 이 인생의 기록은 사라집니다.」는 **그대로** 쓴다(새 문구를 쓰지 않는다 — 문구 기준 85행).
- 시험: `rebirth` 뒤 `localStorage`의 게임 키에 이전 판 글이 없음, 엔딩 새로고침 때 연표에 note 줄이 보임.

### 5-8. 새로고침 · 탭 닫기 · 입력 초안 (NC-8)

| 상황 | 결과 |
|---|---|
| 자동 카드 시트 + 새로고침 | 같은 카드가 다시 뜬다(적격 유지). **입력 중이던 글은 사라진다** |
| 수동 시트 + 새로고침 | 시트가 닫힌다. 글은 사라진다. 열기 전의 `paused`는 저장된 대로 |
| 탭 닫기 · 뒤로가기(사이트를 벗어남) | 글은 사라진다. 경고창(`beforeunload`)은 띄우지 않는다 |
| 1번을 누른 직후 닫기 | 이미 상태에 들어가 있고 `pagehide` 저장(App.tsx:221~247)이 마지막 상태를 한 번 더 쓴다 |
| 두 탭에서 동시에 열기 | 한 쪽이 저장하면 다른 쪽은 기존 「밀린 화면」 |

**추천**: 입력 초안을 어디에도 저장하지 않는다. 이유는 (1) 2번의 보조 설명이 「아무것도 저장하지 않고 넘어갑니다」인데 초안 보존은 사용자가 남기지 않기로 한 글을 남기게 되고 (2) 초안이 `sessionStorage`에 있는 것도 FR8의 「이 기기에만 저장」을 흐리고 (3) 140자 글이라 다시 쓰는 비용이 작고 (4) 모바일 탭 폐기로 잃는 경우는 형진 님 보고를 받고 정해도 늦지 않다. 대안은 `sessionStorage` 초안(열림 동안만, 닫기·저장·새 인생 때 삭제).

### 5-9. 포커스 규칙 (R-036) — 48칸 표는 그대로, 기록 시트용 작은 표를 따로

`decideLifeFocus`의 8순간 × 2 × 3 = 48칸 기대값은 **하나도 바꾸지 않는다.** 이유: 기록 시트의 포커스는 모달이라 「포커스가 어디 있었든」 같은 곳으로 가고(규칙 2와 같은 근거), 닫을 때의 대상만 **여는 길**에 달려 있어 `(순간 × 자동 × 위치)` 표에 끼우면 한 축이 어색하다. 별도 순수 함수 `decideNoteFocus(moment, via)`와 작은 표(5 × 2 = 10칸)를 만든다.

| 순간 | `via` = 자동 카드 | `via` = 「생각 남기기」 버튼 |
|---|---|---|
| `opened` (시트가 막 열림) | 질문 제목(h2, `tabindex=-1`) — 입력란이 아니다(모바일에서 키보드가 질문을 가리지 않게) | 같음 |
| `emptyError` (빈 입력 1번) | 입력란 | 입력란 |
| `confirmOpened` | 「돌아가서 이어 쓰기」 | 같음 |
| `confirmBack` | 입력란(캐럿은 글 끝) | 같음 |
| `closed` (저장·담아 두기·Esc) | 인생 화면 제목(`preventScroll`) | 「생각 남기기」 버튼 |

- 같은 커밋에서 `choiceResolved`와 `opened`가 겹치면(5-4절 둘째 행) **`opened`가 이긴다**(훅의 효과 순서). 시험.
- `closed` 뒤 결정 카드가 이어서 뜨면 기존 `choiceAppeared` 규칙이 그 뒤 순서로 동작한다.
- 포커스 이동 뒤의 스크롤은 모달이라 문서를 건드리지 않는다(`preventScroll`, M7b와 같다).

## 6. 접근성 · 모바일

### 6-1. 가상 키보드 (QM2-1 (g) — 입력란과 두 버튼이 보인다)

**원인**: ① 시트가 `94dvh` 아래 정렬이라 키보드가 시트 아래쪽(버튼)을 덮는다. iOS Safari는 키보드가 올라와도 레이아웃 뷰포트가 줄지 않고 `visualViewport`만 줄어든다. Android Chrome 기본(`resizes-visual`)도 같다. ② `dvh`는 주소창 변화만 반영하고 키보드는 반영하지 않는다. ③ 입력란 글자 < 16px이면 iOS가 확대한다.

**기준** (▲ 값은 designer·QA가 실기기로 확인)

| # | 기준 |
|---|---|
| K1 | 시트가 열려 있는 동안 `window.visualViewport`의 `resize`·`scroll`을 듣고 `--vv-h`(높이)·`--vv-top`(`offsetTop`)을 시트 바탕(`.overlay`)에 건다. 바탕은 `top: var(--vv-top); height: var(--vv-h)`로 **보이는 영역**에 맞고 시트 `max-height`는 그 안에서 정해진다(`visualViewport` 없으면 `dvh`로 물러남) |
| K2 | **compact 상태**: 입력란에 포커스가 있고 `visualViewport.height < 520px`(▲)이면 인용 박스·두 버튼의 보조 설명을 숨겨 높이를 줄인다(포커스를 잃으면 돌아온다). 개인정보 안내·글자 수·오류 안내는 숨기지 않는다 |
| K3 | **보장**: `visualViewport.height ≥ 340px`(▲)일 때 입력란 전체와 「적어두고 살기」·「마음속에 담고 살기」 **두 버튼이 모두 보이는 영역 안**(`offsetTop`~`offsetTop + height`)에 있다. 그보다 낮으면(가로 모드 등) 포커스를 가진 입력란은 늘 보이고 두 버튼은 시트 안 스크롤로 닿는다 |
| K4 | 입력란 포커스 때 `scrollIntoView({ block: 'nearest' })`로 입력란을 보이는 영역에 둔다. 문서(바탕)는 스크롤 잠금(7-1절)이라 움직이지 않는다 |
| K5 | 입력란 글자 크기 계산값 ≥ 16px |
| K6 | 키보드가 내려가면(포커스 해제·`visualViewport` 복귀) compact가 풀리고 시트가 원래 높이로 돌아온다 |
| K7 | 글자 200%·폭 320처럼 K3가 물리적으로 불가능한 조합은 위 K3 후반(스크롤로 닿음)이 기준이다 |

**시험 방법**: Playwright는 실제 가상 키보드를 띄우지 못한다. `page.addInitScript`로 `window.visualViewport`를 높이·`offsetTop`을 바꿀 수 있는 가짜(`EventTarget`)로 바꾸고 `resize`를 일으켜 K1~K6을 단언한다(높이 300 · 340 · 400 · 520, 폭 360·320, 글자 100·200%). **실기기(iPhone Safari 16+, Android Chrome)에서 형진 님·QA가 한 번 확인**하는 것을 완료 기준에 넣는다.

### 7-4. 완료 기준

**기능**

1. **카드 스케줄**: 세 시대 × 1000판(`dueNote`를 소비 모드로 돌린 시뮬레이션)에서 판당 자동 카드 ≤ 7 · 같은 종류 ≤ 1 · 한 해 ≤ 1장 · 간격 ≥ 2년 · 창 밖 0장 · 에러 0. 사망 나이 70세 이상 판의 평균 카드 수와 종류별 도달률을 **보고**한다(기획자 추정: 평균 6.0~7.0 ▲ — 못 맞으면 마스터가 NC-4로).
2. **인생 불변**: 같은 시드·같은 선택에서 (a) 카드를 모두 쓴 판 (b) 모두 건너뛴 판 (c) 자동 모드 판 (d) `noteCards` 꺼진 판의 `stats`·`assets`·`flags`·`seen`(note- 키 제외)·`rngState`·`history`(note 행 제외)가 모두 같다(세 시대 × 200판).
3. **시트**: 질문·인용(있을 때만)·입력란·개인정보 안내·글자 수·「1. 적어두고 살기」·「2. 마음속에 담고 살기」·끄기/켜기 칸이 보이고, 열린 동안 나이·진행률·자동 선택이 3초 동안 변하지 않는다.
4. **1번**: 빈 입력은 기록 0·카드 열린 채·안내·포커스 입력란. 정상 입력은 연표 note 행 1줄, 시트 닫힘, 인생 기록 맨 아래 「나의 기록」 줄. 연타·더블탭은 1건.
5. **2번**: 글이 없으면 저장 없이 닫힘(자동 카드는 소비). 글이 있으면 확인 1번 → 「돌아가서 이어 쓰기」는 글 유지, 확정은 저장 없이 닫힘. Esc는 2번과 같다.
6. **입력 규칙**: 3-8절 A1~A20이 모두 기대대로이고 `finalizeNote`가 멱등이며 `Intl.Segmenter` 없이도 안전하다.
7. **저장·복원**: note 행(그림 문자·깃발·결합 문자·RTL 포함)이 저장→새로고침 뒤 같은 글. 이름에 숨은 문자는 여전히 null(H6). v8 옛 저장이 그대로 이어진다. 설정 v3이 읽히고 `noteCards` 기본 true.
8. **자동 모드·끄기**: 자동 모드 켜짐 또는 `noteCards` 꺼짐에서는 시트가 뜨지 않고 카드가 소비되며 연표에 줄이 없다. 켠 뒤에는 이후 카드부터 뜬다.
9. **수동 기록**: 열면 정지, 닫으면 이전 `paused`를 유지한 채 재개(시계 되감김 0). 40개 도달 뒤 41번째 줄은 생기지 않는다. 5-4절 표의 모든 행이 동작한다.
10. **엔딩·삭제**: 엔딩 연표에 「나의 기록」 줄이 시간순으로 나오고, 「다시 태어나기」 뒤 이전 판 글이 `localStorage`에 없다. 엔딩 새로고침에서 연표가 같다.
11. **개인정보**: 의견 보내기 주소에 글 0(`feedbackUrl` 회귀), 외부 도메인 요청 0건, 오류 메시지·`console`에 글 0, 글이 설정 키·`sessionStorage`·속성·`document.title`에 복사되지 않음(P1~P5).
12. **인용**: ①만 인용 박스가 있고 나머지에는 빈 박스가 없다(세 시대 표시 문자열 ≤ 100자). `usedBy`·`candidateFor`가 `note-…` id와 일치. 기록 카드 인용은 MD2 판정 분모·분자에 없다.
13. **착수 작업**: T1~T4 판정(7-1절)이 모두 통과한다.

**공통 접근성 · 모바일**: 6-4절 표의 16①③⑤⑩·17①②③⑤를 자기 화면에서 통과. 6-1절 K1~K7은 가짜 `visualViewport` e2e로, 실기기 한 판(iPhone Safari · Android Chrome)은 완료 기준에 넣는다.

### 11-5. K03 — 확인 복귀 직후 Enter

- 사실: 「돌아가서 이어 쓰기」를 누르면 확인 단계가 사라지고 1번·2번이 **새 요소로 다시 만들어져** 마운트 가드 400ms가 걸립니다. 포커스는 이미 입력란(`decideNoteFocus('confirmBack')`)으로 가므로 곧바로 Enter를 치면 입력란의 줄바꿈입니다. QA가 본 것은 300ms 뒤 Tab으로 1번에 닿아 Enter를 친 경우입니다.
- 이 가드는 필요합니다. 확인 단계의 버튼들이 있던 자리에 1번·2번이 다시 나타나므로, 「돌아가서 이어 쓰기」 더블탭의 둘째 탭이 새로 나타난 1번(저장)이나 2번에 떨어지는 길을 막는 장치입니다(11-1과 같은 부류).
- **결정(D4 추천): 그대로 둡니다.** 가드 중 눌림에 안내를 다는 것은 가드 버튼 전체(약 30곳)에 같은 규칙이 필요해 G5·G6(안내 없음)과 어긋납니다. 「입력란으로 포커스를 돌려 줄바꿈이 되게」는 이미 그렇게 동작합니다.
- 시험(r2-11): 돌아가기 직후 포커스가 입력란이고 Enter가 줄바꿈이 됨(3줄 한도 안에서), 돌아가기 후 450ms 뒤 Tab → 1번 Enter는 저장됨, 돌아가기 직후 400ms 안의 1번 눌림은 저장 0(기존 동작 고정).

### 11-7. R-411 정합 — 기록 40개면 자동 카드를 시트 없이 소비

- **규칙 한 곳**: 설정이 정하는 처리(`noteResponse`)가 기록 수도 봐서 `autoMode`이거나 `noteCards`가 꺼졌거나 기록이 `NOTE_LIMITS.total`(40) 이상이면 `consume`입니다. reducer의 `advance`·`skip`·`autoChoose` 경로와 `App`의 `autoNote` 파생 판정이 같은 함수를 부릅니다. 소비는 `seen`에만 남기고 연표 줄은 없으며(마음속에 담고 살기와 같음), 스탯·플래그·`rngState`를 바꾸지 않습니다.
- 정오표:

| 위치 | 현재 | 정정 |

| 5-5절 첫 불릿 | 「…자동 카드는 7장이라 이 한도에 닿지 않는다.」 | 「자동 카드는 이 한도에서 시트 없이 소비된다(11-7). 이 안내 시트는 「생각 남기기」 버튼으로 열 때만 보인다.」 |
