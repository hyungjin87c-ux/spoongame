## 0. 한 화면 요약

1. **조르기 사건 = 선택 필드 `ask`가 있는 사건**이다. 새 사건 9개(장난감·게임기 4 · 예체능·배움 3 · 강아지 2), 모두 `once`·`track: common`, 나이 4~12(`toy`는 4~12, `lessons`·`pet`은 5~12). 영역 표지 `ask` 하나만 가지며 결정자 규칙 **R1a**(R1 바로 뒤 — 영역에 `ask`가 있으면 나이와 무관하게 본인)가 사람이 고르는 카드로 만든다(1절).
2. **들어줄 확률**은 `clamp(BASE[종류][재력] + 0.06 × (C − 3) + (떼쓰기 ? 0.10 : 0), 0.05, 0.95)`. 입력은 재력 단계·사이 `C`·종류·선택 네 가지뿐이다. 값은 전부 ▲ 설계값이고 근거가 되는 통계가 저장소에 없다(2절).
3. **난수는 진행 RNG를 쓰지 않는 해시**: `famHash01(가족 시드, FAMILY_TAG.ASK=20, 종류 번호, 나이×2+칸)`. 같은 판·같은 카드는 같은 값이고, 조르기와 떼쓰기가 `u1`을 공유해 「조른다가 들어줌이면 떼쓰기도 들어줌」이 성립한다(2-3).
4. **효과**는 5갈래 표(들어줌 3종 · 거절 · 사이 나빠짐 · 참기) 하나가 정한다. 기대 행복 손계산으로 어느 칸에서도 한 선택지가 지배하지 않고(참기 우위 2칸, 떼쓰기 우위 9칸, 나머지 조르기), 자동 성향 선택 비율은 어느 칸에서도 약 42% 아래다(3절).
5. **떼쓰기 사이 비용**: 거절당한 떼쓰기만 `s(C) = clamp(0.50 + 0.10 × (3 − C), 0.20, 0.80)`로 사이 −1단계(평생). 플래그 이름은 **`parent_strained` 추천**(상태형, 세 안 비교 — 4절). 배포 뒤 바꾸면 One-way다.
6. **한 종류 최대 1장**은 새 저장 이름 없이 푼다 — 이벤트 풀이 만드는 파생 필드 `askPeers`(같은 종류의 다른 사건 id)를 `isEventEligible`이 `seen`으로 본다. 그래서 One-way 이름은 `parent_strained` 하나다(1-4).
7. **노출 손계산**: 사건 가중 토이 45 · 배움 40 · 강아지 30 ▲로 판당 평균 **약 1.9장**, 4~12세에 1장 이상 나온 판 **약 95%**(목표 1.5~2.5장·80%). 결정 칸은 구조 변화 없이 **가중으로만** 나눠 쓴다(5-1).
8. **판 길이**: 조르기 몫 약 +0.44분, FM7b 몫(SPEC 5절) +0.8분 이상을 합치면 평균 약 35.9분으로 임계 35분을 넘을 수 있다 — 결정 Q1 절차(내용은 줄이지 않고 실측 보고)대로다(5-2).
9. **K6**: 「같은 시드는 같은 어린 시절(13세 전)」은 **「첫 조르기 카드 전까지(빠르면 4세)」**로 개정한다. 개정 문장과 고칠 곳 9군데를 6절에 적었다.
10. **DS1**: 함께 사는 부모 = 가족 계획(`firstGone`·`divorce`)과 나이만 읽는 순수 함수. **「없음(0명)」은 구조상 0건이다**(INV-2c·R-558) — 방어 분기로 두고 기본 문구 「부모님」을 유지하는 것을 추천한다(10절).

## 1. 분류 (AK1·AK2)

### 1-1. 영역 `ask`와 규칙 R1a

`DECISION_AREAS`에 코드 `ask`(아이의 요구)를 더한다. `PARENT_AREAS`·`SELF_AREAS`·`reaction`과 별개의 영역이고 **다른 영역과 함께 쓰지 않는다**(영역이 정확히 `['ask']`). 판정 규칙은 R1 바로 뒤에 한 줄이 끼어든다.

| 순서 | 조건 | 결정자 |
|---|---|---|
| R1 | `age ≥ 19` | 본인 |
| **R1a (신설)** | 영역에 `ask`가 있음 | **본인** (나이와 무관) |
| R2 | 영역에 `reaction`이 있음 | 흘러감 |
| R3 | `childActUntil`이 있고 `age ≤ childActUntil` | 흘러감 |
| R4 | `age ≤ 12` | 부모 |
| R5 | 13~18세: 부모 영역이 하나라도 있음 / 없음 | 부모 / 본인 |

- 코드 위치: `deciderFromRow`의 R1 다음에 한 줄(`if (row.areas.includes(ASK_AREA)) return 'self'`). `decisionFor`·`resolveDelegated`는 바뀌지 않는다 — `who === 'self'`라 지금처럼 `pending`에서 멈춘다.
- **PD13 가중은 닿지 않는다**: `selfAreaWeightFactor`는 `age < SELF_FROM_AGE(13)`이면 1을 돌려주므로 4~12세 조르기 사건에는 ×2.0이 곱해지지 않는다(시험으로 잠근다 — 가중은 3절의 `weight` 하나가 전부).
- `parentTableProblems`에 점검 ④를 더한다: 영역이 `['ask']`인 행 ⇔ 이벤트에 `ask` 필드가 있음, 나이 범위가 종류별 한계 안(`toy` 4~12 · `lessons`·`pet` 5~12). ①②③은 그대로다(조르기 사건은 13~18세에 일어나지 않아 ③이 닿지 않는다).

### 1-2. 어떤 사건이 조르기인가 — 데이터 모양 (AK2, 제안)

```jsonc
{
  "id": "ask-toy-b", "title": "<≤16>", "text": "<상황 ≤74, 주어 없음>",
  "stages": ["infant", "school"], "ageRange": { "min": 4, "max": 12 },
  "yearRange": { "from": 1980, "to": 2000 },
  "track": "common", "weight": 45, "once": true, "noCitation": "D",
  "ask": { "kind": "toy" },
  "choices": [
    { "id": "beg",     "label": "<조른다 꼴>",   "result": "<들어줌>", "askDenied": "<안 들어줌>" },
    { "id": "tantrum", "label": "<떼를 쓴다 꼴>", "result": "<들어줌>", "askDenied": "<안 들어줌 — 사이 안 나빠짐>", "askStrained": "<안 들어줌 — 사이 나빠짐>" },
    { "id": "endure",  "label": "<참는다 꼴>",   "result": "<참음>", "effects": { "stats": { "happiness": -1 } } }
  ]
}
```

- 이벤트 단계 `ask: { kind }`(`toy` | `lessons` | `pet`) 하나만 둔다. 갈래별 **문장**은 선택지 곁에 둔다 — `result` = 들어줌, `askDenied` = 거절, `askStrained` = 거절 + 사이 나빠짐(떼쓰기만). `parentLabel`·`parentResult`와 같은 선택 필드 방식이라 `result` 필수 규칙을 건드리지 않고, 문장을 한 줄씩 읽는 designer·reviewer에게 읽기 쉽다.
- **갈래별 효과는 데이터에 쓰지 않는다**: 들어줌·거절·사이 나빠짐의 효과는 코드 표 `ASK_EFFECTS`(3절) 한 곳이 정한다. `beg`·`tantrum`에 `effects`·`bonuses`·`requires`·`parentLabel`·`parentResult`가 있으면 빌드 실패. **`endure`는 일반 선택지**라 `effects`를 데이터에 두되, 표의 `endure` 행과 같아야 한다(lint).
- 저장 대상이 아니다(저장 스키마 불변 — 데이터에서 읽는다). 문서화: `docs/data/events-schema.md`에 `ask`·`askDenied`·`askStrained` 절을 더한다(AK2).
- 세 선택지는 **항상 보인다**(`requires` 없음, PD5-c와 같은 정신) — 선택지 id는 `beg` · `tantrum` · `endure` 고정, 이 순서.

### 1-4. 나이·범위·한 종류 1장·같은 해 1장

- **나이 4~12** — 13세부터는 지금처럼 공부·친구·취미를 스스로 고른다(R5 그대로). 3세 이하 0건.
- **범위**: 장난감·게임기 / 예체능·배움 / 강아지. **학습 학원은 제외**(결정 Q3): `infant-early-lessons`·`school-tutoring`·`school-academy-night`는 부모 결정 카드 그대로이고 판정 ①(재력별 사교육 참여율 52.8~84.9%)에 영향이 없음을 시험으로 확인한다.
- **같은 해 한 장**: 선택지 카드 간격 2년(`MIN_YEARS_BETWEEN_CHOICES`)을 그대로 받는다 — 추가 코드 없음.
- **한 종류 최대 1장 → 판당 최대 3장**(종류가 셋이다). 한 판의 4~12세 창이 시대 경계(예: 2000/2001)를 넘으면 같은 종류의 다른 시대 사건 둘이 모두 후보가 될 수 있다(손계산: 판의 약 30%가 경계 하나 이상을 넘는다). 막는 방법 두 가지 중 **추천은 (A)**다.
  - **(A) `askPeers` 파생 필드** — `createEventPool`이 `ask`가 있는 사건마다 같은 종류의 다른 사건 id 목록을 `askPeers`로 채운다(파생 필드, 데이터에 쓰지 않음 — `eras`와 같은 방식). `isEventEligible`이 `askPeers`의 id 중 하나라도 `seen`에 있으면 false. 새 저장 이름 0개(One-way 이름은 `parent_strained` 하나로 유지). 코어 변경: `createEventPool` + `isEventEligible` 몇 줄 + 시험 — 정밀 레인(AK2)에 포함한다.
  - (B) 종류별 플래그 `asked_toy`·`asked_lessons`·`asked_pet` — 모든 갈래 효과가 켜고 사건 `conditions.notFlags`가 읽는다. 엔진 변경은 없지만 **저장에 이름 3개가 남아(One-way)** 이름을 바꾸면 마이그레이션이 필요하다.
  - `seen`은 카드가 **떴을 때**(`stepYear`가 `pending`을 만들 때) 기록되므로 해결 전 새로고침에도 같은 종류가 다시 뜨지 않는다.

## 2. 판정 (AK3)

### 2-1. 입력의 범위 (PD0 2-2와 같은 방식 — 격자 시험이 잠근다)

| 쓰는 것 | 쓰지 않는 것 |
|---|---|
| 부모 재력 단계 `character.parentWealth`(1~5) · 사이 `C`(1~5, 2-2) · 종류 `ask.kind` · 선택(`beg`/`tantrum`) · 카드가 뜬 나이 `pending.age`(해시 키) · 판 시드(`peerSeed ?? seed`, 해시와 사이의 ±1단계) | 부모 직업·부모 나이·성별·이름·지역·형제 순서·집안 살림 잔액·주거 형태·아이의 스탯·외모·달력 연도(시대) · **양육 방식(직접)** |

- 양육 방식은 `C`의 기울임(방임 −2 · 엄격 −1 · 자유 0 · 헬리콥터 +1)으로만 들어간다. 형제 순서·집안 살림 잔액은 부모 결정(PD0 2-4)에서는 입력이지만 **조르기에서는 일부러 뺀다**(SPEC 2-3 — 입력이 네 가지뿐이어야 낙인이 설명된다).
- 성별은 쓰지 않는다 — 문장도 성별을 전제하지 않는다(「인형」·「딱지」를 성별에 붙이지 않는다, 8절).

### 2-2. 식과 값

```
p(beg)     = clamp( BASE[종류][W] + 0.06 × (C − 3),          0.05, 0.95 )
p(tantrum) = clamp( BASE[종류][W] + 0.06 × (C − 3) + 0.10,   0.05, 0.95 )
```

| `BASE` ▲ | 1단계 | 2단계 | 3단계 | 4단계 | 5단계 | 설계 원칙 |
|---|---:|---:|---:|---:|---:|---|
| 장난감·게임기 | 0.35 | 0.50 | 0.65 | 0.80 | 0.90 | 재력 한 단계 ≈ 0.15 |
| 예체능·배움 | 0.25 | 0.40 | 0.55 | 0.70 | 0.80 | 장난감보다 0.10 낮음(돈·시간이 더 든다) |
| 강아지 | 0.10 | 0.20 | 0.35 | 0.50 | 0.65 | 가장 큰 약속이라 가장 낮음 |

- **근거 구분 — 전부 설계값**: 저장소에는 장난감·예체능 조르기·반려동물 입양을 소득별로 쪼갠 통계가 없다. 참고만: `s-026`(`private-education-by-income`)의 소득별 사교육 참여율 52.8~84.9%는 **학습+예체능 합계 참여율**이라 `lessons`의 직접 근거가 아니다(「들어주느냐」와 「다니느냐」는 단위가 다르다). 반려동물 양육 가구 비율은 저장소에 값이 없다(FD22 수집 대기, `family-model.md` 5절) — 값을 화면·인용에 쓰지 않는다. 틀(원칙): ① 재력에 단조 비감소 ② 종류 순서 장난감 ≥ 예체능 ≥ 강아지(같은 칸에서) ③ 3단계 장난감 0.65를 닻으로 한 단계 0.15 ④ 5단계−1단계 = 0.55 ≥ 완료 기준 6의 30%p.
- **`0.06 × (C − 3)`**: 사이 한 단계 ≈ 재력 한 단계의 40%. `C`가 가장 먼 집(1)과 가장 가까운 집(5)의 차는 0.24(재력 약 1.6단계). 「형편이 주, 사이가 보조」(형진 님 답).
- **`+0.10`**: 떼쓰기는 재력 약 0.7단계만큼 낫다.
- **하한 0.05·상한 0.95**: 어느 칸도 「확정 거절·확정 승낙」이 되지 않는다.
- **낙인 방지(G4) — `C = 3`의 1단계**: 장난감 0.35 ≥ 0.30 · 예체능 0.25 ≥ 0.20 · 강아지 0.10 ≥ 0.10(경계 값, 시험은 `≥`). 하한 0.05는 `C ≤ 2`의 강아지 1단계에서만 닿는다.

**`C` = 함께 사는 부모 중 가장 가까운 분의 사이**(`closenessOf`의 최댓값, 가족 카드에 보이는 사이 말과 같은 함수·같은 값, INV-14 정신). 함께 사는 부모는 10절 DS1이 낸다. 한 분이면 그분의 값, 없으면 `C = 3`(방어 분기).

| 양육 방식(지금 세상 비율) | 두 분이 함께일 때 `C`의 평균 | 한 분일 때 평균 | 계산 |
|---|---:|---:|---|
| 방임(15%) | 2.32 | 2.00 | 부모 한 사람 = 4 − 2 + 시드(−1 20% · 0 60% · +1 20%) → {1,2,3} 확률 .2/.6/.2, 둘 중 큰 쪽 |
| 엄격(25%) | 3.32 | 3.00 | {2,3,4} |
| 자유(30%) | 4.32 | 4.00 | {3,4,5} |
| 헬리콥터(30%) | 4.96 | 4.80 | {4, 5, 6→5} |
| **전체(두 분)** | **3.96** | 3.69 | `C = 1` 0.6% · 2 10.0% · 3 21.6% · 4 28.2% · 5 39.6% |

→ `C`는 높은 쪽으로 치우친다. **`BASE`는 `C = 3` 기준이라 평균적으로 실제 확률은 `BASE + 약 0.06`**이다(두 분 함께 기준). 이 때문에 5단계 장난감은 `C ≥ 4`(약 68%)에서 상한 0.95에 닿는다. 값 표를 읽을 때의 주의이지 오류가 아니다.

**조르기 확률 격자(손계산, `C = 1 · 3 · 5`)** — 떼쓰기는 같은 칸에 +0.10(상한 0.95, 하한 0.05 안에서).

| 종류 · `C` | 1단계 | 2단계 | 3단계 | 4단계 | 5단계 |
|---|---:|---:|---:|---:|---:|
| 장난감 `C=1` | 0.23 | 0.38 | 0.53 | 0.68 | 0.78 |
| 장난감 `C=3` | 0.35 | 0.50 | 0.65 | 0.80 | 0.90 |
| 장난감 `C=5` | 0.47 | 0.62 | 0.77 | 0.92 | 0.95 |
| 예체능 `C=1` | 0.13 | 0.28 | 0.43 | 0.58 | 0.68 |
| 예체능 `C=3` | 0.25 | 0.40 | 0.55 | 0.70 | 0.80 |
| 예체능 `C=5` | 0.37 | 0.52 | 0.67 | 0.82 | 0.92 |
| 강아지 `C=1` | 0.05 | 0.08 | 0.23 | 0.38 | 0.53 |
| 강아지 `C=3` | 0.10 | 0.20 | 0.35 | 0.50 | 0.65 |
| 강아지 `C=5` | 0.22 | 0.32 | 0.47 | 0.62 | 0.77 |

- 가장 낮은 칸(강아지 1단계 `C ≤ 2`)에서도 떼쓰기까지 하면 약 0.08~0.18이다 — 「늘 거절」인 칸은 장난감·예체능에 없다. 1단계 판에서 조르기 카드 2장을 모두 거절당할 확률(조른다, `C=3`, 장난감 + 예체능)은 0.65 × 0.75 ≈ 49%다(손계산) — SPEC의 「흙수저는 거절이 잦다」와 맞고, 거절 문장은 이유를 말하지 않는다(L6).

**종류별 평균 들어줌 비율(조른다, `C` 분포 반영, 지금 세상 수저 비율 25·30·28·14·3 — PD0 2-7이 쓴 값)**: 장난감 ≈ 0.62 · 예체능 ≈ 0.52 · 강아지 ≈ 0.33 (`BASE`의 수저 가중 평균 0.56/0.46/0.27 + 0.06). 5단계−1단계 ≈ 0.52 / 0.54 / 0.55 ≥ 0.30(완료 기준 6).

### 2-3. 해시 난수 (결정 K5 — 진행 RNG를 읽지도 쓰지도 않는다)

```
famSeed = famSeedOf(peerSeed ?? seed)
u1 = famHash01(famSeed, FAMILY_TAG.ASK, ASK_KIND_NO[kind], 나이 × 2 + 0)     // 들어줌: u1 < p 이면 들어줌
u2 = famHash01(famSeed, FAMILY_TAG.ASK, ASK_KIND_NO[kind], 나이 × 2 + 1)     // 떼쓰기 사이 비용: u2 < s(C)
```

- `FAMILY_TAG.ASK = 20`(마지막 `SIB_LOSS = 19` 다음, 시험이 기존 태그와 겹치지 않음을 확인). `ASK_KIND_NO = { toy: 1, lessons: 2, pet: 3 }` — 한 판에 한 종류는 한 번이라 `(종류, 나이)`가 유일하다. **사건 번호 대신 종류 번호를 쓰는 이유**: 사건 id를 바꾸거나 시대 사건을 나눠도 같은 시드의 값이 그대로다. 두 상수는 바꾸지 않는다(알려진 시드의 결과가 바뀐다 — `FAMILY_TAG`와 같은 취급, 저장 마이그레이션은 필요 없다).
- 성질: ① 같은 상태 → 같은 `u1`·`u2` ② `famHash01`은 `famHash01(famSeed, tag, a, b)`의 네 인자라 SPEC의 「사건 번호·나이·칸」 세 칸은 `(종류 번호, 나이×2+칸)` 두 칸으로 묶는다 ③ **`u1`을 조르기·떼쓰기가 공유**: `p(tantrum) ≥ p(beg)`이므로 「조른다가 들어줌이면 떼쓰기도 들어줌」이 항상 성립하고 같은 카드의 「부모님 기분」이 선택에 따라 뒤바뀌지 않는다 ④ `u1`·`u2`는 서로 독립(상관 0, 시험) ⑤ 선택 하나가 진행 난수를 한 칸 쓰고 버리는 지금 규칙(`resolveChoiceCore`, R-039)은 그대로 — 그래서 같은 상태에서 세 선택 모두 이후 `rngState`가 같다(완료 기준 4).
- 알려진 성질: 저장·새로고침 뒤 같은 카드에서 다른 선택지를 골라 보면 `u1`이 같으므로 「조른다가 안 들어줌」을 본 뒤 「떼쓰기」로 바꾸면 0.10 구간에서만 결과가 달라진다. 이 게임에는 되돌리기가 없고 카드는 한 번만 해결된다 — 새 위험이 아니다.
- 같은 판의 `closenessOf`가 쓰는 시드 ±1단계(`FAMILY_TAG.CLOSE`)와 이 태그는 독립이다.

- 효과 합산은 기존 검증(R-046)을 통과한다(최악 −300·+4).

### 3-2. 기대 행복 손계산 — 지배 방지 점검 (`C = 3`, 완료 기준 10의 근거)

`EV = p × 들어줌 행복 − (1 − p) × 거절 행복`. 조른다: 거절 −2. 떼쓴다: `p+0.10`, 거절 −3. 참는다: 항상 −1. `R`은 떼쓰기가 사이를 나쁘게 할 확률 `(1 − p_t) × s(3=0.50)`.

| 종류 · 단계 | 조른다 p | 조른다 EV | 떼쓴다 p | 떼쓴다 EV | 사이 위험 R | 참는다 |
|---|---:|---:|---:|---:|---:|---:|
| 장난감 1 | .35 | −0.25 | .45 | −0.30 | .275 | −1 |
| 장난감 2 | .50 | +0.50 | .60 | +0.60 | .20 | −1 |
| 장난감 3 | .65 | +1.25 | .75 | +1.50 | .125 | −1 |
| 장난감 4 | .80 | +2.00 | .90 | +2.40 | .05 | −1 |
| 장난감 5 | .90 | +2.50 | .95 | +2.70 | .025 | −1 |

읽는 법(손계산, 행복만 본 것 — 지식·건강·집안 살림은 뺐다):

1. **참는다가 행복 기대값 최선인 칸은 2개**(예체능 1단계, 강아지 1단계). 나머지 13칸은 조르기·떼쓰기가 참기보다 낫다 → 「참기가 늘 최선」이 아니고 「조르기가 늘 최선」도 아니다.
2. **떼쓰기의 행복 기대값 우위**는 장난감 2단계~·예체능 4단계~·강아지 3단계~(+0.05~+0.40)에서 나고, 그 값은 사이 위험 2.5~20%와 맞바꾼다. 부유한 칸에서는 위험이 작아 떼쓰기가 거의 공짜로 보일 수 있다 → 마스터가 알아야 할 점이다(AQ9: 11절 사다리 — 떼쓰기 보너스 0.10 → 0.08, 또는 떼쓰기 거절 행복 −3 → −4).
3. **자동 성향 선택**(`autoChoiceWeights` 방식, `T = 6`, 기대 효과로 점수)은 점수 차가 5 이하라 선택 비율이 평탄하다. 극단 칸 손계산: 장난감 5단계·자유·`C=5`는 조른다 41% · 떼쓴다 41% · 참는다 17%, 강아지 5단계·헬리콥터·`C=5`는 38 · 41 · 20%, 예체능 1단계·방임·`C=1`은 34 · 28 · 39%. **어느 칸에서도 한 선택지 ≈ 42% 이하**라 완료 기준 10(≤ 90%)에 큰 여유가 있고, 세 선택지 모두 0이 아니다(`exp` > 0).
4. **서사 위험(G4)**: 1단계의 예체능·강아지에서는 말을 안 하는 쪽이 기대값이 높다. 설계 의도(「안전하지만 아프다」)이지만 「형편이 어려우면 포기가 합리적」이라는 결론이 낙인처럼 읽힐 수 있다. 거절 행복을 −1로 낮추면 조르기가 어느 칸에서도 참기보다 나빠지지 않아(= 참기가 지배당해 선택의 의미가 사라진다) 의도와 어긋나므로 **−2를 유지**하고, reviewer 전수 판독과 플레이테스트 확인 포인트 ①②로 본다(SPEC 위험표).

## 4. 사이 비용 (AK5)

### 4-1. 확률 `s(C)`

`떼쓰기`가 **거절당한 경우에만** `u2 < s(C)`로 「사이 나빠짐」 갈래가 된다. `s(C) = clamp(0.50 + 0.10 × (3 − C), 0.20, 0.80)`.

| `C` | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| `s(C)` | 0.70 | 0.60 | 0.50 | 0.40 | 0.30 |

- `C`가 1~5이면 클램프 0.20·0.80은 닿지 않는다(방어용). 사이가 먼 부모일수록 높다.
- 조른다·참는다·들어줌에서는 `parent_strained`를 켜지 않는다(0%, 시험).
- 떼쓰기를 고른 카드 한 장이 사이를 나쁘게 할 평균 확률 ≈ **16%**(손계산: 평균 거절 확률 ≈ 0.40 × `s` ≈ 0.40). 자동 성향이 판의 약 13%, 항상 떼쓰는 전략이 약 38%에서 켠다(1.9장 기준).
- **한 번 켜지면 안 꺼지고 쌓이지 않는다**(−1 한 번). 켜진 뒤 그 판의 이후 조르기 카드는 `C`가 1단계 낮아져 `p`가 0.06 낮고 `s`가 0.10 높다. 성인기 `cared_parents`(+1)가 같은 판에 켜지면 되돌려지는 것은 기존 표의 효과이고 새 회복 사건은 없다(Q4).
- 가장자리: 부모 사이가 이미 1단계이면 `parent_strained`가 켜져도 `closenessOf`는 1에서 멈춘다(최소 1). 두 분 모두 1단계인 판은 약 0.6%, 한 분 판은 약 3%라 영향이 작다(손계산). `관계 −1` 스탯과 결과 문장은 그대로 일어난다.

### 5-3. 「다음 결정으로」·자동 모드·저장

1. **「다음 결정으로」(AK6 ②)**: `advanceUntilDecision`은 `pending`이 생기면 멈추므로(`s.pending === null` 루프) 조르기 카드(본인 카드)에서 자동으로 멈춘다 — **코드 변경 0**, 시험·e2e만 고친다. 부모·흘러감 해는 지금처럼 지나간다. 어린 시절을 한 번에 건너뛴다고 가정한 시험·e2e 헬퍼는 12개 e2e 파일(13세 언급)과 `advanceUntilDecision`을 쓰는 15개 시험 파일이 의심 대상이다(AK10이 점검).
2. **자동 모드(AK6 ①)**: `autoChoiceWeights`에 `ev.ask` 분기를 더한다 — `beg`·`tantrum`은 **기대 효과**(갈래 효과의 `p` 가중 평균: `E[스탯] = p × 들어줌 + (1 − p) × 거절`, 떼쓰기는 `(1 − p_t) × s(C)`로 사이 나빠짐 갈래를 가른다)로 점수를 내고, `endure`는 일반 경로(데이터 `effects`)다. 점수 → 가중치(`exp(점수 / 6)`)는 지금과 같다. 순수·결정론이고 `u1`·`u2`를 읽지 않는다. 인라인 카드 + 자동 선택은 지금의 `autoResolveStep` 경로 그대로다.
3. **저장(AK6 ③)**: 조르기 카드는 일반 선택 카드처럼 `pending.choiceIds`에 저장되고 저장 구조·스키마 버전·`HistoryEntry`는 바뀌지 않는다. 새로고침해도 같은 카드이고 결과는 해시라 같다. 이미 지나간 해의 연표 줄은 바뀌지 않는다. 조르기 사건이 없던 구형 저장은 열린다(진행 중인 4~12세 판에는 앞으로 새 사건이 후보로 들어온다 — 같은 시드의 인생이 바뀌는 것은 AK10의 재생성 몫).
4. **선택 해결(AK4)**: `resolveChoiceCore`가 `ev.ask`에서 `askOutcomeOf`로 갈래를 정해 효과·플래그·`lastChoiceAge`·연표 한 줄(문장 + 「(선택: 조른다)」 꼴)을 지금과 같은 경로로 처리한다. 틱 종류는 `resolved`. 해시 키는 `pending.age`를 쓴다(해결 시 `state.age`와 같다).
5. **영향 줄(PD8·EC5)**: `previewChoice`는 `beg`·`tantrum`에서 빈 영향을 돌려주고(효과 필드가 없다) UI가 고정 한 줄(문구 designer)을 그린다. `endure`는 일반 영향 줄이다. EC5 전수 시험은 「일어난 갈래의 실제 효과 = `ASK_EFFECTS`의 해당 갈래」를 갈래별로 따로 본다.
6. **`closenessOf` 필요조건**: `familyTables()`(지연 덩어리 `familyData`)가 필요하다 — 조르기 카드는 인생 단계에서만 뜨고 그때는 게임 데이터가 로드돼 있다. 시험이 만든 가짜 풀은 표를 먼저 불러온다.
7. **이혼·별세가 난 해**: `C`는 그 해 플래그(`mother_apart` 등) 그대로의 `closenessOf`를 읽는다(가족 카드와 같은 함수·같은 값). 계획은 그 해를 「함께 있던 해」로 보지만 플래그가 해 시작에 이미 켜졌다면 한 부모의 값이 −1이다 — `p` ±0.06이 그 해에만 닿는 경미한 가장자리다.

## 7. 반려동물 (AK9)

- **입양**: 들어줌 갈래가 `pet_dog`를 **켜기만** 한다(`school-puppy`의 `keep`과 같다). 입양 관찰(`fam-pet-in`)·수명 이별(`fam-pet-out`)·로그 12·13은 FM7b가 맡는다(`family-model.md` 5-1절 — `pet_*`가 켜졌는데 로그에 없으면 그 해를 입양 해로 기록).
- **배제(양방향)**: 반려동물 사건 둘(`ask-pet-a`·`ask-pet-b`)과 `school-puppy`는 모두 `notFlags`에 `pet_dog`·`pet_cat`·`pet_other`를 둔다. 둘 중 하나가 입양으로 끝난 판에서 다른 쪽은 0건이다. 조르기가 거절된 판에서는 `school-puppy`가 그대로 나올 수 있다(거절 문장에 이유가 없어 모순이 아니다). 이미 `pet_farewell`인 판의 재입양은 이별이 입양 뒤 10년 이상이라 8~14세 안에서 닿지 않는다(손계산: 입양 5세 + 최소 수명 10년 = 15세).
- **종과 범위**: 강아지만 있다(Q2). `pet_cat`·`pet_other`는 읽기(배제)만 한다. 입양한 판에서 같은 종류 두 번째 조르기는 한 종류 1장 규칙이 막는다.
- **FM7b 의존과 스위치**: 반려동물 묶음(입양 관찰·`fam-pet-in/out`·수명)이 **같은 배포에 없으면 반려동물 사건 2개를 데이터에서 끈다.** 스위치는 한 곳 — `src/data/askTable.ts`의 `ASK_PET_ENABLED`가 ① 이벤트 목록에서 `ask-pet-*` 포함 여부(반려동물 사건은 별도 파일 `ask-pet.json` 하나로 두어 목록 포함이 한 줄) ② `PARENT_DECISION_TABLE`의 반려동물 행 ③ 문서 기계 판독 블록의 `pet` 표지 행(스위치가 꺼지면 시험이 건너뜀) ④ `PARENT_TABLE_COUNTS`의 집계를 함께 정한다. 장난감·예체능은 독립이다. **출시 뒤에는 끄지 않는다**(끄면 `pending`·`seen`·`pet_dog` 판과 정합이 깨진다) — 출시 전에만 정한다. 시험: 스위치 꺼짐일 때 풀·표·집계에 반려동물 0건, 켜짐일 때 9건.
- **파일 순서**: `school-puppy`의 `notFlags` 추가는 `school.json`을 건드리므로 FM7b(`keep`에 `pet_dog`)가 먼저, 그 위에 AK9가 얹는다(SPEC 구현 순서).
- **조르기 입양 판 비율** 약 14%(5-1, 손계산 — 공식 양육 가구 비율이 저장소에 없어 비교하지 못한다. FD22 수집 뒤 재점검).
- **조정 필요(designer·FM7b)**: 들어줌 문장과 `fam-pet-in` 줄이 같은 해에 두 줄 나란히 남는다. 문장이 겹치지 않게 역할을 나눈다 — 조르기 결과 문장은 「들이기로 한」 사실만, `fam-pet-in`은 이름·첫 해(FM7b). 줄 수 +1은 판 길이 5-2의 FM7b 몫에 이미 들어 있다.

## 10. 도장 주어 (DS1·K10)

### 10-1. 「그 해 함께 사는 부모」 함수

```ts
export type CoParents = 'both' | 'mother' | 'father' | 'none';
// core/parentSubject.ts (신설) — 순수 함수, 난수·Date 없음, 현재 플래그를 읽지 않는다
export function coParentsOf(game: FamilyGame, age: number): CoParents {
  const sc = familyScheduleOf(game);            // 별세·이혼 계획 (`firstGone`, `divorce`)과 출생 때 가족만 읽는다
  const out = (i: 0 | 1): boolean =>             // i: 0 어머니 · 1 아버지
    (sc.firstGone !== null && sc.firstGone.who === i && age > sc.firstGone.at) ||
    (sc.divorce !== null && sc.divorce.leaver === i && age > sc.divorce.at);
  const mother = !out(0), father = !out(1);
  return mother && father ? 'both' : mother ? 'mother' : father ? 'father' : 'none';
}
```

- **계획과 나이만 읽는다.** `parents_gone`·`mother_gone`·`father_gone`·`mother_apart`·`father_apart`를 입력으로 읽지 않는다. 어른이 된 뒤(52~64세 사건이 `parents_gone`을 켠 뒤) 어린 시절 줄을 그려도 그 줄 나이의 주어가 나온다. `familyViewOf(game, age)`는 `parents_gone` 플래그를 읽으므로 엔딩 연표에서 쓰지 못한다.
- **별세·이혼이 난 해(`age == at`)는 두 분이 함께 있던 해**이고 그다음 해(`age > at`)부터 한 분이다 — `familyViewOf`의 `age > firstGone.at`·`age > divorce.at`와 같은 경계(`R-634 (a)`로 0세 해 → 1세 해로 옮겨진 별세도 `parentGoneAtOf`가 이미 처리한 `at`을 쓴다).
- **동치 시험**: 7000판(`FAMILY_INV_LIVES=1000` 방식) × 나이 0~18 전수에서 `coParentsOf` = `familyViewOf(game, age)`(`parents_gone`을 끈 상태)의 `household` 부모와 같다. `ownAge > FAMILY_MAX_AGE`(100) 조건은 19세 미만에서 닿지 않는다(부모 나이 최대 56 + 18 = 74). 도메인은 나이 ≥ 0 정수.
- **옛 저장**: `family`가 없는 구형 저장은 `legacyFamilyFrom`이 계획을 즉석에서 만들고, 저장 필드·`HistoryEntry`는 바뀌지 않는다(DS4).
- **문구**: 두 분 「부모님이/부모님의 결정」 · 어머니만 「어머니가/어머니의 결정」 · 아버지만 「아버지가/아버지의 결정」 · 없음 「부모님」(기존). 세 주어 모두 세 글자라 글자 수가 같다.

### 10-2. 「없음(0명)」 도달 빈도 — 구조상 0 (K10)

- **어림**: 신규 판에서 20세 미만에 함께 사는 부모가 0명인 판은 **없다.** 근거 ① `firstGoneOf`는 먼저 떠나는 **한 분만** 모델링하고 두 번째 별세는 모델 밖이다 ② `divorcePlan`(R-558 안 B)이 「이미 정해진 `leaver`가 먼저 떠나는 분과 다르고 그분이 `EARLY_LOSS_MAX_AGE(19)` 이하에 떠나면 이혼 없음」으로 만든다(함께 살던 분이 미성년 때 별세해 아이 곁에 부모가 없게 되는 판 제거) ③ 같은 분이 이혼으로 나가고 별세도 하는 판은 남는 분이 있다 ④ `tests/familyConsistency.test.ts`의 INV-2c가 「20세 전에는 함께 사는 부모가 한 분 이상」을 7000판에서 이미 전수 점검한다(`tests/sceneFamily.test.ts`도 같다). DS1은 같은 계획을 읽으므로 `none`은 **방어 분기**다.
- **추천(AA13)**: 기본 문구 「부모님」을 유지한다(바꿀 이유가 없다). developer 측정 항목: 7000판 × 나이 0~18에서 `none = 0` 단언, 그리고 `both`·`mother`·`father`의 부모 결정 줄 단위 건수(도장이 한 분으로 바뀌는 줄의 비율 — 기능이 얼마나 보이는지 보고, 게이트 아님). 구조상 0이라 이 문서는 빈도를 따로 어림하지 않는다. `none`이 1건이라도 나오면 문구 문제가 아니라 INV-2c 위반(가족 계획 버그)이므로 작업자 반환(버그)이다.
- **독립성**: 이 절은 1~9절과 무관하다. 조르기 설계가 승인되기 전에도 DS1~DS4(S1)를 먼저 낼 수 있고, 조르기의 `C`가 이 함수를 선행으로 쓴다(S2).

### 13-2. 마스터에게 확인 필요 (기획자가 스스로 정하지 않은 것)

- **AQ1 효과의 자리**: SPEC AK2는 `ask` 필드에 「갈래별 결과 문장·효과」를 쓰는 모양이다. 이 문서는 효과를 코드 표 한 곳에 두고 문장은 선택지 필드에 둔다(1-2절). SPEC 문면대로 사건 JSON에 효과를 쓰는 안도 가능하다(사건 9개가 복사 → 표와 일치 lint).
- **AQ2 종류당 1장의 수단**: `createEventPool`·`isEventEligible` 변경은 이벤트 풀의 공개 인터페이스(파생 필드)를 건드린다 — AK2를 정밀 레인 그대로 두고 검수(opus)에 명시한다.
- **AQ3 판정 사다리 위쪽 여유**: 지난 세상 연결률 여유 0.33%p(9절). 지난 구간 사건을 4장에서 늘리지 않는다고 못박을지.
- **AQ4 반려동물 가중 30**: 조르기 입양 약 14%가 FM7b의 반려 줄 분량·실제 양육 비율과 맞는지(공식 값 없음, FD22 대기). 더 낮추려면 15~25.
- **AQ5 1980~2000 「TV 게임기」**: 보급 연도를 모르는 채 쓰지 않는다. 소재 창고 요청(K4)에 연도 확인을 넣을지, 넣기 전에는 조립·변신 장난감만 쓴다.
- **AQ6 `lessons-c`(2026~, 코딩·로봇 교실)**: 다가올 세상 구간이라 시대어 lint가 허용한다(K3과 충돌 없음). 사건별 승인 대상이 아님(K9)을 재확인.
- **AQ7 `REAL_NAMES` 더하기**: 상표 10개(닌텐도·패미컴·게임보이·플레이스테이션·엑스박스·포켓몬·레고·바비·다마고치·슈퍼마리오). 강화라 K3과 충돌하지 않지만 목록은 reviewer 판독 뒤 확정한다.
- **AQ8 `report:ask` 신설**: SPEC AK10의 보고 목록에 없다. `report:parent`와 같은 방식의 스크립트 하나를 더하는 데 동의하는지.
- **AQ9 떼쓰기 우위**: 부유한 칸에서 떼쓰기의 행복 기대값이 조른다보다 +0.05~+0.40 높고 사이 위험은 2.5~20%다(3-2절). 7000판에서 기대 행복 최대 전략의 선택 분포를 **보고만** 하고, 떼쓰기가 60%를 넘으면 사다리(11절 4·3번)를 쓸지.
- **AQ10 거절 −2의 서사**: 1단계 예체능·강아지에서 참기가 기대값 최선이다(3-2절 4번). 설계 의도로 유지하고 플레이테스트 확인 포인트 ①②로 본다는 데 동의하는지.
- **AQ11 정합 위치**: DS5가 적지 않은 PD4-8·PD0 2-8·0절·1-1·1-2·5절·코드 주석 3곳(6절)을 DS5에 넣을지.

### 13-3. SPEC과 어긋나거나 SPEC에 없는 점 (SPEC 본문은 고치지 않았다 — 마스터가 판단)

1. **효과의 자리**(AQ1): SPEC AK2는 효과를 `ask` 필드에 두는 모양인데 이 문서는 표 한 곳을 추천한다.
2. **한 종류 1장·판당 3장의 구현 수단**이 SPEC에 없다 — `askPeers`(코어 파생 필드) 또는 플래그 3개가 필요하다(1-4절). AK2에 적어야 한다.
3. **해시 입력 칸 수**: SPEC 2-3은 「사건 번호·나이·칸」 세 칸인데 `famHash01`은 `(시드, 태그, a, b)`라 `(종류 번호, 나이×2+칸)`으로 묶는다. 사건 번호 대신 종류 번호를 쓴다(사건 id·시대 분할이 바뀌어도 값 불변).
4. **「다음 결정으로」(AK6 ②)는 코드 변경이 없다** — 이미 `pending`에서 멈춘다. 시험·e2e만 고친다(5-3).
5. **`PARENT_TABLE_COUNTS`**: SPEC은 「본인 구간이 있는 카드」가 조르기 수만큼 는다고 적었는데 새 키 `askCards`를 두는 것을 추가로 제안한다.
6. **`C`의 평균이 3이 아니다**: 평균 3.96이라 `BASE`의 실제 평균은 `+0.06`이다(2-2절). SPEC 완료 기준 5·6은 영향이 없다(방향·차이 점검).
7. **K10 「없음」 빈도**: SPEC은 7000판 실측을 기다리는 모양인데 INV-2c·R-558이 구조상 0건을 보장한다(10-2절). 측정 항목은 `none = 0` 단언으로 바꾼다.
8. **DS5 정합 위치가 모자란다**(6절, AQ11).
9. **연결률 여유**: SPEC 완료 기준 15의 「가안 4장」은 맞으나 지난 구간 여유가 0.33%p뿐이다(9절).
10. **효과의 집안 살림 −100**은 150 단위 관례 밖이다(3-1절) — 동작에는 문제가 없다.
