## 1. 전제와 시간 구조

- 알파는 2013~2020년생이다. 19세가 되는 해는 2032~2039년이라 **성인기 전부가 전망 구간**이다(PJ7). 실제 구간은 출생 해~2025년의 어린 시절뿐이다.
- 보드는 **19세에 켜진다**(AL1). 0~18세는 SPEC-005의 연령별 선택 규칙 위에서 진행하고, 학창기에 조립형의 씨앗(진로 탐색·온라인 학습·AI 도구 사용)을 플래그로 남긴다. 씨앗 플래그 이름은 가칭: `explore_career`, `online_learning`, `ai_tool_basic`(AL6의 `ai_tool_*` 계열).
- 전망 지평(PJ3): 알파 마지막 출생 연도 2020년생은 80세가 되는 해가 2100년이다. 지평 이후에는 연표·전망 사건 없이 일반 이벤트만 나온다. **보드 규칙은 지평과 무관하게 계속 돈다**(보드 자체는 전망이 아니라 판의 상태다). 지평 이후에 열려 있는 전환은 나이에 자연스러운 것(`care.self`, `work.taper → rest`)뿐이다(6절).
- 알파 판의 2026년 이후 줄은 모두 「전망」 표시이고, 알파 성인기 이벤트마다 `basisIds` 최소 1개를 단다(AL8).

## 2. 생애 보드 `lifeBoard` (AL2)

### 2-1. 축과 상태

| 축 | 상태 id (이름) | 경제로의 번역 (2-5절) |
|---|---|---|
| **배움** `learn` | `formal`(정규 과정) · `retrain`(재교육 중) · `self`(독학·프로젝트) · `rest`(쉼) | `formal` = 학생 상태(나이 제한 없이), `retrain` = 일 슬롯 시간 −0.3 ▲, 나머지는 영향 없음 |
| **일** `work` | `employed`(고용 1곳) · `multi`(프로젝트·N잡, 2~3개) · `create`(창작·창업) · `carer`(돌봄 전념) · `taper`(일을 줄여 가는 중, **추가 제안**) · `rest`(쉼) | 슬롯 식(3절)으로 일 상태 계수를 덮어쓴다 |
| **거처** `home` | `parents`(부모 집) · `share`(공유·단기 계약) · `mobile`(이동 거주) · `rent_long`(임차 장기) · `own`(자가) | 기존 `dwelling` 경로(`renting`·`own_home`·`lives_with_parents` 플래그)를 그대로 쓴다 |
| **관계** `bond` | `solo`(혼자) · `partner`(동거·파트너) · `married`(결혼) · `extended`(공동체·가족 확장) | `has_partner`·`married` 가상 플래그 |
| **돌봄** `care` | `none`(없음) · `child`(자녀) · `parent`(부모) · `self`(자신) | `has_child`·`cared_parents`·`in_care` 가상 플래그 |

- 상태 공간: 4 × 6 × 5 × 4 × 4 = **1,920 벡터**. 한 나이의 최대 엔트로피는 `log2 min(표본, 1,920)`(표본 800이면 약 9.6비트).
- **`taper` 추가 제안의 이유**: AL7은 정년 대신 「일을 줄여 가는 노년」을 말하는데 SPEC의 일 축 후보에는 그 상태가 없다. `rest`로 쓰면 55~70세의 일 축이 「쉬는 사람」과 「줄이는 사람」을 구분하지 못한다. `taper`는 슬롯 가중 합 ≤ 0.5이고 55세 이상일 때의 이름이다(파생 상태, 직접 설정도 가능).
- 관계 `extended`(공동체·가족 확장)의 경제 번역은 `married`와 같게 [가정, ▲] 시작한다. 근거가 없는 가정이라 마스터가 확인한다.

### 2-2. 저장 모양

```
lifeBoard = { learn: { s: 'formal'|..., since: 나이 }, work: {...}, home: {...}, bond: {...}, care: {...},
              jobs: [ { kind: 'employed'|'project'|'create', w: 0.1~1.0, since: 나이 } ] }       // 최대 3
```

- `since` = 그 축의 마지막 전환 나이(AL2). 알파 판에서만 존재한다(선택 필드, MG1의 새 버전 안).
- **검증(`parseGame` 방식)**: 상태 id가 허용 집합 안, `since ≤ 현재 나이`, `jobs ≤ 3`, `jobs`의 `w` 합 ≤ 1.3, 보드가 19세 이전이면 초기 상태. 위반 시 판을 버리지 않고 **보드를 `deriveBoard(flags, dwelling, seen)`로 다시 만든다**(플래그는 정상일 때). 플래그가 보드와 어긋나면 **보드가 우선**하며 플래그를 다시 동기화한다.
- 표시(프로필 카드의 축 요약, N10-③)는 designer 몫이다. 이 문서는 데이터만 정한다.

### 2-3. 전환 규칙

| # | 규칙 | 검증 |
|---|---|---|
| B1 | 한 해의 보드 전환 ≤ 2개 ▲ (이벤트 하나가 바꾸는 축은 **하나**. 두 축이 함께 움직이는 일은 다음 해의 후속 이벤트로 잇는다) | 시뮬레이션 단언 |
| B2 | 한 축의 전환은 다른 축 완료를 **선행 조건으로 요구하지 않는다.** 예외: ① `care.child`는 그 이벤트가 켜는 자녀 플래그 ② `care.parent`는 부모가 살아 있음 ③ `work.taper`는 55세 이상(나이 조건) ④ `home.own`은 자산 조건(경제 가드, 축 조건 아님) | 빌드 lint: 이벤트 `conditions`에 위 예외 외의 다른 축 상태가 필수로 들어가면 실패 |
| B3 | 모든 전환 이벤트의 선택지는 지배 선택지 없이 대가가 있다(E11·E15, 기존 R-352 표기 지배 점검이 알파 이벤트에도 적용) | 기존 시험 |
| B4 | **`home.own`은 목표가 아니다.** 어떤 엔딩 판정·분포표·문구도 자가를 우대하지 않고, 자가를 고르는 이벤트는 선택지 ≥ 3개 중 하나다 | 리뷰 + lint(엔딩 문구) |
| B5 | 같은 축의 연속 전환 간격 ≥ 2년 ▲ (변화가 잦다는 인상을 막고 `MIN_YEARS_BETWEEN_CHOICES = 2`와 맞춘다) | 시뮬레이션 단언 |
| B6 | 19세 이전 보드는 활성이 아니다. 19세에 초기 상태(2-4절)로 켜진다 | 단위 테스트 |
| B7 | **카드 수 중립**: 알파의 전환 이벤트는 정석 사슬 이벤트(첫 일·미팅·결혼·출산·집 마련 등, 기준선 2절의 문 이벤트 50개 중 청년·중년 사슬)를 **대체**한다. 총 결정 카드 수 목표(소프트 24 / 하드 30, `timingTable.ts`)를 늘리지 않는다 | `report:time` 알파 판 |
| B8 | 평균 전환 수 ≥ 8▲ (19~70세, AL9). 19~70세 51년에 약 6년에 한 번이며 B5·B1을 만족한다 | 시뮬레이션 |

- **카드 수 계산(B7의 이유)**: 선택지 확률 `c`(청년 0.5 · 중년 0.36 · 노년 0.6, `EVENT_FREQUENCY`)와 선택지 사이 최소 간격 2년(선택이 일어난 해 뒤 한 해는 막힌다)이면 연평균 선택 카드는 `c ÷ (1 + c)`장이다 — 청년 0.33, 중년 0.26, 노년 0.38. 후보가 충분할 때의 상한으로 20~39세 20년에 약 6.7장, 40~64세 25년에 약 6.6장, 65~70세 약 2장, **20~70세 합계 약 15장**이다(코드 읽기 어림, 시뮬레이션으로 확인). 이 가운데 8장 이상이 보드 전환이면 성인기 결정 카드의 절반 안팎이 전환이 된다 — 정석 사슬을 대체해야만 가능하다.

### 2-5. 경제 번역 — 새 금액 장치 없이 (AL4의 「임시 대응표」)

SPEC-006 장치가 들어오기 전까지 기존 엔진의 입력을 바꾸는 최소 변경만 한다.

| 보드 | 엔진 입력 | 방법 |
|---|---|---|
| 일 | 일 상태 계수 | `incomeOf`에 **숫자 덮어쓰기**(`jobFactor`)를 받는다. 알파가 아니면 기존 `ECONOMY.state[state]` |
| 일 (덮어쓰기를 받지 않는 구현이면) | `WorkState` | 표 아래 대응표 |
| 배움 `formal` | 학생 상태 | `workStateOf`의 `college && age ≤ 25` 조건을 알파에서는 `learn.s = formal`로 대체(나이 제한 없음) |
| 거처 | `dwelling` | 전환 이벤트가 `parents → lives_with_parents`, `share·mobile·rent_long → renting`, `own → own_home` 플래그를 켠다. 기존 `dwellingAfterFlags`가 주거를 정한다 |
| 관계·돌봄 | 소득 계수·생활 인원 | 가상 플래그(`married`·`has_partner`·`has_child`·`cared_parents`·`in_care`)를 켜고 끈다. `has_partner`는 R1에서 경제 효과가 없다 — 동거의 비용 분담(SPEC-006 몫)은 이번에 넣지 않는다 [가정, 마스터 확인] |

- **알파는 자동 주거 전환을 끈다.** R1의 `dwellingAfterFlags`는 결혼하면 부모 집(`family`)에서 재력 단계별로 `own`/`jeonse`/`rent`로 옮기는데 알파에서는 거처 축이 명시적으로 정한다(보드가 `parents`라면 결혼해도 거처는 그대로). 미혼 30세 `naturalDwelling` 규칙은 `lives_with_parents` 플래그가 있으면 이미 막혀 있어 그대로 둔다.
- **`WorkState` 대응표(덮어쓰기를 쓰지 않을 때)**: `employed` → 취업 / `multi` → 취업(×0.95) / `create` → 창업 / `carer` → 그 밖(계수 0.55가 너무 크므로 `carer` 계수 0.1▲ 신설 필요) / `taper` → 취업(×0.45▲) / `rest` → 그 밖. `carer`·`taper`는 R1 표에 없는 상태라 **어느 쪽이든 `ECONOMY.state`에 값 두 개(▲)가 더해진다**(GM9의 경제 표 변경, 설계값 표시).
- 변동성(「소득은 합산하되 변동이 커지고」)은 난수가 아니라 **이벤트**가 만든다(economy-model 1절 3번). `multi`/`create`일 때 소득 공백·불안정성 이벤트(`assembled`, E13 `dark-real`)의 가중이 슬롯 수에 비례해 오른다. 사회보험·소득 공백 서술은 공식 조사의 경향만 쓰고 수치는 원문 확인된 것만 쓴다(AL4).

### 2-6. 다른 세대의 파생 보드 `deriveBoard`

AL10을 같은 정의로 재려면 X·밀레니얼에도 같은 모양의 보드가 필요하다. 기준선(`baseline004Lib.ts`)의 축 상태 정의 v0를 다음처럼 옮긴다. **기준선의 `관계` 축 「결혼+자녀」는 두 축이 섞인 값이라 분리한다**(`bond = married`, `care = child`).

| 축 | v0 상태 | 새 상태 | **공통 투영**(알파 상태도 이 칸으로 접힌다, 5절 ① 공정성 보고) |
|---|---|---|---|
| 배움 | 정규 / 재교육 / 독학·수험 / 쉼 | `formal` / `retrain` / `self` / `rest` | 같음 |
| 일 | 학생 | 일=`rest`, 배움=`formal` | 돌봄·쉼·학생 |
| | 고용 1곳 | `employed` | 고용 |
| | 사업 | `create` | 사업·창작 |
| | 고용+사업 | `multi` | 복수 |
| | 수험 | 일=`rest`, 배움=`self` | 돌봄·쉼·학생 |
| | 임시·쉼 | `rest` | 돌봄·쉼·학생 |
| | 은퇴 | `taper`(`senior-retire` 이후) | 줄임·은퇴 (알파 `taper`도 여기) |
| 거처 | 부모 집 / 월세 / 전세 / 자가 / 돌봄 시설 | `parents` / `rent_long` / `rent_long` / `own` / (돌봄 시설은 `care.self`와 함께 `rent_long`) | 부모 집 / 임차 / 자가 (`share`·`mobile`·`rent_long`은 임차로 접힌다) |
| 관계 | 혼자 / 파트너 / 결혼 / 결혼+자녀 | `solo` / `partner` / `married` / `married`+`care.child` | 혼자 / 파트너 / 결혼 (`extended`는 결혼으로 접힌다) |
| 돌봄 | 없음 / 자녀(출산 뒤 18년) / 부모 / 자신 | `none` / `child` / `parent` / `self` | 같음 |

- 파생 보드는 저장하지 않고 **측정 전용**이다(저장된 `lifeBoard`는 알파만). 측정 때만 `flags`·`dwelling`·`seen`을 읽는다.
- 기준선의 숫자(X 대리 4.57 / 밀레니얼 대리 4.46비트)는 v0 정의의 값이라 **새 `deriveBoard`로 다시 재야 한다**(GM9). 기준선 값은 참고다.

## 3. 일 슬롯 `jobs` (AL4)

### 3-1. 구조

슬롯 = `{ kind, w, since }`. `kind` ∈ `employed`(고용) · `project`(프로젝트·플랫폼 일감) · `create`(창작·창업). `w`는 그 해 쏟는 시간 비중(0.1~1.0). 슬롯은 최대 3개, 소득이 있는 슬롯은 `employed`·`project`·`create`뿐이다(돌봄 전념 `carer`는 슬롯 없음).

### 3-2. 소득 식 (설계값 ▲)

```
jobFactor = min( 1.15, ( Σ_i  w_i × K[kind_i] ) × OVERLAP[n] )         // n = 슬롯 수
K       = { employed: 1.0, project: 0.8, create: 0.6 }                 // ▲ 종류별 시간당 소득 상대값
OVERLAP = { 1: 1.00, 2: 0.95, 3: 0.90 }                                // ▲ 전환·조율 비용
시간 합 Σ w_i > 1.0 이면 그 해 건강 −1 ▲ (이미 있는 자연 변화 경로에 얹는다)
labor   = CURVE(a) × EDU × jobFactor × L(y) ... (economy-model 16-3의 나머지 곱은 그대로)
```

- 근거: 공식 통계로 정할 수 없는 값이다(미래 직업 구조). 모두 **설계값**이며 화면에 숫자로 보이지 않는다(S6). 합산 상한 1.15는 「N잡이 공짜 점심이 되지 않게」 하는 상한이다.
- 예(계산값):

| 슬롯 | 계산 | `jobFactor` | 비교 |
|---|---|---:|---|
| 고용 1.0 | 1.0 × 1.0 × 1.00 | 1.00 | R1 취업 상태와 같음 |
| 고용 0.6 + 프로젝트 0.5 | (0.6 + 0.4) × 0.95 | 0.95 | 시간은 1.1이라 건강 −1 |
| 프로젝트 0.5 + 프로젝트 0.5 + 창작 0.3 | (0.4 + 0.4 + 0.18) × 0.90 | 0.88 | 시간 1.3 |
| 창작 0.8 | 0.8 × 0.6 × 1.00 | 0.48 | R1 창업 상태(0.8)보다 낮다 — 창작의 불확실성을 이벤트 보너스가 위쪽 변동으로 만든다 |
| 고용 0.4(`taper`) | 0.4 × 1.0 | 0.40 | 줄여 가는 일 |

- **R1 창업 계수 0.8과의 정합**: 알파의 `create`는 `0.6`으로 R1 `business 0.8`보다 낮다. 창업의 위쪽 변동은 R1처럼 보너스 이벤트(지식·외모·가족 사업)가 맡는다. 두 값이 어긋나는 것이 불편하면 `K.create`를 0.8로 올릴 수 있다(마스터 확인).

### 3-3. N잡 측정용 정의

- **`multiYear(a)`** = 그 해 소득 원천이 둘 이상 (`jobs`에서 소득 있는 슬롯 ≥ 2). 알파는 `jobs`로 직접. 다른 세대는 `deriveSlots`로 근사한다 — `has_career ∧ own_business`는 둘, `youth-gig-work/juggle`은 선택 뒤 ▲5년 동안 둘, `youth-startup/side`는 사업이 이어지는 동안 둘.
- **전제 조건(경고)**: R1 플래그는 한 번 켜지면 꺼지지 않는다 — `youth-startup`의 「사업을 시작한다」가 `has_career`를 지우지 않아 **겸업 플래그가 부풀려진다**(기준선 3-3절, 참고값 25~28%). 그래서 다른 세대의 `multiYear`는 **`side_business` 플래그를 분리하거나 사업 시작이 `has_career`를 해제하는 이벤트 변경이 선행**해야 의미가 있다(콘텐츠 변경, 설계 문서 A의 이벤트 변환 또는 GM8·GM9). 그 전의 다른 세대 값은 근사이며 공식 통계와 직접 견주지 않는다.

## 5. AL10 지표 재정의 (GM0 마스터 결정 3)

### 5-1. 왜 바꾸나 (기준선 근거)

| ① 경로 다양도 | 25·35·45·55·65세 5-튜플 엔트로피 알파 ≥ 밀레니얼 1.5배 | 9.45 / 9.34비트(표본 상한 9.88) | 이미 상한의 95%라 **최대 1.06배**. 달성 불가 |
| ② N잡 | 19~64세에 일 슬롯 ≥ 2인 해가 한 번이라도 있는 판 비율, 알파 ≥ 40%, X ≤ 15% | 엄격 17.3 / 30.1% | X 대리가 이미 15%를 넘음. 게다가 **생애 중 한 번이라도**(누적) 대 공식 통계는 **한 시점의 비율**이라 견줄 수 없음 |

### 5-2. ① 나이별 5축 벡터 엔트로피 평균 `H̄`

- **정의**: 나이 `a ∈ {25, 35, 45, 55, 65}` 각각에서, 그 나이까지 산 판의 5축 상태 벡터(`learn/work/home/bond/care`)의 분포 `P_a`의 섀넌 엔트로피 `H_a`(비트)를 구하고 다섯 값의 평균을 `H̄`로 한다. 기준선의 「서로 다른 5-튜플 25칸」과 달리 **각 나이를 따로 보므로** 표본 상한(log2 n)에 붙지 않는다.
- **추정**: 알파와 비교 세대의 **표본 수를 같게** 맞춘다(작은 쪽에 맞춘 무작위 부분표본 n=800을 20회 반복해 평균). plug-in 추정의 편향은 대략 `(관측된 서로 다른 벡터 수 − 1) ÷ (2 n ln2)`비트(예: 150종이면 약 0.1비트)로 다양할수록 과소추정되는 방향이라 알파에게 **보수적**이다.
- **두 값을 같이 보고한다** (비교의 공정성):
  - `H̄_native` = 알파는 자기 상태(1,920 벡터), 다른 세대는 `deriveBoard`의 새 상태.
  - `H̄_common` = 모두 2-6절의 공통 투영(일 5 · 거처 4 · 관계 3 · 배움 4 · 돌봄 4)으로 접은 값. 알파 고유 상태가 많아서 생기는 「정의가 만든 차이」를 걸러낸다.
- **기준선(참고, v0 정의)**: X 대리 4.57 · 밀레니얼 대리 4.46비트(random), 축별 평균 배움 0.33 · 일 1.52 · 거처 1.30 · 관계 1.45 · 돌봄 0.31(합 4.91 → 결합 4.57, 축 간 중복 약 0.34비트). 새 `deriveBoard`로 **다시 재야 한다**(관계 축에서 자녀를 분리했으므로 값이 달라진다).
- **목표(▲, 설계 의도)**: `H̄_native(알파) ≥ 1.5 × H̄_native(밀레니얼)` — 밀레니얼이 4.46이면 **6.7비트**(유효 경로 수 2^H로는 22 → 104종). `H̄_common(알파) ≥ 1.2 × H̄_common(밀레니얼)` ▲. 절대 비트가 아니라 **상대**로 둔 이유는 GM10의 현실성 보정이 밀레니얼 값을 바꾸기 때문이다.
- **가능성 점검(엔트로피 예산)**: `H̄ ≤ Σ(축별 엔트로피) − 축 간 중복`. 6.7비트를 얻으려면 중복 약 0.5비트를 가정해 축별 엔트로피 합이 약 7.2비트 필요하다. 상태 수로 본 축별 상한은 배움 2.0 · 일 2.58 · 거처 2.32 · 관계 2.0 · 돌봄 2.0비트(합 10.9). 예시 예산: 배움 1.2 · 일 1.9 · 거처 1.7 · 관계 1.5 · 돌봄 1.0 = 7.3비트. **기준선에서 배움(0.33)과 돌봄(0.31)이 거의 상수**이므로 알파의 배움·돌봄 축이 실제로 갈라지지 않으면 목표는 못 맞는다 — 이 두 축의 전환 유형(T-L*, T-C*)이 설계의 핵심이다.
- 시험: 알파 1000판·밀레니얼 1000판(시드 동일 규칙) 비율, 축별 엔트로피 예산표를 함께 출력, 같은 시드 재현. 기존 「경로 25칸 서명」 지표는 참고 열로 남긴다.

| 대상 | X·밀레니얼(관측된 세대)만 | 알파 (비교로 밀레니얼) |
| 정의 | **한 시점의 비율**: 나이 `a`에서 `multiYear(a)`인 판의 비율, 30~59세 평균(나이대별도 보고) | **생애 중 한 번이라도**: 19~64세에 `multiYear`인 해가 1년 이상 있는 판 비율 |
| 목표 | 공식 부업(겸업) 취업자 비율 ± 허용 폭(▲). **수치는 확인 필요(DC26)** | 알파 ≥ 40% ▲ (SPEC의 설계 의도 숫자, **통계가 아님**), 밀레니얼 같은 정의 대비 ≥ 1.5배 ▲ (보고, 단언 아님) |
| 근거 | 경제활동인구조사 부가조사의 부업 취업자, 고용노동부 플랫폼 종사자 실태조사 | DC12 알파 보고서(경향만, 수치 인용 금지), 설계 의도 |
| 제약 | 3-3절 경고(겸업 플래그 분리 선행) 이전에는 **측정하지 않는다** | 슬롯이 있는 알파는 즉시 가능 |

- 「알파 40%」는 미래 수치라 통계로 정할 수 없다(PJ8·S6). 그래서 **체험 지표**로 이름 붙이고, 화면·문장에 쓰지 않고, 시뮬레이션 목표로만 둔다. 기준선의 X 17.3%·밀레니얼 30.1%(누적, 선택 기반)는 ②-A와 **견줄 수 없다**.

### 5-4. ③ 정석 경로 — 주변 분포로 쪼개서 본다

- **정석 4단 3~4%는 하나의 통계가 아니다.** 공식 통계에는 「취업·결혼·출산·내 집을 모두 밟은 사람의 비율」이 없다(교차 통계 없음). 그래서 ③을 다음으로 바꾼다.
  - **현실성 지표 (③-A, X·밀레니얼)**: 주변 분포를 각각 공식 통계와 견준다 — 혼인 경험, 출산(자녀 있음), 자가 거처, 취업, 그리고 가능한 곳에서는 **연쇄 조건부 분포**(혼인 경험자 중 자녀 있음, 부부·자녀 가구의 자가 비율). 지표·출처·허용 폭은 `realism-calibration.md`의 비교표가 정한다. 정석 4단 비율은 **보고만** 하고 목표를 두지 않는다.
  - **체험 지표 (③-B, 알파)**: 「보드 번역 정석 4단」 = 19~64세에 ① `work ∈ {employed}`로 ≥ 3년 ② `bond = married` 한 번이라도 ③ `care = child` 한 번이라도 ④ `home = own` 한 번이라도(순서 무관). 목표 **알파 ≤ 밀레니얼(같은 정의)의 0.5배** ▲ (SPEC의 알파 ≤ 15% 대 X·밀레니얼 ≥ 35%의 비 0.43에서 온 설계 의도), 절대 수치는 보고만. 이 지표는 「알파가 정석을 못 하게 설계됐는가」가 아니라 「정석 4단이 유일한 경로가 아닌가」를 본다.
- 정석의 각 단계가 알파에도 있으므로(4절) 알파 값은 0이 될 수 없고 0이 되면 설계 오류다.

## 6. 전망 지평과 시나리오

- 알파 판의 보드는 시나리오(낙관·기준·비관, PJ4)와 **독립**이다. 시나리오는 이벤트 문장과 전망 사건에만 영향을 주고, 보드 규칙·슬롯 식은 시나리오로 바뀌지 않는다(바뀐 경제 값은 공식 전망이 없어 지어낼 수 없다 — PJ8).
- 지평 이후(예: 인구 전망의 마지막 해 이후): 전망 근거가 닿는 `assembled` 이벤트는 닫히고, 나이에 자연스러운 전환(`care.self`, `work.taper → rest`)과 일반 이벤트만 남는다. 지평 이후의 알파 판 길이와 서술 범위는 N12(마스터).

## 8. 마스터가 정할 것 (추천 포함)

1. **일 축에 `taper` 추가.** 추천: 추가(AL7의 「일을 줄여 가는 노년」을 표현하려면 필요). 반대 선택이면 `rest`로 접고 55세 이상 구분을 포기.
2. **`extended`·`partner`의 경제 번역.** 추천: `extended`는 `married`와 같게, `partner`는 효과 없음으로 시작하고 SPEC-006에서 동거 비용 분담을 검토.
3. **알파 자동 주거 전환 끄기.** 추천: 끈다(거처 축이 명시). 켜 두면 결혼과 거처가 어긋난다.
4. **AL10 ① 정의**: 나이별 5축 벡터 엔트로피 평균, `native` 1.5배 · `common` 1.2배 ▲ — 추천 그대로(5-2절).
5. **AL10 ②·③을 현실성 지표와 체험 지표로 가르기.** 추천: 가른다. 알파 절대 수치(40%, 15%)는 체험 지표(설계 의도)로만 두고 화면에 쓰지 않는다. 체험 지표의 숫자는 마스터가 확정.
6. **겸업 플래그 분리 선행(3-3절).** 추천: GM9 착수 때 `side_business` 분리 또는 사업 시작이 `has_career`를 해제하게 변경. 그 전의 N잡 현실성 비교는 보류.
7. **`K.create` 0.6 대 0.8.** 추천: 0.6으로 시작하고 측정 뒤 조정.
8. **카드 수 중립(B7).** 추천: 채택. 알파 성인기 결정 카드 총량을 소프트 24 / 하드 30에서 늘리지 않는다.
