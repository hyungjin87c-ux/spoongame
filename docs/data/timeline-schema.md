# SPEC-004 GM1 설계 문서 A-1 — 연표(timeline) 스키마·출현 규칙·지역 체감 구조·연표 줄 시간 규칙·lint·`WORD_YEARS`·1차 사건 목록

- 상태: **초안 r0 (마스터 승인 전)**. SPEC 본문(`docs/spec/SPEC-004-세대.md` r3)과 `src/`는 고치지 않았다. 마스터가 승인한 뒤 SPEC(TL·RG·SS·GC·EY 절, 데이터 형식)에 반영한다.
- 작성: planner (GM1 설계 문서 A). 날짜 2026-10-27. 기록: `ai-log/2026-10-27_SPEC-004_spec-GM1A.md`.
- 같이 읽는 문서: `docs/data/event-conversion.md`(이벤트 140개 전환표) · `docs/data/generations.md`(세대 정의) · `docs/data/bgm-spec.md`(BGM 사양 골격). 문서 B(경제 연도 축·당시 화폐·알파 생애·현실성 보정)는 다른 planner가 쓰며 이 문서가 건드리지 않는다.
- 근거: SPEC-004 r3(GS·GD·TL·SS·GC·RG·BG·MG·GE, N20~N24 마스터 결정, GM1 행) · `docs/data/spec-004-baseline.md`(GM0, 끝의 「마스터 결정 2026-10-27」 1·2·5·6) · `docs/data/era-motifs-7090.md`(EM-001~112) · `src/data/timingTable.ts`·`src/core/timing.ts`(시간 모델 상수) · `src/core/eventLint.ts`(지금 lint) · `docs/data/events-schema.md`.
- 표기: **▲** 설계값(기획자 제안, 확정 아님). **확인 필요** = 이 문서가 웹을 열지 않아 사실·수치를 확인하지 못했다는 뜻이다(연도·명칭은 일반 지식 수준이고 DC1·DC9·DC14가 공식 자료로 확인한다). **T-번호** = 마스터가 정할 것(맨 끝 10절). 사건 번호 H-… · R-… · X1~4 · GX1~4는 SPEC 부록 A·A-2·A-3·B의 후보 번호다.
- 한계(정직하게): 이 작업에는 명령 실행 도구가 없어 `report:time`·`baseline004.ts`를 돌리지 못했다. 시간 계산은 `docs/data/spec-004-baseline.md` 5·6절의 측정값과 `src/data/timingTable.ts` 상수로 **손계산**했고 재현식을 5절에 적었다. 세대별 판 길이는 시대 3종 모델의 대리값이다(GM10에서 7세대로 다시 잰다).

## 1. 한눈에

| 항목 | 결론 |
|---|---|
| 사건 종류 5종 | 체험(경제·사회·문화) / 배경 / 지역 체감 / 갈등 / 전망 → 범주 코드 7개(2절). 사건 하나는 **한 판에 최대 한 줄**, 기간 사건은 **변형이 있는 가장 이른 해**에 놓는다(first-fit, T-04) |
| 새로 더하는 필드 ▲ | `tier`(줄 예산 우선순위) · `status`(draft/verified) · `bgmMood`/`bgmBan` · `parent`(배경↔지역 체감 짝) · 변형의 `ageBands`(배열)·`requires`(상태 조건)·`perspective`/`closeness` |
| **연표 줄 시간 규칙 (GM0 결정 2)** | 줄 **하나 = +6.75초**(`timelineLineMs` 기본 4000 × 연출 계수 1.6875), 그 줄이 어느 해에 앉든 같다. 조용한 해 위의 줄은 11.81 + 6.75 = **18.56초**. 현재 상수 그대로(조용한 해를 서술 해로 승격 28.69초)는 12줄에서 +2.6분이라 M24 밖이다 |
| **12줄이 M24 안에 드는가** | **든다.** 규칙 C(6.75초)로 12줄 = +1.35분 → 평균 34.76분(≤35), 시대별 32.19 / 35.86 / 36.23분(≤36.5). 여유는 평균 0.24분·다가올형 0.27분으로 **얇다**. 이 규칙으로 평균 기준 최대 **14줄** |
| **그러나 자연 줄 수는 12가 아니다** | 사건 DB가 SPEC 완료 기준 크기(사건 68)이고 TL6 「모든 판에서 정해진 대로」를 그대로 두면 세대별 **약 9~37줄**(산업화 37 · 베이비붐 35 · 86 33 · X 30 · 밀레니얼 22 · Z 14 · 알파 9, ±30%)이다. 6.75초로 곱하면 밀레니얼 36.99분(시대별 상한 초과), 7세대 평균 35.36분(상한 초과). 후보를 모두 쓰면(86레코드) 평균 36.13분. **마스터 선택지 표는 5-6절** |
| lint | 파일 종류 5갈래 매트릭스(6-1) · 시험 예문 통과/걸림 각 5개 이상 · `WORD_YEARS` 약 80행(낱말·구 약 95개, 7절) |
| `WORD_YEARS` 규칙 | 낱말의 `[처음, 마지막]`이 이벤트의 **유효 연도 범위**(`yearRange` ∩ [1940 + 최소 나이, ∞))를 포함해야 한다. 지금 lint의 「노년 전용 새 기기 면제」(R-067)는 이 규칙의 특수한 경우가 된다 |
| 1차 사건 목록 | 45건(변형 사건 38 + 배경 7)이 GD4 핵심(tier 1), 12건이 GE2·GE3 보강(tier 2). 모두 **DC1 미확인** |
| GD5 도달 | 핵심 변형 사건 38건의 **최소 커버 밴드 합 85**(사건당 평균 2.2). 부록 A의 예시 변형은 **28건 중 25건이 핵심 세대에 닿지 않는다**(8-3). TL4 밴드별 최소 중 **40대 이상(중년·장년·노년) 70개는 1차 목록으로 3개뿐** — 후보 보강 필요 |
| 마스터가 정할 것 | T-01 ~ T-14 (10절, 추천 포함) |

## 2. 사건 종류와 필드

### 2-1. 종류 ↔ 범주 코드

| 종류 | 범주 코드 (SPEC TL2) | 줄 형태 | 변형 축 | 선택지·효과 | 비고 |
|---|---|---|---|---|---|
| 체험 | `experience-economy` · `experience-social` · `experience-culture` | 서술형 또는 결정형 | `ageBands` 필수, `wealth`·`region`·`requires` 선택 | 결정형만(기존 이벤트 id를 가리킴) | 경제·문화만 `bgmMood` 허용 |
| 배경 | `background` | **사실 한 줄** | 없음 | **필드 자체가 없음**(SS3) | `bgmBan` 필수 true |
| 지역 체감 | `regional` | 사실 기반 한 줄 | `closeness` × `ageBands` | **필드 자체가 없음**(SS3) | `approved` 필수, `bgmBan` 필수 true |
| 갈등 | `conflict` | 서술형 또는 결정형 | `ageBands` + `perspective` | 결정형이면 대응 선택지(E11) | `perspectives` ≥ 2, `quote` 선택 |
| 전망 | `projection` | 서술형 | `ageBands` + `scenario` | 없음 | `years` ≥ 2026, 가능성 서술(PJ5), 수치는 전망 지표와 일치 |

사건 id: 체험·배경·갈등 `h-###`, 지역 체감 `r-###`, 전망 `p-###`. 후보 번호(H-E06 등)는 `candidate` 필드(개발·문서 메타, 화면·저장에 없음)에 둔다.

**기록 단위 원칙 [T-05]**: **서로 다른 충격·결정·날짜는 레코드를 나눈다.** 부록 A의 「1973, 1979」(석유파동)는 레코드 둘(`1973` / `1979~1980`), 한국전쟁은 개전(1950)과 휴전(1953) 둘, 과외 금지(1980)와 해제(2000)도 둘이다. 한 레코드의 `years`는 **하나의 현상이 이어진 기간**이다. (후보 번호는 `H-E03a`·`H-E03b`처럼 접미사를 붙인다.) 이렇게 나누면 후보 78건이 레코드 약 86개가 된다.

### 2-2. `timeline.json` 구조 (TL1 확장 제안)

```ts
type AgeBand = 'infant' | 'child' | 'teen' | 'twenties' | 'thirties' | 'middle' | 'preSenior' | 'senior'; // 0~6 / 7~12 / 13~19 / 20s / 30s / 40~54 / 55~64 / 65~ (TL3)
type Category = 'experience-economy' | 'experience-social' | 'experience-culture' | 'background' | 'regional' | 'conflict' | 'projection';

interface TimelineFile {
  meta: { schemaVersion: 1; firstYear: 1940; lastActualYear: 2025; updatedOn: string };
  events: TimelineEvent[];
}

interface EventBase {
  id: string;                       // h-### | r-### | p-###
  candidate?: string;               // 'H-E06' (문서용)
  category: Category;
  years: [number] | [number, number]; // 닫힌 구간. background·regional은 [한 해]
  officialName?: string;            // 공공기관 사용 명칭 (TL9). 이름 없이 가리키는 사건은 생략 + nameless: true
  nameless?: boolean;
  status: 'draft' | 'verified';     // DC1 확인 전/후. 배포 빌드는 verified만 싣는다 (V-05)
  basisIds: string[];               // ≥ 1. draft는 「근거를 찾을 자리」, verified는 events-stats-basis.md 행
  tier: 1 | 2 | 3;                  // 1 = GD4 핵심(항상) · 2 = GE2·GE3 보강 · 3 = 그 밖 (줄 예산, 5-6절)
  sensitivity: 'normal' | 'dark-real' | 'political' | 'disaster' | 'epidemic'; // epidemic은 SPEC의 4값에 더하는 제안 (bgm-spec.md B-06)
  motifs?: string[];                // EM-### (GE1). 시험이 제외 8·보류 3 ID가 0건임을 단언
  bgmMood?: 'tense' | 'lively';     // 경제·문화 체험만 (bgm-spec.md)
  bgmBan?: boolean;                 // 변주 금지 해 표지 (bgm-spec.md). background·regional 필수 true, 감염병 체험 true
  banYears?: [number, number];      // 금지 범위가 사건 연도(years)보다 넓을 때 (한국전쟁 1950~1953 등). background·regional만
}
```

종류별로 붙는 필드:

```ts
interface ExperienceEvent extends EventBase {
  category: 'experience-economy' | 'experience-social' | 'experience-culture';
  kind: 'narrative' | 'decision';
  decisionEventId?: string;         // decision이면 events/*.json의 이벤트 id (선택지·효과는 거기에 있다)
  fallbackText?: string;            // 결정형이 간격 규칙(CHOICE_PACING)에 막혔을 때 서술형 대체 문장
  variants: Variant[];
}
interface BackgroundEvent extends EventBase {
  category: 'background';
  text: string;                     // 사실 한 줄 ≤ 50자 ▲. variants·decisionEventId·effects 없음
}
interface RegionalEvent extends EventBase {
  category: 'regional';
  parent?: string;                  // 같은 사건의 배경 줄 id (T-08)
  regions: { direct: RegionId[]; related?: RegionId[] };
  closeBasis?: string[];            // 공공 기록에 해당 시도 주민의 피해가 기록됐다는 근거 행. 없으면 close 변형 금지 (SS4)
  approved: boolean;                // 형진 님 사건별 승인 (RG11). false면 빌드 제외
  variants: RegionalVariant[];
}
interface ConflictEvent extends EventBase {
  category: 'conflict';
  kind: 'narrative' | 'decision';
  decisionEventId?: string;
  fallbackText?: string;
  perspectives: { id: string; ageBands: AgeBand[]; concern: string }[]; // ≥ 2 (GC1). concern은 개발·판독용 메타(화면에 안 나옴)
  quote?: string;                   // 대사 한 개. 비하·낙인어는 여기에만 (GC2)
  variants: Variant[];              // 각 변형은 perspective id를 가진다
}
interface ProjectionEvent extends EventBase {
  category: 'projection';
  variants: (Variant & { scenario?: ('optimistic' | 'baseline' | 'pessimistic')[] })[];
}

interface Variant {
  ageBands: AgeBand[];              // ≥ 1. 한 문장을 인접 밴드가 같이 쓸 수 있다 (T-07)
  text: string;                     // 합쇼체 한 문장. 달력 연도 금지
  wealth?: ('low' | 'mid' | 'high')[];   // 수저 1~2 / 3 / 4~5 (TL5). 사건이 실제로 갈릴 때만
  region?: ('capital' | 'non-capital')[]; // 서울·인천·경기 / 그 밖 (TL5)
  requires?: { flags?: StateFlag[]; notFlags?: StateFlag[] }; // 상태 조건 (T-06)
  perspective?: string;             // conflict 전용
}
type StateFlag = 'has_career' | 'own_business' | 'married' | 'has_child' | 'no_child' | 'own_home' | 'renting' | 'college'; // 허용 목록 ▲

interface RegionalVariant {
  closeness: 'news' | 'near' | 'close';
  ageBands: AgeBand[];
  text: string;                     // ≤ 60자 ▲. close는 「…소식을 들었습니다.」 틀 하나 (RG6)
}
```

`RegionId`는 4-1절의 17개 id다. `wealth`·`region`은 **선택 축**이다. 변형이 없는 조합은 기본 문장(축 없는 변형)으로 돌아가고 사건은 사라지지 않는다(TL5).

## 3. 출현 규칙

### 3-1. 한 사건 = 한 판에 최대 한 줄, 기간 사건은 first-fit 앵커 [T-04]

SPEC TL6은 「해당 연도에 모든 판에서 정해진 대로」라고만 쓰고 기간 사건(`years: [from, to]`)에서 몇 줄이 나오는지는 쓰지 않았다. 기간마다 한 줄씩 나오면 줄 수가 사건 수 × 기간이 되어 5절의 시간이 무너진다. 제안:

- **사건 하나는 한 판에 최대 한 줄**이다. 그 줄이 앉는 해(앵커 해)는 사건 `years` 안에서 **출생 이후에 살아 있고 변형이 닿는 가장 이른 해**다.
- 앵커 해 계산은 **상태(플래그)를 보지 않는다.** 나이 밴드와 수저·지역 축만 쓴다(V-08이 「기본 변형 보장」을 요구하는 이유). 같은 출생 연도·같은 수저·같은 지역이면 앵커 해가 같다.
- 앵커 해에 못 닿는 사건(그 판 인물이 사건 기간 중 변형이 있는 밴드를 지나지 않음)은 그 판에서 **나오지 않는다**(TL4, 인접 밴드 변형 빌리기 금지).

```
anchorYear(ev, person):                     // 순수 함수. 사망 연도를 모르는 채 계산한다
  for y in ev.years.from .. ev.years.to:    // 오름차순
    if y < person.birthYear: continue       // 아직 태어나지 않음
    band = bandOf(y - person.birthYear)
    if exists v in ev.variants with band in v.ageBands
         and axesMatch(v, person.wealthGroup, person.regionGroup)  // requires는 무시
       return y
  return null                               // 이 사건은 이 출생 연도·수저·지역에 앵커가 없다
```

앵커 해가 오기 전에 사망한 판은 그 줄을 보지 못한다(사망 해에는 줄이 없다, 3-3절).

예: H-S01(과밀 학급, 1962~75)에 `child`(7~12세) 변형만 있다고 하자. 1955년생은 1962년에 7세라 그 해에 줄이 나오고, 1963년생은 1970년(7세)에 나온다. 반면 1948년생은 기간 안에 14~27세라 이 사건이 **그 판에서 나오지 않는다.** 그래서 GD5(8-2절)가 사건마다 핵심 세대가 닿을 밴드를 요구한다.

대안(기간 안의 해마다 한 줄)은 비추천이다(시간·밀도). 해마다 확률로 한 줄은 TL6 「확률이 아니라 시대의 공통 체험」과 어긋난다.

### 3-2. TL4 변형 고르기

```
pickVariant(ev, ctx):                       // ctx = { age, wealthGroup, regionGroup, flags, scenario }
  band  = bandOf(ctx.age)
  cands = ev.variants.filter(v => v.ageBands.includes(band))
  cands = cands.filter(v => requiresOk(v.requires, ctx.flags))      // 상태 조건
  if projection: cands = cands.filter(v => !v.scenario || v.scenario.includes(ctx.scenario))
  cands = cands.filter(v => (!v.wealth || v.wealth.includes(ctx.wealthGroup)) && (!v.region || v.region.includes(ctx.regionGroup)))
  if cands.length == 0: return null         // 사건이 나오지 않는다 (인접 밴드·다른 사건 문장 빌리기 금지)
  score(v) = (v.wealth ? 4 : 0) + (v.region ? 2 : 0) + (v.requires ? 1 : 0)   // 수저·지역 모두 > 수저 > 지역 > 기본 (TL5), 같으면 더 구체적인 쪽
  return cands.maxBy(score), 같은 점수는 데이터 선언 순서의 첫째         // 난수 없음 — 같은 시드·같은 나이는 같은 문장
```

수저 그룹: 1~2단계 `low` / 3단계 `mid` / 4~5단계 `high`. 지역 그룹: 서울·인천·경기 `capital` / 그 밖 `non-capital`(출생 시도 기준).

### 3-3. 한 해 줄 수 상한과 우선순위 (TL6)

- 한 해 연표 줄 ≤ 3. **배경 줄과 그 사건에서 파생된 지역 체감 줄(`parent`로 이어진 짝)은 같은 사건 한 쌍**으로 보아 둘 다 나온다(5·18, 대구 지하철, 세월호처럼 SS1이 「배경 한 줄에 더해 지역 변형 줄」이라 한 것). 쌍이 있는 해는 체험 ≤ 1줄이다. 쌍이 없는 해는 TL6 그대로 체험 ≤ 2 + 배경 또는 지역 체감 1줄 [T-08].
- 같은 해에 후보가 상한을 넘으면 **배경 > 지역 체감 > 갈등 > 체험**, 같은 종류 안에서는 `tier` 1 > 2 > 3, 같은 tier는 사건 id 오름차순으로 남기고 나머지는 **같은 `years` 안의 다음 해(앵커 해 다음 후보)로 밀린다.** 밀 해가 없으면 그 판에서 빠진다. 밀림은 상태를 보지 않으므로 결정적이다.
- 결정형은 기존 선택지 간격 규칙(`CHOICE_PACING`)에 걸려 못 열리면 `fallbackText`를 서술형 줄로 낸다(TL6). 결정형 줄도 시간은 카드 읽기 시간 모델을 따르고, 서술형 대체 줄이 되면 연표 줄 시간 규칙(5절)을 따른다.
- 사망한 해에는 연표 줄을 내지 않는다(엔딩으로 넘어간다).
- 사건 없는 연속 해 ≤ 5년▲(실제 구간)은 **후보 보강 기준이자 보고 항목**(V-26)이다. 앵커 해가 사건 기간의 앞쪽으로 몰리므로 출생 연도별 보고가 필요하다.

### 3-4. 줄 예산 (선택, 5-6절 O1)

줄 예산을 쓰는 경우 `tier 1`은 예산과 무관하게 항상 나오고(GD5), `tier 2·3`은 세대별 예산(`TIMELINE_LINE_BUDGET[세대]`)까지 **시드로 결정적인 표본**을 낸다(같은 시드·같은 출생이면 같은 줄). 이때 TL6의 「모든 판에서 정해진 대로」는 tier 1에만 엄격히 적용된다.

## 4. 지역 체감 구조 (RG7 데이터 구조)

### 4-1. 전제와 시도 id

- **주인공은 평생 출생 시도에서 지낸다**(이주 모델 없음) [T-10, 가정]. 지역 체감의 관계는 「출생 시도와 사건 지역의 관계」다(RG7). 이촌향도 같은 이주는 체험 사건(RE-01)의 `region` 변형으로 다룬다.
- **시도 id는 행정구역 연혁과 무관한 안정 키**로 17개를 둔다 ▲: `seoul` `busan` `daegu` `incheon` `gwangju` `daejeon` `ulsan` `sejong` `gyeonggi` `gangwon` `chungbuk` `chungnam` `jeonbuk` `jeonnam` `gyeongbuk` `gyeongnam` `jeju`. 출생 연도별로 존재하는 시도 목록·당시 이름(예: 직할시 → 광역시)과 안정 키의 대응은 DC7 표(`eraRegions`)가 가진다. 출생 시 `birthRegion`은 이 id로 저장하고 당시 이름은 표시용이다. 2026년의 통합 행정구역은 출생 연도 상한(2020) 때문에 출생 판정에 쓰이지 않고 표시용 「지금의 시도」 대응에만 쓴다.
- `capital` 그룹 = `seoul` + `incheon` + `gyeonggi`.

### 4-2. 관계 판정

```
relationOf(birthRegion, ev.regions) =
   birthRegion in ev.regions.direct  → 'direct'
   birthRegion in (ev.regions.related ?? []) → 'related'
   else 'other'
```

### 4-3. 허용 단계표와 추첨 (SPEC RG7을 그대로 옮기고 한 칸을 해석으로 채움)

| 관계 | 나이(앵커 해) | 허용 단계 | 추첨 분포 ▲ (화면 비공개) |
|---|---|---|---|
| 직접 | 13세 이상 | near, close | near 60 / close 40 |
| 직접 | 7~12세 | near | near 100 |
| 직접 | 0~6세 | near (부모 시점 3인칭) | near 100 |
| 관련 | 7세 이상 | news, near | news 50 / near 50 |
| 관련 | 0~6세 | **없음** (사건이 나오지 않음) [해석 — 표에 없는 칸. N4 연계 확인] | — |
| 그 밖 | 7세 이상 | news | news 100 |
| 그 밖 | 0~6세 | 없음 (RG7 「어느 관계든 0~6세 news」) | — |

```
closenessOf(ev, person, heavyOff):                       // 지역 체감 전용 해시 스트림 — 다른 사건의 난수 소비를 바꾸지 않는다
  allowed = ALLOWED[relationOf(person.birthRegion, ev.regions)][ageGroup(person.ageAtAnchor)]   // ageGroup: 0~6 / 7~12 / 13+
  if allowed is empty: return null
  u = hash01(person.seed, ev.id, 'closeness')            // 같은 판·같은 사건이면 항상 같다
  c = pick(allowed.dist, u)
  if c == 'close' and (ev.closeBasis is empty or heavyOff): c = 'near'    // SS4, RG8
  return c

lineOf(ev, person, heavyOff):
  c = closenessOf(...)
  if c is null: return null
  v = ev.variants.find(closeness == c and ageBands.includes(bandOf(age)))
  if v is null and c == 'close': v = ev.variants.find(closeness == 'near' and ageBands.includes(bandOf(age)))   // close 변형이 없는 밴드는 near로
  return v ?? null                                       // 없으면 사건이 나오지 않는다 (TL4)
```

추첨 결과와 폴백 모두 상태·다른 난수를 보지 않으므로 RG10(점수 불변: 켠 판과 끈 판의 상태 해시 일치)이 구조적으로 성립한다. `heavyOff`(SPEC-005 「무거운 장면 끄기」)는 **어느 문장을 보이는지**만 바꾸고 판의 상태·난수는 바꾸지 않는다.

### 4-4. 사건 레코드 규칙

- **앵커 해 하나**(`years` 길이 1). 여러 해에 걸친 현상(제주 1948~1954 등)은 정의한 날짜 하나로 앵커를 잡거나 사건을 나눈다. [T-10]
- `parent`: 같은 사건의 `background` id. 둘은 한 쌍으로 3-3절 줄 수 규칙을 쓴다. 쌍이 없는 지역 사건(재난 등)은 `parent`가 없다.
- `closeBasis`는 「공공 기록에 해당 시도 주민의 피해·영향이 기록됐다」는 근거 행이다(SS4). `close` 변형은 `closeBasis`가 있는 사건에만 있을 수 있다(V-16).
- `approved`는 형진 님이 사건별로 승인한 뒤에만 true(RG11). 배포 빌드는 false를 싣지 않는다. 승인된 사건의 연도는 BGM 금지 해에 자동으로 들어간다(`bgmBan`, bgm-spec.md).
- 감염병은 지역 변형을 만들지 않는다(SS5): `regional`에 감염병 사건이 없다는 단언.

### 4-5. 변형 격자 (사건당 최소 구성)

한 사건이 모든 (관계 × 단계 × 밴드)를 채우면 14개를 넘는다. RG5의 「사건당 5~6개」는 **밴드를 묶는 `ageBands` 배열**로 맞춘다. 최소 구성 ▲:

| 관계·단계 | 밴드 묶음 예 | 최소 변형 수 |
|---|---|---|
| 직접 · near · 영유아 | `infant` (부모 시점 3인칭) | 1 |
| 직접 · near · 어린이 | `child` | 1 |

**규칙 C의 근거**
1. 연표 줄은 **짧은 한 문장**이다. 부록 A 예시 8줄을 센 글자 수는 평균 약 30자(20~39자)이고 지역 체감 한계는 60자▲다. 느린 독자 속도(`READ_MODEL.cpm.high` = 500자/분)로 33자(평균에 여유를 얹은 값)는 약 4.0초, 한계 60자는 7.2초다. 기본 4000ms는 평균 줄을 느린 독자가 읽는 시간이며, 거기에 `holdScale` 1.6875(1배속을 80% 속도로 늦춘 형진 님 결정 LM7b)를 곱한 6.75초는 한계 60자 줄(7.2초)에 가깝다.
2. 조용한 해 위의 줄은 11.81초(기존 호흡) + 6.75초이므로 줄을 읽고도 호흡이 남는다. 가장 긴 줄도 18.56초 안에서 읽힌다(시험: 모든 줄의 느린 독자 읽기 시간 ≤ `quiet + timelineLineMs`).
3. 어디서든 같은 값이라 모델이 단순하다: `T_추가 = 줄 수 × 6.75초 ÷ 배속`(전체 판 모델은 `holdTotalMs`에 항 하나). 「이미 사건이 있는 해에 줄이 앉는지」를 `report:time`이 따로 세지 않아도 된다.
4. 배속 2·4·8배에서는 다른 연출 대기와 같은 비로 줄어든다. 「다음 결정으로」 건너뛰기에서는 연출이 없으므로 영향이 없다.

### 5-7. 코드 반영 스케치 (developer용 — 이 문서는 `src/`를 고치지 않았다)

- `TickInfo`/`TickCounts`에 `timelineLines`(그 해 연표 줄 수, 배경·지역 체감·갈등·체험·전망 모두) 추가. 기존 `lines`/`extraLines`와 별도 항이다.
- `LifeLengthMode.timelineLineMs`(short30 4000, long60 5000▲) 추가. `holdMsFor(kind, { …, timelineLines })` = 기존 대기 + `timelineLines × round(timelineLineMs × holdScale)`. 조용한 해(`quiet`)·서술·결과 모두 같은 항이고, 선택(`choice`) 해는 결과 해(`resolved`)로 넘어갈 때 더한다. 사망 해에는 0.
- `holdTotalMs` += `counts.timelineLines × round(timelineLineMs × holdScale)`. `estimatePlaySeconds`와 `report:time`에 열 `timelineLines`(판당 평균·세대별) 추가. `LIFE_LENGTH_MODES.timeMin`·카드 수 판정은 그대로(M24 구간을 바꾸는 결정이 있을 때만 별도).
- 단위 시험 후보: `holdMsFor('quiet', { mode:'short30', timelineLines:1 }) = 18563`(11813 + 6750), `timelineLines:3`의 합, 선택 해가 결과 해로 넘어갈 때만 더해짐, 배속 나눗셈, 모든 연표 줄의 느린 독자 읽기 시간 ≤ `quiet + timelineLineMs`.
- SPEC 개정 후보(승인 뒤): TL13 「줄당 4초▲」를 이 규칙으로 바꾼다.

### 5-8. 한계

1. 판 길이 기준선은 시대 3종 모델(v0.2.1)이다. 7세대 모델이 생기면 값이 달라진다(GM10). 이 절의 합격/불합격은 **대리 판정**이다.
2. 자연 줄 수는 레코드 수 × 변형 폭 0.5의 어림이다(±30%). `timeline.json`이 있어야 정확해진다.
3. 줄이 앉는 해의 종류(조용/서술/카드)에 따라 규칙 A·B는 값이 달라지지만 C·C3·D는 같다. 연표 줄이 특정 나이에 몰리면 조용한 해 비율이 평균(53~55%)과 달라질 수 있는데, C 계산은 이 비율에 의존하지 않는다.
4. 전망 구간 줄(PJ5, 알파·Z·밀레니얼에게 많다)은 이 계산의 12줄·자연 줄 수에 **포함하지 않았다.** 같은 `timelineLineMs`를 쓰면 한 줄이 6.75초이므로 GM9에서 합산해 다시 확인한다(T-02).

### 6-2. TL9: 연표의 이름·연도 규칙

1. **허용 이름 목록은 DB에서 자동으로 만든다**: 각 사건의 `officialName`을 낱말로 쪼갠 집합 + 직책 허용 목록(`대통령`·`국회`·`헌법재판소`·`군` 등 실명 아닌 직책, `background`에서만 ▲). 이 집합 밖의 `REAL_NAMES` 낱말(삼성·월드컵 …)은 연표 문장에서도 걸린다. 이름이 논쟁인 사건은 `nameless: true`로 「그해 {월}에 {시도}에서 있었던 일」로 가리킨다.
2. **달력 연도 표기는 연표 문장에서도 금지**한다. 허용은 시스템이 붙이는 줄 앞 연도·출생 연월·인용 박스(R-150)뿐이다. 문장 안의 월(「6월」)은 허용한다.
3. **상호·브랜드·서비스·작품 이름은 쓰지 않고 일반 명사로 쓴다**(M5). 공식 명칭 자체가 상호를 포함하면(예: 백화점 이름이 든 사고 명칭) `nameless` 또는 일반 명사 표기로 가린다 [R-09 계열, reviewer 확인].

### 6-4. GC2·GC3·GC4·GC5: 세대 비하·낙인·평가어

- **`GENERATION_SLUR_WORDS`**(`src/data/generationSlurs.ts`): 세대를 겨냥한 비하·낙인 낱말. 대표 예시는 형진 님이 든 하나뿐이고(「꼰대」), 전체는 reviewer·마스터가 판독해 정한다. 이 문서에는 목록을 적지 않는다.
- 판정: 낱말이 **갈등 사건의 `quote` 필드 안**이면 통과(사건당 ≤ 1개, 같은 낱말 반복 금지, V-19), 그 밖이면 어느 파일·어느 필드에서도 실패(GC3). `text`의 `{quote}` 자리는 시스템이 인용 부호 「」로 감싸 넣는다. 주인공이 비하어를 **말하는** 선택지·결과는 없다(듣거나 전해 듣는 것만). 시험: 대사 안 통과 5 / 서술에서 걸림 5.
- **`quote`의 어체 [T-09]**: 이벤트 본문의 「인용 부호 금지」(2026-10-18 결정)는 연표 갈등 사건에는 적용할 수 없다(대사가 필수). 제안: `quote`는 ≤ 30자▲, 평서체(~다) 허용, 해요체·반말 종결(~요/~어/~야) 금지, 느낌표·물음표·이모지 금지.
- 세대 외 집단(성별·지역·장애·직업·인종) 비하는 대사에서도 금지(GC5). 직업·성별 비하어(EM-003 등)는 낱말을 쓰지 않고 상황 문장으로만 쓴다.
- 세대 이름 + 평가어 결합 금지(GC4)와 `GENERATION_EVAL_WORDS` 목록 초안은 `docs/data/generations.md` 6절이다. 연표 파일도 그 목록으로 검사한다.

### 6-5. 상태 어휘 (연표 변형에 `requires` 허용 [T-06])

부록 A 예시에는 「자녀의 카드 빚 이야기」「회사에서 명예퇴직을 권유」「손주」「부모(성인 시점)」처럼 **그 사람이 그 상태일 때만 말이 되는** 변형이 많다. 이벤트 쪽에는 이미 상태 어휘 규칙(`STATE_WORD_RULES`: 자식·배우자·부모님·직장·혼자)이 있다. 연표 변형에도 같은 규칙을 적용하되 변형에 `requires`를 줄 수 있게 한다.

| 말 | 변형에 필요한 `requires` |
|---|---|
| 자식·자녀·손주·아들·딸·아이(가족) | `flags: [has_child]` |
| 배우자·남편·아내·부부 | `flags: [married]` |
| 일터·출근·퇴근·직장·회사·상사·동료 | `flags: [has_career]` 또는 `[own_business]` |
| 혼자 | `notFlags: [married]` |
| 부모님(성인이 자기 부모를 말할 때) | 이벤트 쪽 `parents_gone`은 허용 플래그 8개 밖이라 **성인 시점 변형에서 「부모님이 …」는 쓰지 않는다**(영유아·어린이·청소년 시점의 「부모」, 자녀를 둔 부모 시점은 위의 `has_child` 행으로 허용) |

대안은 연표 문장에서 상태 낱말을 아예 금지하는 것이다(문장이 「주변」「이웃」「친구」 중심이 된다). 추천은 `requires` 허용이다 — 실업·명예퇴직·내 집 마련처럼 상태가 경험을 가르는 사건에서 현실성이 크다. `requires`는 허용 플래그 8개에 한정한다. V-08이 상태 조건 변형마다 기본 변형을 요구하므로 앵커 해는 상태와 무관하다.

## 7. `WORD_YEARS` — 낱말별 쓸 수 있는 연도

### 7-1. 정의

- 한 행 = `{ pattern, from?, to?, kind, basis }`. `pattern`은 낱말 또는 짧은 구/정규식. `from`/`to`가 없으면 열려 있다.
- **`from` = 그 해부터 일반 시민의 일상 소재로 쓸 수 있는 해**(기술·제도가 처음 나온 해가 아니라 일상 소재가 된 해). 처음 나온 해는 비고에 적는다. 이 값은 모두 ▲이며 DC9·DC14가 공식 자료로 확인한다(근거 상태 = 「일반 지식」).
- **유효 연도 범위**: `effective(event) = ( max(yearRange.from ?? 1940, 1940 + 최소 나이), yearRange.to ?? ∞ )`. 이벤트·연표 사건 문장에 `pattern`이 있으면 `[from, to]`가 `effective`를 **포함**해야 한다(TL11). 연표 사건은 `years`와 변형의 밴드로 같은 계산을 한다.
- 지금 lint의 「지난 세상 노년 전용 이벤트는 새 기기 소재 허용」(R-067)은 이 규칙의 특수한 경우다: 노년 전용 이벤트의 `effective.from` ≥ 1940 + 65 = 2005라서 2005 이전에 있던 낱말(휴대전화·인터넷·메신저 …)은 자동 통과하고 스마트폰(2009)은 걸린다.
- 지금 lint의 5개 목록(`NEW_SCHOOL_WORDS`·`NEW_DEVICE_WORDS`·`NEW_CHILDCARE_WORDS`·`OLD_WORLD_WORDS`·`FUTURE_WORLD_WORDS`)은 이 표로 번역했다. **기존 이벤트의 동작은 그대로**(연도 제한이 없는 이벤트는 이전처럼 해당 낱말을 못 쓴다)이고, 연도 범위가 있는 이벤트와 연표 문장만 새로 허용되는 해가 생긴다. 한 가지는 오히려 **더 엄격**해진다: 노년 전용 이벤트가 쓰던 면제(R-067)는 스마트폰·앱·태블릿·와이파이(2009년 이후 낱말)에는 더 이상 통하지 않는다 — 현재 노년 이벤트 23개 문구를 점검했을 때 해당 낱말은 없다(「낯선 기계」는 낱말이 「기계」).

### 7-3. 뉴스 매체 낱말 연도 (RG9-② 「뉴스로」 단계 — DC14)

지역 체감 `news` 변형의 매체 낱말은 **앵커 해**에 맞게 쓴다.

문장 예: 지역 체감 `news` 변형은 앵커 해가 1985 미만이면 「라디오 뉴스로」, 1985 이상이면 「텔레비전 뉴스로」처럼 **사건마다 앵커 해에 맞는 낱말을 직접 쓴다**(한 변형에 해를 둘 이상 걸치지 않는다). 위 구간은 `WORD_YEARS`의 라디오(마지막 1990) · 텔레비전(처음 1961) · 인터넷(처음 1995) · 스마트폰(처음 2009)과 겹쳐 점검된다.

### 7-4. 확인 목록 (DC9·DC14)

휴대전화·삐삐·PC통신·PC방·초고속 인터넷·스마트폰·메신저 보급 시작 연도(과기정통부·방송통신위원회·KOSIS), 급식·국민학교 명칭·육아휴직·어린이집·산후조리원·청약 도입 연도(교육부·국가법령정보센터·보건복지부), 컬러 방송·텔레비전 보급(방송통신위원회), 연탄 사용 가구 비중(통계청 주택총조사), 재택근무·가상자산·대화형 인공지능 확산 연도. 확인된 값은 `from`/`to`를 고치고 근거 행(`basisId`)을 단다. 확인 못 한 값은 `▲ 확인 필요`로 두고 reviewer가 판독한다.

## 8. 연표 사건 1차 목록 (GD4 핵심 배경 + GE2·GE3 소재 반영 후보)

DC1(날짜·공식 명칭 확인)은 **전부 미확인**이다. 아래 연도·명칭은 SPEC 부록 A·A-2·A-3의 일반 지식 초안이다. 「DC1 상태」는 확인이 얼마나 쉬운지(안정 = 널리 알려진 날짜·명칭, 연도 확인 = 시작·종료 연도 확인 필요, 범위 정의 = 기간 사건이라 현상의 범위를 먼저 정해야 함, 명칭 확인 = 공식 표기 확인 필요)이다. 확인 순서는 tier 1 → tier 2 순이다.

### 8-3. 읽고 알아 둘 것

1. **부록 A 예시 변형은 예시일 뿐이고 GD5에 닿지 않는다.** 예시가 있는 28건 중 **25건이 핵심 세대의 최소 커버를 채우지 못한다**(위 표 「부족」 열). 가장 큰 구멍: 월드컵 2002(X는 20대·30대인데 예시는 15·45·8세), 금 모으기(X 10대·20대인데 예시는 8·43세), 석유파동 1973(산업화 10대~30대인데 예시는 9·40세). 작성할 때는 이 표의 최소 커버를 먼저 채운다.
2. **도달 불가 변형이 있다(V-09)**: H-S02의 「41세(부모)」는 1969~74년에 40세 이상인 출생 연도(1934년 이전 출생)가 게임에 없어 아무도 못 본다. 성인의 「부모 시점」 변형은 사건 연도가 이른 사건에서 대체로 닿지 않는다.
3. **밴드 편중**: TL4 밴드별 최소 합 184 중 **중년 28 + 장년 18 + 노년 24 = 70은 1차 목록(85개 최소 커버)으로는 M 3개뿐**이다. GD4의 핵심 배경이 각 세대의 청소년·청년기에 몰려 있어서다. 판의 55~60%가 40세 이상 해인데(baseline 1-6절 1순위 「장년·노년 얇음」) 연표 변형이 비어 있으면 그 구간의 시대 체감이 약하다. 40세 이상이 겪는 사건(의료보험 H-S03, 금리 급등 H-E13, 연금 논쟁 H-G05, 정년 연장 H-G07, 장기요양 H-S10의 노년 변형, 코로나 노년 변형, 인공지능 노년 변형)을 tier 1·2 변형에 **노년·장년 밴드로 더 얹는** 방식과 소재 창고 요청(「노년기 생활」, baseline 마스터 결정 6)이 필요하다. 후보를 마스터가 정한다(T-13).
4. 알파 H-S18(2025년 5~12세)의 영유아 변형(「형이 말하는 고교학점제 이야기」류)은 억지스러울 수 있다. 달성하지 못하는 세대 × 사건은 GD5 문서의 「달성 못 함」 목록에 올리고 변형을 억지로 만들지 않는다(GD5 본문).
