## 0. 먼저 읽을 것 — 마스터가 알아야 할 발견 10가지

1. **모드는 지금 코드에 저장값으로만 있고 동작이 없습니다.** `LIFE_LENGTH_MODES`는 코드 어디에도 없고(검색 0건), 엔진(`life.ts`)·시간 모델(`timing.ts`)·시계(`App.tsx`)는 `lifeLength`를 읽지 않습니다. `scripts/pipelineLib.ts`가 시드 홀짝으로 `short30`·`long60`을 번갈아 돌리지만 두 모드의 결과가 같습니다. 구현된 것은 LM1(첫 화면 선택)과 LM3(판에 고정)뿐이고 LM2·LM4·LM5(재료만)·LM6·LM7은 비어 있습니다(1절).
2. **지금 모델의 「1배속 수동 약 21분」은 새 글자 수를 넣으면 약 24.8분입니다.** 모델 밖에 있던 것이 세 가지입니다 — 인용 박스(+2.1분), 제목·영향 줄·합쇼체로 늘어난 글자(+1.1분), 한 해 여러 줄(+0.2분). 연출을 그대로 두면 SPEC 목표 하한(25분) 바로 아래에서 시작합니다(1-3절).
3. **SPEC LM2의 초기값(연출 ×1.2 · 결정 카드 26~30 · 기록 카드 제외)은 새 읽기 시간으로 계산하면 닫힙니다.** 지금 세상 28.1~29.7분(카드 24.8~28장), 세 시대 평균 27.4~28.9분입니다(2-6절). SPEC을 쓸 때의 읽기 시간(18초)이 아니라 새 읽기 시간(26초)에서 맞는 값입니다.
4. **판 길이의 민감도는 다음과 같습니다**: 카드 1장 ≈ 0.5분, 연출 계수 0.1 ≈ 1.45분, 카드당 읽기 1초 ≈ 0.44분. 카드 26.5장에서 연출 계수만 1.1~1.3으로 조정해도 **읽기 시간 r이 14~43초 어디로 나오든 25~35분 안에 넣을 수 있습니다**(2-6절). 사람 실측이 모델과 좀 어긋나도 한 단계 보정으로 닫힙니다.
5. **판당 결정 카드 수는 간격 규칙이 위쪽을 막습니다.** 모든 이벤트가 `once: true`(140개 전부)이고 결정 카드 사이 최소 간격이 2년(`MIN_YEARS_BETWEEN_CHOICES`)이라 한 판은 **최대 42~43장**입니다. 30분 모드의 26~30장은 그 62~71%라 가능하지만 상단은 빠듯하고, **1시간 모드의 45~55장은 간격 규칙을 풀기 전에는 수학적으로 불가능합니다**(3-3절). 2차 안건입니다(LD-5).
6. **LM2와 LM5가 서로 부딪칩니다.** LM2 공식은 「Σ(기록 카드 × 입력 시간)」을 판 시간에 더하는데, LM5(와 M7c 5-3절)는 카드 열람 시간을 시간 목표에서 빼라고 합니다. 글자 그대로 읽으면 결정 카드를 읽는 시간(모델의 중심)까지 빠집니다. 이 문서는 **결정 카드의 읽고 고르는 시간은 포함, 카드를 접어 둔 시간·기록 시트가 열린 시간은 제외**로 정리했습니다(2-5절, LD-1).
7. **1시간 모드를 1차에 열면 실제로는 약 38~41분입니다**(연출 ×2.0, 카드 수는 지금 풀의 27장). 「약 1시간」이라는 이름과 실제가 어긋나 R-202가 막았던 「거짓 약속」과 같은 문제가 됩니다. 50분에 닿으려면 연출 ×2.5(조용한 해 한 번에 17.5초)가 필요합니다. 이 문서는 **1차에서는 닫아 두고 표·시험·시뮬레이션까지만 준비**하는 안을 추천합니다(3절, LD-4).
8. **플레이 시간 타이머의 재료는 이미 `App.tsx`에 다 있습니다.** `visible`·`game.paused`·`exitAsk`·`showTitle`·`superseded`·`folded`(M7b)·`noteOpen`(M7c)이 모두 App 수준 값이고 시계의 `running`이 같은 값으로 켜지고 꺼집니다. 엔딩 시안에는 자리까지 있습니다(`mockups/ending.html`). 저장은 **게임 상태의 선택 필드**(스키마 v8 유지)를 추천합니다. 시간을 연출·결정 읽기·접기·기록·그 밖으로 **나눠 기록하면 한 판으로도 읽기 시간 r을 직접 보정**할 수 있습니다(5·6절).
9. **취약한 통계 둘은 「최댓값」과 「임계에 0.1%p 붙이기」가 원인입니다.** 대안은 비율(「빈 해 5개 이상인 판 ≤ 0.5%」)과 모드별 카드 수 판정(평균·하드 상한 근접 비율)이고, 임계는 측정값에서 표준오차 3배 이상 떨어뜨려 잡습니다(7절).
10. **영향 범위가 넓습니다.** 결정 카드 수를 늘리면 20세 이후 경제(`check:economy`·`finalDistribution`)를 다시 재야 하고, `HOLD_MS`·`READ_SEC`·`CHOICE_PACING`·`TIME_TARGET_MIN`을 직접 쓰는 파일이 9곳(`src/core/timing.ts`·`life.ts`, `scripts/simulate.ts`·`simulateLib.ts`·`pipelineLib.ts`, `tests/simulation.test.ts`·`pacing.test.ts`·`progress.test.ts`, `e2e/life.spec.ts`)입니다(2-8절).

## 2. 30분 모드 시간 모델 (LM2)

### 2-1. 공식과 용어

```
판의 시간 T  =  Σ연출  +  Σ결정 읽기                       ← 시간 목표(판정)의 대상
Σ연출        =  k × [ q·Hq + n·Hn + c·Hr + e·E ]  ÷  배속     (Hq·Hn·Hr = HOLD_MS, E = 한 줄 더할 때마다 +대기)
Σ결정 읽기    =  Σ(카드마다) r        r = 글자 읽기 + 고르는 시간 + 인용 읽기(인용이 있는 카드만)
참고(목표 밖)  =  기록 시트가 열려 있던 시간 + 결정 카드를 접어 둔 시간 + 일시정지 + 탭 가림 + 나가기 (LM5)
```

- q·n·c는 조용한 해·서술 해·결정 카드 해의 수이고, e는 한 해에 두 줄 이상 남은 해의 **추가 줄 수의 합**입니다(마일스톤 + 일반 사건 + 결정 결과).
- SPEC LM2의 「Σ(기록 카드 × 입력 시간)」 항은 **목표에서 뺀 참고 항으로 내립니다**(2-5절, LD-1). 기록 카드의 입력 시간은 사람이 얼마나 쓰느냐로 0.8~10분을 오가서 「약 30분」의 대상이 될 수 없습니다.
- 배속은 연출에만 곱합니다(읽는 시간은 배속과 무관). 목표 판정은 **1배속 수동**에서만 합니다. 8배속 + 다음 결정으로는 참고입니다(판정 아님, LM7).

### 2-4. 판당 결정 카드 수와 `CHOICE_PACING` 재조정

|---|---|---|---|
| soft | 23 | 평균 목표 + 약 2.5 → **29** | 판의 상위 15% 정도만 감쇠 |
| softFactor | 0.3 | 0.3 (그대로) | |

## 5. LM6 플레이 시간 표시

### 5-1. 무엇을 세고 무엇을 빼는가

2-5절의 표가 기준입니다. 타이머는 **상태에서 버킷 하나**를 고르는 순수 함수와 그 버킷에 시간을 더하는 누적기로 나눕니다(`decideLifeFocus`처럼 표로 시험합니다).

**버킷** (인생 단계에서만. 앞에서부터 처음 맞는 것):

| 순서 | 조건 | 버킷 | 표시값에 |
|---:|---|---|---|
| 1 | 밀린 화면 · 첫 화면 다시 열기(`showTitle`) · 나가기 확인(`exitAsk`) | `idle` | 제외 |
| 2 | 탭 가림(`visibilityState === 'hidden'`) | `idle` | 제외 |
| 3 | 일시정지(`game.paused`) | `idle` | 제외 |
| 4 | 기록 시트 열림(`noteOpen`) | `note` | 제외 |
| 5 | 결정 카드 대기 중이고 접힘(`pending !== null && folded`) | `fold` | 제외 |
| 6 | 결정 카드 대기 중이고 열림 | `decide` | **포함** |
| 7 | 그 밖(연출 시계가 흐르는 중) | `hold` | **포함** |

- 불변식(시험): **시계의 `running`이 참인 모든 상태는 버킷 `hold`**이고, 자동 선택 타이머가 걸린 상태는 `decide`입니다. 시계와 타이머가 서로 다른 값을 읽어 어긋나지 않게 같은 입력(`App.tsx` 한 곳)에서 만듭니다.
- 룰렛·출생신고·엔딩 단계에서는 더하지 않습니다. 사망 직전 마지막 해까지 셉니다.
- **배속의 영향**: `hold` 버킷은 실제로 흐른 시간이므로 8배속이면 짧아집니다. 목표 판정은 1배속 수동에서만 하므로 **판이 깨끗했는지**를 함께 기록합니다(5-2절의 `offSpeed`·`auto`·`skips`).
- 한 번에 5초를 넘게 건너뛴 시계 틱은 5초만 셉니다(기기 절전·디버거 정지 방어).

### 5-2. 기록할 값과 저장 위치 (LD-6)

게임 상태의 **선택 필드** `play`입니다(없으면 시간을 재지 않은 판 — M8 이전에 시작한 저장).

```
play?: { hold, decide, fold, note, idle,        // 밀리초 정수
         offSpeed, auto, skips, resumes }       // 1배속이 아니었던 hold의 ms · 자동 모드 중의 ms · 「다음 결정으로」 횟수 · 이어하기 횟수
```

- **표시값 = hold + decide** (분:초, 소수 버림).
- `깨끗한 판` = `offSpeed = 0 && auto = 0 && skips = 0`. `resumes`는 새로고침·탭 닫기 뒤 돌아온 횟수입니다(그 해 연출이 처음부터 다시 흘러 hold가 한 해 안쪽만큼 늘 수 있어 보정에서 감안합니다 — 6-3절).
- **저장 위치**: 게임 저장(`suzeo-game:save`)의 선택 필드입니다. **스키마 v8을 올리지 않습니다** — 진행 중인 판을 잃지 않습니다(M7c NC-1과 같은 방식). 값이 이상하면(음수·비정수·문자열·상한 초과) **그 필드만 버리고 판은 그대로 엽니다**(NC-2 「거부하지 않고 걷어 낸다」). 상한은 각 값 24시간입니다. 이 기기의 `localStorage`에만 있고 서버로 가지 않습니다.
- **갱신 시점**: ① 해가 진행될 때 ② 선택·기록 저장·일시정지 전환 ③ `pagehide`·`visibilitychange(hidden)` ④ 인생 화면이 열려 있는 동안 10초마다. 탭을 닫기 직전의 마지막 10초는 잃을 수 있습니다(허용: 닫을 때마다 최대 10초).
- **누적**: 새로고침·탭 닫기 뒤 이어하기는 저장된 `play`에서 이어 쌓습니다. 「다시 태어나기」·「새로 태어나기」는 새 판이라 0에서 시작합니다. 엔딩에 들어가면 더 쌓이지 않고, 엔딩에서 새로고침해도 같은 값이 보입니다. 다른 탭이 저장을 앞서면 기존 「밀린 화면」 규칙(R-011)을 따릅니다 — 이어받은(`adopt`) 판의 `play`를 그대로 씁니다.
- 시간 주입: 누적기는 `now()`를 인자로 받는 순수 함수라 헤드리스에서 합성 시퀀스로 시험합니다. 개발 서버의 `?__timescale=N`에서는 흐른 시간에 N을 곱해 **모델 시간**으로 셉니다(e2e가 30분을 기다리지 않게. 배포 번들에서는 1).
- 대안과 비교: 별도 `localStorage` 키(예: `suzeo-game:playlog`)는 게임 스키마를 건드리지 않지만 판과 어긋날 수 있습니다(저장 삭제·다른 시드의 값 남음, 시드 묶기 필요). 스키마 v9로 올리면 진행 중인 판이 모두 새 게임이 됩니다(C6). 그래서 선택 필드를 추천합니다.

### 5-3. 엔딩 표시와 문구 (designer 몫 — 뜻 초안)

- 위치: 엔딩의 「N번의 선택」 줄 아래(`ending-choices`, `EndingScreen.tsx:138~140`)의 같은 카드 또는 시안(`mockups/ending.html:81`)의 별도 카드. `data-testid="ending-playtime"`.
- 형식: `mm:ss`, 분은 상한 없이 두 자리 이상(61분 5초 = `61:05`, 100분 = `100:00`). 1시간 모드(2차)에도 그대로입니다.
- 뜻 초안(합쇼체): 「이 판의 플레이 시간 27:46」 + 작은 글씨 「일시정지·카드를 접어 둔 시간·기록을 쓴 시간은 뺐습니다. 이 기기에만 저장됩니다.」 (시안의 「(일시정지 제외, 이 기기에만 저장)」을 넓힘). 분해를 보일 때는 「연출 15:10, 결정 읽기 12:36」(쉼표 나열 — QM2-10 가운뎃점 금지). 깨끗하지 않은 판이면 「배속이나 자동 모드를 쓴 판이라 시간 비교에는 쓰지 않습니다.」
- 시각 마크업은 `<time datetime="PT27M46S">`를 쓰면 스크린리더가 시간으로 읽습니다(보조). 대비·글자 확대·줄바꿈 기준(CM10·CM11·QM3-1·QM2-10)은 엔딩 화면의 기존 기준을 그대로 통과합니다.
- `play`가 없는 판(M8 이전 저장)은 **줄을 그리지 않습니다.**

### 5-4. 개인정보

### 6-2. 마스터가 형진 님께 보낼 안내문 초안

> 형진 님, 인생 길이 「약 30분」이 실제로 몇 분인지 한 번 재어 주시면 좋겠습니다. 아래 순서로 한 판을 끝까지 해 주십시오.
>
> 1. 폰에서 https://hyungjin87c-ux.github.io/spoongame/ 를 열고 「약 30분」이 골라져 있는지 확인한 뒤 「태어나기」를 누릅니다.
> 2. 배속은 1배속, 자동 모드는 끈 채로 둡니다. 「다음 결정으로」는 누르지 않습니다. (눌러도 게임은 되지만 이 측정에는 쓸 수 없습니다.)
> 3. 평소 읽는 속도로 읽고 고르시면 됩니다. 서두르거나 일부러 천천히 하지 않으셔도 됩니다. 화면이 꺼지지 않게 충전 중이나 자동 잠금을 길게 해 두면 좋습니다.
> 4. 전화가 오거나 쉬실 때는 「일시정지」를 누르거나 앱을 벗어나셔도 됩니다. 그 시간은 빠집니다. 「생각 남기기」 카드는 쓰셔도 되고 건너뛰셔도 됩니다. 이것도 시간에서 빠집니다.
> 5. 엔딩 화면이 나오면 아래를 알려 주십시오. 엔딩 화면 캡처 한 장이면 충분합니다(이름과 적은 글은 가려도 됩니다). ① 이 판의 플레이 시간 ② 몇 번의 선택 ③ 몇 세에 떠났는지 ④ 태어난 세상(지난·지금·다가올)
> 6. 한 줄만 덧붙여 주십시오. 길다 / 적당하다 / 짧다, 그리고 늘어진다고 느낀 나이대가 있었는지.
>
> 한 판만 해 주셔도 보정이 됩니다. 세 세상을 한 판씩 모두 3판 해 주시면 가장 정확합니다. 이름과 연락처는 적지 말아 주십시오.

(참고: 엔딩에 「플레이 시간」 줄이 없으면 이전 빌드입니다. 그때는 푸터의 빌드 표기를 알려 달라고 덧붙이면 됩니다.)

### 6-3. 결과로 모델을 보정하는 규칙

**읽는 시간 r은 사람이 정하고, 연출 계수·카드 수는 설계 레버입니다.** 같은 판의 분해 기록으로 이 둘을 가릅니다.

1. **깨끗한 판만 씁니다.** `offSpeed`·`auto`·`skips` 중 하나라도 0이 아니면 시간 판정에서 뺍니다(참고로만 기록). `resumes`가 있으면 아래 2번의 허용을 `10초 × resumes`씩 넓힙니다(다시 흐른 한 해 연출의 평균 길이).
2. **연출 시간 점검 (코드 결함 검출)**: `hold`가 **모델 연출 합**(판의 `history`로 q·n·c·추가 줄을 되살려 `k`를 곱한 값)의 **±5%** 안이어야 합니다. 밖이면 읽기 시간이 아니라 타이머·연출의 결함이므로 보정 대신 개발 이슈로 올립니다. 분해 기록이 없으면(캡처에 없으면) 이 점검은 건너뜁니다.
3. **읽는 시간 계산**: `r_판 = decide ÷ 카드 수`. 분해가 없으면 `r_판 = (플레이 시간 − 모델 연출 합) ÷ 카드 수`로 추정합니다(모델 연출 합은 사망 나이·선택 수·시대 평균 서술 비율로 재구성, 오차 약 ±1분).
4. **r 점검**: 모든 깨끗한 판의 `r_판` 평균이 `[낮음, 높음]` 범위(2-2절, 지금 세상 18~35초) 안이면 `median`을 `r_판` 평균으로 바꿉니다(판 수가 1이면 `median`을 `(기존 + 측정) ÷ 2`로 반만 옮깁니다 — 한 판의 변동을 그대로 받지 않으려고). 범위 밖이면 `low`·`high`도 `측정 평균 ± 30%`로 옮기고 마스터에게 보고합니다.
5. **판정**: `median`을 바꾼 모델로 시대별 평균 T를 다시 계산합니다. **세 시대 평균이 27~33분, 시대별이 25.5~34.5분**이면 통과입니다. 한 판의 실측 T가 25~35분 밖이어도 4번의 `r_판`이 범위 안이고 2번이 통과면 모델은 맞고 그 판이 평균에서 벗어난 것으로 봅니다(표준편차 ≈ 2.5분).
6. **밖이면 레버를 이 순서로** 움직입니다: (i) 연출 계수 `holdScale` — SPEC 범위 1.1~1.3 안에서 0.05씩 (ii) 카드 수 — `EVENT_FREQUENCY`(청년·중년·노년)·페이싱으로 ±2장, 판정 구간 안에서 (iii) 둘이 한계인데도 밖이면 **마스터 결정**(목표 구간·「약 30분」 이름 조정). 레버를 움직인 뒤 모델 평균이 27~33분인지 시뮬레이션으로 확인합니다.
7. **다시 재는 조건**: ① 6번의 레버를 움직였을 때 ② `READ_MODEL` 상수나 이벤트·인용의 평균 글자 수가 ±10% 변했을 때(M7d 등) ③ 결정 카드 수 평균이 ±2장 변했을 때 ④ 같은 사람의 두 판이 정규화 뒤에도 20% 이상 어긋날 때(판 수를 늘림). **최대 2회**(SPEC LM7)이고, 그 뒤에도 안 닫히면 마스터가 개입합니다.
8. 8배속 + 다음 결정으로의 시간은 참고로만 적습니다(판정 아님).

**허용 오차 요약**: 사람 실측 판정은 25~35분(SPEC) · 모델 평균 27~33분 · 연출 합 일치 ±5% · 시대 상수 읽기 평균과 카드별 정밀 합계 ±5%입니다.

### 6-4. QA의 몫 — 연출 시간만 실측하고 읽는 시간은 모델

- QA(`qa`)는 **배포용 번들(`e2e:prod` 계열, 시간 배율 없음)에서 1배속 실제 시계로** 연출 시간을 잽니다(8절 QA 항목). 읽는 시간은 AI 체류 시간이 사람과 달라(6.9초, `timingTable.ts` 주석의 QA-001 M3 측정) 재지 않고 모델 값을 씁니다.
- 자동 모드 1배속으로 한 판을 끝까지(약 17~19분) 돌려 엔딩의 `hold` 합이 그 판의 모델 연출 합과 ±2%인지 봅니다(자동 선택은 3초 고정이라 읽는 시간이 섞이지 않습니다 — 가장 강한 연출 실측입니다).

### 6-5. `report:time` (제안)

`npm run report:time`(`scripts/timeReport.ts`)은 시대 × 모드 × 전략 × 판수(기본 1000)를 소비 모드(기록 시트 없음)로 돌려 다음을 출력합니다. **판정이 아니라 보고**이고 불변식 위반이 있으면 종료 코드 1입니다(`report:notes`와 같은 방식).
① 판당 카드 수 분포(평균·분위·하드−1 이상 비율)와 단계별 평균 ② 자연 분포(페이싱 끔) ③ 연출 합(종류별 해 수 q·n·c·추가 줄) ④ 실제 글자 수 표(본문·라벨·결과·제목·영향 줄·인용 요약·출처 줄)와 `READ_MODEL`의 대조 ⑤ 읽기 낮음·중앙·높음·상한별 T의 시대별 평균·분포 ⑥ 카드별 정밀 합계와 시대 상수의 차 ⑦ 기록 카드 참고 시간 ⑧ 8배속 + 다음 결정으로 참고 ⑨ 영유아 수치(`sim:infant`와 같은 정의). 이 표가 이 문서의 △·◇ 칸을 대체합니다.

### 7-4. 임계를 잡는 규칙 (재발 방지)

1. **임계 = 측정값 + 최소 3 표준오차**입니다(평균 지표는 0.35 이상, 비율 30% 근처는 +4.4%p 안팎). 여유가 3 SE보다 작으면 임계를 올려 맞추지 않고 원인(콘텐츠·확률)을 먼저 봅니다. 임계를 올려야 하면 **보고 항목으로 올려 마스터가 승인**합니다(M7a·M7e의 알려진 차이 방식).
2. **최댓값은 판정하지 않습니다.** 분위수·비율을 판정하고 최댓값은 보고합니다.
3. 같은 지표를 세 시드 묶음(1000판 × 3)으로 재서 묶음 사이의 차를 시험 주석에 적습니다(M7a의 방식). 묶음 사이 차이가 임계 여유의 절반을 넘으면 표본을 늘립니다.

**F-1 열기만 한 탭이 저장을 써서 첫 탭이 「밀린 화면」이 됨** (TB01 ×3, 회귀 B03·B03b)

- 규칙 ①: `resumes`는 앱이 뜰 때 올리지 않는다. 저장에서 불러온(또는 다른 탭에서 이어받은) 판은 **그 탭에서 hold 또는 decide가 처음 쌓이는 표본에서 한 번만** +1 한다. 이 탭이 새로 시작한 판은 +1 하지 않는다(`playTimer.ts#samplePlay`의 `resumePending`).
- 규칙 ②: 저장 effect가 아닌 저장(10초마다·`pagehide`·가림 때 flush)은 이 탭이 마지막으로 읽거나 쓴 값과 **`idle`만 다르면 쓰지 않는다**(`storage.ts#isIdleOnlyChange`). hold·decide·fold·note·offSpeed·auto·skips 중 하나라도 늘었거나 인생 상태가 다르면 쓴다. 알던 값이 없거나 읽을 수 없으면 쓰는 쪽에 맡긴다. 상태가 바뀔 때의 저장(선택·기록·해 진행·일시정지 전환)은 전과 같다.
- 5-1·5-2절: 버킷 7줄·표시값(hold + decide)·`play` 9키·스키마 v8은 그대로다. 5-2절의 `resumes`는 「돌아온 횟수」에서 **「돌아와서 시간이 실제로 쌓인 횟수」**로 좁혀진다(표시값에 안 들어가므로 영향 없음). idle은 쓰기 조건에서만 빠지고 `play` 안에는 그대로 쌓인다(새로고침 때 마지막 저장 이후의 idle이 사라질 수 있으나 표시값이 아님).
- 불변식: R-047(열기만 한 탭은 저장소에 쓰지 않아 활성 탭을 밀어내지 못함)과 R-011(다른 탭이 저장을 바꾸면 이 탭은 멈추고 이어받음)을 `play`가 있는 판에서도 지킨다.

**F-2 저장이 막힌 기기에서 열기만 해도 저장 실패 안내가 뜸** (TB02 ×4)
- 원인: F-1과 같다. 부팅 때 `resumes`가 올라 첫 저장이 시도되고 실패했다.
- 규칙: 규칙 ①·②로 열기만 한 탭은 저장을 **시도하지도 않는다**. 실패 안내(`save-notice`)는 **인생 상태를 담는 저장(저장 effect)이 실패한 때만** 뜬다. 10초 주기 flush는 시간 값만 새로 쓰는 보조 저장이라 실패해도 안내하지 않고 다음 주기에 다시 시도한다(13-2절 ②).
- 5-1·5-2절: 갱신 시점 ④ 「10초마다」는 **사람이 한 일(hold·decide·fold·note·skips)이 쌓였을 때만** 쓴다로 좁혀진다. 5-2절의 「닫을 때마다 최대 10초 잃음」 허용은 그대로다.
- 불변식: R-006(저장 실패는 가벼운 안내만 띄우고 앱은 계속 동작)과 NC-11(진행이 없으면 아직 저장을 시도하지 않음, 기록은 메모리·인생 기록에 남고 기존 `save-notice`)이 그대로다.

**F-3 지난 세상 모델 시간이 시대별 하한 25.5분 아래** (Hx1·Hx5 시간, R-415)
- 원인: 연출 계수 1.2에서 지난 세상이 25.24~25.40분으로 하한에 붙었다(측정값에서 3 SE 이상이라는 LD-9 위반).
- 규칙(마스터 결정 ⓐ): `short30.holdScale`을 **1.25**로 한다. 8750(조용한 해) / 21250(서술) / 16250(결과) ms, 둘째 줄부터 줄당 +6250ms(1세 서술 3줄 해 33750ms). **8-1·8-3의 1.2 숫자(8.4 / 20.4 / 15.6초, +6.0초, 32.4초)와 12절의 1.2 기준 예상 판 길이(25.5 / 28.0 / 28.3분)는 이 값으로 대체**한다: 1배속 수동 모델 판 시간은 약 26.2 / 28.7 / 29.0분, 세 시대 평균 약 28.0분(QA 5000판 독립 계산 26.08 / 28.78 / 29.01, 평균 27.96). 판정 구간(시대별 25.5~34.5, 평균 27~33)과 레버 순서(연출 계수 1.1~1.3 → 카드 ±2장 → 마스터)는 그대로이고 1.25가 새 초기값이다.
- 5-1·5-2절: 관계없다(시계 표만 바뀐다). 타이머의 5초 클램프·버킷은 그대로다.
- 불변식: LD-9(임계는 측정값에서 3 SE 이상) — 지난 세상이 하한 25.5분에서 약 0.6분(개발 표본 7.4 SE, QA 5000판 약 19 SE) 위다.

**함께 닫는 것 — R-422 탭 가림** (TB04 RECORD): 탭이 가려져 있는 동안 흐른 시간은 버킷과 무관하게 **idle**이다. 타이머가 `visibilitychange`를 렌더보다 먼저 듣고 표본마다 `document.visibilityState`도 본다(`playTimer.ts#setHidden`, `usePlayTimer.ts`). 5-1절 버킷 2번(탭 가림 → idle)의 시점이 「렌더가 본 때」에서 「가려진 때」로 앞당겨질 뿐 표는 같다. 가림 이벤트 없이 멈춘 시간은 5초 클램프가 상한이다(알려진 한계, 13-3절 TB04-b).

### 13-2. 규칙의 경계 — 두 질문과 추천

**① 보이는 탭이 결정 카드를 10초 넘게 띄워 decide가 쌓여 저장을 쓰는 것 (QA TB03 — 열기만 한 다른 탭이 밀림)을 허용할지: 추천 허용.**
- 규칙 ②의 기준은 「사람이 한 일이 쌓였는가」이고, 보이는 탭에서 결정 카드를 열어 둔 10초는 사람이 읽은 시간이다. 이때 쓰는 탭이 이기고 열기만 한 다른 탭이 「밀린 화면」(「이 탭에서 이어하기」)이 되는 것은 M3부터 있는 마지막 쓰기 우선(R-011) 그대로다.
- R-047의 약속은 「열기만 한 탭은 쓰지 않는다」이지 「다른 탭이 쓴 뒤에도 안 밀린다」가 아니다. 진행 손실은 0이다(`decideSave`의 충돌 판정 그대로, PL16: 되감기·이중 계산 0).
- 쓰지 않으면 새로고침·탭 닫기에서 읽던 시간을 잃어 「잃는 시간 ≤ 10초」(5-2절)를 못 지킨다. 「가장 최근에 입력한 탭만 쓰기」는 입력 추적이 필요해 복잡하고 얻는 것이 없다.
- 가려진 탭은 idle만 쌓여 쓰지 않으므로, 한 번에 한 탭만 보이는 모바일에서는 이 경우가 거의 없다(두 창을 나란히 두는 데스크톱만).
- 코드 주석(`App.tsx#flush`, `storage.ts#isIdleOnlyChange`)과 e2e(`m8-playtime-save` 「허용한 경우」)에 이미 적혀 있다. 승인하면 QA TB03은 RECORD가 아니라 PASS 시험이 된다.

**② 10초 주기 저장 실패가 안내를 띄우지 않는 것 (QA TB02-13s)이 R-006·NC-11과 맞는지: 추천 맞음, 규칙으로 확정.**
- R-006이 안내하려는 것은 **인생 진행을 잃을 수 있는 저장 실패**다. 선택·기록·해 진행은 모두 저장 effect를 지나므로, 저장이 막힌 기기에서는 다음 상태 변화(연출이 흐르면 한 해 안쪽, 8.75초~)에 안내가 반드시 뜬다. 결정 카드를 읽고 있는 동안에는 이미 카드가 뜰 때의 저장이 실패해 안내가 떠 있거나(진행이 있었던 경우) 열기만 한 판이면 잃을 진행이 없다.
- flush가 실패해 잃는 것은 최대 10초분의 시간 값(표시값 오차)이지 인생이 아니다. 여기서 안내를 띄우면 카드를 10초 읽을 때마다 진행이 없는 탭에서 배너가 뜨는데, 진행이 없는 탭의 안내는 R-006·NC-11 시험이 막아 온 것이다.
- 시도는 한다(조용히). 안내 시점 = 「상태가 바뀌는 저장의 실패」 하나로 못 박는다.
