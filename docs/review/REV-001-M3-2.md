### R-036 최종 키보드 동작 (마스터 결정 `ai-log/2026-10-14_SPEC-001_decision-M3.md` 그대로)
- **Tab 순서**: 컨트롤 그룹은 상태와 무관하게 항상 `1배 → 2배 → 4배 → 8배 → 다음 결정으로 → 자동 모드` (6개 모두 Tab 정지점). 선택지가 뜨든 사라지든, 자동 모드가 켜지든 꺼지든 같다. 선택지가 뜨면 선택지 제목·선택지 버튼이 컨트롤 그룹보다 DOM 앞에 생기지만 그룹 안의 순서는 변하지 않는다.
- **"다음 결정으로"가 누를 수 없을 때**(선택지 대기 중, 자동 모드 중): `disabled`가 아니라 `aria-disabled="true"` + 입력 무시. 포커스는 받는다. 클릭·Enter·Space(= 버튼의 click)는 모두 무시되고 흐림(0.55)으로 표시된다. 가드(화면 진입 0.4초)와 합쳐져 둘 중 하나라도 비활성이면 무시, 가드가 풀려도 호출자 비활성은 유지.
- **각 상태에서 Space/Enter**:
  - 수동 + 포커스가 8배(또는 2·4배) 버튼 + 선택지 등장 → 포커스는 그대로(aria-live로 "선택지가 나왔습니다: 제목"). 이때 Space/Enter는 그 속도 버튼을 누른다. **Tab → "다음 결정으로"(비활성) → Space/Enter는 무시**, 한 번 더 Tab → "자동 모드". 자동 모드·선택지·연표는 바뀌지 않는다.
  - 수동 + 선택지 없음 + "다음 결정으로"에서 Enter/Space(또는 마우스) → 연출 없이 다음 결정까지 진행. 선택지가 뜨면 **선택지 제목으로 포커스 이동**(방금 skip을 눌렀다는 명시적 표시 `noteSkip`으로 판단). 그 뒤 Space/Enter(키 반복·연타 포함)는 제목에서 아무 일도 하지 않는다. Tab 한 번에 첫 선택지 버튼(입력 가드 0.4초 동안은 무시).
  - 자동 모드: 선택지가 떠도 포커스 이동 없음. "다음 결정으로"는 비활성(Tab으로는 닿고 Space는 무시). 자동 모드 버튼에서 Space → 해제.
  - 복원(새로고침)으로 선택지가 이미 있는 채 열림: 수동은 선택지 제목, 자동은 인생 화면 `h1`.
  - 키보드로 선택지를 고른 뒤 포커스가 body로 떨어지면 인생 화면 `h1` → 다음 Tab부터 `1배 → … → 자동 모드` 순서로 컨트롤 그룹.
- **R-048(자동 모드를 끄는 순간)**: 선택지가 대기 중인 채 자동 → 수동으로 바뀌면 같은 규칙 재적용 — 포커스가 컨트롤 안(자동 모드 버튼 등)이면 이동 없이 aria-live 알림, 그 밖(body·제목 등)이면 선택지 제목. 다시 켜면 알림 문구를 지운다.
