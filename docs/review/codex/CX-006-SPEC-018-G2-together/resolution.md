### CX-006-001 (중간) — 느린 독자 줄별 판정이 설명보다 느슨해 40분을 넘는 줄을 통과시킨다
- **재현**: 예. `tests/judgeMargins.test.ts`의 줄별 단언은 `u.margin < 2 && !isKnownUnder3({ ...u, margin: u.margin + 1.5 }, true)`라, 줄별 예외의 `floor`가 F면 실제 여유 F − 1.5 SE까지 통과한다. 마스터가 넣은 `{ 느린 독자, alpha, floor: 0, lineOnly }`는 실제 −1.5 SE까지 허용했고, 주석의 「줄별 0 SE(상한을 넘지 않음)」와 달랐다. Codex가 잰 알파 시험 · 자동 성향 줄 40.15 ± 0.12분(−1.22 SE)은 G2 개발 측정의 「줄 하나 −1.2 SE」와 같다.
- **원인(마스터 실수)**: 개발 에이전트가 제안한 예외 줄을, 줄별 판정에 1.5 SE 덧여유가 붙는다는 것을 다시 따져 보지 않고 넣었다. 같은 파일의 이전 줄별 예외(노년 genx `floor` 1.5 = 「하한 아래로 내려가지 않음」)는 이 뜻을 바르게 적고 있었다.
- **처리 — 형진 님 결정 후속 264**:
  1. 느린 독자(읽기 「높음」) 시대별 평균 상한 **40 → 40.5분** — `scripts/marginsLib.ts#READER_HIGH_LIMIT_MIN`(새 상수) · `tests/simulation.test.ts` 「읽는 시간 수준별 보고」. 세 시대 평균 상한 36 → 36.5분(후속 263 ②)과 같은 원인(판당 부모 카드 약 0.36장)·같은 폭이고 내용은 줄이지 않는다.
  2. 줄별 예외의 뜻을 「임계를 넘지 않음」으로 되돌렸다. 느린 독자 예외 두 줄(합친 `floor` 1.5 · 줄별 `floor` 0)은 새 상한에서 여유가 생겨 목록에서 뺐다. 남은 줄별 예외(노년 genx · 알파 95% 분위)는 둘 다 `floor` 1.5 = 실제 여유 ≥ 0 SE다. 알파 95% 분위 주석의 「줄별 한계 1.5 SE」도 「실제 여유 ≥ 0 SE」로 바로잡았다.
  3. 줄별 단언을 이름 있는 함수 `lineAlert`와 상수 `LINE_SLACK_SE`(1.5)로 꺼내 주 시험과 경계 시험이 같은 식을 쓰게 했다.
- **추가 시험**(`tests/judgeMargins.test.ts`):
  - 「줄별 예외의 실제 뜻 (Codex CX-006-001)」 — 모든 줄별 예외 `floor` ≥ 1.5 · 95% 분위·노년 genx는 실제 여유 0 허용 / −0.01 경보 · 느린 독자는 예외 없음(−1.22 SE · 1.99 SE 경보, 2 SE 통과) · 예외는 적힌 시대에만 · 합친 판정은 줄별 예외를 쓰지 않음 · 합친 예외(알파 노년 −7.0)는 덧여유 없이 그대로 · 목록의 지표 이름이 실제 지표 이름과 같음(이름이 바뀌어 예외가 조용히 빠지지 않게).
  - 「느린 독자 상한 40.5분 · 95% 분위 한도 41분」 — 두 상수 값 고정.
- **재검증(마스터)**: `npm exec -- vitest run tests/judgeMargins.test.ts tests/simulation.test.ts` — 2파일 · 50 통과(513초, `marginReport(1000)` 12,000판 재측정 포함 — 느린 독자 예외 없이 줄별 경보 0) · `tests/codingRules.test.ts`·`tests/repoHygiene.test.ts` 24 통과 · `npm run typecheck` 통과 · `npm run check:todo` 실패 0. 전체 `npm test`는 돌리지 않았다(바뀐 파일이 시험 2개와 측정 도구 1개뿐 — v0.6.1 배포 전 T3에서 돈다).
