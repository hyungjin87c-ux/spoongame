## 브라우저 적대적 QA

Windows Chrome 157 데스크톱 1280×800, Playwright의 격리된 임시 프로필을 사용했다. `npm run dev`는 연결된 모듈의 캐시 쓰기에 실패했다. 작업 폴더 캐시를 지정하면 기동했으나 Chrome의 루프백 연결과 개발 모듈 요청이 실패했다. 최종 QA에서는 대상 코드의 Vite 빌드 결과를 메모리에 생성하고 Playwright에서 그대로 응답해 실제 DOM·앱 세션·로컬 저장을 검증했다. 개발 서버의 HTTP 전송 경로 자체는 미확인이다.

- 밀레니얼 시드 4의 19세 첫 진행 직전 저장에서 앱을 진행했다. 분야 카드 `[machine, professional, clerk]`가 새로고침 및 페이지 이탈 후 뒤로 가기에서 같은 키·순서로 복원됐다. `machine`을 더블클릭하자 19세 선택 줄 하나가 남고, 20세에 `[mach-assy, mach-drive, mach-car]`가 열렸다.
- 같은 세부 카드 원문을 별도 프로필에서도 열었다. 새로고침과 시트→자동 인라인→수동 시트 전환에서 키·후보가 같았다. 두 경로에서 `mach-drive`를 더블클릭하면 20세 합격 줄 하나와 같은 직업·지원 횟수가 남았다.
- 세부 대기의 후보 한 개를 `removed-job`으로 바꿔 다시 열면 20세에 카드를 다시 만들고 모르는 ID를 제외했다. 이 경우 저장 계약의 같은 해 재진행으로 `rngState`가 2200060399→3399790542로 바뀌었다. 정상 복원에서는 분야 카드의 `rngState`가 같았다.
- 같은 시드에서 이미 합격한 원문의 직업 ID만 `removed-job`으로 바꾸자 21세에 다시 지원할 수 있었고, `clerk-sme` 합격 때 `incomeAdj`가 1,200→2,400이 됐다(001).
