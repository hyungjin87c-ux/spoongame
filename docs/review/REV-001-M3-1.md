### R-035 실측 (수정 전 → 수정 후)
- 방법: 알려진 시드(20261013)의 출생 저장을 주입하고 "살아가기"를 더블클릭(`mouse.dblclick`)·같은 좌표 빠른 3연타. 버튼 폭의 1/8·1/4·3/8·1/2·5/8·3/4·7/8 지점(= 좌 1/4·우 1/4·중앙 포함) × 출생 문구 3종(재력 1·3·5단계, 문구 길이가 달라 버튼 높이가 다르다) × 입력 2종 = 뷰포트당 42회. "이 탭에서 이어하기"는 저장을 주입한 인생 화면에서 storage 이벤트로 밀린 화면을 만든 뒤 같은 방식으로 7지점. 매회 새 브라우저 컨텍스트, 시작 화면 버튼의 가드가 풀린 뒤 클릭. "상태 변함" = `settings.speed`·`autoMode`·`age`·`pending` 중 하나라도 바뀜(저장과 화면 모두 확인). "닿음" = 둘째 입력이 어떤 버튼 위에 떨어짐(1배 버튼은 이미 1배라 닿아도 상태가 안 변한다).
- 대조군 `?__guard=0`은 모든 가드를 끈 상태라 수정 전/후가 같다(재력 3단계 × 7지점 × 더블클릭 = 7회). 수정 후 기본 가드 열의 "(가드 N)"은 닿은 N회가 모두 닫힌 버튼(aria-disabled)에 닿아 무시됐다는 뜻이다.

1. 컨트롤 가드는 인생 화면이 마운트될 때마다 걸린다 — 새로고침 직후에도 0.4초 동안 속도/자동 모드 버튼이 안 눌린다(전환 직후가 아니라도 마운트 기준이라 구분하지 않음).
2. 선택지가 사라질 때 포커스가 body로 떨어졌으면 인생 화면 제목(이름 `h1`)으로 보낸다(대안: 나이 줄). 자동 모드에서는 옮기지 않는다.
3. 수동 모드에서 포커스가 컨트롤 안에 있으면 "선택지가 나왔습니다: {제목}"을 `aria-live`(`.sr-only`)로만 알린다. 자동 모드는 알리지 않는다(선택지마다 소음이 되므로).
4. R-039는 "수동 선택도 난수 1회 소비" 방식을 골랐다(주 수열에서 한 칸 예약). 자동 선택 전용 파생 수열은 저장 필드·복원 규칙이 늘어 쓰지 않았다. 저장 모양이 안 바뀌어 `SCHEMA_VERSION`은 올리지 않았다.
5. R-047의 "첫 저장 생략"으로 개발 전용 `?__quota` 환경에서 저장 실패 안내가 로드 직후가 아니라 첫 진행(저장 시도) 때 뜬다 — 잃을 진행이 없는 시점에는 안내하지 않는 쪽이 맞다고 보고 테스트를 맞췄다.
6. TODO에 새 항목을 만들지 않고 기존 항목의 근거를 현행 이름으로 갱신했다(R-040 지침과 항목 신설 승인 범위를 넘지 않기 위해).
