## 2. 코드

- 줄 키 `나이-종류-이벤트id-n`이 SPEC의 「저장 인덱스 키」와 다른 것은 **타당**: 인덱스 키면 상한에서 출생 다음 줄이 지워질 때 300개 키가 모두 다른 내용을 가리켜 모든 줄이 갱신되고 보정도 깨진다. 지금 키는 충돌할 수 없다(나이·n은 숫자, 종류에 하이픈 없음, 같은 base는 n으로 갈림). 남는 경계(상한에서 같은 base 줄의 n이 당겨짐)는 정상 플레이에서 무시할 수 있다(지적 아님).
- 위치 보정: 업데이트 직전 보이던 첫 줄(키)·오프셋 → 직후 같은 키의 실제 이동량만큼 이동. 굵은 글씨가 풀려 줄바꿈이 바뀌는 것까지 흡수. 보던 줄이 지워진 경우·다른 판으로 바뀐 경우·부드러운 스크롤 처리까지 갖춤.
- 300줄에서 새 줄 수: `addedAbove`가 지난 맨 위 줄의 새 위치로 셈(길이 그대로여도, 시험 있음).
- live region: 키가 안정적이라 기존 `li` 재사용(e2e 확인), 상한에서도 새 `li` 하나만. 관찰: 한 번에 여러 줄이 붙으면 최근 → 과거 순으로 읽힘(QA NVDA 관찰).
- 성능: 레이아웃 강제는 갱신마다 한 번, 8배속 e2e에서 프레임마다 ≤ 2px.
