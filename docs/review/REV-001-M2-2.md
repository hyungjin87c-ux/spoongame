### D. 이어받으며 추가로 고친 것 (REV 지적 아님)
- `e2e/robust.spec.ts` "키보드만으로 타이틀부터 사망까지 진행할 수 있다 (Tab·Enter·Space)": 첫 e2e 실행에서 1건 실패(부하가 큰 병렬 실행에서 약 1/80 재현). 원인은 **테스트의 경쟁 상태**였다 — 연출을 500배로 줄인 상태에서 첫 선택지가 뜰 때 앱이 의도대로(R-030) 포커스를 선택지 제목으로 옮기는데, 그 순간이 Tab 이동 도중이면 Space가 엉뚱한 곳에 눌렸다. 앱 동작은 맞고 테스트가 화면이 안정되기 전에 키를 눌렀으므로 테스트만 고쳤다(선택지가 떠 시간이 멈추고 포커스가 제목에 놓일 때까지 기다린 뒤 Tab 이동). 검증: 고치기 전 `--repeat-each=40 --workers=10`에서 1건 실패 재현 → 고친 뒤 `--repeat-each=80 --workers=12`(160회) 전부 통과. 검증 방식은 약화하지 않았다(자동 모드를 Space로 켜고 사망까지 가는 단언은 그대로).
- `docs/data/events-schema.md`·`src/data/events/index.ts` 주석: "`npm run build` 첫 실행에서 잘못된 이벤트 데이터가 예외로 드러난다"는 문장이 사실이 아니었다(실측: 오타 낸 이벤트 파일로 `npm run build`가 성공). 앱을 열 때와 `npm test`에서만 잡힌다고 정정했다.
- 죽은 코드 삭제: `src/core/timing.ts#isSpeed`(어디서도 호출되지 않음, 세션 reducer는 `SPEEDS.includes`를 직접 쓴다), `src/data/birthTable.ts`의 `eventPoolId` 필드(M2 자리표시였고 M3에서 이벤트의 `eras` 필터로 시대별 풀을 만들기로 해 쓰이지 않음). 삭제 전후로 `typecheck`·`npm test`·`build`·`e2e`를 다시 돌려 영향이 없음을 확인했다.
