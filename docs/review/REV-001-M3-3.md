## QA 공격 지점 (최종본)
1. 터치 더블탭: "살아가기"·"이 탭에서 이어하기" 더블탭·3연탭(360×480~740, 가로). 자동 모드 켜짐·8배 저장 상태에서도
2. 키보드(R-036): 2·4·8배 포커스 → 선택지 등장 → Tab → Space/Enter는 무반응이어야 함(한 번 더 Tab → 자동 모드 Space는 켜지는 것이 정상, 기록만). "다음 결정으로" Space/Enter 연타·길게 누르기 → 선택지 제목 포커스, 선택 확정 없음. 흐린 "다음 결정으로" 클릭 무반응. 1배에서 Shift+Tab. 선택 뒤 Tab 5번에 "다음 결정으로"
3. 자동 모드 해제(R-048): 선택지가 떠 있는 순간 해제 후 포커스·안내. 8배속 자동 선택 직전 해제 — 해제가 화면에 보인 뒤 한참 있다가 선택이 확정되면 실패. 빠른 켜고 끄기 반복
4. 진입 직후 0.4초: 속도·자동 버튼 무반응·흐림, 자동 모드 내내 흐린 "다음 결정으로"
5. 다중 탭: 열기만 한 둘째 탭이 첫 탭을 밀어내지 않는지 / 탭 주고받기 반복 / 탭 복제 / 빈 저장소에서 두 탭 동시 열기(나중 탭이 밀려도 "이어하기" 한 번에 탈출) / 나란히 둔 두 창이 둘 다 진행 중이면 다시 밀리는 것은 예상 동작(기록만) / 밀린 화면에서 멈추거나 오류 화면이면 실패
6. R-052 회귀 감시: 단일 탭에서 저장을 건드리지 않고 플레이하는 동안(새로고침 연타, 탭 가림·복귀, 8배+자동 포함) 밀린 화면이 한 번이라도 뜨면 실패
7. 저장 차단: 빈 저장소는 즉시 안내, 기존 저장이 있으면 첫 진행 때 안내. 복구 시 사라짐
8. 저장 변조: 변조 → 새로고침 / 같은 탭 콘솔에서 저장을 바꾸거나 지운 뒤 새로고침 없이 진행(밀린 화면 → 이어하기 → 유효하면 그 상태, 없거나 손상이면 새 게임 — R-054 예상 동작) / 엔딩에서 저장 키만 지우고 새로고침(새 게임, 설정 유지)
9. 새로고침 연타: 선택지 대기 중, 선택 직후, 8배+자동 중, 사망 순간
10. 프로덕션: `npm run e2e:prod`, `vite preview`에서 정상 3판, 이벤트 JSON을 일부러 깨고 `npm run check:events`(원복 필수)
11. 유지: 시간 실측은 기록만(R-037), 360×568·640에서 3지선다 + 안내 + 자동 문구 겹침, 배속 연타, 첫 선택지 전 사망 문구, 엔딩에 재시작 수단 없음, 자동 모드가 켜진 채 새 판 시작

### 임의로 정한 것 (이견 있으면 알려 주세요)
1. 이벤트는 110개로 만들었다(요구는 60개 이상). 시대·단계 칸마다 후보를 넉넉히 두어야 판당 선택지 20~25개가 풀 부족 없이 나오고(조건부 이벤트가 많아 실제 후보는 6~7할), 한 판에 쓰이는 이벤트는 약 35개(전체의 3할)라서 다시 해도 다른 사연을 만난다.
2. 판당 선택지는 평균 약 23~24개로 맞췄다. 확률만으로는 33개까지 늘어 1배속 시간 상한을 넘으므로 **한 판의 선택지 수 조절**(부드러운 상한 23 이후 확률 x0.3, 하드 상한 26)을 엔진에 추가했다(`CHOICE_PACING`). 단계별 확률은 노년이 굶지 않도록 중년을 낮추고 노년을 높였다.
3. 8배속 + 다음 결정으로의 시간은 읽는 시간 중앙 가정(18초)에서 약 7.2~7.6분으로 목표 "약 8~10분"의 아래쪽이다. 선택지 20~25개와 중앙 18초를 함께 지키면 8분에 닿지 못하고(25개여도 약 8.2분), 24초(QA 실측 상단)에서는 9.5~9.9분, 30초에서는 11.8~12.3분이다. 선택지 수를 늘리지 않고 가정을 바꾸지 않은 채 그대로 보고한다. 선택 결과 문구를 읽는 시간(약 4초)은 건너뛰기 모드 모델에 들어 있지 않다.
4. 행복·관계의 평균 회귀는 표(MOOD_DRIFT) 한 곳에서 정하고, 영유아기(0~6세)에는 적용하지 않는다(출생값은 어린 시절의 사실).
5. `docs/data/events-distribution.md`는 손으로 쓰지 않고 데이터에서 생성하며, 테스트가 문서와 데이터의 일치를 지킨다. 모티브 한 줄은 `scripts/eventMotifs.ts`에 있다.
