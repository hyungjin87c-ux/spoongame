## 배경

- 지금 외모는 「또래 사이에서 상위 약 46%」처럼 퍼센트로만 말한다(출생신고·프로필·엔딩 세 자리, `standingLabel(looksStanding)`). 형진 님 피드백: 퍼센트 대신 **이목구비를 간단히 서술**해 달라(예: 「이목구비가 뚜렷하고, 잘생겼다」 · 「눈이 작고 눈썹이 진하고 피부가 좀 탄 느낌이었습니다」).
- 2026-11-08 형진 님 확정(후속 205·206): **시안 B**(첫인상 한 줄 + 특징 하나)를 세 자리에 같은 글로 쓰고 프로필 칸에는 첫 문장만 쓴다 · 가장 높은 단계는 「잘생긴·예쁜」 허용 · **피부색 낱말은 넣되 외모 단계와 무관하게 임의로**(낮은 단계에 몰리지 않게), **그림 피부색은 그대로** · 퍼센트는 뺀다 · 점·보조개 허용 · 0~6세 어휘 제한(광대·턱선·갸름 제외) · 1단계 첫인상 「옅은 편인」은 designer 제안대로.
- 이 SPEC은 **문구 데이터 + 순수 함수 하나 + 화면 세 곳**이다. 저장 구조·확률·난수 수열·외모 점수는 건드리지 않는다. 다음 배포(SPEC-013 시대의 창 개편 · SPEC-014 질문 문장)와 같은 배포에 싣는다.

### 읽어서 확인한 사실

- 외모 단계는 이미 `looksTierOf(looks)`(5단계: 상위 10% · 11~30% · 가운데 40% · 하위 11~30% · 하위 10%)로 얼굴 그림이 쓴다. 글도 같은 5단계를 쓰면 **그림과 글의 단계가 같은 경계**다(시안 9절).
- 외모 값은 `Character.looks`(0~100) 고정이고 한 판에서 안 변한다. 글은 **저장하지 않고 매번 같은 입력(`Character`·`Game.seed`)에서 다시 만든다**(시안 11절). `Game.seed`(최초 난수 시드)는 저장돼 있고 불변이라 같은 인물의 글을 세 자리에서 같게 만들 수 있다. 이 시드로 **갈라낸**(`forkRng`·`mixSeed`) 별도 수열을 쓰면 인생 진행 난수(`rngState`)를 소비하지 않는다.
- 성별은 `male | female` 둘이다 — 「잘생긴·예쁜」 분기는 이 값 하나로 된다.
- 화면 자리: 출생신고 격자 「외모」 칸(`BirthScreen.tsx`, 지금 반쪽 칸 8자/줄) · 프로필 카드 `data-testid="profile-looks"`(`Cards.tsx`, 12~14자/줄) · 엔딩 최종 스탯 `data-testid="final-looks"`(`EndingScreen.tsx`). 보조 문구 `BIRTH_TEXT.looksSub`(「또래 사이에서」)는 세 자리가 같이 쓴다.
- 출생 체중의 「(3.3kg은 상위 약 N%)」와 엔딩 도착 자리의 `standingLabel`은 **외모와 별개 자리**라 그대로다.
- 출생신고·엔딩 글은 판 길이 시간 모델의 입력이 아니다(`lifeTable`·`life.ts`의 읽기 글자 수는 선택지 카드만 — 코드 읽음). developer가 `report:time` 한 번으로 불변을 확인한다.

## 글 규칙 (AP1·AP2·시험의 기준 — 시안 2절을 계승하고 이번 결정을 반영)

1. **구조**: 첫 문장 = 첫인상(단계·성별이 정하는 고정 수식구) + 명사·어미(자리가 정함). 둘째 문장 = 특징 하나(B군 · 점·보조개 · 움직임 · 피부 낱말, 5·1단계는 A군 둘째 축도 가능). 첫 문장의 수식구는 **(단계, 성별)로만 정해지고** 난수·나이·자리에 따라 바뀌지 않는다.
2. **단계 ↔ 첫 문장 1:1**: 5단계에 서로 다른 수식구가 하나씩이고 같은 수식구가 두 단계에 나오지 않는다. 5단계만 성별로 둘(남·여)이고 1~4단계는 성별 무관 하나다.
3. **평가 낱말**: 「잘생긴」은 5단계 남, 「예쁜」은 5단계 여에만 나온다. 「미남」「미인」「훈남」「꽃미남」 등 다른 평가·성별 낱말은 0. 낮은 단계에는 평가가 아니라 서술(「순한 인상」「옅은 편」)만 쓴다.
4. **금지 낱말 0**: 시안 2절 목록(못생긴·볼품없는·투박한·촌스러운·밋밋한·느끼한·평범한·납작코·주걱턱·짝눈·뻐드렁니·여드름·뚱뚱한·마른·몸 낱말 전부) + 피부 금지(칙칙하다·거무튀튀하다·창백하다·잡티·피부가 나쁘다·피부가 좋다 등 designer가 AP1에서 목록 확정) + 실존 인물·연예인·직업 비교 0 + 수염·화장·쌍꺼풀 낱말 0 + 느낌표·이모지 0.
5. **피부 낱말은 색·햇볕 반응을 중립으로 말하는 것만**(「피부가 흰 편이다」「피부가 가무잡잡하다」「햇볕에 잘 탄다」 같은 꼴 — 정확한 낱말은 AP1). 어느 단계에도 같은 확률로 붙는다.
6. **광대·턱선·갸름은 전 나이에 0**(구현 편차 (가), 2026-11-09 — 「볼이 둥글다」「볼살이 통통하다」 같은 낱말로 대신). 7세 이후 어휘는 이 세 낱말 계열을 뺀 시안 표대로.
7. **글자 수**: 프로필(첫 문장만) ≤ 24자▲ · 출생신고·엔딩(두 문장) ≤ 36자▲, 상한 각각 36·54자(시안 8절).
8. **같은 인물은 언제나 같은 글**: 세 자리에서 바뀌는 것은 명사(아기/아이/얼굴)·어미(~입니다/~이었습니다)와 둘째 문장의 유무뿐이다.

## 완료 기준

기능:

1. **(단계 ↔ 첫 문장 1:1)** 외모 값 0~100 전 구간 × 성별 2 × 세 자리 × 나이대(0 · 3 · 7 · 19 · 20 · 50 · 80세)에서 첫 문장의 수식구는 (단계, 성별)로만 정해진다. 1~4단계 수식구는 성별과 무관하고 서로 다르며, 5단계는 남·여가 다르고 다른 단계와 겹치지 않는다. 「잘생긴」은 5단계 남에게만, 「예쁜」은 5단계 여에게만 나온다.
2. **(피부 독립)** ① 구조: 같은 시드·같은 성별이면 외모 값이 0~100 어디든 **피부 낱말 유무·종류가 같다**(피부 선택이 단계·외모값을 읽지 않는다). ② 통계: 고정 시드 범위(단계당 ≥ 5,000 표본, 결정적)에서 단계별 피부 낱말 포함률의 최대−최소 ≤ 3%p▲, 피부 낱말 하나하나의 단계별 비중 차도 ≤ 3%p▲(낮은 단계에 몰리지 않는다). 전체 포함률은 25%▲(결정 Q1 (가)) ±3%p▲.
3. **(금지 낱말 0)** 글 규칙 4의 금지 목록·성별 평가 낱말(「미남」 등)·「~요」·느낌표·이모지가 어떤 입력 조합에서도 0건. 퍼센트(「%」)·「또래 사이에서」·「상위」·「하위」가 세 자리 외모 줄에 0건.
4. **(같은 인물, 세 자리 같은 글)** 같은 `Character`·시드에서 세 자리 글의 명사(아기/아이/얼굴)·어미를 정규화하면 **낱말 열이 같고**, 프로필 글은 출생신고 글의 첫 문장과 정규화 뒤 같다. 둘째 문장이 출생신고와 엔딩에서 같다.
5. **(결정성)** 같은 입력으로 두 번 부르면 같은 문자열이다(`Math.random`·`Date`를 읽지 않는다). `looksText` 호출이 `rngState`·`generateBirth` 결과·가족 골든(L0F)을 바꾸지 않는다(`git diff` 불변). 다른 시드는 둘째 문장이 고루 갈린다(단계마다 둘째 문장 종류 ≥ 15▲, 한 문장 점유 ≤ 15%▲).
6. **(저장 불변)** `SCHEMA_VERSION`·`Game`·`Character` 타입이 그대로이고 새 저장 필드가 없다. 옛 저장(v0.4.1·v0.4.0·v0.3.0 fixture)이 열려 새 서술로 보이고 `save → load → save`가 바이트 동일이다.
7. **(어휘·글자 수)** 전 나이 글에 광대·턱선·갸름이 0건(구현 편차 (가)). 글자 수가 글 규칙 7의 상한을 넘지 않는다(출생신고·엔딩 ≤ 54자, 프로필 ≤ 36자). 글꼴 조각 밖 글자 0(`tests/fonts.test.tsx` — 밖의 글자가 꼭 필요하면 s2·s3만 다시 만든다, s0·s0b·s1 불변).
8. **(화면)** 출생신고 「외모」 칸이 한 줄 전체이고 두 문장, 프로필 `profile-looks`는 첫 문장만, 엔딩 `final-looks`는 두 문장. `looksSub`·퍼센트 외모 줄이 `src/`에 남지 않는다(출생 체중·엔딩 도착의 `standingLabel`은 남는다). 360px·글자 200%·다크에서 가로 넘침 0·겹침 0.
9. **(승인)** AP1의 낱말 표·예시 묶음을 형진 님이 승인했고(승인 기록은 `docs/design/appearance-text-draft.md`의 확정판 절) 승인된 낱말만 데이터에 있다.
10. **(예산)** 초기 로드 gzip ≤ 400,000B(`npm run e2e:prod`), 증가가 +1,500B▲를 넘거나 SPEC-013·014와 합쳐 +9,500B▲를 넘으면 마스터에게 보고. `report:time` 불변.
11. **(회귀)** `npm run build`·`npm test`·`npm run e2e`(출생신고·엔딩·인생 화면을 보는 파일)·`npm run e2e:prod` 통과. 바뀐 기대값 외에 지워진 시험이 없다.
