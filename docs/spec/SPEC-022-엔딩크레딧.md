## 배경
엔딩의 「출발선 대비 자리」는 와닿지 않아 삭제하기로 했다(후속 256, CX-004-001). 그 대신 형진 님이 Codex에 엔딩 크레딧의 기획·디자인을 맡겼고(DSN-001), 「이 삶의 이름들」(후속 257)과 끝의 「수저 변화」(후속 257 추가 요청·258·259·260)를 정했다. 이 명세는 그 결정을 구현 가능한 문장으로 옮긴 것이며 새로 기획하지 않는다. 이름 크레딧은 경제와 무관해 먼저 나가고, 수저 변화는 마칠 때 수저가 게임의 노년 순자산에 달려 있어 노년 경제 보정(SPEC-020)이 끝 수저 분포를 고른 뒤에 켠다.

## 할 것

### EC1 이름 크레딧 「이 삶의 이름들」 [STANDARD · v0.6.1]
화면과 줄 모양의 정본은 plan-2 3·4·8·9·13절이다. 아래는 구현자가 시험으로 옮길 수 있게 줄인 계약이다.

1. **진입 버튼**: 회고 화면 `EndingScreen`(기존)에 「이 삶의 이름들 보기」 버튼 하나를 둔다(`data-testid="ending-credits-open"` 새). 누르기 전에는 아무것도 시작하지 않는다.
   - 진입부는 plan.md 3절대로 제목 「이 삶의 이름들」 · 설명 한 줄 「이름과 시간을 다시 펼칩니다.」 · 버튼의 순서다(모양은 시안 `mockups/ending-entry.html`, 문구는 `copy.md`). 제목·설명은 조작 요소가 아니고 버튼은 이 하나뿐이다.
   - 자리: **사망 줄·선택 횟수 카드(`ending-death`·`ending-choices`가 든 섹션, 기존) 바로 아래, 최종 스탯(`ending-stats`, 기존)·연표 위.** SPEC-017의 사망 기록 서류가 아직 없는 지금 엔딩 기준이다. SPEC-017 구현 뒤에는 「서류 바로 아래」(plan-2 2절)로 그쪽에서 맞춘다.
   - `GuardedButton guardKey={ENDING_GUARD_KEY}`(기존)로 만든다 — 인생 화면 마지막 입력의 둘째 탭이 떨어져 크레딧이 열리지 않게 한다.
   - 새로고침·이어하기는 저장된 회고를 열 뿐 크레딧을 자동 시작하지 않는다. 첫 장면(SPEC-017)에서 크레딧으로 이어 자동 재생하지 않는다.
2. **줄별 데이터 계약**(논리 항목 기준. 새 저장 필드 없이 종료 상태에서만 파생한다. 줄 문자열의 꼴은 plan-2 13절 전문과 같다):

   - 이름·선택·시대의 최대 논리 항목은 21 + 4 + 3 = 28개이다. 사람이 21명을 넘는 모델이 생기면 이름을 자르지 않고 정지 목록으로 바꾼다.
   - 명단 순서: 어머니 → 아버지 → 조부모(pgf·pgm·mgf·mgm) → 형제(o1~ 다음 y1~) → 배우자/연인 → 자녀(c1~) → 친구(f1~). `role`과 `key`로 정하며 `familyCardOf`의 기존 정렬과 같다.
   - 호칭은 `CardRow.label`(기존)을 그대로 쓴다(「전 배우자」·「연인」·「멀어진 친구」 포함 — plan.md 4절 「확정 호칭만 따른다」). 호칭을 역할에서 다시 만들지 않는다.
   - 같은 이름의 서로 다른 key는 둘 다 남긴다. 사인·추모 표식·관계 점수·「끝까지 곁을 지킨」 같은 해석을 붙이지 않는다. 별세한 사람도 같은 크기·같은 호칭 규칙이다. 이 명단은 기존 카드가 확인하는 사람이며 과거 인연 전체의 복원이라고 쓰지 않는다.
   - 줄의 나이는 `core/format.ts`의 `ageText`(기존)를 거친 한국 나이다. 단계 판정과 시대 줄의 20세 조건은 게임 나이다.
3. **본인 큰 결정(최대 4)**: `history`를 저장된 순서로 읽어 **단계(학창 7~19 · 청년 20~39 · 중년 40~64 · 노년 65 이상, `lifeTable`의 게임 나이)마다 첫 적격 기록 한 건**을 고른다.
   - 적격 = `kind: 'choice'` + `by === undefined`(부모·자녀가 정한 일 제외) + 사건 ID가 허용 목록(plan-2 4-1의 38개 표 — 확인 3)에 있음. 허용 목록은 **데이터 파일 한 곳**(새, 크레딧 덩어리 안)에 두고 코드에 ID를 흩어 적지 않는다. 그 파일의 설명에 지금 규칙의 사실을 적는다 — `school-early-work`·`school-family-priority`·`school-career-choice`·`school-high-pick` 넷은 부모 결정 분류표(`src/data/parentDecisionTable.ts`)가 사건 나이 전 구간(게임 12~17세)을 부모·흘러감으로 정해 본인 선택 기록이 새로 생기지 않고, `school-exam`(게임 16~19세)은 게임 19세에 일어난 때만 본인이며, `school-career-choice`·`youth-first-job`은 맞춤 인생 판에서 추첨되지 않는다.
   - 효과·돈·합격 여부·선택 라벨·긍정/부정으로 순서를 바꾸지 않는다. 같은 단계에서 앞 index가 이긴다. 미루기·거절도 같은 자격이다. `by` 없는 옛 기록은 본인 선택으로 읽는다(plan-2 4-1).
   - 빈 단계를 일상 선택·부모 결정·알 수 없는 ID로 채우지 않는다. 직무 지원 기록을 실제 직업으로 바꿔 쓰지 않는다. 현재 사건 데이터로 제목·질문을 소급 교체하지 않는다.
4. **시대 줄(최대 3)**: `eraRowsOf`(기존) 결과 중 청년·중년·노년 단계마다 가장 이른 줄 한 건. 조건은 모두 만족해야 한다. 게임 나이 20 이상이며 출생~사망 범위 안, `forecast === false`, 연도 ≤ `ERA_ACTUAL_LAST_YEAR`(기존, 2026 — 컴퓨터 달력이 아님), 2110년 끝 안내 제외.
   - heavy(`EraRow.heavy`, 기존)는 전체에서 한 건. 앞 단계가 heavy를 골랐으면 뒤 단계는 가장 이른 non-heavy, 없으면 생략한다.
   - 원문 `line`만 쓰고 가구 영향 `second`는 쓰지 않는다. 거주·목격·피해와 잇는 문장을 붙이지 않는다.
   - 정치·재난은 승인된 원문 사실 한 줄 그대로다(예: 2016년 촛불 줄도 규칙 안이다 — review.md 관찰 ④).
   - **입력**: 시대의 창 10년 덩어리는 엔딩 화면에 없다(`eraRowsOf`는 `ctx.windows`가 비면 빈 목록을 돌려주고, 덩어리는 인생 화면만 받아 모듈 메모리에 둔다). 크레딧은 (출생 연도 + 20)의 10년대부터 min(사망 연도, 2026)의 10년대까지를 `src/data/familyArtLoader.ts#loadEraDecade`(기존)로 **모두** 받은 뒤 `eraRowsOf(birthYear, death.age, { regionKey: birthReport.region, seed: famSeedOf(peerSeed ?? seed), gentle, band, windows })`로 만든다.
   - `regionKey`·`seed`는 인생 화면(`LifeScreen.tsx`)의 호출과 같은 값이라 같은 해에 같은 줄이 나온다. `gentle`·`band`는 `line`·`heavy`를 바꾸지 않아 줄 선택과 무관하다.
   - 범위가 비면(20세 전 사망, 또는 출생 연도 2007 이상 — 게임 나이 20이 2027년 이후라 알파 전부·Z세대 2007~2012) 받지 않고 시대 장도 없다. 그림 조각 `loadFamilyArt`(기존)와 인생 화면의 `useEraData`(기존 — 실패한 10년대를 건너뛴다)는 쓰지 않는다.
   - 한 덩어리라도 실패하면 9항의 오류·다시 시도로 처리한다. 받은 것만으로 줄을 고르거나 시대 장이 빠진 전문을 내지 않는다.
5. **가림(`settings.gentle`)**: 실제 가림은 **현재 설정**이 정하고 `gentleUsed`는 안내 줄만 정한다. 선택·시대가 heavy이면 제목·질문·고른 길·결과를 함께 빼고 「무거운 일이 있었습니다 · {분류}」(시대는 「… · 시대의 일」)만 남긴다.
   - heavy 판정은 기존 것을 쓴다 — 선택은 `heavyKindOfEntry(entry)`(`src/core/gentle.ts`), 시대는 `EraRow.heavy`. 새 판정 함수를 만들지 않는다.
   - 문장·분류·버튼 이름은 기존 `VEIL_TEXT.rowLead` + `HEAVY_KIND_TEXT[분류]` · `SCENE_TEXT.eraVeilKind` · `veilButtonLabel(open, age, 분류)`를, 펼침 상태는 `useVeilOpen`(기존)을 그대로 쓴다.
   - 크레딧은 `src/ui/dash/Veil.tsx`의 `VeiledText`(기존)를 쓰지 않는다(닫힌 원문을 `hidden`으로 DOM에 두는 부품이다). 닫힌 줄은 원문 노드를 렌더하지 않고 펼친 때만 만든다. 펼침 버튼에는 `aria-expanded`를 두고 `aria-controls`는 펼친 때만 건다. 줄 모델은 펼침 판정 함수(`useVeilOpen`이 주는 `isOpen(id)` — 이 훅은 id 집합을 내주지 않는다)를 입력으로 받아 닫힌 줄의 원문 필드를 비운다.
   - 닫힌 원문은 크레딧 컨테이너(`data-testid="credits-screen"` 새) 안의 DOM·접근성 이름·투명 글자·툴팁 어디에도 없다. 「펼쳐 보기」는 그 한 건에만 적용하고 자동 이동을 멈춘다. 접기·설정 변경·재진입·새로고침 때 다시 닫힌다. 펼침 버튼 이름에는 나이·분류만 있다.
   - heavy 줄을 가려도 그 줄의 자리는 유지한다(가림 때문에 선택이 달라지지 않는다).
6. **짧은 삶·옛 저장**:
   - 20세 전 사망판(게임 0~19)에는 **시대 장과 마칠 때 수저 추산이 없다.** 선택 장은 3항 그대로다 — 학창 단계(게임 7~19)에 적격 본인 선택이 있으면 그 한 건이 남고 없으면 장 제목도 없다. 구성 = 머리 · 가족 · [학창 선택 0~1건] · [EC2 켬: 출생 수저만] · 끝. 「피우지 못한 꿈」 같은 가정을 붙이지 않는다.
   - 가족 장 생략 조건은 `game.family === undefined` 또는 `birthReport === null` 둘뿐이다. 둘 다 앱에서는 생기지 않고(저장 검증이 엔딩 단계에 `birthReport`를 요구하고, 판을 열 때 `ensureFamily`(기존)가 `family`를 채운다) 시험이 직접 만든 상태에서만 생긴다.
   - `birthReport === null`이면 `familyCardOf`가 throw하므로 부르지 않는다 — 머리는 「{연도}년에 태어났습니다.」이고 가족 장·시대 장이 없다.
   - `ensureFamily`가 채운 옛 저장 스냅샷(`family.lg === 1`)은 생략 대상이 아니며 가족과 삶 카드와 같은 명단을 낸다. `persona`가 없는 판은 있는 장만 쓴다. 새 이름·미래 가족 계획으로 채우지 않는다.
   - 어느 경우에도 빈 장 제목·「없음」 글자가 없고 끝 장이 있다.
7. **길이와 조작**(정본 plan-2 8절, plan 6절):
   - `N` = **줄 모델의 줄 문자열을 줄바꿈 없이 이어 붙인 것**의 Unicode 코드 포인트 수(`[...lines.join('')].length` — UTF-16 길이나 DOM `textContent`로 세지 않는다).
     - 센다: 화면 제목·장 제목·호칭·이름·줄 라벨(「본인이 정한 일」 등)·본문·끝 장. 가림 판은 가림 문장. (EC2 켬) 수저 장면의 제목·사실 문장·근거 줄·끝점 라벨과 수저 이름(`aria-hidden`이어도 보이므로 센다)·닫혀 있어도 보이는 「추산 기준」 제목 5자.

   - `D_read = max(18, ceil(8 + N/7))`초. 초당 7자는 확인되지 않은 ▲ 가설이며 v0.6.1 플레이테스트에서 조정한다.
   - 자동 흐름은 처음 4초·마지막 4초 정지, 가운데 `D_read − 8`초 동안 선형 이동한다(가속·페이드·확대·화면 전환 없음, 배경·글자 색 불변). 마지막 4초가 끝 문장을 읽는 시간이다. 시간 → 위치는 순수 함수(새)다. (EC2가 켜지면 수저 4.8초 머묾이 한 번 더해진다 — EC2 8항.)

   - **정지 목록으로 시작**하는 여섯 경우: ① `D_read > 90` ② 명단 21명 초과 ③ 이동거리 ÷ (`D_read − 8`) > 36 CSS px/s ④ 움직임 줄이기(OS 설정·`data-motion=reduce`) ⑤ 글자 확대 ⑥ 이동거리 ≤ 0(본문이 한 화면에 다 들어와 흐를 것이 없음). 글·사람을 자르거나 빨리 흘려 맞추지 않는다. 정지 목록에는 시간 제한이 없다.

   - 늘 보이는 조작: 회고로 돌아가는 단추(건너뛰기 역할 — 문구는 `copy.md`), 처음부터 보기. **자동 흐름이 가능한 판에서만** 일시 정지/이어 보기·목록으로 보기가 더 보인다. 정지 목록으로 시작한 판에는 전체 자동 흐름의 재생 단추를 그리지 않아 재생 단추로 자동 흐름을 켤 길이 없다(「처음부터 보기」의 판정에서 조건이 풀리면 자동으로 열릴 수 있다 — 아래. EC2 수저 장면을 여는 단추는 확인 1이 따로 정한다).
   - 문서 끝에는 회고로 돌아가는 주 단추와 보조 「처음부터 보기」가 문서 흐름 안에 있다. 끝에 도착해도 자동으로 닫지 않으며 초점도 옮기지 않는다. Space/Enter는 초점이 놓인 단추의 기본 동작만 한다.

   - **닫는 길 넷 = 회고로**: 단추 · Escape · 브라우저/기기의 뒤로가기(SPEC-005 NT5와 같은 규칙) · 헤더 로고(아래 「회고와의 관계」). 어느 길로 닫아도 회고의 스크롤 위치를 되돌리고 **호출한 진입 버튼에 초점**을 준다.
   - 뒤로가기: 크레딧이 열릴 때 history 항목 하나를 더하고(주소 불변), 단추·Escape·로고로 닫을 때는 그 항목을 되돌려 닫는 길이 몇이든 history는 한 걸음이다 — `src/ui/infoPanelHistory.ts`(기존) 방식을 **크레딧 덩어리 안에서** 재사용한다(훅은 첫 덩어리에 이미 있고, 호출 코드는 크레딧 덩어리에 두어 `EndingScreen` 정적 코드가 늘지 않는다). 「처음부터 보기」는 항목을 새로 더하지 않는다. 새로고침하면 표식이 남아 있어도 닫힌 회고이고, history 표식은 저장 키가 아니다.
   - **회고와의 관계**: 크레딧이 열린 동안 `EndingScreen`을 언마운트하지 않는다(마운트 효과 — 제목 초점·맨 위 스크롤 — 가 다시 돌지 않게). 회고 본문(`main.ending`)은 `hidden`으로 탭 순서·접근성 트리에서 뺀다. 헤더 로고의 「첫 화면으로」 확인 단계(`ending-home-ask`, 기존)는 크레딧 중에는 열지 않는다 — 로고를 누르면 먼저 회고로 돌아간다. Escape는 크레딧이 열려 있으면 크레딧만 닫는다.

9. **지연 로드·성능**: 크레딧 화면·줄 모델·허용 목록·스타일은 버튼을 누른 뒤 `import()`로 받는 별도 덩어리(새 폴더 `src/credits/`)이고, 이어서 시대의 창 10년 덩어리(4항 — 2026년 이하 10년대만)를 받는다. `EndingScreen`은 이 덩어리의 구현·데이터를 정적으로 따라오지 않는다.

   - 연타해도 덩어리는 한 번만 받는다(진행 중·성공한 로드). 실패하면 공유하던 약속을 풀어 「다시 시도」가 새 요청을 보낸다(`src/data/gameData.ts` 방식). 로드 실패 시 회고·다시 태어나기는 그대로이고 오류 문구와 다시 시도가 보인다. 실패가 저장을 덮어쓰거나 인생을 초기화하지 않는다.
   - **오류 경계**: 크레딧 영역은 자기 오류 경계를 둔다. 줄 모델 계산·렌더 중의 예외도 로드 실패와 같은 화면(오류 문구 + 다시 시도 + 회고로)으로 처리하고 최상위 `ErrorBoundary`(기존 — 「저장 지우고 새로 시작」)로 올라가지 않는다. 시험용 예외 주입은 개발 서버 전용 탐침 `?__creditsThrow`(새, 가칭 — `?__crash` 전례, 읽는 곳은 EC2 11항과 같이 `App.tsx`뿐)로 한다.
   - 수저 덩어리의 **로드 실패**는 시대 덩어리와 같이 오류 문구·다시 시도로 처리한다(장면이 빠진 전문을 내지 않는다 — 같은 삶이 진입마다 다른 전문·N이 되지 않게). 받은 뒤 수저 추산·장면 렌더에서 난 **예외**만 그 장을 뺀 전문·N(스위치 끔과 같은 화면)으로 처음부터 그리고 나머지를 보인다.
   - 첫 로딩 한도 400,000 B. 기준선 = EC1 구현 직전 커밋에서 `npm run e2e:prod`가 찍는 「MG8 초기 로드 … 합계」 네 값(Chromium·WebKit × PC 1280×800·모바일 360×740)이며 실행 기록에 적는다(참고: 2026-11-13 기록 Chromium 390,252 B · WebKit 394,354 B — 여유 9,748 B · 5,646 B). SPEC-020 변경이 먼저 합쳐지면 기준선을 그 커밋에서 다시 잰다.

### EC2 수저 변화 장면 「태어나고 마칠 때」 [CRITICAL · 배포 조건부]
정본은 plan-2 5~7절과 후속 258·260. 함수·데이터·화면을 **스위치 끔**으로 먼저 넣고, 배포 조건(아래 12항)을 통과한 뒤에만 켠다.

1. **마칠 때 수저 계산(순수 함수 한 벌, 새)**: `src/core/`의 새 파일(가칭 `endSpoon.ts` — React·타이머·Date·Math.random 없음, `corePurity` 통과)에 셋을 둔다.
   - `ageRowOf(deathAge)` = 연령 행(2항) · `endStandingOf(net, deathAge)` = F 0~100(3항) · `endSpoonOf(net, deathAge, mixture)` = 마칠 때 수저 1~5 | 「20세 전」 | 「추산 불가」 | 「장면 없음」(4항의 경계 판정 포함).
   - `endSpoonOf`는 나이·순자산·`mixture`만 보며 판정 순서는 「장면 없음」(나이 이상·`mixture` 이상) → 「20세 전」(게임 0~19) → 「추산 불가」(순자산 없음·비유한) → 1~5다. `mixture`가 다섯 칸·유한·음 아님·합 > 0인지 이 함수가 먼저 확인한 뒤에만 `wealthBottomPercent`를 부른다(그 함수는 합 ≤ 0에서 RangeError를 던지고 칸 수·음수는 보지 않는다).
   - `spoonSceneOf(game)`(새, 가칭 — 수저 덩어리 안의 순수 함수, 장면만 쓴다)가 장면 입력을 모으는 한 곳이다: `character.parentWealth`가 1~5의 정수가 아니거나 `generation`이 null이면 `wealthMixtureOfGame`을 부르지 않고(세대가 없으면 그 함수가 throw한다) 「장면 없음」, 아니면 출생 수저와 `endSpoonOf(assets?.net ?? null, death.age, wealthMixtureOfGame(game))`의 결과를 함께 돌려준다(20세 전 판에는 `assets`가 없다).
   - `src/core/birth.ts`에 이미 `wealthStanding(weights, wealth)`(기존 — 출생 수저 표현, `core/index.ts`로 공개)가 있으므로 그 이름을 쓰지 않는다.
   - 입력: 종료 `assets.net`(이미 부채가 빠진 순자산 — `assets.debt`를 다시 빼지 않는다, 현재가치 만 원) · **사망 나이(게임 나이)** · `mixture`(수저 비율 다섯 칸, 인자로 받는다). 태어날 때 수저 = `character.parentWealth`(1~5).
   - `mixture`는 장면이 `wealthMixtureOfGame(game)`(기존 — 출생신고·프로필 카드와 같은 값: 시도를 직접 고른 판은 줄어든 연도 집합)을, 측정이 `wealthMixtureOfProfile(profile)`(기존)을 넘긴다.
   - **장면 없음**: 사망 나이가 0 이상의 정수가 아니거나(음수·소수·NaN·Infinity) `mixture`가 다섯 칸의 유한한 음이 아닌 수(합 > 0)가 아니면 `endSpoonOf`가, 출생 수저가 1~5의 정수가 아니거나 세대가 없으면 `spoonSceneOf`가 「장면 없음」을 내고 **장면 전체를 생략**한다(plan-2 5-2). 임의 칸·흙수저로 채우지 않고 throw로 크레딧을 깨지 않는다(이름 크레딧은 그대로, N에도 장면 글자 없음 — 스위치 끔과 같은 화면). 「추산 불가」·「20세 전」과 구분한다.
   - 이 함수들은 SPEC-020 측정·배포 게이트와 **같은 함수**다. 측정·게이트·장면이 각자 만들지 않는다. 먼저 구현되는 쪽이 만들고 다른 쪽이 가져다 쓴다.
   - 새 파일과 분포 데이터 파일은 `src/core/index.ts` 배럴에 싣지 않고, 배럴에 실린 어떤 모듈도 이 두 파일을 import하거나 다시 내보내지 않는다(코어에 선례가 없는 첫 사례다 — `standing.ts`는 배럴에 줄이 없지만 `birth.ts`가 다시 내보내 첫 덩어리에 있다). `tests/lazyBoundary.test.ts`의 정적 그래프 잠금 목록에 두 파일을 더한다.
   - 수저 장면(화면·추산 함수·마디표·연령 행)은 크레딧 덩어리와 **별개의 동적 import 덩어리**다. 크레딧 덩어리는 이 파일들을 정적으로 import하지 않고 스위치가 참일 때만 `import()`를 호출한다. 부르는 곳은 크레딧 덩어리와 측정 스크립트뿐이다(파일 경로로 직접 import).
2. **연령 행 `AGE_ROW`**(게임 나이 기준): 0~19 추산 안 함 · 20~29 → 29세 이하(M 5,000·평균 10,796) · 30~39(15,585·25,060) · 40~49(28,384·48,389) · 50~59(31,685·55,161) · **60~64 → 60세 이상(25,000·53,591)** · **65 이상 → 65세 이상(22,100·49,279)**. 경계는 `< 65` / `≥ 65`. 게임 19는 화면 20세지만 이 규칙에서는 20세 전이다.
   - 표는 `spend-invest-model.md` 5-11-5와 10절 기계 블록의 `AGE_ROW` 줄과 행·숫자가 같아야 하며 **코드에는 데이터 파일 한 곳**(새)에만 둔다(P25 열은 SPEC-020 지표용으로 같은 파일에 둔다). 65 이상은 상한 없이 같은 행이다(기계 블록의 끝 130은 표기이고 게임의 나이 상한은 105다).
3. **자리 F(x | 나이)** — `networth-distribution.md` 4절 안 B:
   - `x ≤ M`: `F = F_all(x × 23,860 / M)` · `x > M`: `F = 100 × Φ(ln(x/M) / σ)`, `σ = √(2 ln(평균/M))`(표에 인쇄된 σ가 아니라 평균·M에서 다시 계산).
   - `F_all`은 4-1의 21개 마디 사이 선형 보간이다. 맨 아래(x < −10,000)는 0.1로 고정. 마디표와 연령 행은 **데이터 파일**(수저 덩어리 안)이며 4절 숫자를 그대로 옮긴다. 11월 13일 쏠림 측정의 성긴 분위수 재보간은 쓰지 않는다. Φ는 `erf`로 계산한다.
   - **순자산 0 이하는 마지막 수저를 흙으로 둔다**(override). 금액·빚을 강조하지 않는다.
   - **추산 불가**: 게임 나이 20 이상인데 순자산이 없거나(null) 유한한 숫자가 아니면(NaN·Infinity) 「추산 불가」이며 0으로 보지 않는다. 이 상태와 1항의 「장면 없음」 입력은 저장 검증이 막아 유효한 저장에서는 생기지 않으므로 단위 시험으로만 확인한다(`isValidAssets` 기존 — 순자산은 −200,000~2,000,000의 정수 · 자산은 게임 나이 20 이상에만 있고 그때는 반드시 있다 · `death.age === age` · 나이 상한 105 · `parentWealth`는 1~5 · 출생 뒤 단계는 세대가 반드시 있다).
4. **수저 이름 붙이기**: F를 `mixture`의 누적 경계에 대어 1~5를 붙인다. 경계 네 개는 `wealthBottomPercent(mixture, k)`(기존, k = 1~4)의 **반올림하지 않은 값**이다 — 출생 수저 구간과 같은 입력이며 **새 경계 표를 만들지 않는다.** `startBandOf`(기존)의 반올림·끝값 보정 결과는 쓰지 않는다. 경계와 정확히 같으면 아래 단계에 둔다(`p ≤ 경계`). 반올림한 백분위·표시 경계로 판정하지 않는다. (설계 근거 경계: 밀레니얼 26·56·83·97 등 — 화면에 쓰지 않는다.)
5. **문장 표**(두 단계가 같아도 같은 말투·크기·시간, 평가어·상승/하락 색 기호 없음):

   | 경우 | 사실 문장 | 작은 근거 줄 |
   |---|---|---|
   | 올라감 · 그대로 · 내려감 | {출생 등급 이름}로 태어나 {마침 등급 이름}로 마쳤습니다. | 가구주 연령대별 통계를 바탕으로 추산했습니다. |
   | 20세 전 | {출생 등급 이름}로 태어났습니다. | 마칠 때의 수저는 추산하지 않았습니다. |
   | 추산 불가 | {출생 등급 이름}로 태어났습니다. | 마칠 때의 수저는 추산하지 못했습니다. |

   - 등급 이름 = `GRADE_NAME[1~5]`(기존, `src/data/birthReportText.ts` — 이미 「수저」로 끝난다). 예: 흙수저로 태어나 동수저로 마쳤습니다. / 은수저로 태어나 은수저로 마쳤습니다.
   - 제목은 「태어나고 마칠 때」. 성인 추산 판은 그림 아래에 라벨 묶음 둘 — 「태어날 때」·「마칠 때 · 추산」과 각 수저 이름·점 다섯(채운 점 N개) — 을 둔다. 「다이아몬드수저」는 필요하면 줄바꿈하되 줄임표로 감추지 않는다.
   - 20세 전·추산 불가는 그림 아래에 「태어날 때」와 출생 수저 이름·점만 둔다. 「마칠 때 · 추산」 라벨·둘째 수저·빈 칸·화살표·「추산 기준」 접힘은 **없다**(plan-2 13절 이용수 전문 — N에도 「추산 기준」 5자가 없다).
6. **「추산 기준」(접힘, 기본 닫힘 — 성인 추산이 된 판에만 둔다)**: 「2025년 가계금융복지조사의 가구주 연령대별 평균과 중위값을 바탕으로 분포를 추산했습니다. 가구주 연령대는 이 삶이 끝난 나이로 골랐습니다.」 / 「태어날 때는 가족의 형편을, 마칠 때는 이 삶의 마지막 순자산을 나타냅니다. 두 시점의 기준은 같지 않습니다. 수저 이름의 경계는 태어난 세대의 비율을 함께 씁니다.」 — 출생(가족 형편)과 마침(본인 순자산)이 재는 대상이 다르다는 점을 이 문구가 밝힌다. 펼치면 자동 이동을 멈춘다.
7. **개인 백분위 숫자·금액·눈금·막대는 어디에도 없다**(기본 화면·접힌 「추산 기준」·접근성 이름·DOM 속성 모두, 후속 260 A②). 점수·순위·「성공」「역전」「몰락」 같은 말과 칭찬·한숨도 없다. 0 이하 흙수저에 금액·부채 문장을 덧붙이지 않는다. 평가어 금칙어 목록은 데이터 한 곳(새)에 두고 위 세 낱말로 시작한다.
8. **연출 A(같은 자리에서 겹쳐 바뀜, 후속 260 A①)**: 시작 수저 0.8초 → **출생 그림은 불투명도 1로 그대로 둔 채** 같은 자리 위에 마침 그림의 불투명도만 0→1로 2.4초(교차 페이드가 아니다 — 출생 그림을 흐리게 하지 않아 중간에 바탕이 비치지 않는다) → 마침 수저 1.6초, 합 **4.8초**.
   - 중간 단계(2·3·4)를 보여 주지 않고 화면·배경·글자를 함께 바꾸지 않는다. 올라감·내려감이 같은 동작이다. 연출(자동 흐름의 머묾)에서 같은 단계는 수저 하나가 4.8초 머문다. 20세 전·추산 불가는 출생 수저 하나와 한 문장이 4.8초 머물고 변화가 없다.
   - 연출 동안 바뀌는 것은 그림뿐이다 — 라벨 묶음(이름·점)과 사실 문장·근거 줄은 장면이 보이는 처음부터 끝까지 그대로 보인다(plan-2 7절). 연출에서 같은 단계는 그림 하나에 라벨 묶음 둘, 20세 전·추산 불가는 어느 보기에서도 그림 하나에 「태어날 때」 묶음 하나다(나란히 정지 화면의 같은 단계는 두 수저 — 아래 정지 목록 줄과 9항).
   - 자동 흐름에서는 수저 장면에서 이동을 멈추고 4.8초 머문 뒤 잇는다(plan-2 8절 「추가 그림 머묾」). 장면의 자리는 끝 장 바로 앞(그 판에 있는 마지막 장 뒤)이고 **한 번만** 더해진다. 자동 총길이 = `D_read + 4.8`초(상한 94.8초. 스위치 끔·장면 없음이면 `D_read`). 끝 4초는 끝 문장 몫이라 두 번 세지 않는다.
   - **머묾 자리** = 수저 장면 섹션의 아래 끝이 보이는 영역에 처음 들어오는 스크롤 위치(문서 끝 위치가 먼저면 끝 위치). 시간 → 위치 함수는 이 자리에서 4.8초 동안 값이 변하지 않고, 그림의 진행(불투명도)은 그 4.8초 안의 경과 시간만으로 정해진다(순수 함수). 흐르는 동안 머묾 전의 장면은 연출의 시작 상태(출생 그림만)다.
   - 4.8초 도중 멈추면(EC1 7항의 멈추는 때 전부 — 자동 흐름·정지 목록 공통) 그림은 그 시점 상태로 멈춘다. 다시 이으면(자동 흐름의 「이어 보기」, 정지 목록의 장면 단추) 남은 시간만 마저 잇고 처음부터 다시 틀지 않는다(시안 `credits-2.mjs`의 멈춤·이어 보기와 같다). 자동 흐름에서 이어 볼 때 스크롤이 이미 머묾 자리를 지났으면 그림을 마침 상태로 두고 머물지 않는다.
   - **정지 목록(움직임 줄이기·글자 확대가 아닐 때)에서의 시작 방식은 확인 1**이다. (가)면 장면에 두 수저가 나란히 정지해 있고 조작 띠의 단추(문구는 `copy.md` — 시안 「장면 보기」)를 눌러야 겹침 4.8초가 한 번 재생되며, 끝나면 마침 수저에 머물고 단추는 「다시 보기」가 된다. (나)면 장면이 화면에 들어올 때 4.8초가 한 번 자동 재생되고(목록은 움직이지 않는다) 다시 보기는 단추다.
   - 자동 판이 장면에 닿기 전에 멈춰 있는 동안과 「목록으로 보기」로 바뀐 뒤에는 장면이 이 정지 목록 규칙(확인 1)을 따른다(멈춘 채 손으로 내려가도 장면을 볼 수 있다). 자동으로 끝까지 본 뒤 다시 보는 길도 같은 단추(「다시 보기」) 하나이며, 장면만 그 자리에서 다시 재생하고 흐름은 다시 시작하지 않는다.
   - 변화가 없는 판 — 20세 전·추산 불가·같은 단계(plan-2 8절 표 「수저는 정지」) — 에는 장면 단추가 어느 보기에도 없고(「다시 보기」 포함) 정지 목록 (나)의 자동 재생도 없다(재생할 변화가 없다 — 시안은 이 판에도 단추가 눌린다). 정지 목록에서 20세 전·추산 불가는 출생 수저 하나와 「태어날 때」 묶음 하나, 같은 단계는 두 수저가 나란히 정지해 있다. 자동 흐름의 4.8초 머묾은 이 판들에도 그대로다.

    - **디자인 시스템 개정(같은 변경)**: `docs/design/design-system.md` 6절 「수저 아이콘 큰 변형」 행·10절 11항(32px 이상은 `sp-N-lg`)에 「수저 변화 장면 한정 예외」를 적는다. 6절 「수저 칩」 행·10절 4항의 등급명 허용 자리 목록에 **「엔딩 크레딧의 『태어나고 마칠 때』 장면」**을 더한다. `src/data/birthReportText.ts` 머리 주석에는 같은 자리를 「『이 삶의 이름들』(SPEC-022)의 『태어나고 마칠 때』 장면」으로 적는다(「딧」은 `src/`에 쓸 수 없다 — EC1 8항). 이 장면은 `gradeChip`(`.grade`) 대신 그림 + 라벨 묶음(이름·점 다섯)과 사실 문장을 쓰는 예외로 적는다(닫힌 SPEC-003 R-136 본문은 고치지 않는다).
    - 등급명은 이 장면 안(라벨 묶음 둘·사실 문장)에만 나오고 크레딧의 다른 장과 회고 화면에는 없다.
11. **끄는 스위치**: 상수 `ENDING_SPOON_ENABLED`(새 — `spend-invest-model.md` 5-11-8의 가칭과 같은 이름)를 전용 파일 한 곳(새, 가칭 `src/data/endingSpoonSwitch.ts` — `PERSONA_ENABLED` 전례)에 둔다. 값 하나만 바꾸면 켜고 끌 수 있고 저장·설정 형식과 무관하다(One-way 아님).
    - **꺼져 있으면 장면 0**: 장 제목·그림·문장이 없고, 수저 덩어리를 받지도 않으며, 끝 장은 수저 장면을 뺀 마지막 장(시대 → 없으면 선택 → 없으면 명단 → 없으면 머리)에 바로 이어진다.
    - 켜는 길: vitest는 `vi.mock`. e2e와 Codex 검증은 개발 서버 전용 탐침 `?__spoon=1`(새 — `import.meta.env.DEV`일 때만 읽는다, 기존 `?__timescale`·`?__crash`와 같은 방식)으로만 켠다. 탐침은 `src/App.tsx`(첫 덩어리)에서만 읽어 값으로 내려 준다 — 크레딧·수저 덩어리는 주소를 읽지 않는다(`?__creditsThrow`도 같다).
    - 제품 번들에는 탐침으로 켜는 경로와 탐침 이름이 없다. `e2e-prod/smoke.spec.ts`의 탐침 검사는 `index.html`의 `<script src>`만 읽으므로, `PROBES`에 `__spoon`·`__creditsThrow`를 더하는 것과 함께 크레딧 버튼을 누른 뒤 받은 js 응답 본문에도 두 이름이 없는지 본다.
12. **배포 조건**(후속 259·260 B1): 스위치를 켜는 조건은 `spend-invest-model.md` 5-11-5 지표 **(f) 하나**다(후속 260 B1 = 같은 문서 11절 Q1 (가) · 5-11-8 3항 ⓐ · 5-11-4 ④ — 이미 정해져 다시 묻지 않는다. 확인 5는 알림이다).
    - 판정 집단의 끝 수저 칸 비율과 그 집단의 출생 수저 칸 비율의 차가 다섯 칸 모두 |차| ≤ ▲8%p이다(조건은 이것 하나 — 흙수저 칸도 여기에 든다. 밀레니얼이면 흙수저 끝 ≤ 26 + 8 = 34%로 설계 문서 9-2절 ▲34와 같은 값이다). 8%p는 9-2절 ▲34의 값을 따른다. 고정 숫자 34는 밀레니얼 밖 집단에는 쓰지 않으며 r4가 9-2절·기계 블록 `oldGateBottomEndPct`를 이 식으로 고친다(맨 아래 4).
    - 판정 측정은 5-11-6대로 `check:economy` 6,000판이다. 그 프로필(「지금 세상」·산업화·X·알파 — 밀레니얼 없음) 중 어느 집단으로 판정하는지는 SPEC-020 r4가 한 줄로 정하고 이 명세는 그것을 따른다. 세대 셋 × 300판 이동표는 쏠림 확인용으로 같은 기록에 붙인다.
    - 「배포 조건」 열의 나머지 지표((a)~(e)·(g)·(h))는 측정 기록에 함께 싣되 SPEC-020 쪽의 보고·불변 가드이며 이 스위치를 막지 않는다.
    - (f) 통과 전에는 켜지 않는다. 노년 하위층 진단 D1~D6 → 레버 → (f) 재측정 순서이며 계수를 비틀어 맞추지 않는다. 켜는 변경은 스위치 값 한 줄(시험은 상수 값을 읽으므로 고치지 않는다) + 측정 기록 링크이고 **형진 님 승인 뒤**, 켠 빌드의 T3를 거쳐 한다(완료 기준 39). 조건이 오래 닿지 않아도 문구·길이·연출을 바꾸지 않는다(plan-2 요지). EC1은 이 조건과 무관하게 먼저 나간다.
