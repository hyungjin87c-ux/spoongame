## 배경

### 요청 요약 (2026-10-15, 원문은 위 파일)
형진 님이 '80억 분의 1' 화면 캡처 5장(출생 신고·대시보드·5세 기록 카드·6세 중대 결정 카드 등)을 보내며 요청했다. 캡처는 구조·흐름만 참고하고 그래픽·로고·고유 문구는 복제하지 않는다.
1. 모든 화면에 게임명 「수저 게임」을 크게, 한반도+수저 심볼 배치. 디자이너를 별도 임명하고, 디자인은 검증 에이전트가 유저 눈으로 정체성을 평가.
2. 첫 화면: 「N명이 이 시뮬레이션 속에서 각자의 삶을 살고 있어요.」, 우측에 한국 사회 통계(출생률·사망률·노인빈곤율·자살률·지역별 인구수 등) 캐러셀, 하단 중앙 고정 「태어나기」, 태어날 세상·인생 길이(약 30분/약 1시간) 선택.
3. 태어나기 → 수저 5종과 태어날 지역이 룰렛처럼 나란히 돌고 하단에 확률 명기 → 출생 확정 → 출생신고 페이지(80억 분의 1 벤치마킹).
4. 살아가기 → 대시보드: 상단 진행률 바(차면 한 살), 일시정지·1·2·4·8배, BGM·생각 남기기·다크 모드·의견 보내기·나가기. 프로필 카드(2D 얼굴·이름·성별·출생·거주·출신 가정 소득분위·학력), 상태 바(건강·행복·지식·관계 0~100), 성인 이후 자산 현황, 가운데 인생 기록(스크롤).
5. 8세 이전의 빈 시간을 부모 입장의 사건으로 채움(예방접종·첫 걸음마·첫 단어·동생 맞이 등), 중대 결정 카드에 통계·연구 인용, 영유아 기억·첫사랑·연애·질병·부모 노화·시기·질투·중년의 인생 등을 짧게 쓰는 자유 기록(「적어두고 살기 / 마음속에 담고 살기」).
6. 자산 현황이 성인 이후 결정에 영향을 주고, 선택지마다 자산·관계·행복·건강 영향을 작은 글씨로 표기.
7. 한국 사회 풍자(입시·부모 갈등·학비·결혼·육아 비용)를 중대 결정으로. 네이트판 톡톡 카테고리를 참고한 인생 콘텐츠 DB와 통계청·법원·기사 통계 근거.
8. GitHub 관리로 모바일에서 검토·피드백. 형진 님이 정할 것은 알려 달라.

### 이 게임이 이루려는 것 (형진 님 원문 요약) — 모든 항목은 아래 G 중 하나 이상에 기여해야 한다

- **G4** 한국 사회 문제를 중대 결정으로 풍자해 보여 준다.

- [ ] **SC3 데이터와 검증**: `src/data/koreaStats.json`(형식은 "데이터 형식"). 값마다 `docs/data/korea-stats-sources.md`의 행(통계표·원문 값·열람일)과 `basisId`로 연결되고 테스트가 대조한다. 필수 필드·기준 연도 정수·값 범위를 빌드가 검증한다. 접근 원칙은 SPEC-002 S3(로그인·가입·인증키 없이 공개된 통계표·보도자료만, 수치는 원문과 대조).
- [ ] **SC4 갱신 방법**: 지표별 발표 주기와 갱신 절차를 `korea-stats-sources.md`에 적는다(개발자가 값을 고치고 빌드·배포하는 수동 절차, 앱은 실행 중 외부 요청 없음). 화면에 「통계 기준: <연도> · 마지막 갱신 <날짜>」 표시.
- [ ] **SC5 동작**: 자동 전환 주기 ▲ 7초, 이전·다음 버튼·페이지 점·**일시정지 버튼**(WCAG 2.2.2), 포인터가 올라가거나 포커스가 있으면 정지, 터치 스와이프, 키보드 ←/→, 점 버튼의 접근 가능한 이름(「3/10 합계출산율」). 「움직임 줄이기」이면 자동 전환을 끈다. 자동 전환은 스크린리더가 읽지 않는다(`aria-live="off"`).
- [ ] **SC6 자살률 슬라이드 안전 규칙**: 값(인구 10만 명당)·기준 연도·출처와 **자살예방 상담전화 안내**(24시간 번호는 보건복지부·한국생명존중희망재단 공식 안내에서 수집 때 확인해 기입 ▲ 109, 확인 전에는 쓰지 않는다 — C10)가 **같은 슬라이드 안에** 있다. 방법·장소·동기 서술 없음. 게임의 사건·선택지에는 자살·자해를 쓰지 않는 SPEC-002 결정은 유지.
- [ ] **SC7 차트 구현**: 차트는 SVG 직접 구현. 차트 라이브러리 등 새 의존성은 마스터 승인과 사유 기록 없이는 추가하지 않는다.

### RL 출생 룰렛

- [ ] **RL1 구성과 연출**: 「태어나기」 → 룰렛 화면. **수저 릴**(흙·동·은·금·다이아몬드 수저 5종이 계속 바뀜)과 **지역 릴**(시도 17개▲, Q2)이 **나란히** 돌아간다. 가속 → 회전 → 감속 정지. 총 연출 시간 ▲ 4~6초, 수저 릴이 마지막에 멈춘다 ▲, 「건너뛰기」 버튼 제공. 「움직임 줄이기」이면 회전 없이 후보 전체를 보이고 결과만 강조한다.
- [ ] **RL2 결과는 먼저 정해져 있다**: 릴이 멈추는 값은 출생 로직(`generateBirth`, 시드 RNG)이 정한 결과와 같다. 연출이 확률을 바꾸지 않는다. 단위 테스트: 룰렛 결과 = 출생 로직 결과(1000판), 연출 코드에 `Math.random` 없음.
- [ ] **RL3 확률 표기**: 각 릴 **아래 작은 글씨**로 확률을 적는다. 수저: 선택한 세상의 `wealthWeights`(설계값)에서 계산해 합이 100(표시 반올림은 합 100이 되게 보정). 「이 확률은 게임의 설계값이에요(통계가 아님)」를 함께 표기한다 — 설계값 유지·통계 재설정은 Q4. 지역: 시도별 출생아 비율(통계청 출생통계의 최근 확정 연도, 소수 1자리, 합 100.0), 기준 연도와 출처 표기. 지난·다가올 세상의 지역 확률은 「지금 통계를 바탕으로 한 설계값」임을 표기한다(SPEC-002 S4 방식).
- [ ] **RL4 수저 표기**: 5종 이름은 색·아이콘·글자를 함께 보인다(DS3). 이름은 「다이아몬드수저」로 쓴다(요청 표기).
- [ ] **RL5 확정과 복원**: 태어나기를 누르는 시점에 출생 결과가 저장된다. 룰렛 도중·직후 새로고침하면 룰렛이 다시 돌지 않고 결과가 확정된 모습으로 복원되며 결과는 같다(새로고침 연타 포함, R-021 유지). 확정 뒤 「출생신고 보기」로 이동한다. **다시 굴리기는 없다**(SPEC-001 「다시 뽑기 없음」 유지).
- [ ] **RL6 접근성**: 회전 중 값은 스크린리더가 읽지 않고 결과만 `aria-live`로 알린다. 키보드로 건너뛰기·이동 가능.

### BR 출생신고

- [ ] **BR1 문서 구성**: 헤더 「출생 신고」, 큰 이름, 한 줄 서술문, 정보 격자, 같은 해 태어난 사람들(VP3), 비교 표(BR5, 있을 때), 하단 「살아가기」. 80억 분의 1의 구조를 참고하되 한국 지역·한국 통계 중심으로 구성하고 문구·그래픽은 자체 제작(DS8).
- [ ] **BR2 항목**: 이름 / 성별 / 출생 연월 / 출생지(시도+시군구) / 가정 형편(수저 직접 표기 + 5단계 점 표시, 표기는 Q4) / 부모 나이(어머니·아버지) / 부모 직업(각각) / 주거(자가·전세·월세·반지하 등) / 출생 체중(kg, 백분위) / 형제 순서(첫째·둘째 …) / 교육방식(SPEC-001 유지) / 외모(SPEC-001 유지). 종교·국적 선택은 두지 않는다.
- [ ] **BR3 한 줄 서술문** (요청 예시 형식): 「{연}년 {월}월, {시도} {시군구}의 {형편 서술} 가정에서 {체중}kg {남자아이|여자아이}로 태어났습니다. {첫째|둘째|…}입니다. ({체중}kg은 {상위|하위} 약 N%)」. 같은 문장이 대시보드 인생 기록 0세 첫 줄이 된다(어체는 C1). 문장 생성 규칙표를 단위 테스트한다.
- [ ] **BR4 통계 근거와 가중**: 출생 체중(성별별 분포, 근거 통계청 출생통계의 체중별 분포 → 백분위는 R-018 표현 규칙: 상위/하위 ≤ 50%, 중앙은 전용 문구), 부모 출산 연령(통계청 평균 출산 연령 기준), 형제 순서(출생아의 출산 순위 비중), 시군구(시도 안의 시군구별 출생아 비율), 부모 직업(한국표준직업분류 대분류 기준 가중표), 주거(자가·전세·월세 비중 등) — **모든 가중표는 근거 행(EV1)에 출처·기준 연도·열람일을 적고**, 수저 단계별 보정 값은 「설계값」으로 구분한다. 지난·다가올 세상에는 지금 통계를 시대 보정해 쓰고 그 사실을 출생신고 하단에 한 줄 표기한다. 실제 상호·기업 이름 금지.
- [ ] **BR5 비교 표 (근거가 확인된 행만)**: 「같은 해 태어난 아이 평균」과 「이 가정」을 견주는 표(요청의 G3: 수저의 영향 체감). 후보 행: 기대수명의 소득 수준별 차이, 사교육 참여·비용의 소득별 차이, 대학 진학률의 소득별 차이. **출처가 확인된 행만** 넣고 3행 이상▲, 확보하지 못한 행은 넣지 않는다. 행마다 출처·기준 연도 표기. (해외 국가 비교표는 만들지 않는다.)
- [ ] **BR6 영유아 가족 정합**: 출생 때 정한 형제 순서·부모 나이·직업은 이후 이벤트와 모순되지 않는다. 예) 「동생을 맞이한」 사건은 출생 순서가 첫째인 판에서만(IN4), 부모 사별·퇴직 사건은 부모 나이와 어긋나지 않는다 — 한 판 모순 0건을 flow 테스트로 단언(CM9).
- [ ] **BR7 안전한 이동**: 「살아가기」는 연타 가드(R-014), 새로고침해도 같은 출생신고(R-021), 진입 직후 입력 가드(0.4초).

### DB 대시보드

- [ ] **DB1 레이아웃**: 폭 ≥ 960px에서 3열 — 좌(프로필 카드·상태 바·자산 현황) / 중(인생 기록) / 우(가족과 삶·같은 해 태어난 사람들). 좁은 화면(360px)은 1열: 헤더 → 프로필 → 상태·자산 → 인생 기록 → 가족과 삶 → 또래. 가로 넘침 0(360·320px, 확대 200%).
- [ ] **DB2 진행률 바**: 헤더에 나이(큰 숫자)와 바. 바는 그 해의 연출 시간 동안 0→100%로 차오르고 100%가 되면 나이가 +1 된다. 일시정지·카드 대기·선택지 대기 중에는 멈추고, 배속에 따라 속도가 바뀐다. 순수 함수 `yearProgress(경과, 연출 시간)` 단위 테스트 + e2e(단조 증가, 나이 증가 시 0으로 리셋).
- [ ] **DB3 컨트롤**: 진행 줄 — 일시정지/계속, 1·2·4·8배, 다음 결정으로, 자동 모드 [가정: 유지, Q6]. 도구 줄 — BGM, 생각 남기기, 다크 모드, 의견 보내기, 나가기. 일시정지는 연출 타이머·진행률을 정지하고 **탭이 다시 보여도 자동 재개하지 않는다**(사용자가 정지한 상태 유지). 360px에서 터치 대상 ≥ 44×44px▲, 가로 넘침·가림 0, 아이콘만 있는 버튼은 접근 가능한 이름을 가진다. SPEC-001의 입력 가드(진입 직후 0.4초, 연타)·포커스 규칙(R-030·R-036)을 새 컨트롤과 카드에 그대로 적용한다.
- [ ] **DB4 BGM**: 켜기/끄기 버튼(기본 꺼짐 ▲, 사용자 제스처 뒤에 시작해 모바일 자동재생 정책을 지킨다). Web Audio로 **코드가 직접 생성**하는 잔잔한 칩튠 루프 1곡 이상, 반복 피로를 줄이는 패턴 4개 이상▲(코드 진행·멜로디 변주), 볼륨(기본 낮음 ▲) 조절, 켬/끔·볼륨 저장. 탭이 가려지면 일시 중단. 음원 파일·외부 라이브러리 없음, **기존 곡의 멜로디를 쓰지 않는다**. 테스트: 시퀀스 데이터(음 높이·길이)가 음계·마디 규칙에 맞는지 단위 테스트, 실제 소리는 형진 님이 모바일에서 청취해 확인(완료 기준).
- [ ] **DB5 생각 남기기**: 언제든 눌러 현재 나이의 짧은 기록을 남긴다(FR 입력 규칙 동일). 열면 게임이 자동으로 일시정지하고 닫으면 이전 상태로 돌아간다.
- [ ] **DB6 다크 모드**: 버튼으로 라이트↔다크 전환. 처음에는 시스템 설정(`prefers-color-scheme`)을 따르고 수동 선택은 저장. 모든 화면이 두 테마에서 가로 넘침·가림 없이 보이고 DS3 대비 점검이 두 테마에서 통과한다.
- [ ] **DB7 의견 보내기**: GitHub 이슈 작성 화면(새 탭, `rel="noopener noreferrer"`)으로 연결한다. 주소 구성 함수 `buildFeedbackUrl`이 **허용 목록 필드만** 채운다 — 빌드 버전·현재 화면 이름·세상·인생 길이. **캐릭터 이름·나이·자유 기록·저장 데이터·브라우저 정보는 넣지 않는다**(테스트: 어떤 상태에서도 URL에 이름·기록 문자열이 없다). 저장소 주소는 빌드 설정에서 읽는다(DP1).
- [ ] **DB8 나가기**: 첫 화면으로 이동하고 저장은 유지된다(첫 화면에서 「이어서 살기」, FS6). 확인 한 단계를 둔다 [가정] (C3).
- [ ] **DB9 프로필 카드**: 얼굴(DS4), 이름, 성별, 출생(연월), 거주(시도·시군구), **출신 가정**(5단계 점 + 수저 이름, Q4), **학력**, 외모(상위/하위 약 N%, 출생신고와 같은 표현). 학력은 나이×플래그 표로 정한다(▲ 취학 전 / 초등학교 / 중학교 / 고등학교 / 대학교 재학·졸업 / 중퇴·취업 등 — `left_school`·`college`·`early_work` 플래그 연동, 표를 단위 테스트). 얼굴은 나이에 따라 갱신(DS4).
- [ ] **DB10 상태 바**: 건강·행복·지식·관계 4개를 0~100 바 차트로(`role="meter"`, 수치 병기), 「상태는 무엇을 뜻하나요?」 접이식 도움말에 각 상태의 뜻을 적는다.
- [ ] **DB11 자산 현황 (성인 이후)**: 20세부터 **순자산·연 소득·부채**를 표시한다(단위는 Q3). 20세 미만에는 숨기고 「아직 부모님 집에서 지냅니다 · 가정 형편 N단계」 한 줄만 보인다. 값 변화가 EC 규칙과 일치한다.
- [ ] **DB12 인생 기록**: 가운데 영역에 **한 줄씩 쌓인다**(시간순, 새 줄이 아래에 붙고 자동으로 맨 아래로 이동. 사용자가 위로 스크롤하면 자동 이동을 멈추고 「새 기록 N개 · 맨 아래로」 표시). 영역 안에서 **스크롤**된다. 줄 형식 「{나이}세 {문장}」. 종류: 사건 / 선택 결과 / 나의 기록(FR, 시각적으로 구분) / 단계 / 사망. 저장 상한(`HISTORY_LIMITS.maxEntries` 160)을 새 규모에 맞게 올린다(▲ 300, 최악 판 저장 크기 ≤ 200KB▲).
- [ ] **DB13 가족과 삶**: 어머니·아버지(나이·직업·상태), 형제자매(관계·나이 차), 성인 이후 배우자·자녀(`has_partner`·`married`·`has_child` 플래그와 표시가 일치). 부모 나이는 해마다 오르고 사별(`parents_gone`)은 표시에 반영된다.
- [ ] **DB14 가상 인구 줄**: 인생 기록 맨 위에 고정 줄 하나 「지금 이 시뮬레이션 속 {N}명이 함께 살고 있어요」 ▲(쌓이는 기록과 구분, FS2와 같은 N·보조 설명).

### EC 경제 모델·선택지 영향 표기

- [ ] **EC0 설계 문서 먼저**: M5 착수 시 `docs/data/economy-model.md`(상태 값·해마다 변화 규칙·계수 표·근거 지표·기존 이벤트 변환 규칙)를 쓰고 마스터가 승인한 뒤 구현한다. 시대(지난·다가올 세상)의 화폐 가치 처리 방식이 Q3에 달려 있다.
- [ ] **EC1 상태**: 20세 이상 `assets = { 순자산, 연 소득, 부채 }`(정수, 내부 단위는 Q3). 20세 미만은 부모 자산 모델을 만들지 않고 가정 형편 단계(1~5)만 쓴다. 독립(20세) 때 초기값은 집안 형편·학력·학자금 대출 여부로 정한다(SPEC-001 `INDEPENDENCE` 규칙의 대체).
- [ ] **EC2 해마다 변화**: 순자산 변화 = 연 소득 − 생활비(주거 형태·부양 가족 반영) − 부채 이자. 소득은 학력·일 상태(`has_career`·`own_business` 등)·시대에 따른다. 계수는 `src/data/economyTable.ts`(설계값)에 두고 근거 지표(가계금융복지조사 등)는 EV1 행에 적는다. 자산이 모자라면 부채가 늘고 이자가 다음 해 순자산을 깎는다(「빚이 빚을 만든다」).
- [ ] **EC3 선택지의 자산 효과**: 이벤트 스키마에 `effects.assets`(`net`·`income`·`debt` 변화)와 `requires.assets`(순자산·부채 조건)를 추가한다. 기존 `wealth` 효과는 변환표로 새 모델에 옮기고, **모든 기존 이벤트에서 증감 부호가 같음**을 자동 점검한다(예외는 문서에 사유). 이벤트·선택지 id는 바꾸지 않는다.
- [ ] **EC4 불가피한 선택과의 합류**: 자산이 모자라 비용을 못 내는 선택지는 보이지 않거나 「대출을 받아」 경로(부채 증가)로 바뀐다. SPEC-002 E15(불가피한 선택)와 합쳐 같은 이벤트에서 재력·자산별로 보이는 선택지 수가 다른 이벤트를 10개 이상▲ 둔다.
- [ ] **EC5 영향 표기 규격**: 모든 선택지 아래 한 줄 작은 글씨로 **변화가 있는 항목만** 표기한다 — 자산·관계·행복·건강·지식. 형식 「자산 ▼▼ · 행복 ▲」(▲/▼ 개수 1~3 = 크기 단계, 경계는 `IMPACT_STEPS` 표 ▲: |Δ| 1~2 = 1칸, 3~6 = 2칸, 7 이상 = 3칸, 자산은 원 단위 환산표). 색에만 의존하지 않고, 스크린리더용 문장(「자산이 크게 줄어요」)을 제공한다. **표기는 지금 캐릭터 기준의 실제 적용값**(재력·외모 보너스 포함)이며, 이벤트 × 선택지 × 대표 캐릭터 전수에서 표기 방향·단계 = 실제 `resolveEffects` 결과(테스트). 표기에 없는 스탯 변화는 일어나지 않는다(숨은 효과 0).
- [ ] **EC6 연애 시나리오 (요청 예시)**: 청년기 연애 시작 이벤트의 「연애를 시작한다」에 「자산 ▼」가 표기되고 같은 이벤트에 「썸으로 남긴다」가 있다. 자동 모드 성향 선택이 자산·부채를 반영해, 부채 판(순자산 < 0)에서 연애를 시작하는 비율이 비부채 판보다 낮다(시뮬레이션 단언, 차이 ≥ 10%p▲). 소극적 선택에도 얻는 것이 있어 지배 선택지가 아니다(E11).
- [ ] **EC7 밸런스·엔딩 재측정**: 새 모델로 `finalDistribution`(엔딩 출발선 대비)을 다시 만들고 `check:dist`를 통과시킨다. 시뮬레이션 판의 연령별 순자산·부채 보유 비율을 통계(가계금융복지조사)와 견주어 큰 차이가 있으면 계수 표를 조정하고 근거에 기록한다(허용 폭 ▲ M5에서 마스터 확정).

### IN 영유아기(0~7세) 콘텐츠 — 「부모 입장에서 정말 많은 일이 일어난다」

- [ ] **IN1 규모**: 영유아기 이벤트를 현재 11개에서 **40개 이상▲**(서술 ≥ 22, 선택지 ≥ 18)으로 늘린다. 0~7세 **각 나이마다** 그 나이에서 일어날 수 있는 이벤트가 4개 이상▲ — 현재 0세·7세는 0개이므로 0세(출생·예방접종 등)와 7세(입학 준비·유치원 졸업 등)를 채운다. 세 시대 각각에서 영유아 이벤트 25개 이상▲이 일어날 수 있다.
- [ ] **IN2 사건 없는 해 줄이기**: 시대별 1000판에서 0~7세 8해 중 인생 기록에 줄이 하나도 안 생기는 해가 평균 ≤ 1.0, 최대 ≤ 3▲. 영유아기 인생 기록 줄(출생 줄 제외) 평균 ≥ 10줄▲. 영유아 단계 판당 선택지(중대 결정 카드) 평균 ≥ 4개▲(현재 약 1.8).
- [ ] **IN3 마일스톤 사건은 반드시 일어난다**: 기본 예방접종(0세) · 첫 걸음마 · 첫 단어는 정한 나이 범위 안에서 **모든 판**에 일어난다(그 전에 사망한 판 제외, 시뮬레이션 단언). 발달 시점은 영유아 발달 기준(근거 행 기입). 요청 예시의 사건(예방접종·첫 걸음마·첫 단어·엄마와의 시간·동생 맞이·어린이집/유치원)이 모두 포함된다.
- [ ] **IN4 동생 맞이 카드 (요청 예시)**: 2~4세▲, **출생 순서가 첫째인 판에서만**(BR6). 중대 결정 카드로 상황(「동생을 처음 봤다. 부모의 애정이 줄어든 듯하다」)과 선택지 3개 — 예: 엄마가 동생을 살피면 운다 / 동생을 예뻐해 준다 / 동생의 장난감을 빼앗는다(「해코지」는 폭력 장면 묘사가 아닌 유아기 질투 행동의 담담한 서술로, 아래 안 할 것 참조). 선택지는 유아 심리 연구가 말하는 형제 출생 뒤 첫째의 전형적 반응(퇴행·관심 끌기·돌보기·질투 표현)을 반영하고 각각 근거 행(EV1)에 연결한다. 지배 선택지 없음(E11), 영향 표기(EC5)·인용(MD2) 포함.
- [ ] **IN5 소재 범위 (최소 포함)**: 예방접종·영유아 건강검진·돌잔치·이유식·첫 걸음마·첫 단어·어린이집(입소 대기·적응·감염)·유치원·입원·응급실·배변 훈련·떼쓰기·영상 노출·사교육 시작의 압박·조부모 돌봄·맞벌이와 육아휴직·층간소음·이사·소아과 대기. 각 소재는 EV 근거 행 또는 소재 목록 행(T2)에 연결된다. 부모의 사정·감정은 서술하되 주어는 「아이」 또는 이름(R-070).
- [ ] **IN6 시대 정합**: 시대 소재 금지어 표(`ERA_BANNED_WORDS`)에 영유아 소재를 추가한다(예: 지난 세상에서 「어린이집 대기」「영어 유치원」 금지, 대신 골목·조부모·집안일). 시대 전용 영유아 이벤트 각 3개 이상▲.
- [ ] **IN7 수저에 따른 차이 (G3)**: 같은 이벤트에서 재력 단계에 따라 보이는 선택지·결과가 다른 영유아 이벤트 8개 이상▲(예: 어린이집 선택, 사교육 시작, 병원 선택). 시뮬레이션에서 재력 1~2단계 판과 4~5단계 판의 영유아 선택지 구성 차이가 관측된다.
- [ ] **IN8 규칙 계승**: 영유아 문구 3인칭(R-070), 담담한 어조·길이 권장 최대(제목 16·본문 70·라벨 24·결과 80자)·시대 금지어·모순 0(E10·E11)을 그대로 지킨다. 새 이벤트 모두 `once: true`.

### MD 중대 결정 카드 (통계·연구 인용)

- [ ] **MD1 카드 UI**: 선택지 이벤트는 모두 **중대 결정 카드**로 보인다. 요소 — 헤더(「중대 결정」·나이), 제목, 상황 문장, 인용 박스(있을 때), 선택지 2~3개(각각 영향 표기 EC5), 「잠깐 내려 두기」(카드를 접어 인생 기록을 볼 수 있고 게임은 정지 유지, 「결정 다시 열기」 제공), 자동 모드 안내. 카드가 뜨면 포커스가 카드로 이동하고 접으면 복귀한다(R-036 규칙을 새 카드에 적용, `decideLifeFocus` 표 갱신).
- [ ] **MD2 인용 규칙**: 중대 결정 카드의 70% 이상▲이 통계 또는 연구 인용을 하나 가진다. 형식 — 요약 문장 ≤ 100자▲ + 출처 줄 「기관·저자(연도), 자료 이름」. 규칙(SPEC-002 S6 이어받음): 원문 문장을 그대로 옮기지 않고 요약, 수치는 원문 값과 일치, 지어낸 수치·뜻이 바뀌는 반올림 금지, 시대 정합(지난 세상은 그 시기 통계가 있을 때만, 다가올 세상은 「지금 기준으로는」), 의료·법률·재무 조언처럼 읽히지 않음. 모든 인용이 `citations.json`에 있고 `basisId`로 EV1 근거 행과 연결되며 테스트가 대조한다(근거 없는 인용 0).
- [ ] **MD3 연구 인용의 정확성**: 연구 인용은 저자·연도·자료 이름을 원문(논문·보고서·기관 자료)에서 직접 확인한 것만 쓴다. 요약 도구·검색 스니펫만 본 값은 쓰지 않는다. 문헌 후보(원문 확인 전이라 인용문으로 쓰지 않음): 애착 이론·낯선 상황 실험, 형제 출생 뒤 첫째의 행동 변화 연구, 아동기 부정적 경험과 성인기 건강 연구, 영유아 스크린 노출 권고(WHO 등), 질병관리청 국가예방접종 일정, 영유아 건강검진·발달 선별검사 기준.
- [ ] **MD4 카드 상한**: 한 판의 카드 수·읽는 시간은 LM2가 정한다.

### FR 자유 기록 — 「적어두고 살기 / 마음속에 담고 살기」

- [ ] **FR1 기록 카드 종류**: 요청의 7종을 모두 만든다 — ① 영유아기 기억(정확히 5세▲) ② 청소년기 시기·질투(13~17세) ③ 첫사랑의 추억(`first_love` 플래그 뒤 또는 15~25세) ④ 청년기 연애담(20~34세, 연애·이별 플래그에 따라 문구 분기) ⑤ 아팠던 경험(큰 병·건강 이벤트 뒤 또는 건강 하락 임계) ⑥ 부모님이 나이가 들었다고 느낀 때(부모 나이 ≥ 65▲, `parents_gone`이 아닐 때) ⑦ 중년에 느끼는 인생이란(45~55세). 판당 6~8회▲. 카드 정의는 `src/data/notes.json`(형식은 "데이터 형식"). **질문 문구는 80억 분의 1 문구를 복제하지 않고 자체 작성**한다(예: 「{이름}이 다섯 살이던 때, 기억나는 장면이나 느낌이 있다면 짧게 남겨 보세요」).
- [ ] **FR2 카드 UI**: 질문 · 통계/연구 한 줄 인용(영유아 체험이 성인기까지 영향을 준다는 근거 — 요청의 G, MD3 규칙 적용) · 여러 줄 입력란 · 선택 2개 「1. 적어두고 살기」「2. 마음속에 담고 살기」(문구는 요청 원문). 카드가 뜨면 게임은 멈춘다.
- [ ] **FR3 입력 규칙**: 최대 길이 140자▲(사용자가 인식하는 글자 단위, 이모지·결합 문자 포함), 줄바꿈 ≤ 3줄▲, 앞뒤 공백 제거·연속 공백 정규화, 제어 문자·제로폭 문자 제거. 붙여넣기가 상한을 넘으면 잘라 넣고 안내한다. **공백만·빈 입력이면 「적어두고 살기」는 기록하지 않고** 입력란 아래 안내(「적을 말이 없다면 2번을 골라도 괜찮아요」)를 보이며 카드는 닫히지 않는다. 한글 입력(IME) 조합 중에는 제출·길이 계산이 조합 완료를 기다려 마지막 글자가 사라지지 않는다.
- [ ] **FR4 안전한 표시**: 입력은 **항상 글자로** 표시된다 — `<script>`·`&`·마크다운·URL·HTML 엔티티가 해석되지 않고 그대로 보인다(`dangerouslySetInnerHTML` 사용 금지를 점검). 공백 없는 초장문·긴 URL도 가로로 넘치지 않고(`overflow-wrap: anywhere`), RTL 문자·결합 문자가 주변 UI 순서를 뒤집지 않는다(`dir="auto"` + 격리, QA-001 사용감 6 이월 해소).
- [ ] **FR5 「적어두고 살기」**: 글을 저장하고 인생 기록에 「나의 기록」 줄(나이·주제·내 글)로 쌓는다. **이 기기에만 저장**되고 서버로 가지 않으며 의견 보내기 주소·로그에 들어가지 않는다(DB7). 한 판 기록 수 상한 40개▲(자동 카드 + 생각 남기기 합). 저장 실패(쿼터)면 안내를 보이고 입력 내용을 지우지 않는다.
- [ ] **FR6 「마음속에 담고 살기」**: 아무것도 저장하지 않고 카드가 닫힌다. 입력란에 글이 있는데 이 버튼을 누르면 「적은 글은 저장되지 않아요」 확인을 한 번 보인다.

### LM 인생 길이 모드·시간

- [ ] **LM1 선택**: 인생 길이 값 `short30`(약 30분) / `long60`(약 1시간)을 첫 화면에서 고른다(FS5). 설정으로 저장돼 다음 판의 기본값이 된다.
- [ ] **LM2 시간 모델**: 한 판의 시간 = Σ연출 대기(`HOLD_MS` × 모드 계수) + Σ(선택지 × 읽기 시간) + Σ(기록 카드 × 입력 시간). 모드 표를 `src/data/timingTable.ts`의 `LIFE_LENGTH_MODES`에 둔다. 초기값 ▲(M8에서 측정해 조정):

| 모드 | 1배속 수동 목표(사람 실측) | 판당 중대 결정 카드 | 판당 기록 카드 | 연출 대기 |
|---|---|---|---|---|
| 약 30분 | 25~35분 | 26~30개 | 6~8개 | 현행의 약 1.1~1.3배 |
| 약 1시간 | 50~70분 | 45~55개 | 10~12개 | 현행의 약 2배 |

  1시간 모드의 카드 수는 이벤트 풀 크기(SA8)에 종속되므로, 풀이 모자라면 연출 대기 비중을 늘린다(Q8). 읽기 시간 가정은 새 카드의 평균 글자 수(인용·영향 표기 포함)로 다시 잰다(묵독 500/600/700자/분 + 고르는 시간 5/10/15초, 기존 방식). `estimatePlaySeconds`가 기록 카드 입력 시간을 포함하도록 확장한다.
- [ ] **LM3 모드 고정**: 모드는 판을 시작할 때 정해져 저장되고 진행 중에는 바꿀 수 없다. 「다시 태어나기」로 첫 화면에 돌아와야 바꿀 수 있다.
- [ ] **LM4 시뮬레이션**: 두 모드 모두 시대별 1000판에서 에러 0, 모순 0, 판당 카드 수가 LM2 범위 안(25개 초과·하드 상한 규칙은 모드별 표로 다시 정의).
- [ ] **LM5 일시정지·가림**: 일시정지·탭 가림·카드 열람 시간은 시간 목표에서 제외한다(LM6의 타이머가 구분해 기록).
- [ ] **LM6 플레이 시간 표시 (실측용, 기획자 제안)**: 엔딩 화면에 「이 판의 플레이 시간 mm:ss」(일시정지·탭 가림 제외)를 표시하고 이 기기에만 저장한다. 사람 실측은 이 값을 쓴다(별도 스톱워치 불필요). (C13)
- [ ] **LM7 사람 실측 절차 (SPEC-001에서 이관)**: 형진 님이 Pages 링크로 각 모드 1판 이상을 1배속·수동으로 완주하고 엔딩의 플레이 시간을 기록한다(QA는 연출 시간만 실측하고 읽는 시간은 모델로 추정). 목표 범위를 벗어나면 `LIFE_LENGTH_MODES`를 조정해 다시 실측한다(최대 2회, 이후 마스터 개입). 8배속+다음 결정으로의 시간은 참고용으로만 기록한다(판정 아님).

- **Q8. 1시간 모드를 어떻게 채울까**: 길이를 늘리는 수단이 (가) 연출 대기를 늘림(느긋한 호흡, 지루할 수 있음) (나) 카드·기록 수를 늘림(내용이 많아지나 이벤트 풀이 100개 이상 더 필요) 중 어디에 비중을 둘까요? **[가정] 둘 다(연출 약 2배 + 카드 약 1.7~2배), 풀이 모자라면 연출 쪽으로 보충**

### 마스터 확인 필요 (기획자가 정하지 않고 올린 것)
- **C1 어체**: 기존 이벤트·연표는 해라체(「~했다」), 요청 예시와 캡처는 합쇼체(「~했습니다」). 기존 엔딩 안내문 일부는 합쇼체여서 QA-001이 어체 혼재를 지적했다. **[가정] 인생 기록(사건·출생 줄)은 해라체로 통일, 출생신고 서술문과 UI 안내문은 합쇼체·해요체**(첫 화면 문구는 요청 원문 그대로). 인생 기록 전체를 합쇼체로 바꾸면 기존 이벤트 112개의 결과 문구까지 다시 써야 한다.
- **C2 한반도 심볼**: 독도·울릉도·제주 표현과 분단·영토 표시 오해 가능성은 designer 시안에 대안을 두고 형진 님이 선택한다.
- **C3 나가기·이어하기**: 나가기 → 첫 화면, 저장 유지, 첫 화면의 이어서 살기와 확인 단계. 새로고침하면 마지막 위치가 아니라 첫 화면이 열리는지(현재는 저장된 화면 그대로 복원) 정해야 한다. **[가정] 나가기를 누른 뒤의 새로고침은 첫 화면, 그 외는 복원**
- **C4 수저 등급명 범위**: 룰렛·출생신고·프로필 카드에 직접 표시하고 이벤트·연표·엔딩 본문에는 쓰지 않는다 [가정].
- **C5 기록 카드 꺼짐·자동 모드**: 자동 모드에서 기록 카드를 건너뛰는 것, 「다음부터 이 창 띄우지 않기」(캡처에는 있고 요청에는 없음)를 둘지.
- **C6 저장 비호환**: v4 이하 저장은 새 게임으로 시작(Pages는 origin이 달라 형진 님 기존 로컬 판과 어차피 공유되지 않는다).
- **C7 코드 라이선스**: 공개 저장소의 라이선스(MIT 등 / 없음 = 모든 권리 보유). 형진 님 선택 사항이라 마스터가 묻는다.
- **C8 검토용 배포**: CLAUDE.md 5-1(검수 승인 전 코드는 별도 브랜치)과 형진 님의 모바일 검토 요구가 부딪친다. `main` 승인분만 배포하고, 형진 님이 승인 전 화면을 보려면 `workflow_dispatch`로 지정 브랜치를 임시 배포하는 방식을 허용할지.
- **C9 네이트판 점검 실패 시**: 이용약관이 자동화된 열람을 금지하면 T1 점검 실패다(점검은 수집 전에 하고 결과를 보고). 실패하면 T7 폴백(창작 소재)과 통계 근거 소재로 대체하는 데 대한 형진 님 합의가 필요하다.
- **C10 사실 확인 두 가지**: (1) 통계청의 기관 명칭 변경 여부(출처 표기에 현재 명칭 사용) (2) 자살예방 상담전화 번호(2024년 통합 번호로 알고 있으나 **공식 안내로 확인하기 전에는 쓰지 않는다**).
- **C11 가상 인구 규모·변동 모델**: 「한국 인구 1/1,000 축소(약 5만 명대) + 출생·사망 반영 완만 변동」이 기본 제안이다. 「접속자」로 오해될 임의 숫자는 정직성 때문에 채택하지 않는다.
- **C12 BGM 기본값**: 기본 꺼짐, 볼륨 조절 포함(요청에는 버튼만 있음).
- **C13 엔딩 플레이 시간 표시**: 사람 실측용 제안(LM6). 요청에 없는 UI 추가.
- **C14 「태어날 세상」의 해석**: 요청의 「태어날 세상」을 SPEC-001의 시대 선택(지난·지금·다가올)으로 읽었다. 다른 뜻이면 알려 주세요.
- **C15 폰트·번들 크기**: designer가 글꼴(오픈 라이선스·번들) 후보와 번들 크기 영향을 M1에서 제안하고 마스터가 확정한다(CM6).
