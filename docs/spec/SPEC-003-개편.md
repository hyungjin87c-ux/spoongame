## 배경

### 요청 요약 (2026-10-15, 원문은 위 파일)
형진 님이 '80억 분의 1' 화면 캡처 5장(출생 신고·대시보드·5세 기록 카드·6세 중대 결정 카드 등)을 보내며 요청했다. 캡처는 구조·흐름만 참고하고 그래픽·로고·고유 문구는 복제하지 않는다.
1. 모든 화면에 게임명 「수저 게임」을 크게, 한반도+수저 심볼 배치. 디자이너를 별도 임명하고, 디자인은 검증 에이전트가 유저 눈으로 정체성을 평가.
2. 첫 화면: 「N명이 이 시뮬레이션 속에서 각자의 삶을 살고 있어요.」, 우측에 한국 사회 통계(출생률·사망률·노인빈곤율·자살률·지역별 인구수 등) 캐러셀, 하단 중앙 고정 「태어나기」, 태어날 세상·인생 길이(약 30분/약 1시간) 선택.
3. 태어나기 → 수저 5종과 태어날 지역이 룰렛처럼 나란히 돌고 하단에 확률 명기 → 출생 확정 → 출생신고 페이지(80억 분의 1 벤치마킹).
4. 살아가기 → 대시보드: 상단 진행률 바(차면 한 살), 일시정지·1·2·4·8배, BGM·생각 남기기·다크 모드·의견 보내기·나가기. 프로필 카드(2D 얼굴·이름·성별·출생·거주·출신 가정 소득분위·학력), 상태 바(건강·행복·지식·관계 0~100), 성인 이후 자산 현황, 가운데 인생 기록(스크롤).
5. 8세 이전의 빈 시간을 부모 입장의 사건으로 채움(예방접종·첫 걸음마·첫 단어·동생 맞이 등), 중대 결정 카드에 통계·연구 인용, 영유아 기억·첫사랑·연애·질병·부모 노화·시기·질투·중년의 인생 등을 짧게 쓰는 자유 기록(「적어두고 살기 / 마음속에 담고 살기」).
6. 자산 현황이 성인 이후 결정에 영향을 주고, 선택지마다 자산·관계·행복·건강 영향을 작은 글씨로 표기.
7. 한국 사회 풍자(입시·부모 갈등·학비·결혼·육아 비용)를 중대 결정으로. 네이트판 톡톡 카테고리를 참고한 인생 콘텐츠 DB와 통계청·법원·기사 통계 근거.
8. GitHub 관리로 모바일에서 검토·피드백. 형진 님이 정할 것은 알려 달라.

- [ ] **FS3 캐러셀 배치**: 폭 ≥ 960px에서 통계 캐러셀이 우측 열에 놓이고(첫 화면 높이 안), 그보다 좁으면 선택 영역 아래에 놓인다. 내용·동작은 SC1~SC7. 어느 폭에서도 캐러셀이 하단 고정 버튼을 가리지 않는다.
- [ ] **FS4 태어날 세상**: 지난 세상·지금 세상·다가올 세상 3개를 라디오 카드로 보인다(`role="radiogroup"`, 기본 지금 세상, 마지막 선택 기억). 카드마다 `ERA_CONFIG.blurb` 한 줄. 선택 상태는 색에만 의존하지 않는다. 지금 세상 카드는 「올해(2026) 태어나는 아이」임을 안내한다(형진 님 결정 Q1). 지난·다가올 세상 카드는 연도 범위 안내를 그대로 둔다.
- [ ] **FS5 인생 길이**: 「약 30분」 / 「약 1시간」 2개를 라디오 카드로 보인다(기본 ▲ 약 30분, 마지막 선택 기억). 한 줄 설명 「평균 수명까지 살아 보는 데 걸리는 시간 — 중간에 닫아도 이 기기에 저장돼요」(뜻 유지). 한 판 시작 뒤에는 바꿀 수 없다(LM3).
- [ ] **FS6 하단 고정 태어나기 버튼**: 하단 중앙에 **고정**되어 스크롤해도 같은 위치에 있다(360×568 ~ 1280×800 모두). safe-area(홈 인디케이터)를 고려하고 본문·출처·캐러셀 마지막 줄을 가리지 않는다(하단 여백). 연타·더블탭에도 출생이 **한 번만** 일어난다(GuardedButton + 룰렛 화면 겹침을 측정하는 e2e, R-035·R-050 방식). 진행 중인 저장이 있으면 같은 자리에 「이어서 살기」가 기본 버튼, 「새로 태어나기」는 보조(누르면 이전 판이 사라진다는 확인 단계 ▲). 첫 화면은 저장되는 화면 단계가 아니라서, 「나가기」로 첫 화면을 연 뒤 새로고침하면 저장된 화면(대시보드)이 그대로 복원된다(마스터 결정 C3). 고정 띠는 키보드 포커스도 가리지 않는다(CM10). 화면 높이가 낮아(400% 확대 상당 등) 고정 띠가 화면 높이의 절반을 넘으면 고정을 풀어 본문 끝에 둔다(QM2-12). 확인 단계의 확정 버튼 이름은 방금 누른 「새로 태어나기」와 달라야 하고 결과(이전 판 삭제)가 드러난다(QM2-6, 문구는 마스터가 고른다).
- [ ] **FS7 출처 표기**: 법원 이름 통계 출처 표기(SPEC-001) 유지 + 통계 캐러셀 슬라이드별 출처(SC2) + 푸터에 빌드 버전(`v<버전> (<커밋 7자>)`, 이슈 보고용). 360px에서 넘치거나 잘리지 않는다. 커밋 7자는 **배포 커밋**(CI의 `GITHUB_SHA`)이고, 로컬 빌드는 작업 트리 `HEAD`에 커밋 안 된 변경이 있으면 구별 표기해 배포본과 같다고 오해되지 않게 한다(QM2-7).
- [ ] **FS8 외부 요청 0**: 첫 화면 로드와 캐러셀 동작 중 외부 도메인 요청이 없다(CM3). 「외부 요청 0」은 「오프라인에서 새로고침해도 열린다」가 아니다 — 서비스 워커가 없다(DP4, QM2-7).

### VP 가상 인구·같은 해 태어난 사람들

- [ ] **VP1 가상 인구 값**: `virtualPopulation(분 단위 시각)` 순수 함수. 기본 규모 ▲ 한국 주민등록인구를 1/1,000로 줄인 가상 인구(약 5만 명대, 근거 통계는 SC·EV에 기록)에서 출생·사망 통계를 반영해 분 단위로 아주 조금씩 변한다(1분 변화량 ≤ 0.05%▲, 하루 변동폭 ≤ ±0.5%▲). 같은 입력이면 같은 값이고 `core`는 `Date`·`Math.random`을 쓰지 않는다(시각은 UI가 주입). 임의 시각 1만 표본으로 범위·연속성을 단위 테스트한다. (규모·변동 모델 기본값은 C11)
- [ ] **VP2 정직한 표기**: 가상 인구라는 설명이 FS2 보조 문구와 정보 설명 한 곳에 있고, 어느 화면에도 「접속자」「동시 접속」 표현이 없다(문구 점검 테스트). 서버 호출·접속자 집계 없음.
- [ ] **VP3 같은 해 태어난 사람들**: `peersOf(시드, 출생 연월)` 결정적 함수로 4명▲을 만든다. 이름은 해당 시대·성별 이름 풀에서(지금 세상은 2025년 풀 — R1은 전국 상위 20, R2부터 SPEC-002 N·I의 시도별 합집합), 성씨는 가중 랜덤, 금지 이름 필터 동일 적용, 지역은 RL 지역 확률로, 수저는 시대 가중치로 정하고 서로 이름이 겹치지 않는다. 같은 시드는 같은 인물이라 새로고침해도 같다(상태에는 시드만 저장). 이름이 풀과 100% 일치함을 1000판 시뮬레이션이 원자료를 직접 읽어 대조한다.
- [ ] **VP4 또래의 현재 모습**: 대시보드 우측(DB13)에 「지금 이 나이에」 열로 또래의 상태 라벨(어린 시절·학교에 다님·일하는 사람·돌봄·은퇴 등)을 보인다. 나이×수저 단계 규칙표(설계값, 통계가 아님을 표기)에서 결정적으로 뽑고, 나이와 모순되는 라벨(예: 5세에 「일하는 사람」)이 0개임을 표 테스트가 단언한다.

### SC 한국 사회 통계 캐러셀

- [ ] **SC1 지표**: 요청의 5개(합계출산율[출생률], 사망률, 노인빈곤율, 자살률, 지역별 인구수[17개 시도])를 포함해 **10개 이상▲**. 후보: 연간 출생아 수 / 기대수명 / 1인 가구 비율 / 평균 초혼 연령 / 가계부채 / 청년 고용률 / 사교육 참여율·비용. 최종 목록은 EV1이 출처를 확인한 뒤 마스터가 정한다.
- [ ] **SC2 슬라이드 내용**: 제목, 값+단위, **기준 연도**, 출처(기관·통계표 이름), 그래프(SVG, 값 라벨 병기), 한 줄 정의(「노인빈곤율: …」). 평가·논평 문구 없이 정의와 값만 쓴다(정치적 중립). **단위·기준 문구 결합 규칙**: 값 옆 칸에는 단위 낱말만 쓰고 「인구 10만 명당」 같은 분모 문구는 기준 줄에 쓰며 「명당 명」처럼 단위가 겹치는 표기는 없다(QM2-4). 구분 기호(「·」)가 줄 끝·첫머리에 남지 않는다 — 글자 200%·폭 320에서도(QM2-5), 사슬이 한 줄보다 길어질 수 있는 나열은 쉼표 나열로 쓴다(QM2-10). **제목에 이름이 든 지표의 값은 같은 화면에 눈에 보인다**(제목이 약속한 값, QM2-11). 그래프 첫 값 글자가 자기 선에 걸리는 것은 조건부로만 허용한다(QM2-8).
- [ ] **SC3 데이터와 검증**: `src/data/koreaStats.json`(형식은 "데이터 형식"). 값마다 `docs/data/korea-stats-sources.md`의 행(통계표·원문 값·열람일)과 `basisId`로 연결되고 테스트가 대조한다. 필수 필드·기준 연도 정수·값 범위를 빌드가 검증한다. 접근 원칙은 SPEC-002 S3(로그인·가입·인증키 없이 공개된 통계표·보도자료만, 수치는 원문과 대조).
- [ ] **SC4 갱신 방법**: 지표별 발표 주기와 갱신 절차를 `korea-stats-sources.md`에 적는다(개발자가 값을 고치고 빌드·배포하는 수동 절차, 앱은 실행 중 외부 요청 없음). 화면에 「통계 기준: <연도> · 마지막 갱신 <날짜>」 표시. 슬라이드 안의 기준 연도 표기(기준 줄·통계 기준 줄·그래프 마지막 점)는 모두 같은 값(`latest.year`)에서 만든다(QM2-4).
- [ ] **SC5 동작**: 자동 전환 주기 ▲ 7초, 이전·다음 버튼·페이지 점·**일시정지 버튼**(WCAG 2.2.2), 포인터가 올라가거나 포커스가 있으면 정지, 터치 스와이프, 키보드 ←/→, 점 버튼의 접근 가능한 이름(「3/10 합계출산율」). 「움직임 줄이기」이면 자동 전환을 끈다. 자동 전환은 스크린리더가 읽지 않는다(`aria-live="off"`). **재개 규칙**: 멈춤 사유(일시정지·포인터·키보드 포커스·탭 가림)가 모두 풀리면 반드시 재개하고, 포인터 밑 요소가 바뀌어도(버튼 아이콘 교체 등) 포인터 이탈을 놓치지 않으며, 화면 표시(「7초마다 다음 지표」/「자동 넘김 멈춤」)와 실제 동작이 항상 일치한다(QM2-2).
- [ ] **SC6 자살률 슬라이드 안전 규칙**: 값(인구 10만 명당)·기준 연도·출처와 **자살예방 상담전화 안내**(24시간 번호는 보건복지부·한국생명존중희망재단 공식 안내에서 수집 때 확인해 기입 ▲ 109, 확인 전에는 쓰지 않는다 — C10)가 **같은 슬라이드 안에** 있다. 방법·장소·동기 서술 없음. 게임의 사건·선택지에는 자살·자해를 쓰지 않는 SPEC-002 결정은 유지.
- [ ] **SC7 차트 구현**: 차트는 SVG 직접 구현. 차트 라이브러리 등 새 의존성은 마스터 승인과 사유 기록 없이는 추가하지 않는다.

### RL 출생 룰렛

- [ ] **RL1 구성과 연출**: 「태어나기」 → 룰렛 화면. **수저 릴**(흙·동·은·금·다이아몬드 수저 5종이 계속 바뀜)과 **지역 릴**(시도 17개, 시군구는 출생신고에서 추첨 — 마스터 결정 Q2)이 **나란히** 돌아간다. 가속 → 회전 → 감속 정지. 총 연출 시간 ▲ 4~6초, 수저 릴이 마지막에 멈춘다 ▲, 「건너뛰기」 버튼 제공. 「움직임 줄이기」이면 회전 없이 후보 전체를 보이고 결과만 강조한다. (QA-003-M3 보완 마스터 확인 6·REV-003-M3-4 R-301: 릴에는 결과 칸 앞뒤 2칸만 보이고, **수저·지역 후보 전체는 릴 아래 확률표로 보인다**.)
- [ ] **RL2 결과는 먼저 정해져 있다**: 릴이 멈추는 값은 출생 로직(`generateBirth`, 시드 RNG)이 정한 결과와 같다. 연출이 확률을 바꾸지 않는다. 단위 테스트: 룰렛 결과 = 출생 로직 결과(1000판), 연출 코드에 `Math.random` 없음.
- [ ] **RL3 확률 표기**: 각 릴 **아래 작은 글씨**로 확률을 적는다. 수저: 선택한 세상의 `wealthWeights`(설계값)에서 계산해 합이 100(표시 반올림은 합 100이 되게 보정). 「이 확률은 게임의 설계값이에요(통계가 아님)」를 함께 표기한다 — 설계값을 유지한다(마스터 결정 Q4). 지역: 시도별 출생아 비율(통계청 출생통계의 최근 확정 연도, 소수 1자리, 합 100.0), 기준 연도와 출처 표기. 지난·다가올 세상의 지역 확률은 「지금 통계를 바탕으로 한 설계값」임을 표기한다(SPEC-002 S4 방식).
- [ ] **RL4 수저 표기**: 5종 이름은 색·아이콘·글자를 함께 보인다(DS3). 이름은 「다이아몬드수저」로 쓴다(요청 표기).
- [ ] **RL5 확정과 복원**: 태어나기를 누르는 시점에 출생 결과가 저장된다. 룰렛 도중·직후 새로고침하면 룰렛이 다시 돌지 않고 결과가 확정된 모습으로 복원되며 결과는 같다(새로고침 연타 포함, R-021 유지). 확정 뒤 「출생신고 보기」로 이동한다. **다시 굴리기는 없다**(SPEC-001 「다시 뽑기 없음」 유지).
- [ ] **RL6 접근성**: 회전 중 값은 스크린리더가 읽지 않고 결과만 `aria-live`로 알린다. 키보드로 건너뛰기·이동 가능.

### BR 출생신고

- [ ] **BR1 문서 구성**: 헤더 「출생 신고」, 큰 이름, 한 줄 서술문, 정보 격자, 같은 해 태어난 사람들(VP3), 비교 표(BR5, 있을 때), 하단 「살아가기」. 80억 분의 1의 구조를 참고하되 한국 지역·한국 통계 중심으로 구성하고 문구·그래픽은 자체 제작(DS8).
- [ ] **BR2 항목**: 이름 / 성별 / 출생 연월(지금 세상은 2026년 고정, 월은 [가정] 통계 가중 추첨 — 남은 결정 R1) / 출생지(시도+시군구, 시군구는 시도 안의 출생아 비율로 추첨 — 마스터 결정 Q2) / 가정 형편(「흙수저(하위 25% 안쪽)」 형식의 수저 이름 + 구간, 5단계 점 표시. 구간은 출생 화면·엔딩이 이미 쓰는 `startBandOf`·`bandLabel`(시대별 가중치표의 누적)을 재사용하고 통계 소득 5분위라고 쓰지 않는다 — 마스터 결정 Q4. 5단계 × 3시대 표를 단위 테스트) / 부모 나이(어머니·아버지) / 부모 직업(각각) / 주거(자가·전세·월세·반지하 등) / 출생 체중(kg, 백분위) / 형제 순서(첫째·둘째 …) / 교육방식(SPEC-001 유지) / 외모(SPEC-001 유지). 종교·국적 선택은 두지 않는다.
- [ ] **BR3 한 줄 서술문** (요청 예시 형식): 「{연}년 {월}월, {시도} {시군구}의 {형편 서술} 가정에서 {체중}kg {남자아이|여자아이}로 태어났습니다. {첫째|둘째|…}입니다. ({체중}kg은 {상위|하위} 약 N%)」. 같은 문장이 대시보드 인생 기록 0세 첫 줄이 된다(합쇼체 — 인생 기록 전체가 같은 어체, 마스터 결정 C1). 문장 생성 규칙표를 단위 테스트한다.
- [ ] **BR4 통계 근거와 가중**: 출생 체중(성별별 분포, 근거 통계청 출생통계의 체중별 분포 → 백분위는 R-018 표현 규칙: 상위/하위 ≤ 50%, 중앙은 전용 문구), 부모 출산 연령(통계청 평균 출산 연령 기준), 형제 순서(출생아의 출산 순위 비중), 시군구(시도 안의 시군구별 출생아 비율), 부모 직업(한국표준직업분류 대분류 기준 가중표), 주거(자가·전세·월세 비중 등) — **모든 가중표는 근거 행(EV1)에 출처·기준 연도·열람일을 적고**, 수저 단계별 보정 값은 「설계값」으로 구분한다. 지난·다가올 세상에는 지금 통계를 시대 보정해 쓰고 그 사실을 출생신고 하단에 한 줄 표기한다. 실제 상호·기업 이름 금지.
- [ ] **BR5 비교 표 (근거가 확인된 행만)**: 「같은 해 태어난 아이 평균」과 「이 가정」을 견주는 표(요청의 G3: 수저의 영향 체감). 후보 행: 기대수명의 소득 수준별 차이, 사교육 참여·비용의 소득별 차이, 대학 진학률의 소득별 차이. **출처가 확인된 행만** 넣고 3행 이상▲, 확보하지 못한 행은 넣지 않는다. 행마다 출처·기준 연도 표기. (해외 국가 비교표는 만들지 않는다.)
- [ ] **BR6 영유아 가족 정합**: 출생 때 정한 형제 순서·부모 나이·직업은 이후 이벤트와 모순되지 않는다. 예) 「동생을 맞이한」 사건은 출생 순서가 첫째인 판에서만(IN4), 부모 사별·퇴직 사건은 부모 나이와 어긋나지 않는다 — 한 판 모순 0건을 flow 테스트로 단언(CM9).
- [ ] **BR7 안전한 이동**: 「살아가기」는 연타 가드(R-014), 새로고침해도 같은 출생신고(R-021), 진입 직후 입력 가드(0.4초).

### DB 대시보드

- [ ] **DB1 레이아웃**: 폭 ≥ 960px에서 3열 — 좌(프로필 카드·상태 바·자산 현황) / 중(인생 기록) / 우(가족과 삶·같은 해 태어난 사람들). 좁은 화면(360px)은 1열: 헤더 → 프로필 → 상태·자산 → 인생 기록 → 가족과 삶 → 또래. 가로 넘침 0(360·320px, 확대 200%).
- [ ] **DB2 진행률 바**: 헤더에 나이(큰 숫자)와 바. 바는 그 해의 연출 시간 동안 0→100%로 차오르고 100%가 되면 나이가 +1 된다. 일시정지·카드 대기·선택지 대기 중에는 멈추고, 배속에 따라 속도가 바뀐다. 순수 함수 `yearProgress(경과, 연출 시간)` 단위 테스트 + e2e(단조 증가, 나이 증가 시 0으로 리셋).
- [ ] **DB3 컨트롤**: 진행 줄 — 일시정지/계속, 1·2·4·8배, 다음 결정으로, 자동 모드(유지, 12·16배 없음 — 마스터 결정 Q6). 도구 줄 — BGM, 생각 남기기, 다크 모드, 의견 보내기, 나가기. 일시정지는 연출 타이머·진행률을 정지하고 **탭이 다시 보여도 자동 재개하지 않는다**(사용자가 정지한 상태 유지). 360px에서 터치 대상 ≥ 44×44px▲, 가로 넘침·가림 0, 아이콘만 있는 버튼은 접근 가능한 이름을 가진다. SPEC-001의 입력 가드(진입 직후 0.4초, 연타)·포커스 규칙(R-030·R-036)을 새 컨트롤과 카드에 그대로 적용한다.
- [ ] **DB4 BGM**: 켜기/끄기 버튼(기본 꺼짐 ▲, 사용자 제스처 뒤에 시작해 모바일 자동재생 정책을 지킨다). Web Audio로 **코드가 직접 생성**하는 잔잔한 칩튠 루프 1곡 이상, 반복 피로를 줄이는 패턴 4개 이상▲(코드 진행·멜로디 변주), 볼륨(기본 낮음 ▲) 조절, 켬/끔·볼륨 저장. 탭이 가려지면 일시 중단. 음원 파일·외부 라이브러리 없음, **기존 곡의 멜로디를 쓰지 않는다**. 테스트: 시퀀스 데이터(음 높이·길이)가 음계·마디 규칙에 맞는지 단위 테스트, 실제 소리는 형진 님이 모바일에서 청취해 확인(완료 기준).
- [ ] **DB5 생각 남기기**: 언제든 눌러 현재 나이의 짧은 기록을 남긴다(FR 입력 규칙 동일). 열면 게임이 자동으로 일시정지하고 닫으면 이전 상태로 돌아간다.
- [ ] **DB6 다크 모드**: 버튼으로 라이트↔다크 전환. 처음에는 시스템 설정(`prefers-color-scheme`)을 따르고 수동 선택은 저장. 모든 화면이 두 테마에서 가로 넘침·가림 없이 보이고 DS3 대비 점검이 두 테마에서 통과한다.
- [ ] **DB7 의견 보내기**: GitHub 이슈 작성 화면(새 탭, `rel="noopener noreferrer"`)으로 연결한다. 주소 구성 함수 `buildFeedbackUrl`이 **허용 목록 필드만** 채운다 — 빌드 버전·현재 화면 이름·세상·인생 길이. **캐릭터 이름·나이·자유 기록·저장 데이터·브라우저 정보는 넣지 않는다**(테스트: 어떤 상태에서도 URL에 이름·기록 문자열이 없다). 저장소 주소는 빌드 설정에서 읽는다(DP1).
- [ ] **DB8 나가기**: 게임을 일시정지 상태로 저장하고 첫 화면으로 이동한다(첫 화면에서 「이어서 살기」, FS6). 확인 한 단계를 둔다 ▲. 나가기 뒤 새로고침하면 저장된 화면(대시보드)이 그대로 복원된다(마스터 결정 C3).
- [ ] **DB9 프로필 카드**: 얼굴(DS4), 이름, 성별, 출생(연월), 거주(시도·시군구), **출신 가정**(「흙수저(하위 25% 안쪽)」 형식 + 5단계 점, BR2와 같은 규칙 — 마스터 결정 Q4), **학력**, 외모(상위/하위 약 N%, 출생신고와 같은 표현). 학력은 나이×플래그 표로 정한다(▲ 취학 전 / 초등학교 / 중학교 / 고등학교 / 대학교 재학·졸업 / 중퇴·취업 등 — `left_school`·`college`·`early_work` 플래그 연동, 표를 단위 테스트). 얼굴은 나이에 따라 갱신(DS4).
- [ ] **DB10 상태 바**: 건강·행복·지식·관계 4개를 0~100 바 차트로(`role="meter"`, 수치 병기), 「상태는 무엇을 뜻하나요?」 접이식 도움말에 각 상태의 뜻을 적는다.
- [ ] **DB11 자산 현황 (성인 이후)**: 20세부터 **순자산·연 소득·부채**를 **실제 원 단위**로 표시한다(형진 님 결정 Q3). 표기 함수 `formatWon`이 만·억 단위로 읽기 쉽게 적는다(예 「−1,200만 원」「1억 2,000만 원」, 음수·0·단위 경계를 단위 테스트). **지난·다가올 세상은 금액 옆에 「지금 가치로 환산」을 항상 표기**하고, 지금 세상은 금액이 올해 가치 기준임을 「상태는 무엇을 뜻하나요?」 도움말에서 밝힌다 ▲. 20세 미만에는 숨기고 「아직 부모님 집에서 지냅니다 · 가정 형편 N단계」 한 줄만 보인다. 값 변화가 EC 규칙과 일치한다.
- [ ] **DB12 인생 기록**: 가운데 영역에 **한 줄씩 쌓인다**(시간순, 새 줄이 아래에 붙고 자동으로 맨 아래로 이동. 사용자가 위로 스크롤하면 자동 이동을 멈추고 「새 기록 N개 · 맨 아래로」 표시). 영역 안에서 **스크롤**된다. 줄 형식 「{나이}세 {문장}」. 종류: 사건 / 선택 결과 / 나의 기록(FR, 시각적으로 구분) / 단계 / 사망. 저장 상한(`HISTORY_LIMITS.maxEntries` 160)을 새 규모에 맞게 올린다(▲ 300, 최악 판 저장 크기 ≤ 200KB▲).
- [ ] **DB13 가족과 삶**: 어머니·아버지(나이·직업·상태), 형제자매(관계·나이 차), 성인 이후 배우자·자녀(`has_partner`·`married`·`has_child` 플래그와 표시가 일치). 부모 나이는 해마다 오르고 사별(`parents_gone`)은 표시에 반영된다.
- [ ] **DB14 가상 인구 줄**: 인생 기록 맨 위에 고정 줄 하나 「지금 이 시뮬레이션 속 {N}명이 함께 살고 있어요」 ▲(쌓이는 기록과 구분, FS2와 같은 N·보조 설명).

### EC 경제 모델·선택지 영향 표기

- [ ] **EC0 설계 문서 먼저**: M5 착수 시 `docs/data/economy-model.md`(상태 값·해마다 변화 규칙·계수 표·근거 지표·기존 이벤트 변환 규칙)를 쓰고 마스터가 승인한 뒤 구현한다. 시대(지난·다가올 세상)의 화폐 가치는 Q3 결정대로 **모든 금액을 지금 가치로 환산한 원 단위**로 계산한다(시대 차이는 물가가 아니라 소득·생활비 계수로 반영하고, 근거가 약한 시대 계수는 설계값임을 문서에 적는다).
- [ ] **EC1 상태**: 20세 이상 `assets = { 순자산, 연 소득, 부채 }`(정수, 내부 단위 ▲ 만 원, 표시는 원 단위 — 형진 님 결정 Q3). 20세 미만은 부모 자산 모델을 만들지 않고 가정 형편 단계(1~5)만 쓴다. 독립(20세) 때 초기값은 집안 형편·학력·학자금 대출 여부로 정한다(SPEC-001 `INDEPENDENCE` 규칙의 대체).
- [ ] **EC2 해마다 변화**: 순자산 변화 = 연 소득 − 생활비(주거 형태·부양 가족 반영) − 부채 이자. 소득은 학력·일 상태(`has_career`·`own_business` 등)·시대에 따른다. 계수는 `src/data/economyTable.ts`(설계값)에 두고 근거 지표(가계금융복지조사 등)는 EV1 행에 적는다. 자산이 모자라면 부채가 늘고 이자가 다음 해 순자산을 깎는다(「빚이 빚을 만든다」).
- [ ] **EC3 선택지의 자산 효과**: 이벤트 스키마에 `effects.assets`(`net`·`income`·`debt` 변화)와 `requires.assets`(순자산·부채 조건)를 추가한다. 기존 `wealth` 효과는 변환표로 새 모델에 옮기고, **모든 기존 이벤트에서 증감 부호가 같음**을 자동 점검한다(예외는 문서에 사유). 이벤트·선택지 id는 바꾸지 않는다.
- [ ] **EC4 불가피한 선택과의 합류**: 자산이 모자라 비용을 못 내는 선택지는 보이지 않거나 「대출을 받아」 경로(부채 증가)로 바뀐다. SPEC-002 E15(불가피한 선택)와 합쳐 같은 이벤트에서 재력·자산별로 보이는 선택지 수가 다른 이벤트를 10개 이상▲ 둔다.
- [ ] **EC5 영향 표기 규격**: 모든 선택지 아래 한 줄 작은 글씨로 **변화가 있는 항목만** 표기한다 — 자산·관계·행복·건강·지식. 형식 「자산 ▼▼ · 행복 ▲」(▲/▼ 개수 1~3 = 크기 단계, 경계는 `IMPACT_STEPS` 표 ▲: |Δ| 1~2 = 1칸, 3~6 = 2칸, 7 이상 = 3칸, 자산은 원 단위 기준 ▲ 500만 원 미만 1칸 / 500만~3,000만 원 2칸 / 3,000만 원 이상 3칸). 색에만 의존하지 않고, 스크린리더용 문장(「자산이 크게 줄어요」)을 제공한다. **표기는 지금 캐릭터 기준의 실제 적용값**(재력·외모 보너스 포함)이며, 이벤트 × 선택지 × 대표 캐릭터 전수에서 표기 방향·단계 = 실제 `resolveEffects` 결과(테스트). 표기에 없는 스탯 변화는 일어나지 않는다(숨은 효과 0).
- [ ] **EC6 연애 시나리오 (요청 예시)**: 청년기 연애 시작 이벤트의 「연애를 시작한다」에 「자산 ▼」가 표기되고 같은 이벤트에 「썸으로 남긴다」가 있다. 자동 모드 성향 선택이 자산·부채를 반영해, 부채 판(순자산 < 0)에서 연애를 시작하는 비율이 비부채 판보다 낮다(시뮬레이션 단언, 차이 ≥ 10%p▲). 소극적 선택에도 얻는 것이 있어 지배 선택지가 아니다(E11).
- [ ] **EC7 밸런스·엔딩 재측정**: 새 모델로 `finalDistribution`(엔딩 출발선 대비)을 다시 만들고 `check:dist`를 통과시킨다. 시뮬레이션 판의 연령별 순자산·부채 보유 비율을 통계(가계금융복지조사)와 견주어 큰 차이가 있으면 계수 표를 조정하고 근거에 기록한다(허용 폭 ▲ M5에서 마스터 확정).

### IN 영유아기(0~7세) 콘텐츠 — 「부모 입장에서 정말 많은 일이 일어난다」

- [ ] **IN1 규모**: 영유아기 이벤트를 현재 11개에서 **40개 이상▲**(서술 ≥ 22, 선택지 ≥ 18)으로 늘린다. 0~7세 **각 나이마다** 그 나이에서 일어날 수 있는 이벤트가 4개 이상▲ — 현재 0세·7세는 0개이므로 0세(출생·예방접종 등)와 7세(입학 준비·유치원 졸업 등)를 채운다. 세 시대 각각에서 영유아 이벤트 25개 이상▲이 일어날 수 있다.
- [ ] **IN2 사건 없는 해 줄이기**: 시대별 1000판에서 0~7세 8해 중 인생 기록에 줄이 하나도 안 생기는 해가 평균 ≤ 1.0, 최대 ≤ 3▲. 영유아기 인생 기록 줄(출생 줄 제외) 평균 ≥ 10줄▲. 영유아 단계 판당 선택지(중대 결정 카드) 평균 ≥ 4개▲(기준선 V1 1.44~1.45). **→ 1차 목표는 「M7a 착수 결정」 (2)로 조정**(빈 해 ≤ 1.5·≤ 4, 줄 ≥ 9, 선택지 ≥ 2.8 / 2차 ≤ 1.0·≤ 3, ≥ 10, ≥ 3.0 — 「선택지 ≥ 4」는 최소 간격 2년 규칙에서 구조상 불가능).
- [ ] **IN3 마일스톤 사건은 반드시 일어난다**: 기본 예방접종(0세) · 첫 걸음마 · 첫 단어는 정한 나이 범위 안에서 **모든 판**에 일어난다(그 전에 사망한 판 제외, 시뮬레이션 단언). 발달 시점은 영유아 발달 기준(근거 행 기입). 요청 예시의 사건(예방접종·첫 걸음마·첫 단어·엄마와의 시간·동생 맞이·어린이집/유치원)이 모두 포함된다.
- [ ] **IN4 동생 맞이 카드 (요청 예시)**: 2~4세▲, **출생 순서가 첫째인 판에서만**(BR6). 중대 결정 카드로 상황(「동생을 처음 봤다. 부모의 애정이 줄어든 듯하다」)과 선택지 3개 — 예: 엄마가 동생을 살피면 운다 / 동생을 예뻐해 준다 / 동생의 장난감을 빼앗는다(「해코지」는 폭력 장면 묘사가 아닌 유아기 질투 행동의 담담한 서술로, 아래 안 할 것 참조). 선택지는 유아 심리 연구가 말하는 형제 출생 뒤 첫째의 전형적 반응(퇴행·관심 끌기·돌보기·질투 표현)을 반영하고 각각 근거 행(EV1)에 연결한다. 지배 선택지 없음(E11), 영향 표기(EC5)·인용(MD2) 포함.
- [ ] **IN5 소재 범위 (최소 포함)**: 예방접종·영유아 건강검진·돌잔치·이유식·첫 걸음마·첫 단어·어린이집(입소 대기·적응·감염)·유치원·입원·응급실·배변 훈련·떼쓰기·영상 노출·사교육 시작의 압박·조부모 돌봄·맞벌이와 육아휴직·층간소음·이사·소아과 대기. 각 소재는 EV 근거 행 또는 소재 목록 행(T2)에 연결된다. 부모의 사정·감정은 서술하되 주어는 「아이」 또는 이름(R-070).
- [ ] **IN6 시대 정합**: 시대 소재 금지어 표(`ERA_BANNED_WORDS`)에 영유아 소재를 추가한다(예: 지난 세상에서 「어린이집 대기」「영어 유치원」 금지, 대신 골목·조부모·집안일). 시대 전용 영유아 이벤트 각 3개 이상▲.
- [ ] **IN7 수저에 따른 차이 (G3)**: 같은 이벤트에서 재력 단계에 따라 보이는 선택지·결과가 다른 영유아 이벤트 8개 이상▲(예: 어린이집 선택, 사교육 시작, 병원 선택). 시뮬레이션에서 재력 1~2단계 판과 4~5단계 판의 영유아 선택지 구성 차이가 관측된다.
- [ ] **IN8 규칙 계승**: 영유아 문구 3인칭(R-070), 담담한 어조·시대 금지어·모순 0(E10·E11)을 그대로 지킨다. 문구는 **합쇼체**(마스터 결정 C1)로 쓰고 길이 권장 최대(제목 16·본문 70·라벨 24·결과 80자)는 합쇼체 기준으로 재산정한 값(M7e)을 따른다. 새 이벤트 모두 `once: true`.

### MD 중대 결정 카드 (통계·연구 인용)

- [ ] **MD1 카드 UI**: 선택지 이벤트는 모두 **중대 결정 카드**로 보인다. 요소 — 헤더(「중대 결정」·연도·나이 — `copy.md` 기준), 제목, 상황 문장, 인용 박스(있을 때), 선택지 2~3개(각각 영향 표기 EC5), 「카드 접기」(카드를 접어 인생 기록을 볼 수 있고 게임은 정지 유지, 「결정 다시 열기」 제공 — 문구는 `copy.md` 기준, R-124 · M7b 착수 결정), 자동 모드 안내. 카드가 뜨면 포커스가 카드로 이동하고 접으면 복귀한다(R-036 규칙을 새 카드에 적용, `decideLifeFocus` 표 갱신).
- [ ] **MD2 인용 규칙**: 중대 결정 카드의 70% 이상▲이 통계 또는 연구 인용을 하나 가진다(**1차 게이트와 판정 방식은 「M7b 착수 결정」 (1) — 70%는 2차 최종 목표**). 형식 — 요약 문장 ≤ 100자▲ + 출처 줄 「기관·저자(연도), 자료 이름」. 규칙(SPEC-002 S6 이어받음): 원문 문장을 그대로 옮기지 않고 요약, 수치는 원문 값과 일치, 지어낸 수치·뜻이 바뀌는 반올림 금지, 시대 정합(지난 세상은 그 시기 통계가 있을 때만, 다가올 세상은 「지금 기준으로는」), 의료·법률·재무 조언처럼 읽히지 않음. 모든 인용이 `citations.json`에 있고 `basisId`로 EV1 근거 행과 연결되며 테스트가 대조한다(근거 없는 인용 0).
- [ ] **MD3 연구 인용의 정확성**: 연구 인용은 저자·연도·자료 이름을 원문(논문·보고서·기관 자료)에서 직접 확인한 것만 쓴다. 요약 도구·검색 스니펫만 본 값은 쓰지 않는다. 문헌 후보(원문 확인 전이라 인용문으로 쓰지 않음): 애착 이론·낯선 상황 실험, 형제 출생 뒤 첫째의 행동 변화 연구, 아동기 부정적 경험과 성인기 건강 연구, 영유아 스크린 노출 권고(WHO 등), 질병관리청 국가예방접종 일정, 영유아 건강검진·발달 선별검사 기준.
- [ ] **MD4 카드 상한**: 한 판의 카드 수·읽는 시간은 LM2가 정한다.

### FR 자유 기록 — 「적어두고 살기 / 마음속에 담고 살기」

- [ ] **FR1 기록 카드 종류**: 요청의 7종을 모두 만든다 — ① 영유아기 기억(정확히 5세▲) ② 청소년기 시기·질투(13~17세) ③ 첫사랑의 추억(`first_love` 플래그 뒤 또는 15~25세) ④ 청년기 연애담(20~34세, 연애·이별 플래그에 따라 문구 분기) ⑤ 아팠던 경험(큰 병·건강 이벤트 뒤 또는 건강 하락 임계) ⑥ 부모님이 나이가 들었다고 느낀 때(부모 나이 ≥ 65▲, `parents_gone`이 아닐 때) ⑦ 중년에 느끼는 인생이란(45~55세). 판당 6~8회▲. 카드 정의는 `src/data/notes.json`(형식은 "데이터 형식"). **질문 문구는 80억 분의 1 문구를 복제하지 않고 자체 작성**한다(예: 「{이름}이 다섯 살이던 때를 떠올려 보면, 기억나는 장면이나 느낌이 있습니까?」 — 카드 문구는 합쇼체, 마스터 결정 C1).
- [ ] **FR2 카드 UI**: 질문 · 통계/연구 한 줄 인용(영유아 체험이 성인기까지 영향을 준다는 근거 — 요청의 G, MD3 규칙 적용) · 여러 줄 입력란 · 선택 2개 「1. 적어두고 살기」「2. 마음속에 담고 살기」(문구는 요청 원문). 카드가 뜨면 게임은 멈춘다.
- [ ] **FR3 입력 규칙**: 최대 길이 140자▲(사용자가 인식하는 글자 단위, 이모지·결합 문자 포함), 줄바꿈 ≤ 3줄▲, 앞뒤 공백 제거·연속 공백 정규화, 제어 문자·제로폭 문자 제거. 붙여넣기가 상한을 넘으면 잘라 넣고 안내한다. **공백만·빈 입력이면 「적어두고 살기」는 기록하지 않고** 입력란 아래 안내(「적을 말이 없다면 2번을 골라도 됩니다」)를 보이며 카드는 닫히지 않는다. 한글 입력(IME) 조합 중에는 제출·길이 계산이 조합 완료를 기다려 마지막 글자가 사라지지 않는다.
- [ ] **FR4 안전한 표시**: 입력은 **항상 글자로** 표시된다 — `<script>`·`&`·마크다운·URL·HTML 엔티티가 해석되지 않고 그대로 보인다(`dangerouslySetInnerHTML` 사용 금지를 점검). 공백 없는 초장문·긴 URL도 가로로 넘치지 않고(`overflow-wrap: anywhere`), RTL 문자·결합 문자가 주변 UI 순서를 뒤집지 않는다(`dir="auto"` + 격리, QA-001 사용감 6 이월 해소).
- [ ] **FR5 「적어두고 살기」**: 글을 저장하고 인생 기록에 「나의 기록」 줄(나이·주제·내 글)로 쌓는다. **이 기기에만 저장**되고 서버로 가지 않으며 의견 보내기 주소·로그에 들어가지 않는다(DB7). 한 판 기록 수 상한 40개▲(자동 카드 + 생각 남기기 합). 저장 실패(쿼터)면 안내를 보이고 입력 내용을 지우지 않는다.
- [ ] **FR6 「마음속에 담고 살기」**: 아무것도 저장하지 않고 카드가 닫힌다. 입력란에 글이 있는데 이 버튼을 누르면 「적은 글은 저장되지 않습니다」 확인을 한 번 보인다.
- [ ] **FR7 자동 모드·끄기**: 자동 모드에서는 기록 카드가 뜨지 않고 「마음속에 담고 살기」로 처리된다 [가정]. 「다음부터 이 창 띄우지 않기」(설정으로 저장, 다시 켤 수 있음) [가정] (C5).
- [ ] **FR8 개인정보 안내**: 입력란 아래 「실명·연락처 같은 개인정보는 적지 마십시오. 이 기기에만 저장됩니다.」 류 안내(뜻 유지, 카드 안 문구라 합쇼체).
- [ ] **FR9 엔딩 반영**: 엔딩 연표에 「나의 기록」 줄이 시간순으로 함께 나온다(마스터 결정 Q5). 「다시 태어나기」를 누르면 이전 판의 기록은 사라진다(기존 안내 문구 유지, 새 판 시작 시 삭제 테스트).

### SA 한국 사회 풍자 사건 (G1·G2·G4)

- [ ] **SA1~SA5 주제별 중대 결정 카드 각 4개 이상▲(합계 ≥ 20▲)**, 각 이벤트는 상황 → 선택지(불가피한 선택 포함) → 영향 표기 → 인용을 갖춘다.
  - **SA1 입시·학원 경쟁**(학창기): 학원과 집을 오가는 일상의 피로, 학원을 늘릴지·줄일지·그만둘지·다른 길을 찾을지. 사교육·청소년 수면·행복 관련 통계 인용.

### `src/data/koreaStats.json` (SC3)
```
{ "meta": { "updatedOn": "YYYY-MM-DD" },
  "indicators": [ { "id": "tfr", "title": "합계출산율", "unit": "명", "kind": "line|bar|number",
                    "latest": { "year": 0, "value": 0 }, "series": [ { "year": 0, "value": 0 } ],
                    "definition": "한 줄 정의", "basisId": "s-001",
                    "source": { "org": "기관", "table": "통계표 이름", "accessedOn": "YYYY-MM-DD" },
                    "safety": "suicide-help | null" } ] }
```
- 지역별 인구수는 `kind: "bar"`에 17개 시도 값. 값은 원문 대조 뒤에만 채운다(이 문서에는 수치를 적지 않는다).
- `unit`은 **단위 낱말만**(명·%·세·년·건·천 명·만 원). 「인구 10만 명당」 같은 분모 문구는 단위에 합치지 않고 따로 둔다(필드로 분리해도, 표시 단계에서 분해해도 된다 — 화면에 나오는 문자열만 QM2-4가 검증한다).

#### QM2-1 고정 요소가 키보드 포커스를 가리지 않는다 (CM10, M2-N14)
- **규칙**
  1. 고정 요소 = 계산된 `position`이 `fixed`이거나 화면 가장자리에 붙은 `sticky`인 요소. 테스트는 이를 화면에서 **자동으로 모으고**(이름·클래스를 손으로 나열하지 않는다 → 새 고정 요소가 생겨도 자동 포함), 높이를 고정값으로 가정하지 않는다(첫 화면 띠는 새 판 68px · 이어하기 120px · 확인 단계 150px로 상태마다 다르다).
  2. 포커스를 받은 요소(키보드 Tab·Shift+Tab·방향키, 프로그램 `focus()` — 화면 전환 뒤 제목, 확인 단계를 닫은 뒤 「새로 태어나기」 복귀, 카드가 뜰 때)는 **포커스 링(outline + offset)까지 포함한 상자**가 고정 요소 상자와 겹치는 면적 0이고 화면 안(위끝 ≥ 0, 아래끝 ≤ 뷰포트 높이)에 있다. WCAG 2.4.11(AA)은 「완전히 가려지지 않음」이지만 이 게임은 일부 가림도 없는 2.4.12 수준으로 정한다.
  3. 예외 둘: ① 고정 요소 자신과 그 안의 요소(「태어나기」·「건너뛰기」 같은 띠의 버튼). ② 요소 자체가 가용 높이(뷰포트 높이 − 상단·하단 고정 요소 높이)보다 커서 한 번에 못 들어가는 포커스 대상(키보드 스크롤 영역인 캐러셀 슬라이드 영역 등) — 위쪽 변과 포커스 링이 가용 영역 안에 보이고 나머지는 그 안에서 ↓·PageDown으로 닿을 수 있으면 통과.
  4. 구현 힌트(강제 아님): 고정 요소 높이를 CSS 변수로 노출(첫 화면은 이미 `--bar-h`)하고 스크롤 컨테이너에 `scroll-padding-bottom`(상단 고정이면 `scroll-padding-top`)을 그 값 + 여유 8px 이상으로 둔다. 같은 패턴을 `docs/design/design-system.md`에 적는다(DS3).
- **완료 기준**
  - (a) 공통 뷰포트 목록 `STANDARD_VIEWPORTS`(한 곳에 정의, 새 화면 e2e도 이것을 쓴다) = 320×568, 360×568, 360×740(터치), 375×812, 667×375(가로), 768×1024, 1024×768, 1280×620, 1280×800 + 확대 상당 640×400, 320×256 — **11종**. 고정 요소가 있는 모든 화면·상태(첫 화면: 새 판 / 이어하기 / 확인 단계)에서 실행한다.
  - (b) 조합마다 Tab으로 한 바퀴 끝까지, 이어서 Shift+Tab으로 처음까지 순회하며 **포커스가 바뀔 때마다** 측정: 포커스 요소 상자와 모든 고정 요소 상자의 겹침 면적 0, 화면 안(예외 ②는 위끝만), 포커스 요소의 보이는 부분 한가운데 점의 `elementFromPoint`가 포커스 요소(또는 그 안·조상). **가려진 포커스 수 = 0.**
  - (c) 순회가 짧게 끊겨 통과하는 일이 없게: 화면의 조작 요소(버튼·링크·라디오 그룹·`tabindex=0`, 비활성 제외) 집합 = 순회로 닿은 집합.

#### QM2-2 자동 전환 재개 불변식 (SC5, M2-A15)
- **규칙** — 멈춤 사유는 ⓐ 일시정지 버튼 ⓑ 포인터(마우스·펜)가 카드 위 ⓒ 키보드 포커스가 카드 안 ⓓ 탭 가림 넷이다(움직임 줄이기는 사유가 아니라 자동 전환 자체가 없는 모드).
  - I1 재개: ⓐ~ⓓ가 **모두** 풀리면 자동 전환이 재개되고 **풀린 뒤 8초 안**(주기 7초 + 1초)에 다음 슬라이드로 넘어간다. 멈춘 채 남는 경로가 없다. 사유가 하나라도 남아 있으면 재개하지 않는다.

  - I3 포인터 이탈: 들어옴/나감 이벤트 쌍만 믿지 않는다. 포인터 밑 요소가 사라지거나 바뀌는 변경(버튼 아이콘 교체·슬라이드 교체·재마운트)이 있어도 포인터가 카드 밖에 있으면 ⓑ는 풀린다. (QA 추정 원인: 「다시 시작」 클릭으로 아이콘이 바뀌어 마우스 밑 요소가 사라지고 `pointerout` 없이 `pointerleave`만 와서 호버 상태가 남음.) 구현 힌트(강제 아님): 재개·전환 시점마다 컨테이너의 `:hover`를 질의하거나, 카드 밖 `pointermove`/`mouseleave`도 함께 듣는다.
  - I4 터치: `pointerType`이 touch인 포인터는 ⓑ로 세지 않는다 — 탭·스와이프 뒤에도 자동 전환이 멈추지 않는다(현행 유지).
- **완료 기준**
  - (a) 재현 절차 e2e(1280×800, 마우스): 카드 밖 → 일시정지 버튼 위로 이동 → 클릭(멈춤) → 카드 밖 → 다시 버튼 위로 → 「다시 시작」 클릭 → **이동 1번(`steps: 1`)으로 마우스를 카드 밖으로** → 8초 안에 슬라이드가 1장 이상 넘어가고 `data-autoplay="on"`, 15초 동안 2회 이상 전환. 이전 구현에서 실패함을 확인한다.
  - (b) 변형 반복: 이탈 방식(`steps` 1·12) × 방향(위·아래·왼·오) × 클릭부터 이탈까지 지연(0·50·500ms)을 각 20회 반복해 **멈춘 채 남는 횟수 0**.

#### QM2-3 글자 확대·리플로 (CM11, M2-V04)
- **규칙** — 서로 다른 두 확대를 모두 지킨다. (가) 글자 크기 확대(WCAG 1.4.4): 기기·브라우저의 글자 크기를 키워도(루트 글자 최대 200%) 내용·기능이 사라지지 않는다. (나) 리플로(1.4.10): 브라우저 400% 확대(= CSS 폭 320px)에서도 가로 스크롤 없이 한 열로 읽힌다.
  - 측정 조건: (가) `html { font-size: 100% / 125% / 150% / 175% / 200% }`(기본 16px → 최대 32px) × CSS 폭·높이 **320×568, 360×740** × 라이트·다크. (나) 브라우저 확대 상당 뷰포트 640×400(1280 창의 200%)·512×384(1024 창의 200%)·320×256(1280 창의 400%). 접이식 폰 280px(글자 100%)는 지금 통과 중이라 회귀 방지로 유지한다.
  - **허용치: 가로 넘침 0px** — `documentElement.scrollWidth − clientWidth ≤ 0`이고 화면에 보이는 모든 요소의 오른쪽 끝 ≤ 뷰포트 폭. 시각적으로 숨긴 표(`sr-only`)는 문서 폭을 늘리지 않는 한 제외한다. 반올림 때문에 1px 의심이 나오면 허용치를 올리지 않고 원인 요소를 고친다.
  - 같이 지킬 것: 글자 잘림 0, 이름표끼리(수저 띠의 「다이아몬드」 등) 겹침 0, 기본 버튼(「태어나기」)이 눌리고 높이 ≥ 44px, 하단 **고정** 띠 높이 ≤ 화면 높이의 절반 — (가)·(나) 모든 조건에 적용하고, 절반을 넘으면 고정을 풀어 본문 끝에 두는 것으로도 충족한다(QM2-12, 2회차 보완).
  - 줄바꿈 금지(`nowrap`) 구간은 한 낱말 길이로 한정하거나 좁은 폭·큰 글자에서는 풀린다. 한 줄에 못 들어가는 가로 배열(수저 띠 등)은 다음 줄로 접는다 — **가로 스크롤로 해결하지 않는다**. 글자·간격·고정 높이는 `rem`/`em` 기반이라 설정이 반영된다.
  - 구조상 불가능한 요소가 나오면 허용치를 임의로 올리지 않고 사유와 함께 planner·마스터에게 올린다.
  - 범위: 새 화면 전부(지금은 첫 화면, 룰렛·출생신고·대시보드·엔딩·카드는 각 마일스톤). 옛 출생·인생·엔딩 화면은 개편 전이라 대상이 아니다. 글자 간격(1.4.12)은 이번에 정하지 않는다(M9에서 판단).
- **완료 기준**
  - (a) `e2e/text-resize.spec.ts`: 첫 화면(새 판·이어하기·확인 단계) × (가) 조건 전부 → 가로 넘침 0px(넘친 요소 목록 출력), 잘림 0, 이름표 겹침 0, 「태어나기」 높이 ≥ 44px·누름 가능, 고정된 띠 ≤ 화면 높이 50%(넘으면 고정 해제 — QM2-12).
  - (b) 캐러셀 14장을 일시정지하고 모두 넘기며 (가) 조건의 320·360에서 같은 단언(그래프 글자 ≥ 12px는 R-206 그대로).
  - (c) (나) 조건 3종에서 가로 넘침 0(M2-A14 유지)과 띠 규칙(≤ 화면 높이 50% 또는 고정 해제 — QM2-12 (a)).
  - (d) 이전 구현에서 실패함을 확인한다: 360×740 · 200%에서 `P.hero__tag`, `SPAN.nowrap`, `SPAN.spoon-fig__name`이 366px > 360px.
  - (e) M2-V04를 같은 절차로 재실행해 PASS. M9 실기기 확인 목록에 「안드로이드 글자 크기 가장 크게로 첫 화면을 열어 가로로 밀리지 않는지」를 넣는다(형진 님).

#### QM2-4 캐러셀 단위·기준 문구 결합 규칙 (SC2·SC4, QA 인상)
- **규칙**
  1. 값 바로 옆 칸에는 **단위 낱말 하나**만 쓴다(명·%·세·년·건·천 명·만 원). 「인구 1천 명당」「인구 10만 명당」 같은 분모 문구는 단위가 아니라 **기준 줄**(「{분모 문구} · {연도}년 기준」)에 쓰거나 값 앞 문장형(「인구 10만 명당 27.8명」)으로만 쓴다. 단위 앞에 같은 낱말로 끝나는 분모가 와서 「명당 명」「건당 건」으로 겹쳐 읽히는 표기는 어디에도 없다.
  2. 정의·보조 문장의 괄호 풀이도 단위를 되풀이하지 않는다. 예) 합계출산율 정의 끝의 「(가임 여자 1명당 명)」은 「한 여자가 …낳을 것으로 예상되는 평균 출생아 수」가 이미 같은 뜻이라 괄호를 삭제하거나 단위를 되풀이하지 않는 문장으로 바꾼다(문구는 developer가 쓰고 reviewer가 읽는다).
  3. 그래프 값 글자·범례·숨긴 표 머리글도 같다. 분모가 있는 값의 기준 어순은 `formatWithUnit`이 이미 만드는 「인구 1천 명당 7.1명」이다.
  4. 슬라이드 안의 기준 연도(기준 줄·「통계 기준」 줄·그래프 마지막 점)는 모두 같은 값(`latest.year`)에서 만든다. 하위 표가 다른 연도·범위를 가질 때는 범위 문구(`scopeLabel`)에 드러낸다.
  5. 표기 형식표(14장 전부 이 넷 중 하나):

| 형식 | 값 줄 | 기준 줄 | 해당 지표 |

| A 단순 | 「{값}{단위}」 | 「{연도}년 기준」 | 합계출산율(명) · 연간 출생아 수(명) · 66세 이상 상대적 빈곤율(%) · 기대수명(년) · 1인 가구 비율(%) · 청년 고용률(%) · 사교육 참여율(%) · 고령인구 비율(%) · 혼인 건수(건; 제목이 「혼인 건수와 조혼인율」이므로 조혼인율 값을 범례 또는 값 아래 줄에 「조혼인율 인구 1천 명당 {값}건」 어순으로 보인다 — QM2-11) |
| B 분모 있는 비율 | 「{값}명」 | 「{분모 문구} · {연도}년 기준」 | 조사망률(인구 1천 명당) · 자살률(인구 10만 명당) |

- **완료 기준**
  - (a) 단위 테스트(`tests/carousel.test.ts`): `buildCarousel()`이 만든 14장 각각의 값 줄·단위·기준 줄·정의·범례·그래프 라벨·숨긴 표 머리글을 모아 **금지 패턴 0건** — `/당 (명|건|세|년|%)(?![가-힣])/`(분모 바로 뒤에 단위만 따로 옴)와 `/(명|건|세|년|%) ?\1(?![가-힣])/`(같은 단위 연속).

#### QM2-5 줄바꿈 규칙 (SC2·FS7, QA 인상)
- **규칙**
  1. 구분 기호(「·」「/」「—」)가 **줄 끝이나 줄 첫머리에 혼자 남지 않는다.** 기호는 뒤따르는 항목과 한 묶음으로 붙이거나(`white-space: nowrap` 묶음) 값 줄과 기준 줄을 나눈다. 여는 괄호가 줄 끝에, 닫는 괄호가 줄 첫머리에 남는 것도 같다. (예: 320px 혼인 건수 「240,326 건 ·」 뒤 「2025년 기준」이 다음 줄로 밀려 「·」만 남던 것) **묶음 자체가 한 줄보다 길어지는 경우(글자 200%·폭 320~360의 「A · B · C」)는 묶음으로 풀 수 없다 — 규칙은 QM2-10(2회차 보완).**
  2. 숫자와 바로 뒤 단위(「240,326 건」「27.8 명」), 날짜·시각 묶음(「11월 1일 0시」)은 중간에서 줄이 바뀌지 않는다. (예: 고령인구 정의의 「(11월 1일 / 0시 기준…」이 「1일」과 「0시」 사이에서 끊기던 것)
- **완료 기준**
  - (a) e2e: 320·360·1280 **× 글자 100·150·200%**(2회차 보완 — 처음에는 폭만 적고 글자 크기를 빠뜨려 구분 기호 단언이 글자 100%에서만 돌았다)에서 14장 전부 + 푸터의 보이는 글자를 글자 단위 `Range`로 줄로 나눠, 줄 마지막(공백 제외) 글자가 `·`·`/`·`—`·`(`인 줄 0, 줄 첫 글자가 `·`·`/`·`—`·`)`·`,`·`.`인 줄 0.
  - (b) 같은 방식으로 `/\d[\d,.]*\s?(%|명|건|세|년|월|일|시)/`에 맞는 모든 곳에서 숫자와 단위가 **같은 줄**에 있고, 날짜·시각 묶음 `/\d+월 \d+일( \d+시)?/`도 통째로 같은 줄에 있다. 글자 200%(QM2-3 조건)에서도 같다.

##### QM2-10 구분 기호 사슬이 한 줄보다 길 때 (QM2-5 규칙 3, M2-C02)
- **용어**: **사슬** = 구분 기호(「·」「/」「—」)로 이은 항목 둘 이상의 글자(「A · B · C」). **항목** = 기호 사이의 글자 덩어리. 쉼표·마침표는 구분 기호가 아니라 문장부호다.
- **규칙** (캐러셀·푸터·앞으로 만드는 모든 화면 공통)
  1. **사슬은 한 줄에 들어가는 만큼만 쓴다.** QM2-5 규칙 1의 묶음(사슬 통째로 한 묶음)은 사슬이 한 줄에 들어갈 때만 기호를 지켜 준다. 한 줄보다 길면(글자 200%·폭 320~360, 항목이 늘어난 데이터) 어디서 끊어도 기호가 줄 끝이나 첫머리에 놓이므로 **줄바꿈 CSS로 풀려 하지 않고 글을 바꾼다**(2·3).
  2. **한 줄을 넘을 수 있는 나열은 쉼표 나열로 쓴다**(「국가데이터처, 행정안전부, 교육부」). 한국어 조판 관례에서 가운뎃점·여는 괄호는 앞뒤 낱말과 떨어져 가장자리에 남으면 끊긴 글로 읽히지만, 쉼표는 앞 항목에 붙어 줄 끝에 놓이는 것이 정상이다. 그래서 쉼표가 줄 끝에 오는 것은 허용, 줄 첫머리에 오는 것은 불허(공백 없이 앞 낱말에 붙으므로 정상 조판에서는 첫머리에 오지 않는다). 항목 안 공백에서 줄이 바뀌는 것은 허용하고, 숫자+단위·날짜 묶음은 QM2-5 규칙 2 그대로다. **쉼표 나열로 써야 하는 것**은 기계적으로 가려진다: ① 항목 수가 데이터·설정에 따라 바뀌는 나열 — 푸터 통계 출처 기관 목록(`data.orgs`)이 이 경우다 ② 아래 (a) 측정에서 한 줄을 넘겨 기호가 줄 가장자리에 놓인 사슬 — 쉼표 나열로 바꾸거나(이 항) 항목마다 줄을 나눈다(3), 둘 중 하나로 고친다. (정의 문구의 나열은 이미 이 방식이다 — 사교육 참여율 정의 「학원, 개인과외, …」, `ai-log/2026-10-15_SPEC-003_dev-M2-r4.md`.)
  3. **「·」 사슬은 한 줄에 확실히 들어가는 짧은 쌍**(예 「인구 10만 명당 · 2025년 기준」)에만 남긴다. 그런 쌍이 (a)의 가장 나쁜 조건에서 한 줄을 넘는 것으로 측정되면 두 항목을 별도 줄(요소)로 나눠 쓴다 — QM2-5 규칙 1의 「값 줄과 기준 줄을 나눈다」와 같은 방식이다(그때 QM2-4 (b)의 기준 줄 단언은 두 요소를 각각 단언하도록 고친다).
  4. **수단은 자유, 기준은 측정**: 기호를 줄 경계에서 감추는 CSS 기법 등 다른 수단도 쓸 수 있으나 (a)의 측정(눈에 보이는 글자 기준)을 통과해야 한다.
- **완료 기준**
  - (a) 줄바꿈 감사: QM2-5 (a)·(b)를 폭 320·360·1280 × 글자 100·150·200% 전부에서, 첫 화면 본문(하단 띠의 새 판·이어하기·확인 단계 글자 포함)·푸터·캐러셀 14장에 돌린다(QA 감사 135회와 같은 표본 + 띠 상태). 구분 기호 단언을 글자 150·200%에서도 켠다(지금 `separators: false`). 줄 마지막 글자가 `·`·`/`·`—`·`(`인 줄 0, 줄 첫 글자가 `·`·`/`·`—`·`)`·`,`·`.`인 줄 0, 숫자와 단위·날짜가 갈라진 곳 0. 실제로 잰 줄 수·글자 수가 공허 통과 방지 하한(QM2-5 시험의 기존 하한) 이상이다.
  - (b) 푸터 기관 나열: 단위 테스트에서 기관 수 1·2·3·5개 입력으로 만든 푸터 글자의 기관 이름 사이 구분자가 모두 쉼표이고 기관 이름 사이에 「·」가 0개다. 화면 글자는 「통계 출처: 국가데이터처, 행정안전부, 교육부 (통계표 이름과 기준 연도는 카드마다 적혀 있습니다)」. designer는 `docs/design/copy.md`에 푸터 출처 줄 행이 없으면 더한다.
  - (c) reviewer가 `src/` 안의 `join(' · ')`·`join('·')`·`join(' / ')` 사용처를 모두 열어, 항목 수가 고정된 짧은 쌍인지 확인한다(데이터로 채우는 나열이면 반려). 새 화면의 문구 조립도 같다.
  - (d) 이전 구현에서 (a)가 실패함을 확인한다(360×740·글자 200% 푸터의 「· 교육부」 — 스크린샷 `qa/screenshots/003/M2r2-C02-footer-360-200.png`와 같은 자리).
  - (e) M2-C02를 같은 절차(360×740·320×568, 글자 200%, 푸터)로 재실행해 PASS, 감사 전 표본 0건.

##### QM2-11 제목이 약속한 값은 화면에 보인다 (SC2·QM2-4 규칙 6, M2-C03·R-230)
- **마스터 결정(R-230)**: 슬라이드 제목은 「혼인 건수와 조혼인율」을 유지하고, 조혼인율 값을 눈에 보이는 화면에 둔다. 형식표 A의 혼인 건수 행은 이 결정과 같은 뜻이라 문구만 정리했다(범례 또는 값 아래 줄 — 어느 쪽이든 된다).
- **규칙**
  1. 조혼인율은 **「조혼인율 인구 1천 명당 {값}건」 어순**(`formatWithUnit`이 만드는 문장형: 이름 + 분모 문구 + 값 + 단위)으로 보인다. 자리는 범례(선 무늬 없이) 또는 값 줄 아래 줄이며 designer가 고른다. 값은 `extraSeries`의 최신 값(2025년 4.7)이고 기준 연도는 슬라이드의 `latest.year`와 같다(QM2-4 규칙 4).
  2. 단위가 다른 보조 계열은 그래프 축에 더하지 않는다(현행 `buildLineChart` 제외 유지 — 선이 늘면 QM2-8 허용 목록이 늘 수 있다). 값은 글자로만 보인다. 데이터 라벨 「조혼인율(인구 1천 명당 건)」을 그대로 쓰지 않는다 — 괄호 안 「당 건)」이 QM2-4 금지 패턴에 걸린다. 화면 라벨은 이름(「조혼인율」)만 쓰고 분모·단위는 `formatWithUnit`이 붙인다.
  3. **일반 규칙**: 제목(슬라이드 제목·카드 제목·패널 머리글)에 이름이 든 지표마다, 그 지표의 값이 같은 화면 안에 **눈에 보이는 글자**로 있다.
     - 「지표」= 본 계열과 보조 계열(`extraSeries`). 「이름이 든」= 제목 글자에 그 이름이 부분 문자열로 들어 있음(괄호 풀이는 뺀 이름으로 비교: 「조혼인율(인구 1천 명당 건)」→「조혼인율」).
     - 「눈에 보이는 글자」= 값 줄·범례·그래프 안 글자·캡션·기준 줄. 대체 텍스트·`sr-only` 표·`title` 속성은 세지 않는다 — 숨긴 표에 값이 있어도 눈은 못 본다.
     - 풀 길은 둘이다: 값을 보이거나, 제목에서 그 이름을 뺀다(제목이 약속하지 않으면 값을 보일 의무도 없다). 이번에는 마스터가 제목 유지·값 보이기로 정했다.
     - 캐러셀뿐 아니라 제목에 지표 이름을 단 모든 카드·패널(M3 출생신고 비교표, M4 대시보드 패널 등)에 같다.
- **완료 기준**
  - (a) 단위 테스트(`tests/carousel.test.ts`): `buildCarousel()` 14장마다 「제목 지표」 목록(제목 ∩ 계열 이름)을 만들고, 각 지표의 최신 값 글자(`formatWithUnit` 결과: 「240,326건」「4.7건」…)가 그 슬라이드의 눈에 보이는 글자 모음에 있다. 검사한 (슬라이드, 지표) 쌍의 수가 14 이상이고 조혼인율 쌍이 들어 있다(공허 통과 방지).
  - (b) 혼인 건수 슬라이드: 눈에 보이는 글자(공백을 하나로 맞춤)에 「조혼인율 인구 1천 명당 4.7건」(값은 데이터)이 있고, QM2-4 (a) 금지 패턴 0, 형식표 A 단언 통과, 기준 연도가 `latest.year`와 같다. R-230이 짚은 구멍을 닫도록 QM2-4 (a)가 모으는 글자 목록에 **범례 글자가 들어 있음**을 단언한다(`FORMS` 시험이 범례를 보지 않아 통과하던 것).
  - (c) e2e(R-231과 겹침 — 한 번에 만든다): 폭 320·360·1280 × 글자 100·200%에서 14장 전부 (a)를 **화면 DOM의 보이는 글자**로 단언한다(보임 = 계산된 `display`·`visibility`·`opacity`가 보이고 폭·높이 > 0, `.sr-only` 제외). 혼인 건수 슬라이드의 조혼인율 줄은 잘리지 않고 가로 넘침 0(QM2-3).
  - (d) 이전 구현에서 (a)가 실패함을 확인한다(혼인 건수 슬라이드의 조혼인율 값 없음).
  - (e) reviewer가 14장의 제목과 보이는 값을 훑어 「제목은 약속했는데 값이 없는」 슬라이드 0건을 판정하고, 조혼인율 줄을 소리 내어 읽어 어색하지 않음을 확인한다(DS7 가독성 근거).
  - (f) M2-C03을 같은 절차(캐러셀 10번째 슬라이드, 320·360·1280)로 재실행해 PASS.

##### QM2-12 낮은 화면에서 하단 띠 — 절반을 넘으면 고정을 푼다 (QM2-3·CM10·CM11·FS6, 기록 4·R-233)
- **마스터 결정(R-233)**: 화면 높이가 낮아(400% 확대 상당 등) 하단 고정 띠가 화면 절반을 넘으면 띠 고정을 풀어 본문 끝에 둔다.
- **규칙**
  1. 하단 고정 띠의 높이가 **뷰포트 높이의 50%를 넘으면(> 0.5) 고정을 푼다** — 띠는 문서 흐름의 본문 끝(캐러셀·출처 다음)에 놓인다(계산된 `position`이 `fixed`·`sticky`가 아님). 50% 이하이면 현행대로 고정이다. 이 기준은 QM2-3의 (가) 글자 크기 조건과 (나) 확대 조건 **모두**에 적용하고, 고정을 풀어서 충족해도 된다.
  2. 기준은 **결과(측정)** 다. 띠 높이는 상태(새 판 68px·이어하기 120px·확인 단계 150px)와 글자 크기(확인 단계 200%에서 254px)에 따라 달라 높이값 하나로는 못 맞춘다. 수단은 자유다. 높이 미디어 쿼리(마스터 예시 `@media (max-height: 300px)`는 확인 단계 150px 기준의 값이다)만으로 모든 조합이 (a)를 통과하면 그것도 되고, 못 맞추면 `--bar-h`와 뷰포트 높이를 견줘 클래스를 거는 높이 측정 방식을 쓴다. 미디어 쿼리의 `rem`은 `html { font-size }`로 재현하는 확대 시험에는 반응하지 않는다(초기 글자 크기 기준이라 실기기 설정에는 반응한다).
  3. 고정이 풀리면 **함께 풀 것**: `html.has-bottom-bar`의 `scroll-padding-bottom`과 `--bar-h`를 쓰는 다른 계산(우측 열 `max-height` 등). 안 풀면 본문 아래에 띠 높이만큼 빈 여백이 남거나 우측 열이 줄어든다. 풀린 띠는 본문 마지막 줄과 겹치지 않고 그 안의 버튼(「태어나기」「이어서 살기」·확인 단계 버튼)은 높이 ≥ 44px로 눌린다.
  4. **CM10과의 관계**: 풀린 띠는 계산된 `position`이 고정이 아니므로 QM2-1의 고정 요소 자동 수집에서 빠진다 — 이 띠가 포커스를 가리는 문제 자체가 사라진다. 다만 QM2-1 (b)의 「포커스 요소는 화면 안」은 그대로여서, 풀린 띠 안의 버튼이 포커스를 받으면 스크롤되어 화면 안으로 들어온다.
  5. **전환**: 창 크기 변화·회전·글자 크기 변경·확인 단계 열기/닫기로 고정 ↔ 해제가 오가도 포커스를 가진 요소가 포커스를 잃지 않는다(확인 단계 열기·닫기처럼 프로그램이 일부러 옮기는 경우는 제외). 확인 단계를 열면(고정 → 해제 전환 포함) 안내문 첫 줄과 포커스를 받은 취소 버튼이 모두 화면 안에 보인다.

#### QM3-1 낱말 중간 끊김 일반 규칙 (CM11·QM2-10, M3-L02 — R-281의 명시 목록을 대체)
- **용어**
  - **낱말** = 공백으로 갈라낸 글자 덩어리에서 앞뒤 구두점·괄호를 뗀 한글·영숫자 부분. 요소 경계(`<span>`·`<wbr>` 등)를 넘어 이어 붙은 글자는 한 낱말이다(「다이아몬드<wbr>수저」는 낱말 하나).
  - **끊김** = 한 낱말의 글자(글자 하나씩 `Range`로 잰다)가 서로 다른 두 줄 이상에 걸친 것. 낱말 **사이**나 구두점 뒤에서 줄이 바뀌는 것은 끊김이 아니다(구분 기호·숫자 단위는 QM2-5·QM2-10이 따로 본다).
  - **한 줄 전체** = 그 낱말에서 위로 올라가 처음 만나는 **칸의 부모**(자식이 칸인 상자)의 내용 폭. 칸 = 부모가 grid·flex인 자식, 표 셀, inline-block. 칸 하나의 폭이 아니다. 예: 「태어난 곳」은 서류 격자(`dl`)의 내용 폭, 또래 장소는 항목(`li`)의 내용 폭, 비교 표 낱말은 표 폭, 릴 칸 낱말은 두 릴 전체 폭.
- **감사 범위**: 새 디자인 화면(첫 화면·룰렛·출생신고, 앞으로 M4 이후 새 화면은 자기 마일스톤에서)의 **눈에 보이는 모든 글자** — 제목·본문·칩·표·출처·푸터·하단 띠·헤더·릴·장식(`aria-hidden`이라도 눈에 보이는 도장 「접수」 등). 낱말의 종류(장소 낱말·직업 라벨 …)로 범위를 좁히지 않는다. 제외는 눈에 보이지 않는 것뿐이다(`display: none`·`visibility: hidden`·`.sr-only`·폭 또는 높이 0).
- **허용은 둘뿐**
  - (a) **한 줄 전체보다 긴 낱말**: 그 글자 크기·폭에서 낱말의 자연 폭(같은 글꼴·크기·굵기·자간, `white-space: nowrap`으로 잰 값) > 한 줄 전체의 내용 폭 + 0.5px이면 끊을 수밖에 없다. **측정으로 판정**하고 낱말·조합 목록을 손으로 늘리지 않는다. R-281의 「글자 200% × 폭 320·360의 「전남광주통합특별시」」 명시 목록은 이 규칙으로 대체되며, 그 조합은 측정이 포함한다. 글자 100%에서는 (a)로 허용되는 끊김도 0이다(R-281의 「글자 100%는 모든 폭 0」 유지).
  - (b) **코드에 명시한 의도된 줄바꿈 지점** `<wbr>`. 목록 `INTENDED_BREAKS`로 관리하며 지금은 「다이아몬드수저」(`src/ui/Grade.tsx`) **하나**다. `<wbr>`는 글자를 더하지 않으므로 읽는 이름은 같다. 목록에 없는 낱말에 `<wbr>`(또는 `&shy;`)를 쓰려면 이유와 함께 목록에 등재한다.
- **그 밖의 끊김은 결함이다.** 낱말이 한 줄 전체보다 짧은데 칸 배치 때문에 끊긴 것 — 반쪽 칸의 「단순노무직」·「서비스직」, 표 칸 안 출처 줄의 「초중고사교육비조사」처럼. 고치는 방법은 낱말 목록을 늘리는 것이 아니라 **칸을 한 줄 전체로 넓히는 것**이다(좁은 폭·큰 글자에서 반쪽 칸을 한 줄 칸으로, 출처 줄을 표 칸 밖 문단으로, 칩·릴 칸 폭 조정 등). 수단은 자유이고 기준은 측정이다. 가로 넘침 0(CM11)은 그대로 우선한다.
- **제목(h1)** 은 (a)(b)를 쓰지 않는다 → QM3-2.
- **완료 기준**
  - (a) 공통 감사기 `measureWordBreaks`가 `e2e/lineBreaks.ts` 한 곳에 있고 첫 화면·룰렛·출생신고 e2e가 함께 쓴다. **판정식**: 끊긴 낱말 w마다 `intended` = (w 안에서 줄이 바뀐 지점이 모두 `<wbr>` 바로 뒤이고 w가 `INTENDED_BREAKS`에 있음) / `unavoidable` = (자연 폭(w) > 한 줄 전체 + 0.5px) / 그 밖은 `broken`. 보고는 `{ checked, words, broken, unavoidable, intended }`(`unavoidable`·`intended`는 낱말·곳·자연 폭·한 줄 폭을 기록으로 남긴다).
  - (b) 감사기 자체 시험(합성 DOM; QA 기록 12의 측정 도구 결함 — 공백 텍스트 노드 누락, 구두점 줄바꿈을 낱말 끊김으로 셈 — 의 재발 방지): 요소 경계 너머로 이어진 글자를 한 낱말로 센다 / 낱말 사이·구두점 뒤 줄바꿈은 세지 않는다 / `<wbr>` 지점 끊김은 `intended` / 칸이 좁아 끊긴 짧은 낱말은 `broken`.
  - (c) e2e: **모든 조합에서 `broken = []`**. 조합 = `STANDARD_VIEWPORTS` 11종 × 글자 100·150·200% × 상태(룰렛 회전 중·결과 4수저·움직임 줄이기, 출생신고 표본 7가지 — QA 감사의 12상태와 같다; 첫 화면은 새 판·이어하기·확인 단계와 캐러셀 14장을 폭 320·360·1280 × 글자 100·150·200%로). 글자 100% 조합에서는 `unavoidable = []`이고 `intended`는 `INTENDED_BREAKS`의 낱말뿐이다.
  - (d) 공허 통과 방지: 화면마다 잰 낱말 수가 실측 하한 이상이고, `words`에 장소 낱말뿐 아니라 제목·칩·직업 라벨·출처 줄·릴 칸의 낱말이 각각 하나 이상 들어 있다(표본 확인용이지 허용 목록이 아니다).
  - (e) `INTENDED_BREAKS` 일치: 단위 테스트가 `src/` 전체에서 `<wbr`·`&shy;`·소프트 하이픈 글자(U+00AD) 사용처를 모아 목록과 같음을 단언한다(목록에 없는 사용도, 코드에 없는 목록 항목도 실패). 「다이아몬드수저」의 화면 글자(`textContent`)는 `<wbr>`가 있어도 「다이아몬드수저」다.
  - (f) 변조 대조(R-281 ④ 방식 — 변이 후 원래 파일로 되돌려 `cmp`): ① 어머니·아버지 칸을 반쪽으로 되돌리면 폭 320 · 글자 150·200%에서 「단순노무직」·「서비스직」이 `broken`으로 잡힌다 ② `INTENDED_BREAKS`에서 「다이아몬드수저」를 빼면 폭 320 · 글자 100%의 릴 칸이 `broken` ③ 제목 글자 크기 상한을 빼면 QM3-2 시험이 실패 ④ 비교 표 출처 줄을 표 칸 안으로 되돌리면 실제로 결함이던 조합에서 「초중고사교육비조사」가 잡힌다. 선택자가 썩어 변조가 안 먹으면 시험이 실패한다.
  - (g) QA의 6개 낱말을 분류로 확인한다: 「정해졌습니다」(제목, QM3-2)·「단순노무직」·「서비스직」은 결함이었으므로 0, 「다이아몬드수저」는 `intended`, 「제주특별자치도」(폭 320 · 글자 200%)·「전남광주통합특별시」(폭 375 · 글자 200%)·「초중고사교육비조사」(글자 200% 폭 640대)는 **측정이 가른다** — 한 줄 전체보다 길면 `unavoidable`(허용), 짧으면 결함이므로 고친다.
  - (h) qa가 M3-L02를 같은 절차(11뷰포트 × 12상태 × 글자 100·150·200%, 독립 측정기)로 재실행해 PASS. 개발 감사기와 qa 측정기의 `broken` 결과가 다르면 리포트에 차이를 적는다. 첫 화면(M2)도 한 번 돌려 결과를 남긴다(결함이 나오면 이 보완의 수정 범위).

#### QM3-2 제목(h1) 글자 크기 상한 (CM11, M3-L02의 제목 부분)
- **규칙**
  1. 새 화면 제목(h1)의 눈에 보이는 낱말은 **어떤 조합에서도 중간에서 끊기지 않는다.** QM3-1의 (a)(b) 허용을 제목에는 쓰지 않는다 — 「정해졌습니 / 다」처럼 한 글자가 홀로 남는 것은 금지다.
  2. **폭 320 · 글자 200%에서도 제목의 가장 긴 낱말이 한 줄에 들어가도록 글자 크기에 상한**을 둔다. 상한은 rem 고정값이 아니라 **줄 폭 기준**이다(루트 글자 200%는 rem이 두 배라 rem 상한만으로는 부족하다). 구현 힌트(강제 아님): `font-size: min(기본 크기, 줄 폭 ÷ (가장 긴 낱말 글자 수 + 여유))`; 가장 긴 낱말 글자 수는 문구 상수에서 계산하고, 단위 테스트가 그 값이 실제 제목의 가장 긴 낱말과 같음을 단언해 새 제목이 상한을 조용히 넘지 않게 한다.
  3. 상한 때문에 제목이 본문보다 작아지지 않는다(제목의 계산 글자 크기 ≥ 같은 화면 본문 문단의 계산 글자 크기). 낱말 **사이**에서 제목이 여러 줄로 접히는 것은 허용한다.
  4. 대상: 첫 화면·룰렛(회전 중·결과)·출생신고의 h1과 앞으로의 새 화면 h1. 출생신고의 큰 이름(`birth-name`)은 제목이 아니라 QM3-1 일반 규칙을 따른다(낱말이 한 줄 전체보다 짧은데 끊기면 결함).
- **완료 기준**
  - (a) e2e: 위 대상 × `STANDARD_VIEWPORTS` 11종 × 글자 100·125·150·175·200%에서 h1의 낱말마다 ① 한 줄에 놓인다(`Range` 줄 수 1) ② 자연 폭 ≤ h1 내용 폭 ③ 제목 계산 글자 크기 ≥ 본문 문단 계산 글자 크기.
  - (b) 룰렛 결과 제목 「태어날 곳이 정해졌습니다」가 폭 320·360 · 글자 200%에서 「정해졌습니」/「다」로 갈라지지 않는다 — 이전 구현에서 실패함을 확인한다(QA 실측: 360×740 · 200%, 360×568·320×256도 같음).
  - (c) 변조: 글자 크기 상한을 빼면 (a)가 폭 320·360(·320×256) × 글자 200%에서 실패한다.
  - (d) reviewer가 320×568 · 글자 200%의 룰렛 결과·출생신고 스크린샷을 이미지로 직접 열어 한 글자가 홀로 남지 않음과 제목의 위계가 유지됨을 DS7 가독성 근거에 적는다.
  - (e) M3-L02 재실행(QM3-1 (h))에 포함한다.

#### QM3-3 안내 문구는 없는 기능을 가리키지 않는다 (BR1·VP3·VP4, M3-O05 — R-201과 같은 계열)
- **규칙**
  1. 화면의 문구가 다른 화면·기능을 가리키면(「대시보드 오른쪽 칸에서 …」「… 화면에서 볼 수 있습니다」), 그 화면·기능이 **지금 배포된 판에 있을 때만** 보인다. 없는 기능을 약속하지 않는다 — 화면 사이 거짓 안내 0(R-201 원칙의 일반화).

#### QM3-5 장식 포함 대비 전수와 강제 색상 렌더 (DS3, M3-O02·R-291)

- **C4** 수저 등급명은 룰렛·출생신고·프로필 카드에 직접 표시하고 이벤트·연표·엔딩 본문에는 쓰지 않는다. **C5** 자동 모드에서 기록 카드는 건너뛰고(「마음속에 담고 살기」 처리), 「다음부터 이 창 띄우지 않기」(캡처에는 있고 요청에는 없음) 설정을 둔다. **C6** v4 이하 저장은 새 게임으로 시작한다(Pages는 origin이 달라 기존 로컬 판과 어차피 공유되지 않는다). **C11** 가상 인구 = 한국 인구 1/1,000 축소(약 5만 명대) + 출생·사망 반영 완만 변동(「접속자」로 오해될 임의 숫자는 채택하지 않음). **C12** BGM 기본 꺼짐·볼륨 조절 포함. **C13** 엔딩에 플레이 시간 표시(사람 실측용, 요청에 없는 UI 추가). **C15** 글꼴·번들 크기는 designer가 M1에서 제안하고 마스터가 확정.

### 남은 결정 (아직 정해지지 않은 것)
- **R1 출생 월 (Q1 부속)**: 지금 세상 출생 연도는 2026으로 고정됐지만 **출생 월**은 정해지지 않았다. 오늘(2026-10-15)보다 늦은 달도 시뮬레이션 안의 시간으로 허용할지, 요청 예시처럼 1월로 고정할지, 올해 1~10월로 한정할지. **[가정] 1~12월을 통계(월별 출생아 수) 가중으로 추첨, 오늘 날짜와 무관**
- **R2 합쇼체 통일 범위 (C1 부속)**: 형진 님이 문구를 정해 준 첫 화면 문구(「~살고 있어요」)와 버튼·선택지 라벨(「~한다」 형태)·시스템 안내(저장 실패 등)의 어체를 어떻게 할지. **[가정] 사건·결과·카드 본문·엔딩은 합쇼체, 첫 화면 문구·버튼·선택지 라벨·시스템 안내는 현행 유지**(라벨까지 합쇼체로 바꾸면 선택지 라벨 수백 개를 더 고쳐야 하고 길이 한도 24자도 다시 잡아야 한다)
- **R3 형진 님 제공 소재의 `seenCount` (C9 부속)**: SPEC-002 T3는 「서로 다른 글 2건 이상에서 공통인 유형만(`seenCount ≥ 2`)」인데, 형진 님이 직접 읽어 요약해 주시는 경우 그 건수를 어떻게 셀지. **[가정] 형진 님이 「이런 유형이 자주 보인다」고 건네는 요약은 유형으로 보고 `seenCount`에 형진 님이 확인한 건수(모르면 1)를 적되, 특정 개인의 고유한 사건이면 올리지 않는다(T3 정신 유지)**
- 나머지 마스터 확인 항목에는 남은 결정이 없다.

### 지금 시점 정리
- 확정 직전에 형진 님께 넘길 것은 **마스터 결정 표와 남은 결정 R1~R3**이다. 이 중 R1은 룰렛·출생신고 구현(M3) 전에, R2는 합쇼체 전환(M7e) 전에, R3은 소재 접수(M6c) 전에 정해지면 된다.
