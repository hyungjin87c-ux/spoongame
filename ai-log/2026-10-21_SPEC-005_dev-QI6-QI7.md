## 1. 구현 요약

### QI6 — 무거운 장면 가리기
- **표지**: 이벤트의 선택 필드 `heavy: { kind }`(6종) — 이벤트 23개(home 3·school 2·health 7·loss 5·bond 3·work 3). `eventId`가 없는 상속 줄은 줄을 만드는 쪽의 글자 상수(`HEAVY_LINES_WITHOUT_EVENT`)로 loss를 매긴다 → 옛 v8 저장의 상속 줄도 같은 길로 잡힌다(M20), 저장 스키마 변경 없음.
- **화면 규칙 (A)**: 가림 여부는 **지금의 설정값 `gentle`** 하나로 정한다. 줄마다 저장하지 않는다. 펼침은 React 상태이고 설정값이 바뀌면 초기화된다(M19), 저장하지 않는다(SV3).
- **`gentleUsed`**: `GameState`의 선택 필드, `true`만 쓴다. `sessionReducer`가 바뀐 상태에 대해 한 규칙(`markGentleUsed`)으로 붙인다 — 켠 채 새 판 시작·판 도중 켜기·켜진 설정으로 저장된 판을 이어 가기 세 길을 모두 덮는다.
- **가림 단위**: 인생 기록 줄(서술·결정·부모·흘러감·상속), 결정 카드(시트·인라인·접힌 띠), 부모·흘러감 카드, 엔딩 연표와 맨 위 한 줄, 첫 화면 자살률 슬라이드.
- **새 세션 액션**: `setGentle`, `autoPick`(가린 카드의 「이번에는 자동으로 고르기」 — 자동 모드 여부와 무관하게 지금의 자동 선택 성향으로 한 번 고른다, 상태는 수동으로 그 선택지를 고른 것과 같다), `seeNotes`.
- **가리지 않는 것(HV8)**: 사망 줄과 엔딩 맨 위 사망 문장(원인 낱말까지)·식구 카드 상태 문구·스탯/자산 미터·결정자 칩·도장·아이콘·첫 부모 카드 안내·기록 카드 ⑤⑥·상담전화.

### QI7 — 새 소식과 소개 패널
- 첫 화면 푸터에 링크 둘(「새 소식」·「소개」)과 「새」 표시(`hasUnseenNotes(APP_VERSION, notesSeen)`), 모달 시트 `InfoPanel`.
- 바깥 `inert`·`useScrollLock`·제목 포커스·닫으면 열었던 링크로 포커스, Esc·「닫기」·뒤로가기가 같은 닫기. 뒤로가기는 열 때 history 표식 하나를 넣고(`{suzeoInfoPanel: 토큰}`), 화면 닫기는 `history.back()`을 부르며 popstate가 500ms 안에 안 오면 직접 닫는다. 새로고침하면 복원하지 않는다.
- 새 소식: 최신 3개 버전 펼침. 소개: Q&A 10개 `<details>`(모두 접힘). 패널 끝 「의견 보내기」(`FeedbackLink variant="panel"`, 주소는 `buildFeedbackUrl(feedbackFieldsOf(첫 화면 값, REPO_URL, BUILD_LABEL))`).
- 패널 전체가 해요체(N1). Q&A 본문의 자리표시자 6개는 데이터에서 만든다(`CarouselData.orgs`, 이름 출처 기관, `helpLine`, `POPULATION_BASIS`, `LIFE_LENGTH_TEXT`, 부모 결정 상수).
- 버전 `0.2.0`(package.json), `notesSeen`은 패널을 열면 `APP_VERSION`으로 저장된다.

### 마스터 확인 사항
1. **WebKit에서 첫 화면 왼쪽 열이 Chromium보다 36px 길다.** `legend.group-title--inline`(`float: left`, QI3)을 WebKit이 분절 컨트롤 옆에 놓지 못하고 위에 쌓는다(「인생 길이」 줄 531~567, 컨트롤 567~605). 스위치 줄이 처음 그려지며 1280×800에서 왼쪽 열 끝이 690이 되어 **이어서 살기 띠(위끝 680)에 10px 걸린다** — 기존 시험 `first-screen-layout.spec.ts:118`(webkit-desktop)이 이 때문에 실패한다. 새 판 띠(732)에서는 괜찮다. 후보 수정(측정만 했음, 적용하지 않음): `.slot--small`을 `display: block`으로 두고 `.seg`를 `inline-flex`로 하면 WebKit 열 끝이 622가 되지만 두 엔진과 모든 첫 화면 시험의 영향이 크므로 designer 판단이 필요하다(`legend { display: contents }`는 WebKit에서 접근성 트리가 깨질 위험이 있어 쓰지 않았다). 사람이 많이 쓰는 PC Chrome·안드로이드 Chrome에는 영향이 없다.
2. **번들**: Chromium(그림 한 장) 367,634B로 충족, **WebKit 최악(그림 두 장) 401,337B가 십진 400KB를 1,337B 넘는다**(400KiB로는 충족). QI3 마스터 확인 4번(그림에 `srcSet`/`sizes`)이 이 여유를 되찾는 길이다.
3. **자살률 슬라이드를 펼쳐 둔 동안에도 자동 넘김이 돈다.** 펼쳐서 읽는 중에 다음 슬라이드로 넘어가면 다시 가려진다(터치 사용자는 최대 약 9초). 펼친 동안 자동 넘김을 멈출지(`paused` 사유에 「가림 펼침」 추가) 결정해 주세요 — 이 회차에는 SPEC 밖이라 넣지 않았다.
4. **v0.2.0 노트의 날짜 2026-10-21은 임시**(QI8 「배포일로 고침」 줄을 TODO에 더했다). `package-lock.json`의 루트 버전 필드는 0.1.0으로 남겼다(`npm install` 없이 `package.json`만 0.2.0으로 올렸고, 락 파일을 건드리면 Vite 의존성 캐시가 다시 만들어져 다른 작업과 충돌했다) — 배포 때 `npm install --package-lock-only`로 맞출지 결정해 주세요.
5. **QI4 의존**: FAQ Q3의 「전망 카드는 예측이 아니라 공식 기관의 추계」 문장은 시험 분기가 전망 슬라이드가 병합되기 전에는 꺼져 있다(QI8에서 켜지는지 확인). Q8 상담전화 줄은 `getUsableIndicator('suicide-rate').helpLine`에서 만들어 QI4가 지표 데이터를 바꿔도 따라간다.
