## 7. 구현 중 찾아 고친 결함 (제품 코드 5건 + 시험 도구 2건)
1. `ui/useBottomBar.ts#useScrollTopOnMount`: StrictMode(개발 모드)가 layout 효과를 passive 효과보다 뒤에 한 번 더 돌려 선택지 카드를 보이게 한 스크롤(`revealCard`)을 맨 위로 되돌렸다 → 처음 한 번만(변조 V3로 잡힘).

3. `styles.css`: 하단 띠·고정 머리가 없는 화면(엔딩·밀린·오류)에서 큰 글자·낮은 화면의 포커스 링이 화면 위로 5px 나갔다 → `html { scroll-padding-block: var(--sp-3) }`.
4. `core/peerNow.ts`: 또래 규칙표의 25~29세에 「돌봄」(허용은 30세부터) → 표 수정(V1).
5. `ui/useYearClock.ts`: 새 나이를 이전 한 해의 100%와 한 프레임 같이 보이던 순간을 막는 layout 효과 알림 추가(방어 코드, 8절 정직 보고).
6. 도구: `e2e/focusObscured.ts`가 `<summary>`를 Tab 정지점으로 세지 못해 집합 대조가 어긋났다 + `resetFocus`가 문서 뒤쪽에 프로그램 포커스가 가 있는 채로 시작하면 첫 Tab이 중간에서 시작해 공허 통과할 수 있었다 → 문서 맨 앞 임시 요소로 출발점을 되돌림.

## 9. 남은 문제 · 부탁
- **BGM 소리 품질은 기계로 못 본다.** 코드가 음을 예약하는 것(AudioContext 1개·기본 꺼짐·볼륨·끄면 멈춤·음원 파일 요청 0)까지만 시험했다. 사람이 귀로 확인해 주세요(M9 사람 실측).
- **V2**: 진행률 바 깜빡임 방어는 시험이 못 잡는다(8절).
- **디자이너 몫**: `copy.md`에 나가기 확인 단계·BGM 볼륨 행 추가, 비활성 「다음 결정으로」 3.77:1 판단, `contrast-report.md` 재생성(머리글이 새 문구로), 인생 기록 단계 줄 모양.
- **범위 밖(그대로 둠)**: 중대 결정 시트(M7b), 생각 남기기 본체(M7c), 자산 금액(M5), 엔딩 여정 막대.
- 개발 서버 전체 e2e는 약 21분이 걸린다. `entry-guard`의 스윕 제한 시간을 120초 → 240초로 늘렸다(12개 조작 요소 × 11 뷰포트).
- 개발 서버 전용 탐침(`?__timescale` 등)을 쓰는 시험은 시간 배율이 크면 인생이 끝까지 흘러 칸이 사라질 수 있다 — 새 시험은 저장된 판을 기준으로 기다린다.
