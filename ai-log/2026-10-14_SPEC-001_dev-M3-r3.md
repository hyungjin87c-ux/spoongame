## 결과 요약
- **R-036 (마스터 규칙 그대로)**: 컨트롤 그룹의 Tab 순서는 항상 `1·2·4·8배 → 다음 결정으로 → 자동 모드`. "다음 결정으로"는 선택지 대기·자동 모드일 때 `disabled`가 아니라 `aria-disabled`(포커스 받음, 클릭/Enter/Space 무시, 흐림 0.55). `GuardedButton.isButtonInert`가 호출자 `aria-disabled`와 가드를 합침(둘 중 하나라도 비활성이면 무시, 가드가 풀려도 호출자 비활성 유지). 사용자가 "다음 결정으로"를 눌러 뜬 선택지는 `noteSkip` 표시로 판단해 선택지 제목으로 포커스 이동(disabled 판정에 기대지 않음). 그 밖의 1회차 규칙(자동 모드 이동 없음 / 컨트롤 안 포커스는 aria-live 알림 / 그 외 선택지 제목 / 복원 경로 동일 / 선택 뒤 body면 `h1`)은 유지.
- **R-048**: 선택지 대기 중 자동 → 수동 전환(`autoTurnedOff`) 때 같은 규칙 재적용. 옛 경쟁 테스트를 가려진 탭 기반의 결정적 테스트 4건으로 나눔(대기 중에 끈 경우 / 대조군 / body 포커스 / 끈 뒤에 뜬 경우).
- **R-049**: `vite-node` `^2.1.9`(lock 2.1.9) devDependencies 선언 — `package-lock.json`은 루트 선언 한 줄만 추가(다른 패키지 버전 변화 0). `tsconfig.node.json` 신설로 Node 전역 선언을 scripts·설정에만 보이게 하고 `typecheck`가 두 설정을 모두 검사(`src/`에 `process`를 쓰면 TS2591로 실패함을 변형으로 확인).
- **R-050**: 겹침 표 삭제 → 뷰포트마다 측정한 교집합 한가운데를 더블클릭. 경계 뷰포트(360x520·600·640)를 14px 이상 겹치거나 26px 이상 안 겹치는 것으로 교체, 안 겹치는 곳은 짧은 점검만. 공허 통과 방지 테스트(겹침 관측 5곳 이상 + 대조군 변화 5곳 이상)를 별도 테스트로. 소요 시간은 직렬이었다면 107초였지만 뷰포트별 독립 테스트 + 측정 전용 집계 테스트로 바꿔 파일 전체 약 32초.
- **R-051 / R-052**: 해당 파일들의 항상 참 단언·제목·주석 정리, reducer "자동 켜짐 + 낡은 key" 단언 복원, 빈 저장소 + 쓰기 실패 e2e, 프로덕션 스모크에 "다음 결정으로 → 선택 반복 → 사망" 추가. `App.tsx`는 저장소 원문을 한 번만 읽고(`readBoot`), 저장 직전 `decideSave`로 비교해 다르면 덮어쓰지 않고 밀린 화면으로, 이미 저장돼 있으면 쓰지 않고 실패 안내를 지움.

## 임의 결정 (이견 있으면 알려 주세요)
1. `vite-node`는 정확한 `2.1.9`가 아니라 프로젝트의 다른 devDependencies와 같은 `^2.1.9`로 선언(lock 해석은 2.1.9 그대로).
2. 설정(`settings`) 저장은 "마지막 쓰기 우선" 그대로 두고 밀린 화면 대상에서 제외(진행을 잃지 않으므로). 저장 직전 비교·밀린 화면 전환은 게임 저장에만 적용.
3. 같은 탭에서 개발자 도구로 저장을 바꾼 뒤 새로고침 없이 계속 진행하면 이제 "저장이 바뀌었습니다" 밀린 화면이 뜬다(예전에는 조용히 덮어썼다). 새로고침하면 그 변경이 존중되는 기존 동작과 같은 방향.
4. 두 탭이 거의 동시에 빈 저장소로 뜨면 나중에 쓰려던 탭이 밀린 화면(이어하기)이 된다.
5. 낡은 뷰포트 표를 쓰지 않으므로 `entry-guard`의 경계(겹침 4px 미만은 "안 겹침"으로 취급). 스위트 수준 하한은 이 환경의 측정값(살아가기 겹침 6곳, 이어하기 3곳)보다 한 곳 여유를 둔 5·2.
6. R-036 e1은 2·4·8배만(1배는 다음 Tab이 2배로 가서 해당 경로가 아님). e2 마우스 변형을 추가.
7. `focusPlaceOf`의 "disabled 버튼 = body" 분기는 이 화면에 disabled 버튼이 없어졌지만 방어용으로 남김.
