# 2026-10-13 SPEC-001 dev-M2-names (이름 원자료 수집)

- 누가: developer
- 무엇을: 형진 님이 지정한 대법원 통계(전자가족관계등록시스템 > 통계서비스 > 상위 출생신고 이름 현황)에서 2008~2025년 연도별·성별 상위 이름을 직접 수집해 원자료로 저장. 게임 데이터(`names.json`, `names.ts`)와의 통합은 하지 않음(다음 단계 지시 대기).
- 결과:
  - 새 파일 2개: `src/data/sources/scourt-birth-names.json`, `docs/data/names-source.md`. (금지 파일은 건드리지 않음. npm 스크립트 실행 없음.)
  - 조회 방식: 페이지가 iframe에서 `POST /ds/report/query.do`(pid=1811, sqlid=1811-0)로 표를 받는다. 이 요청을 가로채 확인한 뒤, 연도·성별만 바꿔 Node.js 스크립트로 36회 순차 호출(요청 간 0.5~1.0초, 재시도 최대 3회, 전부 1회 성공). 이름·건수는 응답에서 스크립트로 추출, 손 전사 없음.
  - 전국 집계: 시도 콤보가 다중 선택이라 25개 코드 전부(현행 시도 + 구 행정구역 코드)를 동시에 선택한 **단일 조회**. 시도별 합산 아님. 3건에서 시도별 개별 조회 합계 = 단일 조회 합계 정확히 일치. 구 코드(광주광역시(구) 등)에 실제 건수가 있어 전부 선택이 필수.
  - 확보 범위: 2008~2025 x 남/여 = 36칸 전부 성공, 칸마다 **상위 20개**(서비스 최대치; 상위 20 + "기타" 21행). 상위 30개 목표는 서비스 한계로 미달. 합계(전체 건수)도 응답에서 얻어 `totals`에 저장.
  - 서비스 최소 연도 2008. 2007·2000을 직접 요청하면 `data: []`. 2008년 이전 자료 없음(안내문 "시행(2008. 1. 1.) 이후", 연도 선택지 2008~2026).
  - 검산: 무작위 3건(2024 남, 2025 여, 2008 남)을 화면에서 재조회해 1~5위 이름·건수, "기타", "합계" 전부 일치. 응답 내부 일관성(36건)도 확인: 이름 행 ratio는 상위 20 합계 대비 %(전체 대비 아님).
  - 이용 조건: 사이트 저작권 보호 정책상 출처 표시를 전제로 자유이용 가능(저작권법 제24조의2). 권장 출처 문구를 meta에 기록.
  - 한계: 등록일 기준·잠정치(출생연도와 어긋날 수 있음), 20위 경계 동점 절단 여부 관측 불가, 한자 구분 불명, 통계청 출생아 수와 대조 안 함.
- 설계/가정(임의로 정한 것): JSON 구조는 `meta` / `years[연도][M|F]` / `totals[연도][M|F]`. "기타" 행은 `years` 배열에서 빼고 `totals.othersCount`로 분리. `ratio`는 화면의 퍼센트 값 그대로.
- 다음 단계: 마스터가 결과를 보고 (1) 2008~2025 상위 20으로 충분한지, (2) 21~30위가 꼭 필요하면 시도별 조회로 하한값 추정을 할지(권장하지 않음), (3) 2008년 이전 연대 이름 풀은 기존 언론 인용 요약+estimated 방식 유지할지 결정 후 `names.json` 통합 지시.
