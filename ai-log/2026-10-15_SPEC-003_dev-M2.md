## 가상 인구 계산식 (`src/core/population.ts`)
`N(분) = round( base + clamp(driftPerYear × (분 − 기준분) ÷ 525,600, ±900) + Σ 진폭ₖ × 값잡음(분 ÷ 주기ₖ) )`
- `base` = 주민등록 인구(행정안전부 2026.09, `region-population-registered`) 51,082,431 ÷ 1,000 = **51,082**. `driftPerYear` = (출생아 254,341 − 사망자 362,968) ÷ 1,000 = **−108.627명/년**(`births`·`cdr.deaths2025`). 기준 시각 2026-10-01 00:00 UTC(에포크 분 29,846,880). 추세 누적은 ±900명에서 멈춤(5만 명대 유지, 설계값). 근거 값은 코드에 적지 않고 접근자에서 읽는다(테스트가 JSON 원자료와 대조).
- 값잡음 네 겹(설계값, 통계 아님): 하루 ±80, 6시간 ±30, 1시간 ±12, 10분 ±4 = ±126명(규모의 ±0.25%). 정수 해시 + smoothstep 보간이라 난수 없이 연속이다. 같은 분이면 같은 값, `Date`·`Math.random` 없음(시각은 `useEpochMinute`가 UI에서 주입).
- 검증(임의 시각 1만 표본, 2020~2080): 항상 50,000~59,999, 1분 변화 ≤ 2명(0.05% 한도의 1/10), 하루 사이 변동 ≤ 0.5%, 1시간 안에 서로 다른 값 여러 개, 한 해 뒤 평균 −108명 근처.
- 화면 표기: 「N명이 이 시뮬레이션 속에서 각자의 삶을 살고 있어요.」(형진 님 지정 문구 그대로) + 보조 문구 「이 기기 안에서 계산한 가상의 사람들이에요. 실제로 게임하는 사람 수가 아니에요.」(designer 시안 최신 문구, 「접속자」 낱말 없음) + 푸터의 가상 인구 설명 한 곳.

## 알려진 것·남은 것
- 간헐 실패: 전체 e2e를 돌리는 동안 다른 developer가 데이터 파일을 고치면 개발 서버가 페이지를 새로 읽어 `injectSave`/`scrollIntoViewIfNeeded`가 「Execution context destroyed」·「not attached」로 실패하는 경우가 한두 번 있었다(다시 돌리면 통과, 같은 시나리오 단독 실행도 통과).
- 첫 화면을 다시 여는 길(「나가기」)은 M4가 붙인다. 지금은 개발 탐침으로만 연다.
- `src/styles.css`(옛 화면)는 그대로다. 옛 화면은 M3·M4에서 새 디자인으로 바뀌면 `body.theme-surface` 분기를 지우면 된다.
- 하단 띠의 safe-area는 `env(safe-area-inset-bottom)`으로 처리했지만 `viewport-fit=cover`는 옛 화면에 영향을 주므로 켜지 않았다(켜지 않아도 iOS 브라우저는 홈 인디케이터를 피해 고정 요소를 놓는다). 대시보드 개편(M4) 때 같이 결정하면 된다.
